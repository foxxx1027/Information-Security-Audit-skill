# Information-Security-Audit-Skill

> **一套面向 Web 平台安全审计的可执行技能库：257 个方法论技能 × 八大类审计分类导航 × 触发式调用机制。**

把安全审计领域的成熟方法论固化为一个个可独立调用的「技能卡片」——每张卡片回答一个问题：**遇到这类审计场景，该怎么一步步做、依据是什么、什么时候不该这么做。** 适用于人工审计作业参考，也可直接装载到 AI Agent（Claude Code / Cursor 等）作为可自动触发的领域技能。

---

## 一、这套技能库是什么

一个技能 = 一份结构化的审计作业方法论，包含**方法论解读、真实应用案例、触发场景、可执行步骤、使用边界、原文依据**六部分。257 个技能覆盖从资产测绘、应用层漏洞、代码审计、基础设施、日志监控、管理合规、第三方集成到渗透验证的完整审计链条。

**规模一览**：

| 维度 | 数量 |
|---|---|
| 技能总数 | 257 |
| 审计分类（八大类 + 通用支撑层） | 9 |
| 应用层安全子域 | 8 |
| 技能集合 | 7 |
| 技能间引用关系（依赖/对比/组合） | 343 |
| 触发测试用例 | 1542 |
| 触发盲测通过率 | 93%–99%（回炉修复后 100%） |

- **导航层（audit-map/）**：按「Web 平台安全审计范围」的八大类组织，每层目录一份说明文档（审计范围定义 + 技能清单 + 归类理由 + 覆盖缺口提示），是按**工作流**找技能的入口；

## 三、技能卡片解剖

每个技能是一份固定结构的 `SKILL.md`，由 **frontmatter 元数据 + 六段正文**构成：

### frontmatter（机器读取部分——决定技能何时被自动激活）

```yaml
---
name: caudit-payment-invariants        # 技能唯一标识（=目录名）
description: |                         # ≤300字：何时调用 + 何时不调用 + 中英双语触发词
  ……处理支付/订单/优惠金额一致性问题时调用；不适用于……
source_chapter: ……                     # 方法论出处（可溯源）
tags: [payment, business-logic, invariant]
related_skills:                        # 技能间引用关系（依赖/对比/组合）
  - slug: caudit-server-side-state-truth
    relation: depends-on
---
```

### 六段正文（人与 Agent 共读部分）

| 段 | 名称 | 作用 |
|---|---|---|
| **R** | 原文依据 | 方法论的一手出处引用（≤150 字，章节可溯），保证「有据可查」 |
| **I** | 方法论骨架 | 用自己的话重写的核心逻辑（5–15 行），没读过原文也能懂 |
| **A1** | 应用案例 | 1–3 个该方法论被实际使用的案例：遇到什么问题 → 怎么用 → 得出什么 → 结果如何 |
| **A2** | 触发场景 ★ | 用户会在什么情境下需要它（3–5 条）、语言信号（中英双语）、与近缘技能的区分——这是技能被精准调用的关键 |
| **E** | 可执行步骤 | 3–7 步操作流程，每步带**完成标准**与**判停条件**，拿来即用而非空泛原则 |
| **B** | 边界 ★ | 什么时候**不要**用、已知的失败模式、时代局限（如旧标准版本差异）、易混淆的邻近方法论——防止滥用 |

## 五、质量保障体系

这套技能库的每个技能都经过两道质量闸门，证据随仓库携带：

### 5.1 准入验证（内容质量）

每个技能入选前通过三重验证，判定记录可溯：

- **跨域验证**：该方法论在至少 2 个独立语境下成立（不同章节、不同对象、不同结论），排除一时兴起的表达；
- **预测力验证**：用它能推导出一个原始材料未直接讨论的新场景结论，排除「只能复述例子」的描述性内容；
- **独特性验证**：抹掉出处后仍非「任何聪明人都会说的常识」，只保留真正差异化、反直觉的方法论资产。

### 5.2 触发盲测（调用质量）

1542 条测试用例（每技能 6 条：3 正向 + 2 诱饵 + 1 边界），由未参与建设的独立 Agent 做全目录「选择题」盲测——面对一条用户话语，从整集合中判断该激活哪个技能或都不激活：

- **诱饵零容忍**：每技能至少 1 条「应触发同集合兄弟技能」的抢调诱饵，专门防近缘技能互相抢调用；
- **回炉机制**：首测通过率 93%–99%，未达标技能回炉修正触发描述后定向复测，**最终 257/257 全部通过**；
- 每技能目录下的 `test-prompts.json`（darwin 兼容格式）与 `test-results.md` 完整保留测试基准与结果。

## 六、使用方式

### 6.1 人工使用（按审计工作流浏览）

```
1. 打开 audit-map/README.md → 找到你当前的审计类别
2. 进入对应目录 README → 看技能清单表，按"一句话说明"定位技能
3. 点击技能链接进入 SKILL.md → 按 E 段步骤执行，B 段确认边界
4. 需要扩展阅读时按"相关 skills"段跳转关联技能
```

### 6.2 Agent 装载（自动触发）

将 `skills/<集合>/<技能目录>` 复制到宿主技能目录（如 `~/.claude/skills/`、`~/.trae-cn/skills/` 或项目级 `.claude/skills/`）：

```bash
# 示例：装载全部技能到用户级目录
for c in webapp-defense code-audit pentest-methodology system-audit-verification \
         compliance-assessment crypto-foundations crypto-engineering; do
  cp -r skills/$c/*/ ~/.claude/skills/
done
```

装载后，当对话中出现匹配场景（如「这个找回密码流程会不会被绕过」「TLS 证书该校验哪些字段」），对应技能按其 `description` 自动激活，Agent 按 E 段步骤给出操作指导。

### 6.3 持续进化（darwin 兼容）

`test-prompts.json` 为 [darwin-skill](https://github.com/) 兼容格式，可接入自动化进化流程做回归测试与迭代改进。

## 八、约定与说明

- **分类是导航不是边界**：技能的适用范围以其 SKILL.md 的 A2/B 段为准；`09-通用安全方法论` 是支撑层，先查 01–08 专属技能，无匹配再回退；
- **覆盖缺口透明**：各分类 README 末尾明示未覆盖的子域（如子域名接管、隐私合规细则、CVSS 定级），使用时需配合外部工具或流程；
- **时代局限标注**：涉及标准版本（如 ISO 27001、等保 1.0→2.0）与技术演进（TLS 1.3、AEAD、后量子）的技能，其 B 段均写明版本差异提示，使用前先读边界。
