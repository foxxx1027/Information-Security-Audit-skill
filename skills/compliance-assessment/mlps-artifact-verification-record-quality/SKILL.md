# 产物核验与记录实质性质检

## R — 原文 (Reading)

> "a.访谈安全负责人，明确是否对审计记录进行分析并生成审计报表；
> b.如对审计记录进行分析并生成报表，检查近期的日志审计报表是否对安全可疑事件
> 进行分析追踪等。"
> "UPS设备仅提供半小时的应急供应，市政供电未在半小时内恢复。柴油发电机异常无法供电，导致系统停运6h，给该企业造成近580万元损失。"
>
> — 原作者 等，原始方法论来源第8章 8.3.3 SQLServer 安全审计（source.txt L6150–6153）+ 第12章 12.4.1 环境管理案例（L10790–10792 附近）

## I — 方法论骨架 (Interpretation)

管理类指标常说"要定期分析、定期巡检"。测评时第一反应是访谈，但访谈只能确认**意图**（有没有这个流程），确认不了**事实**（真的做了吗）。两步法把两者分开：

1. **访谈定流程**：负责人说得出流程、周期、职责——只代表制度设计存在。
2. **实物定事实**：核验近期产物（报表、记录、报告）本身。从未生成报表 = 直接不符合；有报表但只是原始日志罗列 = 未做分析，部分符合。

第二步之上还有一层**实质质检**：记录不等于证据。580 万损失的 UPS 案例里，季度检查记录一应俱全、签字齐备，但通篇"正常"字样、无测试条件与测试数据——签字式检查证明不了设施可用，双电源照样全失效。质检看四要素：测试条件（什么环境下测的）、测试数据（测出了什么数值）、处置人（谁做的谁签的）、时间分布（与业务周期吻合否）。时间戳集中在检查前夕 = 突击补记录；全篇无异常 = 要么没真做要么没真看。证据的效力取决于**内容要素齐全度**，一叠无实质的记录不如一份有数据的记录。

## A1 — 书中的应用 (Past Application)

### 案例 1: SQLServer 审计报表两步法（第8章 8.3.3，fw50）
- **问题**: "能对审计记录分析并生成报表"怎么核？
- **方法论的使用**: 先访谈安全负责人确认是否分析并生成报表；再检查近期报表实物，看是否对安全可疑事件做了分析追踪。
- **结论**: 从未生成报表即不符合；访谈定性 + 记录验证缺一不可。
- **结果**: 两步法成为"分析报告类"指标的固定取证格式。

### 案例 2: UPS/柴发双失效 580 万（第12章 12.4.1，ce50）
- **问题**: 委托物业每季度交检查结果、门禁指纹双控——形式上管理到位，为何停运 6 小时损失 580 万？
- **方法论的使用**: 实质质检维护记录：全是"正常"字样，无带载/启动测试条件与数据，签字只证明"看过"不证明"设施可用"。
- **结论**: 签字式检查不构成设施可用的证据；应急电源检查必须含带载/启动验证与切换演练。
- **结果**: 该案例把环境管理从"有没有记录"推进到"记录能否证明设施真的可用"，成为实质质检的教案。

### 案例 3: 监控有采集无分析（第12章 12.4.5，pr076/ce56）
- **问题**: 系统管理员做运行状态监控，报警齐全，监控管理怎么判？
- **方法论的使用**: 查分析产物——仅在应急事件时忙于救火、事后无总结分析、无分析报告。
- **结论**: 采集报警不构成符合，分析报告才是关键证据；有监测无分析=部分符合。
- **结果**: 三项指标分别落部分符合/不符合/不符合，报告要求落到分析产物上。

### 案例 4: Linux 现场跑 ausearch/aureport（第8章 8.3.2，cs018）
- **问题**: "日志确可分析"如何现场证明？
- **方法论的使用**: 现场执行 `#ausearch`/`#aureport` 生成检索结果与报表，而非只见日志文件存在。
- **结论**: 能力类产物可当场操作验证，产物核验的现场版。
- **结果**: 审计报表项证据从"文件存在"升级为"演示可分析"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 等保/内审/外审核查分析报告、巡检记录、扫描报告、培训记录等过程产物。
2. 客户/供应商出示一叠"季度报告"证明管控有效，需判断证明力。
3. 疑似应付式合规（外审前突击补记录），需识别与定档。
4. 自查整改：把"有记录"升级为"有实质要素的记录"。

### 语言信号 (用户的话里出现这些就应激活)

- "他们给了一摞巡检报告/扫描报告，算证据吗？"
- "记录全是'正常'，可信吗？substantive review 怎么做？"
- "访谈说有流程，要不要看实物？artifact 怎么核？"
- "记录日期都挤在检查前一周，怎么判？"（backdated / paper compliance）

### 与相邻 skill 的区分

- 与 `mlps-triple-consistency-check`（三重一致性核查）的区别: 三重一致性是管理域的整体取证框架（文档↔文档、实地↔制度、记录↔制度）；本 skill 是其中"记录"环节的深度质检技术——记录不仅要有，还要有实质。
- 与 `mlps-preponderant-evidence`（优势证据法）的区别: 后者裁决矛盾证据的强弱排序；本 skill 评定同类（文档）证据内部的效力梯度——数量多不等于效力高。
- 与 `mlps-backup-recoverability-verification`（备份可恢复性验证）的区别: 后者判"备份可否恢复"靠恢复演练实物；本 skill 判"过程记录可否采信"靠要素质检，同为"实物>纸面"家族。

## E — 可执行步骤 (Execution)

1. **访谈定流程**：确认负责人是否执行分析/巡检、周期、职责归属。
   - 完成标准: 流程描述记录在案（只作意图证据，不作符合结论）。
2. **核验产物实物**：索取近期 ≥2 个周期的报表/记录原件；从未生成 → 判不符合，停止。
   - 完成标准: 实物到手并核对与分析声明是否对应（说月度分析就要见到月度报表）。
   - 判停条件: 若拿不出任何产物 → 直接不符合，无需进入质检。
3. **四要素质检**：逐份查测试条件、测试数据（数值/发现项）、处置人与签字、时间分布（与周期/业务吻合度，警惕集中前夕）。
   - 完成标准: 每份记录四要素有/无标注；"全正常"或"无数据"记录单列。
4. **定档与穿透**：要素齐全=可作为符合证据；缺数据缺条件=部分符合并写明缺口；时间戳异常=按形式合规处理，转三重一致性穿透核查（实地/人员交叉验证）。
   - 完成标准: 判定落档 + 缺口/异常描述 + 是否穿透的处置记录。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 技术配置类指标（口令策略、端口最小化）——直接配置取证+实测，记录质检不适用。
- 一次性事件取证（某次应急响应做没做）——那是事件过程还原，不是周期产物核验。
- 记录齐全且含真实异常处置的——已是最强档证据，不必再套形式合规怀疑。

### 作者在书中警告的失败模式

- 访谈确认流程后直接判符合——跳过实物核验，是两步法明文针对的漏洞。
- 签字式检查充当可用性证据（580 万案例）；"全是正常"记录不构成设施可用证明。
- 突击补记录：外审前完善记录（ce40），时间戳与业务周期不匹配即露馅。
- 培训记录"计划有、执行打折、记录遗失"三链断裂（ce39）。

### 作者的盲点 / 时代局限

- **版本提示**：质检要素表源自等保 1.0 管理指标（GB/T 22239—2008 第 11/12 章语境）；2.0 管理域条目有调整，四要素本身（条件/数据/签字/时间分布）是普适审计技术，不受版本影响。
- 批判段盲点：全书整体假设"留痕≈落实"，本 skill 正是书中自带的修正器，但只对个别项（如恢复时限）做了穿透，未上升为系统性规则——使用者应主动把它推广到一切周期性记录。

### 容易混淆的邻近方法论

- document review（一般文档审查）：查有无与对错；本 skill 查记录的**实质要素与真实性信号**（时间分布、数据存在性），深一层。
- sampling audit：决定抽多少；本 skill 决定抽到之后看什么——两者可组合。
