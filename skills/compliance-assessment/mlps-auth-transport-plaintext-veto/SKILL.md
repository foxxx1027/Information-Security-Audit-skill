# 鉴别信息传输保护判据（明文一票否决 + 能力≠默认启用）

## R — 原文 (Reading)

> "a.针对采用Telnet方式远程登录操作系统的情况，则该项不符合。"
> "Oracle11g默认以明文方式进行数据传输，为了防止用户身份鉴别信息等敏感数据在网络传输过程中被窃取，Oracle11g提供了SSL方式对传输数据进行了加密，但需要对其
> 进行配置。"
>
> — 原作者 等，原始方法论来源第8章 8.3.2 Linux 身份鉴别 + 8.3.4 Oracle 身份鉴别（source.txt L5133、L6301–6303）

## I — 方法论骨架 (Interpretation)

传输保护的判定由两条互补规则构成：

**规则一：明文即否决。** 鉴别信息走明文通道，意味着任何旁路节点都可窃听——这是"一票否决型"缺陷，判定二值化：Telnet 管理远程主机＝不符合，SSH＝可继续查。不需要抓多少流量、统计多少口令，协议本身暴露就够了。这条规则把判定从"程度问题"升级为"性质问题"。

**规则二：能力存在≠默认启用。** 产品文档里的"支持 SSL"不构成证据：Oracle 默认明文、SQLServer 默认明文须配"强制协议加密"、RDP 会协商降级。取证必须落在两头——显式配置开关（配置文件里加密参数的实际值、模式是 STRICT 而非 PERMISSIVE）与实测（抓包看握手/密文）。厂商宣传页、功能清单一概无效。

两条规则合起来：先扫协议找明文（快速否决），再对"宣称加密"的通道验开关与抓包（防默认关）。另有适用性前置：REMOTE_OS_AUTHENT=FALSE（该远程登录功能未启用）时，Oracle 该项可先判"不适用"——判适用性在判符合性之前。

## A1 — 书中的应用 (Past Application)

### 案例 1: Linux 远程管理 Telnet 判不符合（第8章 8.3.2，ce23）
- **问题**: 远程登录协议怎么判定传输保护？
- **方法论的使用**: 规则一二值化——`#service --status-all | grep telnet` 查服务启用，启用 Telnet 即不符合；SSH 路径则继续查版本与配置。
- **结论**: 明文协议一票否决，无需附加取证。
- **结果**: 判定指令直接写入测评实施，成为可照抄的裁决。

### 案例 2: Oracle SSL"提供但须配置"（第8章 8.3.4，ce28）
- **问题**: Oracle 11g 声称支持 SSL，传输保护算符合吗？
- **方法论的使用**: 规则二——默认明文；REMOTE_OS_AUTHENT=FALSE 先判不适用；否则查 LISTENER 是否启用 TCPS 加密协议。
- **结论**: 能力存在≠默认启用，未配置加密即不符合。
- **结果**: 形成"默认不安全是厂商常态"的判定认识，SQLServer"强制协议加密"同构复用（cs022）。

### 案例 3: SQLServer 强制协议加密取证（第8章 8.3.3，cs022）
- **问题**: SQLServer 默认明文传输，检查落点在哪？
- **方法论的使用**: 查"强制协议加密"配置项（使用 SSL 请求连接），未启用即不符合。
- **结论**: 证据落在显式开关，而非数据库"支持 SSL"的版本说明。
- **结果**: 与 Oracle 例共同确立平台三例（Telnet/Oracle/SQLServer）同构证据规则。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 等保/内审核查"防止鉴别信息在传输过程中被窃听"类指标（远程管理、DB 连接、应用登录）。
2. 服务网格/微服务宣称"平台支持 mTLS"，验证是否全局 STRICT 且实际握手加密。
3. 红队报告列出 Telnet/HTTP 明文口令，整改后需按同一判据复核。
4. 老系统迁移评估：梳理还有哪些明文管理通道是"一票否决"级风险。

### 与相邻 skill 的区分

- 与 `mlps-data-transit-storage-grid`（数据传输/存储检查格）的区别: 后者是完整性/保密性 × 传输/存储的防漏检查格；本 skill 是其中"传输×保密（鉴别信息）"格的深度判定规则（否决强度+证据规则）。
- 与 `mlps-control-effectiveness-four-checks`（控制有效性四查）的区别: "能力存在≠默认启用"与四查的"生效查"同族，但本 skill 给出更强的判定强度（一票否决）与更具体的证据落点（配置开关+抓包）。
- 与 `mlps-active-verification-perturbation`（主动验证法）的区别: 后者用篡改报文验证完整性识别；本 skill 对保密性用抓包看密文，两者是通信类指标的一对实测手段。

## E — 可执行步骤 (Execution)

1. **枚举承载鉴别信息的通道**：远程管理（SSH/Telnet/RDP/VNC）、DB 连接串、应用登录接口、API/服务间调用，逐条列协议。
   - 完成标准: 通道清单含协议与启用状态（服务/端口证据）。
2. **扫明文，执行一票否决**：发现 Telnet/HTTP 等明文承载口令 → 该项判不符合，记录协议与端口证据。
   - 完成标准: 每条通道有"明文/加密/未启用"三态标注；明文项已定格不符合。
   - 判停条件: 若某通道对应功能整体未启用（如远程 OS 鉴别关闭）→ 先裁"不适用"，记录依据后跳过。
3. **对宣称加密的通道验开关与实测**：查显式配置（加密参数值、模式 STRICT/强制加密），再抓包看握手协议与载荷是否密文。
   - 完成标准: 配置值证据 + 抓包证据双落；"支持但未配置"记不符合。
4. **汇总裁决**：输出通道 × 判定（符合/不符合/不适用）矩阵，不符合项附整改指向（换协议/开强制加密/升模式）。
   - 完成标准: 矩阵无空格，每条不符合都有协议级原因。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 数据存储加密（落盘加密、TDE）——判据是存储保密性那一格，无"协议扫"捷径。
- 通信完整性（防篡改）——须"检测+恢复"成对验收，抓篡改实验，不是看密文。
- 内网管理面"低风险"辩解场景——一票否决不接受"内网所以明文可接受"的折中（书未给此豁免）。

### 作者在书中警告的失败模式

- 以"数据库支持 SSL"作答但配置页未开启加密协议（ce28 信号）。
- RDP 类"协商降级"：客户端不支持强协议时自动落到弱安全层——须查协商下限而非最高能力（第8章 cs009）。
- 混淆适用性与符合性：功能未启用判"不适用"要有配置依据（REMOTE_OS_AUTHENT=FALSE），不能因"难查"就绕过。

### 作者的盲点 / 时代局限

- **版本提示**：判定所依条款为等保 1.0（GB/T 22239—2008）身份鉴别类要求；2.0 沿用且加"通信传输保密性"独立控制点，平台细节（Oracle 11g、SQLServer 2008、RDP 协商）已过时，映射到现行环境（TLS 1.2+、mTLS、证书轮换）须重建检查表。
- 未涉证书管理与加密算法强度（弱密码套件、自签证书链）——"加密了"之外的质量维度书未覆盖。

### 容易混淆的邻近方法论

- 通用"加密流量审计"：重在发现加密滥用（恶意 C2 藏加密）；本 skill 反向——验证应加密处真的加密了。
- pentest 的明文凭据嗅探：作为攻击证据；本 skill 把同一发现收敛为合规判定档位与整改指向。
