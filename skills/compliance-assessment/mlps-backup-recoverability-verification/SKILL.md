# 备份恢复的可恢复性验证

## R — 原文 (Reading)

> "（5）应定期执行恢复程序，检查和测试备份介质的有效性，确保可以在恢复程序规定的时间内完成备份的恢复。"
> "但对于相关备份文件异地备份的重要性等因素考虑欠妥，近期一场大火导致设备损毁，使客户数据信息全部丢失。"
>
> — 原作者 等，原始方法论来源第12章 12.4.11 备份和恢复管理测评指标（source.txt L12258–12263）+ 案例（ce59 摘录，原文见 12.4.11 案例分析）

## I — 方法论骨架 (Interpretation)

备份核查最容易在第一步就走偏：看见备份作业绿了就打勾。本方法把判定重心从**存在性**搬到**可恢复性**——"备份是手段，恢复才是目的"。四层证据链逐层收窄：

1. **识别层**：备份清单是否覆盖重要业务信息、系统数据**和软件系统**——没进清单的数据等于没备份。
2. **策略层**：策略文档八要素——范围、方式、频度、存储介质、保存期、**放置场所、文件命名规则、离站运输方法**。后三样最常缺，恰是火灾案例的致死点：备份介质与设备同址，火烧一次全灭，消防检查通过也救不了。
3. **程序与记录层**：备份过程按程序执行且有记录（周期性记录不连续=执行断档）。
4. **验证层（决定性）**：定期执行恢复程序、测试介质有效性、确认能在规定时限内完成恢复。技术侧配套：本地完全备份至少每天一次+介质场外、异地定时传送、拓扑与硬件冗余。

判分基线可提炼为三条硬证据：无制度文本、无周期性记录、无恢复测试记录——**三项缺一即直接不符合**。云上"自动多副本"的答辩无效：副本通常只覆盖数据平面，回答不了"误删/勒索/区域故障后多久能恢复"（RTO/RPO）。

## A1 — 书中的应用 (Past Application)

### 案例 1: G 公司火灾介质同址全损（第12章 12.4.11 案例，ce59）
- **问题**: 每周日晚自动磁带备份、标号存放、手册写明恢复方法、消防检查通过——为什么一场大火客户数据全部丢失？
- **方法论的使用**: 按策略要素核查——备份磁带与设备同址存放（未异地）、木结构仓库易燃且机房可自由出入。
- **结论**: "有备份"≠"可恢复"；介质存放场所与离站运输正是备份策略必填项。
- **结果**: 判定除前两条外全部不符合；该案成为"存在性思维"的警示教材。

### 案例 2: 微型民企零证据直接不符合（第12章 12.4.11 案例，ce60）
- **问题**: 无数据管理规定、备份凭"突发安全意识"偶尔为之，怎么判？
- **方法论的使用**: 三条硬证据齐缺——无制度文本、无周期记录、无恢复测试。
- **结论**: 提炼判分基线：三项缺一即直接不符合，无需逐项讨论。
- **结果**: 五条要求全部不符合，判定效率与一致性兼得。

### 案例 3: 技术块四项指标（第9章 9.3.3，fw65）
- **问题**: 备份恢复的技术控制点怎么测？
- **方法论的使用**: ①本地完全备份每天至少一次+介质场外；②异地定时批量传送；③拓扑冗余避免单点；④硬件冗余——查策略文档、备份记录、恢复测试报告与介质场外证据四件套。
- **结论**: 技术块与管理块（12.4.11 四层）双线互证。
- **结果**: 备份测评形成"策略→记录→测试→场外"完整证据链。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 等保/内审/ISMS 审核的备份和恢复管理控制点核查。
2. SaaS/云厂商答辩"数据自动多副本不需要备份演练"，需要可辩护的判定。
3. 备份制度设计或整改：按四层建证据链、按八要素补策略。
4. 灾备演练计划评审：验证演练是否覆盖恢复时限与介质有效性。

### 语言信号 (用户的话里出现这些就应激活)

- "我们有备份了，为什么还判不符合？"
- "云上多副本了还要做恢复演练吗？restore test / RTO 怎么验？"
- "备份介质放在机房里行不行？offsite storage 要求是什么？"
- "最近一次恢复演练是什么时候？"（访谈问不出的信号）

### 与相邻 skill 的区分

- 与 `mlps-data-transit-storage-grid`（数据传输/存储检查格）的区别: 检查格的第三块指向本 skill——格网管"备份块不能被数据保护顺带通过"，本 skill 管备份块内部的四层深查。
- 与 `mlps-artifact-verification-record-quality`（产物核验与记录质检）的区别: 恢复测试报告的实质质检（有没有测试数据、时间分布）用后者的技术；本 skill 决定"恢复测试记录"是决定性证据。
- 与 BCP/DRP 方法论的区别: 灾备体系设计（预案、切换、演练编排）；本 skill 是对"备份可恢复"这一控制点的合规判定，是其验证子集。

## E — 可执行步骤 (Execution)

1. **查识别清单**：索取备份清单，核对重要业务信息、系统数据、软件系统（含配置/IaC）三类是否入单。
   - 完成标准: 清单到手且三类齐备；缺类即记缺口。
   - 判停条件: 若三项硬证据（制度/周期记录/恢复测试）同时缺失 → 直接判不符合，跳到步骤 5 出整改框架。
2. **核策略八要素**：逐要素查策略文档——范围、方式、频度、介质、保存期、放置场所、命名规则、离站运输。
   - 完成标准: 八要素有/无清单；"场所+离站"两要素单独标注（火灾案例致死点）。
3. **查周期记录**：看备份记录连续性与介质场外存放证据。
   - 完成标准: 记录覆盖抽查期且日期连续；场外证据（存放位置/交接记录）在手。
4. **验恢复测试**：索取最近恢复演练报告与介质有效性测试，核"规定时限内完成恢复"的实测数据。
   - 完成标准: 演练报告含恢复对象、耗时、结果三要素；答不出"最近一次演练"即记录为缺失。
5. **裁决与整改**：四层全过=符合；缺演练/缺场外=部分符合或不合符（按档位纪律），整改指向"清单补全→策略八要素→周期记录→定期演练+介质测试"。
   - 完成标准: 判定+缺口层定位+整改顺序清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 高可用/冗余架构评审（集群、多活）——那是可用性设计；备份是数据面的最后底牌，两者互补不互代。
- 实时复制/CDP 产品选型——工具问题；本 skill 判的是"无论什么工具，能否证明可恢复"。
- 尚未确定重要数据清单的组织——先做资产识别与分级（接 `mlps-risk-assessment-six-steps` 风险评估六步），否则备份对象无锚。

### 作者在书中警告的失败模式

- 备份介质与被备份系统同机房/同建筑——G 公司火灾全损；消防检查通过不代表可恢复。
- "突发安全意识"式偶发备份：无周期、无清单、无恢复测试（ce60）。
- 委托物业/服务商交"季度检查结果"却不问恢复演练——签字式记录证明不了可恢复（与 `mlps-artifact-verification-record-quality` 同源）。

### 作者的盲点 / 时代局限

- **版本提示**：四层与八要素依等保 1.0（GB/T 22239—2008 + 2015 版报告语境）；2.0 下云备份、快照、跨区/跨账号副本等形态须把"介质场外"翻译为"逻辑异地（跨区/跨账号/隔离域）"，要素框架不变、载体更新。
- 未定义"规定时限"的量化来源（RTO 由谁定、依据什么）——书把时限留给被测方策略，缺少时限合理性的审查程序。

### 容易混淆的邻近方法论

- 3-2-1 备份法则（3 份 2 介质 1 异地）：存储策略口诀；本 skill 是判定程序——四层证据链+三项缺一直接不符合，比口诀可执行。
- replication ≠ backup（云时代常识）：同旨；本 skill 进一步给出"副本答不了 RTO/RPO"的判定话术与四层落点。
