# 测评指标确定规则集（S/A/G 对应 + 就高 + 三分 + 不适用裁决）

## R — 原文 (Reading)

> 「选择对应等级的ASG三类安全要求作为测评指标 就高原则调整多个定级对象共用的某些物理安全或管理安全」（第3章 3.1.2 表3-2，"ASG"为 OCR 噪声，应为 S/A/G）
>
> — 方法论出处，第3章 3.1.2（方案编制·测评指标确定任务）

---

## I — 方法论骨架 (Interpretation)

指标集不是"把标准抄一遍"，而是四条规则的决策产物：

1. **按 S/A 选级**：业务信息安全等级（S）决定 S 类要求、系统服务安全等级（A）决定 A 类要求，通用等级 G 对应整体——指标按各自等级从《基本要求》对应级别选取。
2. **共用项就高**：多个定级对象共用的机房、管理制度、堡垒机等，按其中最高等级对象的要求统一测评——一台共用设施服务的系统再多为低级，也不得被"多数低等级"稀释成低标准。
3. **适用性前置**：先判环境是否触发该要求，再判符合与否——未安装数据库的主机上"OS/DB 管理权互斥"项直接判不适用；不适用项单列表写明原因，绝不默默跳过，也不当不符合处理。
4. **指标三分**：基本指标（按 S/A 选取，有行业标准时以行业指标为基本指标）+ 不适用指标（单列+原因）+ 特殊指标（标准未覆盖或高于标准的自愿项，可赋权重入总分）。
5. **可复算性**：对象合并或拆分会直接改变就高结果与工作量——指标集是可复算的决策产物，报告须能重建推导过程。

## A1 — 书中的应用 (Past Application)

### 案例 1: 共用机房与制度的就高裁决
- **问题**: 一栋楼里同时跑三级和二级系统，机房和制度按几级测。
- **方法论的使用**: 第3章 3.1.2 规定多个定级对象共用的物理安全或管理安全项按"就高原则"统一取更高等级要求。
- **结论**: 共用资源按最高等级对象的要求测评，不因多数对象是低级而降标准。
- **结果**: "共用机房按三级测"成为方案编制的固定裁决；推论——把系统合并定级或拆分定级会直接改变就高结果与工作量。

### 案例 2: 未装数据库的主机判不适用
- **问题**: "同一用户不得同时具有 OS 和数据库管理权限"的指标，落在没装数据库的主机上怎么判。
- **方法论的使用**: 第8章 8.3.1 分两支——安装了数据库的查两组管理员交集；未安装数据库的该要求项判不适用。
- **结论**: 判定分两层——先判适用性（环境是否触发），再判符合性；不适用 ≠ 不符合。
- **结果**: 报告侧以"不适用指标"单列表（附录A 表3-2）呈现并给原因，避免把环境不具备误判为不符合。

### 案例 3: 特殊指标的口径
- **问题**: 用户自愿增加的加固要求（高于基本要求）怎么进报告。
- **方法论的使用**: 附录A 3 规定以列表给出《基本要求》（或行业标准）未覆盖或高于其的安全要求，由用户自愿增加，可赋权重并入总分。
- **结论**: 特殊指标 = 自愿项 + 显式列表 + 可赋权重；不得把基本要求改头换面当特殊指标（判不规范），特殊指标也不得替代基本指标。
- **结果**: 指标三分（基本/不适用/特殊）成为报告"测评范围与方法"章节的固定结构，指标数与权重共同驱动后续得分。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 多个业务系统共用一套云 KMS、运维堡垒机、机房（服务不同等级系统），指标按几级选。
2. 编制测评方案时逐条裁决指标适用性（无拨号网络、未部署某组件的环境）。
3. 用户想加入高于基本要求的加固项，问怎么进报告、算不算分。
4. 行业系统（金融/烟草）需要决定用国标还是行业指标作基本指标。
5. 复核报告时验证指标集推导是否可复算（等级对应、就高、不适用原因）。

### 语言信号 (用户的话里出现这些就应激活)

- "按几级的要求测？""二级系统用了三级机房怎么算？"
- "共用堡垒机/KMS 测几级？"

- "我们自愿加的加固要求怎么体现？"
- 英文: "indicator selection"、"baseline requirements by level"、"not applicable"、"shared infrastructure grading"、"extended requirements"

### 与相邻 skill 的区分

- 与 `mlps-grading-decision`（等保定级决策）的区别: 后者产出等级 G；本 skill 消费 G——按 S/A/G 选指标、按就高调共用项。上游定级错，本 skill 的所有输出跟着错。
- 与 `mlps-assessment-scope-selection`（测评对象确定法）的区别: 后者选"测哪些对象"（覆盖面）；本 skill 给对象定"用哪级要求、哪些不适用"（要求集）。方案编制的两步，先后衔接。
- 与 `mlps-verdict-tiers`（判定档位体系）的区别: 本 skill 的"不适用"是指标级裁决（环境不触发，方案阶段）；后者的档位是测评项级判定（现场阶段）——同一词出现在两个阶段，层级不同。

## E — 可执行步骤 (Execution)

1. **按 S/A/G 映射基本指标**
   - 完成标准: 每个定级对象的 S 级、A 级已知（来自 `mlps-grading-decision`），S/A/G 三类要求按对应等级选取完毕；有行业标准的已决定以行业指标为基本指标并注明。
2. **枚举共用资源并就高**
   - 完成标准: 共用物理/管理资源清单成表，每项标注其服务的对象集合及最高等级，指标按最高等级调整；就高调整项在方案中显式列出。
3. **逐条裁决适用性**
   - 完成标准: 对每项指标回答"本环境是否触发该要求"；不触发项进入不适用表并写明具体原因（如"未部署拨号网络"）。
   - 判停条件: 若不适用项比例异常高（环境与标准前提大面积不匹配，如全云原生环境对照 1.0 条款），停止逐条裁决——先做标准版本适配（对照现行 2.0 云扩展要求），否则会产生整批"伪不适用"。
4. **登记特殊指标**
   - 完成标准: 用户自愿增加项逐条列表（内容、高于/未覆盖基本要求的依据、权重），无把基本要求重复登记为特殊指标的情况。
5. **输出可复算的指标集**
   - 完成标准: 报告含基本指标表、不适用指标表（含原因）、特殊指标表（含权重）；第三方能从等级与共用关系重建整个指标集。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 定级未定或存疑——先回 `mlps-grading-decision`；在错误的 G 上选指标是放大错误。
- 单个测评项的现场判定（符合与否）——那是 `mlps-verdict-tiers` 的阶段。
- 自由安全评估（无基线标准）——没有"按级选取"的前提，规则集不适用。

### 作者在书中警告的失败模式

- 共用资源被多数低等级对象稀释——就高原则被忽略是方案编制阶段最常见、最影响结论正确性的错误（fw16）。
- 不适用不写原因默默跳过——报告口径要求单列给原因（附录A 表3-2）。
- 把环境不具备误判为不符合——适用性前置缺失（fw57）。
- 把基本要求换个名目登记为特殊指标"加分"——判不规范（pr092）。

### 作者的盲点 / 时代局限

- 指标体系基于 GB/T 22239—2008（等保 1.0）十层面控制点结构；等保 2.0（GB/T 22239—2018）改为"安全通用要求 + 云计算/移动互联/物联网/工控扩展要求"，层级与条款号完全重组——本书具体条款表（表3-1 系列）不能直接对号入座，须对照现行标准重新映射；"按级选取/就高/适用性前置/三分"四条规则本身跨版本可用。
- 就高原则隐含"成本向上兼容"假设，对共用 SaaS/云服务场景（无法为单租户提级）会出现结构性不可满足，需以补偿控制与书面声明处理——作者未讨论。

### 容易混淆的邻近方法论

- 指标三分 vs 风险驱动裁剪（ISO 27001 的 Statement of Applicability）：前者按等级基线+适用性，后者按风险评估结果裁剪控制——逻辑源不同，混用会互相污染。
- 就高原则 vs 取平均/按多数：就高是冲突裁决规则，不是协商规则——没有"打折"空间。
