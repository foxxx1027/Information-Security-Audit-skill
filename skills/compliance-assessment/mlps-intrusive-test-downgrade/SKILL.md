# 验证测试的降级权衡与豁免程序

## R — 原文 (Reading)

> 「检查不同于测试，不需在信息系统运行环境中接入设备，不会改变任何系统运行参数和状态，在获取最有效证据的同时所带来的风险也较小，是等级测评中最为有效的测评方法。在测试难以开展的情况下，也可用检查来替代。」
>
> — 方法论出处，第3章 3.2.2（检查方法，PAGE 0044）

---

## I — 方法论骨架 (Interpretation)

当"理想证据"与"作业风险"冲突时，作者给的不是"不能测就算了"，而是一条三段式作业规则：

1. **降级判据**：验证手段所需的权限或副作用超过被测系统承受力（要交出 DBA 账号、要在生产库制造测试数据、要入网跑自动拓扑），即降级为低侵入替代——理想证据力让位于作业风险。
2. **替代证据的质量门槛**：替代检查必须能**直接证明测评项的技术状态**（配置实际值、离线扫描结果、抽查比对），拿"有制度/有采购"这类纸面材料充当替代证据不合格。替代的是验证手段，不是测评项本身——能力缺失类指标仍然要判不符合。
3. **报告义务**：替代理由与未验证范围必须写进报告，不许悄悄缩水。
4. **豁免程序**：因用户原因无法开展验证测试的，由用户出具签章的"自愿放弃验证测试声明"作为报告附件——豁免 = 书面声明 + 责任转移，且声明不免除测评机构对可检查项的核查义务。
5. 典型权衡形态：数据库扫描 → 只读配置检查；自动拓扑生成 → 随机抽查 + tracert。共同逻辑：低侵入优先。

## A1 — 书中的应用 (Past Application)

### 案例 1: 数据库扫描让位于配置检查
- **问题**: 数据库漏洞扫描是最直接的证据，但前置条件是交出 DBA 权限账号、并在库中产生大量测试与日志数据。
- **方法论的使用**: 第4章 4.1.1 判定实测的权限与数据污染副作用超过收益，实践中较少采用，一般通过安全配置检查的方式取证。
- **结论**: "理想工具让位于作业风险"的典型权衡。
- **结果**: DB 类测评以只读配置检查为主证据，扫描仅在可承受环境使用——该取舍被写进工具章节的通行做法。

### 案例 2: 拓扑核对不用自动生成工具
- **问题**: 核对"拓扑图与实际一致"有自动生成工具可用，看似最优。
- **方法论的使用**: 第7章 7.3.1 指出该工具需接入被测网络、生成后还要重新绘制调整，现场一般较少采用；改用随机抽查设备连接端口（进机房实地比对）+ tracert 路由探测验证路径一致性。
- **结论**: 核对文档类证据优先选低侵入、低后处理成本的手段，自动化反而因接入风险与整理成本降级。
- **结果**: 低侵入两法成为拓扑核对的默认路径，与 DB 扫描降级同一权衡逻辑。

### 案例 3: 自愿放弃验证测试的书面豁免
- **问题**: 用户原因（生产不可中断、领导不批）导致验证测试无法开展，报告如何收尾。
- **方法论的使用**: 附录A 4.11 规定将用户签章的"自愿放弃验证测试声明"作为报告附件；未测试且无声明判程序不合规，有声明但未说明原因判部分符合。
- **结论**: 豁免是书面程序（声明+签章+归档），不是口头默许；声明只豁免"验证测试"，不豁免可检查项义务。
- **结果**: 报告中披露未验证范围与潜在风险，责任边界清晰，测评机构免责有据。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户/客户明确拒绝在生产系统（容器集群、核心数据库、交易系统）上执行漏洞扫描或渗透测试。
2. 测试前置条件本身引入不可接受风险（要交管理员凭据、要在生产造数据）。
3. 已安排的测试临时被叫停，需要合规的收尾路径（替代+豁免）。
4. 评审报告时发现"某项未测试但结论照样是符合"，需要判断程序是否合规。
5. 云环境/托管环境中工具接入受 CSP 限制，需要设计等价取证。

### 语言信号 (用户的话里出现这些就应激活)

- "客户不让扫生产，怎么办？"
- "数据库扫描要 DBA 账号，给不了"
- "能不能用检查代替测试？"
- "放弃测试要什么手续/声明？"
- 英文: "cannot test production"、"intrusive testing"、"waiver"、"alternative evidence"、"fallback to inspection"

### 与相邻 skill 的区分

- 与 `mlps-method-role-allocation`（三法角色组合）的区别: 后者是常态下三法角色分派；本 skill 处理例外——常态安排被打断时的降级与豁免程序。
- 与 `mlps-assessment-redlines`（作业红线）的区别: 后者划定测试不可越的纪律边界（授权/限域/陪同）；本 skill 在边界内解决"测不了怎么交差"。
- 与 `mlps-preponderant-evidence`（优势证据法）的区别: 后者裁决已有证据；本 skill 主动补造替代证据并把"未验证范围"显式化。

## E — 可执行步骤 (Execution)

1. **评估测试的侵入性**
   - 完成标准: 已列出该测试所需的权限、状态变更、数据残留，与被测系统承受力对比；结论写明"可承受 / 超出承受"。
2. **设计降级替代**
   - 完成标准: 对每个降级项给出能**直接证明技术状态**的替代手段（只读配置检查、镜像 SBOM 离线扫描、抽查+tracert 等），并自查：替代证据是技术状态还是只有制度文本？后者不合格，重设计。
   - 判停条件: 若替代手段也无法证明技术状态（纯黑盒且无配置可见性），该项如实标注"无法验证"，进入豁免路径并预期档位下调，不得伪装成已验证。
3. **报告披露**
   - 完成标准: 报告中逐项写明替代理由、替代手段与未验证范围。
4. **办理豁免程序（如适用）**
   - 完成标准: 用户签章的"自愿放弃验证测试声明"已作为附件归档；未验证原因已披露；可检查项义务确认未被豁免。
5. **复核结论口径**
   - 完成标准: 凡依赖替代证据的项，结论注明证据形态；凡未验证项，未被评为"符合"，且整改建议中包含后续补测安排。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 测试本来可做只是嫌麻烦——降级是风险管理决策，不是偷懒通道；能测不测违反 `mlps-assessment-redlines` 红线（未授权不测≠可测不测）。
- 纯管理类对象——本就无工具测试，谈不上降级。
- 用户想借"豁免"把明显不符合项洗白——声明只转移验证责任，不改变判定规则。

### 作者在书中警告的失败模式

- 拿"有制度文本"充当替代证据——替代检查必须能直接证明技术状态（pr010）。
- 未测试且无声明即出报告——判测评程序不合规（附录A 4.11）。
- 有声明但未说明原因、未披露未验证范围——判部分符合。
- 为证据力硬上高侵入工具，把测评变成事故面（ce05 的反向警告）。

### 作者的盲点 / 时代局限

- 阶段 0 批判指出：'自愿放弃验证测试可接受而不改变结论效力'是全书未证明的假设——责任转移并不能让"结论基于实测"的前提对被豁免系统成立；使用本 skill 时应在结论中显著提示证据基础的削弱。
- 云原生时代新增了作者未见的中间态：只读 API 审计、CI 管道内扫描、镜像离线分析等"零接入测试"，降级不必然意味着证据强度大跌——可按 `mlps-preponderant-evidence` 的证据分级重新评估替代手段地位。
- 具体声明模板出自 2015 版报告模板（等保 1.0），格式须按现行 2.0 模板复核。

### 容易混淆的邻近方法论

- 降级替代 vs 直接跳过：跳过丢失测评项，替代保持测评项只换证据形态。
- 豁免 vs 不适用：豁免是"本可测但未测"（程序豁免，责任在用户）；不适用是"环境不触发该要求"（判定豁免）——法律与判定语义都不同。
