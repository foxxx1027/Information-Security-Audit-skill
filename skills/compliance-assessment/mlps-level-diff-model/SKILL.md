# 逐级增强三层次 diff 模型

## R — 原文 (Reading)

> 「由此可见，安全要求逐级增强主要表现在三个方面：控制点增加、同一控制点的要求项增加、同一要求控制项强度增强。」「可见，安全要求的逐级增强并不是无规律可循，而是按照"层层剥开"的模式，由控制点的增加到要求项的增加，进而是要求项强度的增强。」
>
> — 方法论出处，第2章 2.2.3（表2-3 控制点计数、表2-4 要求项计数）

---

## I — 方法论骨架 (Interpretation)

标准文本只给各级的静态清单，"三级比二级严"是句空话。作者给了一个三层 diff 模型把"严"变成可计数的差异：

1. **第一层：控制点集合差异**——高级别新增了哪些控制类别（如二级较一级新增安全审计，三级新增网络恶意代码防范、剩余信息保护、抗抵赖等）。先比控制点集合，圈出"有没有"的差异。
2. **第二层：要求项数量差异**——同一控制点下，高级别多了哪些要求项（如身份鉴别三级新增组合鉴别）。比"条数"。
3. **第三层：强度差异**——同一要求项写得更多严，细分三种表现：范围增大（审计从"服务器上"扩到"服务器和重要客户端上"）、要求细化（培训由泛化变书面分岗位）、粒度细化（拨号控制由"用户组"细化为"单个用户"）。
4. **固定比对顺序**："层层剥开"——先控制点、再要求项、最后强度，不可乱序，否则会把"新增类别"误读成"同项加严"。
5. **配套计数表**：控制点 48/66/73、要求项 85/175/290/318 可逐层计数，使"为什么三级比二级贵"获得结构性解释——差异成本可以按层估算。
6. 该模型可迁移到任何"通用标准 vs 专属规范"的对比（行业 vs 国标、2.0 vs 1.0、集团规范 vs 国标）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 国标各级差异的逐层计数
- **问题**: "三级比二级贵"贵在何处，如何解释与预算。
- **方法论的使用**: 第2章 2.2.3 用表2-3/表2-4 逐层计数——控制点 48/66/73 递增、要求项 85/175/290/318 递增，再对同项差异按范围/细化/粒度分类（图2-5）。
- **结论**: 级差是三层叠加而非笼统"更严"；每层差异对应不同的建设成本（新增系统 vs 增配策略 vs 收紧粒度）。
- **结果**: "层层剥开"成为解读任意两级要求差异的固定方法（fw23/fw24）。

### 案例 2: 金融行业标准的增量定位
- **问题**: JR/T 0071 自称比国标严，严在哪些层。
- **方法论的使用**: 第1章 1.5.1 用同一 diff 逻辑定位——JR/T0071—2012 对 64 项要求进行了细化和明确（强度层/要求项层），并新增 117 项 F 类要求（控制点层），如口令被细化到"7 位以上、字母数字符号混合、每三个月更换"。
- **结论**: 行业加严可按三层逐一验证真实增量，避免被"更严"的宣传话术糊弄。
- **结果**: 三层 diff 成为附录B 六关系映射（`mlps-standard-six-relation-mapping`）之外快速定位行业加严点的前置分析框架。

### 案例 3: 强度粒度层的单点实例
- **问题**: "强度增强"听起来抽象，有没有可核查的样例。
- **方法论的使用**: 第7章访问控制条款——拨号控制由二级的"用户组"细化为三级的"单个用户"，属粒度层增强；同书审计范围从主机扩到客户端属范围层增强。
- **结论**: 强度层的三种表现（范围/细化/粒度）各有可核查的文本特征——对照条款主语、宾语与限定词即可分类。
- **结果**: 强度差异不再是感觉，而是可逐条标注类别的比对结果。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 组织从二级升三级（或系统定级变化），要估算新增合规工作量与预算。
2. 对照行业标准（金融/证券/烟草）与国标，问"行业到底严在哪几层"。
3. 等保 2.0 云计算扩展要求 vs 通用要求，定位扩展点在哪些层。
4. 供应商/甲方声称"我们的方案满足更高级要求"，需要逐层验证。
5. 编写差距分析（gap analysis）报告，需要结构化的对比框架。

### 语言信号 (用户的话里出现这些就应激活)

- "三级比二级多要求什么？"
- "这个标准比那个标准严在哪？"
- "升级到三级要加多少东西？"
- "帮我做两个标准的差距分析"
- 英文: "requirements diff"、"gap analysis"、"what does level 3 add"、"standards comparison"、"how much stricter"

### 与相邻 skill 的区分

- 与 `mlps-standard-six-relation-mapping`（跨标准六关系映射）的区别: 后者是"相同/细化/增强/新增/调整/合并"六关系分类法+逐条款映射矩阵（附录B）；本 skill 是"控制点→要求项→强度"三层计数模型——本 skill 回答差异在哪个层，后者回答每条条款的具体关系；先分层计数、再逐条映射，两者可组合。
- 与 `mlps-indicator-selection-rules`（指标确定规则集）的区别: 后者决定"本系统用哪级指标"；本 skill 分析"两级指标之间的差异构成"——一个是选取，一个是对比。
- 与 `mlps-grading-decision`（等保定级决策）的区别: 后者定等级；本 skill 解释等级差的结构与成本——升级决策（要不要定高一级）常用本 skill 做成本侧输入。

## E — 可执行步骤 (Execution)

1. **取得两版标准的完整条款清单**
   - 完成标准: 两个标准（或两级要求）的条款全量在手，按控制点/要求项两级编号对齐。
2. **第一层：比控制点集合**
   - 完成标准: 输出控制点级差异清单——新增/删除/保留的控制点各列一表；"有没有"的差异先定案。
3. **第二层：比同控制点的要求项**
   - 完成标准: 对共有控制点逐个数要求项，输出新增/删除要求项清单（如身份鉴别+组合鉴别）。
4. **第三层：比同要求项强度**
   - 完成标准: 对共有要求项逐条比对文本，按范围增大/要求细化/粒度细化三类标注（盯主语、宾语、限定词的变化）；强度差异逐条有类别标签。
   - 判停条件: 若两标准编号体系完全重组无法逐条对齐（如 1.0 与 2.0），先做语义映射表再回来比对，不得跳过对齐直接"感觉差不多"。
5. **汇总计数与成本解读**
   - 完成标准: 三层差异各有计数（控制点 +N、要求项 +N、强度类 +N）；对每层差异标注对应的整改形态（新建控制/增配策略/收紧粒度），支撑工作量与预算估算。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单一标准内部的条款解读——没有"对比"就没有 diff。
- 风险排序——diff 数量不等于风险大小（新增 10 项低风险要求 ≠ 1 项关键要求失效）。
- 非结构化规范的对比（最佳实践文集、无分层控制的框架）——先重构控制点层级才可用，否则计数无意义。

### 作者在书中警告的失败模式

- 笼统说"更严"而不拆层——无法驱动预算与工作量估算（fw23 的直接动机）。
- 把新增控制点误读成同项加严（或反之）——比对顺序错乱导致差异错账。
- 只数条数不看强度——两个要求项数相同的标准，强度层可能差异巨大。

### 作者的盲点 / 时代局限

- 计数基准（控制点 48/66/73、要求项 85/175/290/318）为 GB/T 22239—2008（等保 1.0）数据；等保 2.0（GB/T 22239—2018）结构重排（通用要求+扩展要求、一个中心三重防护），所有具体计数必须按现行标准重新生成——三层 diff 模型本身跨版本可用，且恰是做 2.0 vs 1.0 对比的趁手工具。
- 行业计数（JR/T 0071 的 64 细化+117 新增）成书于 2012 版行业标准，金融行业规范已多次更新，引用前须核对现行版本。
- diff 模型度量"要求面"差异，不度量"验收严格度"差异——同一条款在不同测评机构手里的松紧不在模型内。

### 容易混淆的邻近方法论

- 三层 diff vs 六关系映射（`mlps-standard-six-relation-mapping`）：diff 分层计数在前、六关系逐条定名在后——先知道差异在哪层，再说每条是什么关系，顺序反了容易把"细化"和"新增"混标。
- 三层 diff vs 版本变更日志（changelog）：changelog 记录修订历史，diff 模型分析两版结构差异——历史与现状不可互替。
