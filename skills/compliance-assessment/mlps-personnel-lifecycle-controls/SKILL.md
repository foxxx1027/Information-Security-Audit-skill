# 人员安全全生命周期管控

## R — 原文 (Reading)

> "①应严格规范人员离岗过程，及时终止离岗员工的所有访问权限；
> ②应取回各种身份证件、钥匙、徽章等以及机构提供的软硬件设备；
> ③应办理严格的调离手续，关键岗位人员离岗须承诺调离后的保密义务后方可离开。"
> "外部人员可以是供应商、安全顾问、外包支持人员……也可以是清洁人员、送餐人员、保安和实习人员。"
>
> — 原作者 等，原始方法论来源第10章 10.4.3 人员离岗测评指标 + 外部人员访问管理（source.txt L8850 附近、L8880 附近段落摘录）

## I — 方法论骨架 (Interpretation)

人员安全不是一个个孤立条款，而是一条**进出闭环**：人进入组织（录用）、在组织中（在职）、离开组织（离岗）、以及始终在边界外张望的人（外部人员）。每一环都有可核查的硬动作：

- **录用**：专门部门负责 + 背景审查 + 保密协议（范围/责任/违约/有效期四要素）+ 关键岗位优先内部选拔并签岗位安全协议。
- **在职**：培训按"计划→执行→记录"三链互证——有计划没执行、有执行没记录，两处断裂即降档；关键岗位定期审查（社会关系/社交活动/操作行为三维）并复做。
- **离岗**：三步收权缺一不可——终止所有访问权限（账号、门禁、令牌）、收回证件设备资产、办理手续并承诺保密义务（含脱密期）。少收一样就留一个后门。
- **外部人员**：识别范围按**能否触达受控区域/系统**穷举——只列供应商与审计方是典型盲区，快递、送餐、保洁、保安都在清单里；管控四步=书面申请→批准→专人陪同/监督→登记备案。

贯穿的判定纪律：**口头确认不构成控制证据**（无法核查、无法追溯、不构成授权链）。远程/云时代的映射：收权对象扩到 IAM 权限、API 令牌、密钥；"陪同"的可等价物是会话录制与操作审计。

## A1 — 书中的应用 (Past Application)

### 案例 1: 关键岗位未识别即无配套协议（第10章 10.4.3，ce37）
- **问题**: 有人员安全管理制度、人事部门管进出，为何仍判部分符合？
- **方法论的使用**: 查识别前置——制度文件未把生产部长等岗位识别为"关键岗位"，保密承诺书/岗位安全协议自然无从签起。
- **结论**: 识别清单是后续一切关键岗位控制的前置。
- **结果**: 判部分符合；整改从"关键岗位识别清单"做起。

### 案例 2: 5 人私企口头确认录用/离岗（第10章 10.4.3，ce38）
- **问题**: 最小规模组织的人员管理基线是什么？
- **方法论的使用**: 对照闭环——录用离岗仅凭老板口头确认，无制度、无程序、无留痕。
- **结论**: 口头确认不可作为控制证据；规模小不豁免，但证据形态必须书面化。
- **结果**: 作为零证据反例入表；最小基线=书面化的人进出记录。

### 案例 3: 外部人员识别漏掉快递/送餐（第10章 10.4.3，ce41/ce42）
- **问题**: 外部人员管理只覆盖技术服务与审查人员，后果是什么？
- **方法论的使用**: 按触达能力穷举——业务往来、监管、快递、送餐被漏；保洁阿姨进机房用吸尘器接服务器电源，导致每晚 6 点反复宕机一个月。
- **结论**: 识别不全→访问无申请无陪同无登记→管控盲区可直接转化为可用性事故。
- **结果**: 门禁虚设的后果以事故形式呈现；穷举口径确立。

### 案例 4: 培训三链断裂（第10章 10.4.3，ce39/ce40）
- **问题**: 年初有培训计划，为什么还判部分符合？
- **方法论的使用**: 三链互证——部分培训未按计划实施、部分记录遗失；另一情形是外审前突击补记录（时间戳集中前夕）。
- **结论**: 计划→执行→记录三段两处断裂即降档；补做的记录失去证据效力。
- **结果**: 培训项判定落到三链各自的证据上。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 等保/内审的人员安全管理五控制点核查（录用/离岗/考核/培训/外部人员）。
2. 外包与远程开发团队人员流动频繁的组织，设计人员安全核查方案。
3. 离职安全事件复盘：追查收权三步哪步漏了（账号还在？令牌没回收？）。
4. 供应商/访客管理制度设计：按触达能力定识别清单与四步流程。

### 语言信号 (用户的话里出现这些就应激活)

- "离职人员的权限怎么收？收哪些？offboarding checklist？"
- "外部人员/访客管理要覆盖哪些人？visitor management 怎么做？"
- "培训记录怎么查？有计划没记录算什么？"
- "老板口头同意算不算控制？"

### 与相邻 skill 的区分

- 与 `mlps-separation-of-duties-dual-axis`（职责分离双轴）的区别: 后者管在岗者的**角色组合**是否互斥；本 skill 管人在**进出组织全程**的控制链。岗位设置指标在两者交界——本 skill 查"专岗有没有人、怎么进出"，后者查"这些人角色冲不冲突"。
- 与 `mlps-artifact-verification-record-quality`（产物核验与记录质检）的区别: 培训/审查记录的实质质检（突击补记录识别）用后者技术；本 skill 决定人员域有哪些记录须查。
- 与 insider risk 管理模型的区别: 威胁预测视角（异常行为检测）；本 skill 是控制点核查视角，两者互补不互代。

## E — 可执行步骤 (Execution)

1. **分段建清单**：按录用/在职/离岗/外部人员四段列出各自的控制动作与应留证据（协议、审批单、权限回收记录、访客登记）。
   - 完成标准: 四段清单各含动作与证据两列。
2. **逐段取证**：录用查责任部门+背景审查+协议四要素；在职查培训三链与定期审查记录；离岗抽 2–3 个样本查三步收权完整性；外部人员查识别清单覆盖面+四步留痕。
   - 完成标准: 每段"通过/缺口"结论；离岗样本逐项核对权限终止、资产收回、保密手续。
   - 判停条件: 若某段完全无书面痕迹（如全靠口头）→ 该段判不符合/零证据，无需再细分取证。
3. **识别清单压力测试**：对外部人员清单追问"快递、送餐、保洁、物业、VPN 供应商触达受控区/系统吗？"——漏一类即盲区。
   - 完成标准: 清单按触达能力重列，漏项记缺口。
4. **判档与整改**：按档位纪律落档（三链两断=部分符合；口头确认=零证据）；整改按"书面化→清单化→三步收权模板→访客四步"排序。
   - 完成标准: 分段判定表 + 整改清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 绩效考核体系、企业文化与满意度——纯人事管理域，无安全控制语义。
- 背景调查的合规性审查（个人隐私边界）——涉及个人信息保护法约束，书未覆盖。
- 安全意识内容设计（课程怎么编）——本 skill 只查"计划-执行-记录"链，不评内容。

### 作者在书中警告的失败模式

- 关键岗位不识别→协议链条整体缺失（ce37）；口头确认当控制（ce38）。
- 外部人员识别想当然漏掉高频流动人员→机房自由出入出事故（ce41/ce42）。
- 突击补培训记录：日期集中前夕、抽访答不出内容（ce40）。
- 离岗只停门禁不收 IAM 权限/令牌/密钥——现代形态的"三步缺一"。

### 作者的盲点 / 时代局限

- **版本提示**：五环节指标属等保 1.0（GB/T 22239—2008 人员安全管理）；2.0 沿用，但外包/远程/自由职业者形态须把"物理陪同"翻译为"会话录制+操作审计+访问窗口"，脱密期 6 个月等参数须对照现行规定复核。
- 阶段 0 批判提示：本书人员域证据以文档+访谈为主，"写了签了=管住了"的形式合规假设在此域最强（背景审查真实性无法穿透），使用者应辅以抽样实证（如离职样本的权限实测）。

### 容易混淆的邻近方法论

- HR 全周期管理（选育用留）：业务视角；本 skill 是安全控制视角，只取与访问、保密、信任相关的切面。
- joiner-mover-leaver（JML/IAM 概念）：身份生命周期自动化；本 skill 是其治理要求侧——JML 是实现，本 skill 是验收。
