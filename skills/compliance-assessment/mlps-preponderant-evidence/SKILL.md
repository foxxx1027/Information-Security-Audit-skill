# 优势证据法（证据矛盾裁决规则）

## R — 原文 (Reading)

> 「在判断单个测评项的测评结果时，在测评证据产生矛盾时，一般采用"优势证据"的方法来判断。一般而言，检查和测试获得的测评证据优先于访谈。」
>
> — 方法论出处，第3章 3.2（表3-4，单项测评结果判定步骤）

---

## I — 方法论骨架 (Interpretation)

这是全书判定体系的地基——一条证据裁决的元规则：

1. **证据按取证方式分级**：测试（主动验证，最强）> 检查（配置/文档/实地的客观记录）> 访谈（人的陈述，最弱）。访谈内部再排序：现场询问 > 电话会议 > 问卷调查（自述性、无追问、回收慢）。
2. **矛盾时取强者**，不做多数表决、不做等权综合——三条访谈抵不过一张配置截图。
3. **弱证据不能支撑肯定结论**：只有访谈证据时，正确动作不是采信，而是补做检查/测试把证据强度升上去，或将该项挂"进一步跟踪"。
4. **判定记录落在强证据上**：判"不符合"时要写明是依据哪份配置证据/测试结果，而非"管理员承认没做"。
5. 这条规则的可迁移性极强：任何"人说的"与"系统显示的"冲突的场景（运维声明 vs 监控数据、供应商承诺 vs 实测），都适用同一裁决顺序。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: "管理员称已启用，配置显示未启用"
- **问题**: 现场测评中运维口头坚称某安全策略已启用，但配置界面显示未启用。
- **方法论的使用**: 按证据强度排序，检查类配置证据压倒访谈陈述。
- **结论**: 判不符合，并以配置证据（截图/回显）作为判定记录。
- **结果**: 该处置被固化为第2章 2.4 现场测评的标准动作，避免被口头承诺带偏结论。

### 案例 2: 问卷调查不得当作访谈充分的证明
- **问题**: 测评方案为省事大量发放问卷，回收后即认为访谈取证已完成。
- **方法论的使用**: 访谈三子类内部再排序——问卷证据量最少、回收周期最长，是访谈类中最弱一档。
- **结论**: "已发放并回收问卷"不构成访谈充分的证明；方案过度依赖单一弱取证方式（全问卷/全访谈）即为质量缺陷。
- **结果**: 该警告写进第3章 3.2.1，成为测评方案评审的检查点。

### 案例 3: 应用测评中仅靠访谈不能判符合
- **问题**: 应用系统多数控制逻辑不可直接观察，测评易退化为"听管理员讲功能"。
- **方法论的使用**: 第9章 9.1 规定应用测评以文档审阅、配置检查、测试为主，访谈只补背景——仅靠访谈描述功能存在不能判符合。
- **结论**: 访谈证据必须升级为配置/测试证据才能支撑结论。
- **结果**: 应用测评方案中每项都配有可检查/可测试的落点，访谈降为辅助。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 合规测评/内审中，受访者说法与配置截图、日志、监控数据不一致。
2. 供应商或平台方宣称"已启用某能力"，但实测或配置核查显示相反。
3. 审阅他人出具的测评/审计报告，需要判断其结论是否建立在足够强的证据上。
4. 设计取证方案时决定"哪类证据够用、哪类必须补强"。
5. 争议裁决：多方陈述冲突（运维 vs 开发 vs 厂商），需要一个公认的证据优先序。

### 语言信号 (用户的话里出现这些就应激活)

- "管理员说开了，但是配置里没开，怎么判？"
- "口头说的算数吗？""访谈证据够不够？"
- "两份证据打架，听谁的？"
- "报告里这条结论的证据链站得住吗？"
- 英文: "evidence conflict"、"conflicting findings"、"which evidence prevails"、"interview vs configuration"、"verify the claim"

### 与相邻 skill 的区分

- 与 `mlps-tool-test-typology`（工具测试类型学）的区别: 后者管工具证据的"形态匹配"（抓包不能证明告警能力）；本 skill 管不同来源证据冲突时"谁压倒谁"。
- 与 `mlps-verdict-tiers`（判定档位体系）的区别: 本 skill 裁决证据采信；后者在采信之后决定结论落哪个档位（符合/部分符合/不符合/不适用/进一步跟踪）。
- 与 `mlps-triple-consistency-check`（三重一致性核查）的区别: 后者用三角互证发现"文档与实际的断裂"；本 skill 在断裂被发现后裁决以哪侧为准。

## E — 可执行步骤 (Execution)

1. **汇总单项全部证据并按来源分类**
   - 完成标准: 每份证据标注来源类型——测试 / 检查（配置、文档、实地）/ 访谈（现场、电话、问卷），可追溯到具体时间与对象。
2. **识别矛盾**
   - 完成标准: 明确列出哪些证据之间互斥、互斥点是什么（如"称已启用"vs"显示未启用"）。
   - 判停条件: 若无矛盾且证据强度足够，直接进入步骤 4 出判定；若证据不足而非矛盾，转补强路径（步骤 3）。
3. **补强弱证据（可选但优先）**
   - 完成标准: 对只有访谈类弱证据的项，已补做检查或测试；确实无法补强的，该项挂"进一步跟踪"而非采信。
4. **按强度裁决并记录**
   - 完成标准: 结论以最强证据为据，判定记录引用该证据的具体内容（截图/回显/测试输出），并注明被推翻的弱证据。
5. **复核裁决一致性**
   - 完成标准: 同一测评项目内所有矛盾的裁决顺序一致，无"此处采信访谈、彼处又不采信"的双标。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯主观/态度类调研（满意度、意识水平）——没有客观证据可排序时，访谈本身就是数据。
- 文档撰写与政策解读类任务，不存在证据冲突。
- 证据本身可能被伪造的高对抗场景——本 skill 只排序证据强度，不解决证据真伪鉴定（那需要时间戳分布、交叉验证等 `mlps-triple-consistency-check` 的技术）。

### 作者在书中警告的失败模式

- 用"已发放问卷并回收"充当访谈取证充分（ce02，第3章 3.2.1）。
- 以口头承诺记"符合"——访谈不能单独支撑肯定结论（第9章 9.1）。
- 多数表决式折中：三条弱证据不能推翻一条强证据。

### 作者的盲点 / 时代局限

- 该规则源自等保 1.0 测评实务（GB/T 28448—2012 语境），但作为证据元规则不受版本影响，可直接用于 2.0 及任何符合性测评。
- 阶段 0 批判指出：全书证据金字塔中权重最大的是文档与访谈类证据——可伪造、易过时；"配置证据"在容器/无服务器等不可见基础设施层获取难度上升，证据分级需按新架构重新映射（如不可变审计日志 > 可删配置）。
- 强证据也可能失真（配置正确但运行态被覆盖），作者未讨论"配置 vs 运行时"的强度排序，外推时应补上。

### 容易混淆的邻近方法论

- 优势证据法 vs "多数表决/加权综合"：前者是等级压制，后者是等权或加权合并——混用会把弱证据的噪声带进结论。
- 优势证据法 vs 交叉验证（triangulation, `mlps-triple-consistency-check`）：交叉验证发现矛盾，优势证据裁决矛盾，先后关系不可倒置。
