# 等保就绪度与迎检自查法

## R — 原文 (Reading)

> 「第二级以上的信息系统，在安全保护等级确定后30日内，需由其运营使用单位或其主管部门到所在地的市级以上公安机关办理备案手续。」（第2章 2.1.2）「对于第三级系统，应每年由测评机构进行一次等级测评。第四级系统每半年进行一次等级测评。」（第2章 2.1.4）
>
> — 方法论出处，第2章 2.1.2/2.1.4；编写组经验：30 日时限、拓扑图与备案表一一对应、三级附加材料三项最常缺失（2.1.2 节）

---

## I — 方法论骨架 (Interpretation)

这套方法的独特之处是把监管要求"反转"成被测方的自查表，并给出排查优先级：

1. **三条自查主线**：备案环节（时限/备案地/材料分级）、监督检查环节（三层检查主体×九项检查内容）、测评频次（三级年测、四级半年测，加变更触发重测）。
2. **高频失分点倒序**：先查备案三件套（30 日内办理、网络拓扑图与备案表一一对应、三级以上附加材料——安全设施设计/改建方案、安全产品清单及认证销售许可、安全组织架构与制度），这三项是编写组点名的"最常缺失"。
3. **一致性优先于补齐**：九项检查内容逐项找的不是"缺材料"，而是"材料存在但与实际不一致"——这是比缺材料更高频的失分形态。自查的主要动作是核对（拓扑图 vs 实际组网、制度文本 vs 实际流程），不是突击写文档。
4. **双触发验证记录**：年测报告（周期）+ 变更后重测记录（事件）都要能拿出来，且日期能对上系统变更史。
5. **变化侵蚀假设**：架构升级、人员离职等持续变化会侵蚀既有措施，检查/自查必须周期性重做，一次合规不等于持续合规。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 备案三常缺项
- **问题**: 组织办备案时最容易栽在哪里。
- **方法论的使用**: 把备案要求拆成可核对的清单——30 日时限、定级报告须含与备案表一一对应的网络拓扑图、三级以上附加三项材料；编写组依据测评实践标注这三处"最常缺失"。
- **结论**: 备案就绪度的核对点是"一致性"（拓扑图 ↔ 备案表 ↔ 实际系统）而非仅"有没有交"。
- **结果**: 该清单直接对应监督检查九项内容之"定级备案与变更"，是自查性价比最高的起点；跨地域部署时有独立服务器的分支须当地独立备案，仅纯网络终端可随总部备案。

### 案例 2: 九项检查内容转自查表
- **问题**: 被测单位不知道公安监督检查会查什么。
- **方法论的使用**: 第2章 2.1.5 列出监督检查的三层主体与九项检查内容，作者将其用作被测方自查表的直接底稿。
- **结论**: 监管检查清单 = 被测方自查清单，逐项核对"材料存在且与实际一致"。
- **结果**: 自查从无头绪变成有固定表可照抄，且"文档-实际脱节"类缺口被提前暴露。

### 案例 3: 频次双轨落进建设管理指标
- **问题**: 年测义务如何被核查。
- **方法论的使用**: 第11章 11.4.9/11.4.10 把系统备案、等级测评列入建设管理控制点——年测+及时整改、变更或级别变化强制重测、选有资质机构、专人负责。
- **结论**: 测评义务在指标侧重现，"该测未测""测完未整改"都是可判不符合项。
- **结果**: 自查须同时备齐周期记录与事件触发记录，缺一即暴露。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 初创/首次进入监管视线的公司，三级系统首次迎检公安监督检查，问"从哪里查起性价比最高"。
2. 年度测评或年检临近，需要提前自查避免现场失分。
3. 被公安机关责令整改后的复核，需要验证整改是否覆盖检查口径。
4. 组织发生架构升级、系统迁移、人员离职等变化后，怀疑既有合规材料已与实际脱节。
5. 接手前任留下的等保材料，需要快速判断可信度。

### 语言信号 (用户的话里出现这些就应激活)

- "公安要来检查了，我们要准备什么？"
- "备案材料有哪些常缺的？""拓扑图要不要跟备案表一致？"
- "年测到期了/上次测评报告还能用吗？"
- "帮我做一份等保迎检自查表"
- 英文: "compliance readiness"、"prepare for inspection"、"self-assessment checklist"、"filing requirements"

### 与相邻 skill 的区分

- 与 `mlps-grading-decision`（等保定级决策）的区别: 前者解决"定几级"；本 skill 解决"定了级、备了案之后，组织迎检是否就绪"。
- 与 `mlps-report-validity-retest`（报告效力与重测）的区别: 后者裁决"测评报告本身的有效期与重测触发"；本 skill 面向被测单位的全套监管义务（备案+检查+频次）。
- 与 `mlps-triple-consistency-check`（三重一致性核查）的区别: 后者是逐项证据的三角互证技术；本 skill 是组织级就绪度的排查顺序与优先级。

## E — 可执行步骤 (Execution)

1. **核对备案三件套**
   - 完成标准: 已逐项确认——定级后 30 日内办理；定级报告内拓扑图与备案表一一对应且与实际组网一致；三级以上附加材料齐备。任何一项不符即列入整改清单首位。
2. **按九项检查内容逐项做一致性核对**
   - 完成标准: 每项检查内容都有"材料 + 与实际一致的核对记录"，重点标注"材料存在但与实际不一致"的缺口（比缺材料更高频）。
3. **核对频次双轨记录**
   - 完成标准: 周期轨（最近一次年测/半年测报告在有效期内）与事件轨（重大变更后的重测或说明）都能出示，日期与变更日志对得上。
   - 判停条件: 若发现"该测未测"（超期无报告），停止逐项自查，转为按 `mlps-report-validity-retest` 判定报告失效范围并优先安排补测。
4. **排查"突击补材料"风险**
   - 完成标准: 对培训记录、巡检记录等易补做材料做了时间戳分布检查（日期是否高度集中在检查前夕），有问题的材料已标记为不可依赖。
5. **输出自查报告与整改排序**
   - 完成标准: 按高频失分倒序输出问题清单（备案三缺 > 文档-实际不一致 > 频次缺口），每项附核对证据位置；主要负责人签字确认。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 测评机构设计现场取证方案——那是测评侧方法论（`mlps-triple-consistency-check` 三重一致性、`mlps-method-role-allocation` 三法组合）的事。
- 定级争议裁决（`mlps-grading-decision`）或测评报告得分复算（`mlps-score-aggregation-chain`）。
- 非中国等级保护体系的合规自查（ISO 27001 内审、SOC 2 readiness 等）——清单口径完全不同。

### 作者在书中警告的失败模式

- 用"突击补材料"应对检查：补做的记录时间戳与业务周期不匹配，反而成为形式合规证据（与 `mlps-triple-consistency-check`/ce40 同源）。
- 只查"有没有"不查"一不一致"：备案信息与实际系统脱节直接动摇备案前提（2.1.2）。
- 以为一次合规终身有效：架构升级、人员离职持续侵蚀措施，须"周期+事件"双触发维持（第12章）。

### 作者的盲点 / 时代局限

- 备案时限、附加材料清单、检查频次（三级年测/四级半年测）均为等保 1.0（公通字[2007]43 号）时代口径；等保 2.0 及《网络安全法》后备案多经全国联网备案平台在线办理、材料口径有调整，实操前须对照现行公安部门要求复核。
- "三项最常缺失"是编写组 2014 年前的测评经验值，非统计数据，当前高频失分点可能已迁移（如云上系统的定级对象说明）。

### 容易混淆的邻近方法论

- 合规自查 vs 内部安全审计：前者对照监管口径，后者对照自身制度；口径混用会导致漏项。
- 迎检自查 vs 整改差距分析（gap analysis）：自查找"迎检会暴露什么"，差距分析找"离标准还差多少"，优先级排序逻辑不同。
