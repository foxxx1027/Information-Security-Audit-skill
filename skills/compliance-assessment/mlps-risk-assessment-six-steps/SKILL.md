# 风险评估六步法与测评耦合

## R — 原文 (Reading)

> 「其具体步骤为：对资产进行分类；从保密性、完整性和可用性3个方面对资产的重要性进行赋值；识别重要资产对威胁可能性进行赋值；分析脆弱性的严重程度；计算风险值和风险等级，得出风险评估结果。」
>
> — 方法论出处，第5章 5.3（风险评估模型六步流程，赋值方法引 GB/T 20984）

---

## I — 方法论骨架 (Interpretation)

一条从清点到排序的流水线，每步都有五级量表：

1. **资产六类盘点**：硬件、软件、环境、数据、人员、服务——后两类最易漏（掌握核心业务的人员、对外信息服务都是资产）；财务视角的资产清单会漏掉信息类资产。
2. **CIA 五级赋值**：每项资产按保密性/完整性/可用性各打五级；可用性可用百分比口径量化（如 99.9% 以上或不允许中断=很高），可直接当 SLA 分级参照。
3. **重要资产阈值**：三性得分相加映射重要性五级，**只有 4、5 级算重要资产**——显式阈值防评估范围无限膨胀，后续威胁/脆弱性分析只聚焦这批。
4. **威胁与脆弱性**：对重要资产赋威胁可能性五级；脆弱性按严重程度×可利用性两层评。
5. **风险值合成**：矩阵法（可能性×损失查二维表）或相乘法（经验函数直接运算）得出风险值与等级排序。
6. **两条纪律**：纯定量是伪精确（数字的前提本身是定性判断；正确做法=综合法：先定性划范围→再定量→最后定性解释）；CIA 价值高不等于风险高——加密完善的租户库风险可能低于暴露公网的管理端，资源按风险值而非资产价值分配。

## A1 — 书中的应用 (Past Application)

### 案例 1: 六步主干的量表化落地
- **问题**: 风险评估容易做成形容词大会，怎么结构化。
- **方法论的使用**: 第5章 5.3.1–5.3.6 逐步配五级量表——资产六类清单、CIA 五级描述（表5-1~5-3）、重要性相加法（表5-4，"重要性等级为4和5的为重要资产"）、威胁赋值、脆弱性分析、矩阵/相乘计算。
- **结论**: 每步有量表、有阈值、有算法，评估结果可复现、可对比。
- **结果**: 六步成为第 5 章操作主干，也是测评报告风险分析环节（每个问题关联资产+威胁定高/中/低）的输入。

### 案例 2: 财务视角的资产清单漏掉信息资产
- **问题**: 某成果转化公司把资产管理交给财务部，清单按办公/软件/硬件分类并颜色标记，看似有模有样。
- **方法论的使用**: 第12章 12.4.2 案例揭示——学生身份信息、成绩、课程等信息资产由开发人员自行维护，无人识别；判定：清单部分符合、信息分类标识不符合。
- **结论**: 财务视角的资产=财物；安全视角的资产=财物+数据（CIA 定值）；六类盘点中数据/人员/服务三类是易漏项。
- **结果**: 该案例成为"资产清单必须由安全口径重造"的直接证据（ce51），支撑六步法第一步的展开方式。

### 案例 3: 纯定量的伪精确警告
- **问题**: 直接给风险算分出数字结论，看起来最客观。
- **方法论的使用**: 第5章 5.2.2 指出定量分析法"容易简单化、模糊化，容易造成误解和曲解"，定量的前提（预测、指标选取）本身是定性的；给出综合分析法——先定性划范围、再定量计算、最后定性解释数字。
- **结论**: 脱离定性基础的数字是伪精确；单一方法都有系统性偏差。
- **结果**: 综合法被确立为默认方法选型；该警告同样适用于附录A 打分体系（分数是合规记分不是风险度量，与 `mlps-compliance-vs-risk-boundary` 衔接）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 为新系统/多租户 SaaS 平台做首次风险分析，不知从哪起步。
2. 资产一堆，不知道评估范围怎么收敛（不能什么都重点分析）。
3. 要给安全问题排整改优先级，需要可辩护的量化依据。
4. 管理层拿资产价值清单当风险排序，需要纠正"CIA 高≠风险高"。
5. 选风险评估方法（定性/定量/工具打分）被供应商的"全自动量化"打动。

### 语言信号 (用户的话里出现这些就应激活)

- "风险评估怎么做/从哪里开始？"
- "资产怎么赋值？重要资产怎么定？"
- "风险值怎么算出来？为什么它排第一？"
- "我们最重要的数据是不是风险最大？"
- 英文: "risk assessment methodology"、"asset valuation"、"CIA valuation"、"risk ranking"、"how to scope a risk assessment"

### 与相邻 skill 的区分

- 与 `mlps-compliance-vs-risk-boundary`（合规与风险分工边界）的区别: 本 skill 是风险评估的操作流水线；后者划定"测评结论 vs 风险结论"的边界——两套结论不可互替。先有边界共识，再用本 skill 做风险侧。
- 与 `mlps-grading-decision`（等保定级决策）的区别: 定级看 CIA 损失最大值得出"应然保障水平"；本 skill 得出"实然风险排序"——定级在前（决定基线），风险评估贯穿（验证差距）。
- 与 `mlps-score-aggregation-chain`（得分聚合链）的区别: 后者的分数度量合规程度；本 skill 的风险值度量损失期望——两套数字语义不同，不得混用排序。

## E — 可执行步骤 (Execution)

1. **资产六类盘点**
   - 完成标准: 清单覆盖硬件/软件/环境/数据/人员/服务六类；数据类按业务/用户/配置细分；人员与服务两类显式列入（最常见的两类遗漏）。
2. **CIA 五级赋值**
   - 完成标准: 每项资产 C/I/A 各有五级赋值与一句理由；可用性赋值对照百分比口径（可作 SLA 参照）。
3. **划定重要资产**
   - 完成标准: 三性相加映射重要性五级，仅 4/5 级进入重要资产清单；清单规模可控（若超半数资产都"重要"，说明阈值执行失败，回步骤 2 校准）。
   - 判停条件: 若赋值普遍偏高导致范围膨胀，不得"都重要"处理——重审赋值理由后再进下一步。
4. **威胁与脆弱性两层评估**
   - 完成标准: 每项重要资产有威胁可能性五级（结合来源与频率）；每个关联脆弱性有严重程度×可利用性两层评分。
5. **计算风险值并排序**
   - 完成标准: 用矩阵法或相乘法得出风险值与等级；输出按风险值排序的问题清单（供整改优先级）。
6. **定性解释与声明**
   - 完成标准: 报告用定性语言解释每个高风险项的成因与假设；声明参数（等权相加、矩阵取值）为经验设定未经信效度论证；资源分配建议按风险值而非资产价值给出。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 回答"是否符合等保要求"——那是测评（`mlps-compliance-vs-risk-boundary` 的另一侧），六步法不输出合规结论。
- 威胁建模（STRIDE 类攻击面分析）——视角不同（资产驱动 vs 攻击者驱动），可互补但不可替换。
- 事件应急的快速风险评估（几小时内要结论）——六步法是完整评估骨架，应急场景需裁剪。

### 作者在书中警告的失败模式

- 纯定量伪精确：报告只有分数没有模型假设说明，不同量纲折成同一分制直接平均（ce08）。
- 评估范围膨胀：没有 4/5 级阈值，全部资产都重点分析，资源被摊薄（fw37 显式阈值的意义）。
- 资产清单财务视角化：漏掉信息类资产，后续分类分级与保护无从谈起（ce51）。
- 把重要资产直接当高风险：跳过威胁与脆弱性分析，风险分析退化为资产盘点（pr016）。

### 作者的盲点 / 时代局限

- 六步骨架源自 GB/T 20984—2007（等保 1.0 时代），现行版本已更新（GB/T 20984—2022），量表与算法细节须按现行标准复核；骨架（资产→赋值→阈值→威胁→脆弱性→合成）稳定。
- 参数未经论证（阶段 0 批判）：C+I+A 等权相加、矩阵取值均为最简合成规则，无信度效度数据——高风险决策不应只依赖该数值，需叠加定性解释与敏感性讨论。
- 新形态资产（模型权重、数据集、供应链组件）在六类中无处安放，需扩展资产分类法。

### 容易混淆的邻近方法论

- 风险评估六步 vs FAIR/OCTAVE：FAIR 聚焦损失频率-幅度量化，OCTAVE 自导式；六步法是国标语境的中量级骨架——混用时量表语义冲突。
- 重要资产阈值 vs 定级（`mlps-grading-decision`）：前者是评估范围内的资源聚焦规则，后者是制度保护等级——"重要资产"不等于"三级系统"。
