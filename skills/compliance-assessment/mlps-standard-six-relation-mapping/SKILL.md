# 跨标准六关系差异映射法

## R — 原文 (Reading)

> "编者对《金融行业信息系统信息安全等级保护实施指引》（JR/T0071一2012）……等行业标准中的等级保护第三级基本要求进行了逐条比对，整理如表附B-1：对各条款的分析结果分为相同、细化、增强、新增、调整、合并等6种不同情况。"
>
> — 原作者 等，原始方法论来源附录B（source.txt L13765–13771，OCR"CB/T22239一2008"噪声原样保留）

## I — 方法论骨架 (Interpretation)

两套标准对表，逐条读下来是一堆碎片，看完仍答不出"行业到底严在哪"。本法把每条差异强制归入六个抽屉之一：

1. **相同**——两边文字一致，无增量；
2. **细化**——行业把国标的定性词翻译成参数（如口令"7 位以上、字母数字混合、每三月更换"）；
3. **增强**——同一要求项行业抬高了强度；
4. **新增**——国标没有的条目（金融 F 类 117 项）；
5. **调整**——措辞或口径变了，须警惕"表面改写、实际弱化"；
6. **合并**——多条并一条，检查面可能变窄。

产出是"条款号×关系"四列矩阵：横向按国标条款号查行业覆盖与关系类型。它决定指标选择——有行业标准时以行业指标为基本指标，六关系正是"为什么换指标"的显式依据。矩阵可复用于任何"通用基线 vs 专属规范"的差异审计，不限于等保体系。

## A1 — 书中的应用 (Past Application)

### 案例 1: 附录 B 三行业 × 国标 2500 行映射矩阵
- **问题**: 金融/证券/烟草行业标准各自声称比国标更严，测评时如何快速定位差异？
- **方法论的使用**: 编写组把三个行业标准与 GB/T 22239—2008 三级要求逐条比对，每条标注六关系之一，形成表附 B-1。
- **结论**: "行业严在哪"从印象变成可按条款号查询的结构化矩阵。
- **结果**: 约 2500 行映射表成为附录 B 主体；测评者按国标条款号横向查行业加严点，无需通读行业标准全文。

### 案例 2: 金融行业细化与 F 类增强（第1章 1.5.1，cs003）
- **问题**: 金融行业标准与国标差异的具体形态是什么？
- **方法论的使用**: 用同一词汇体系归类：口令要求属"细化"（具体到 7 位、每三月更换），F 类 117 项属"新增"，互联网客户端登录提示上次登录信息是国标没有的新增项。
- **结论**: 差异主要落在细化与新增两类，增强与调整占比小但最易被忽略。
- **结果**: 第1章行业章与附录 B 矩阵词汇一致，读者可交叉验证。

### 案例 3: 报告侧指标选择（附录A 表3-1A）
- **问题**: 测评报告的"基本指标"以哪套标准为准？
- **方法论的使用**: 有行业标准时以行业指标为基本指标，六关系矩阵是替换依据的显式化。
- **结论**: 指标替换不是自由裁量，而是六关系映射的直接应用。
- **结果**: 报告模板的指标选择规则与附录 B 矩阵衔接成链。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 金融/证券/烟草行业系统做等保测评，需确定用行业标准还是国标做基本指标、行业加严点在哪。
2. 集团公司下发的安全规范与国家标准并存，需审计集团规范的增量与差异。
3. 标准换版（如等保 1.0→2.0、27001:2013→2022）时做差距分析，把新旧条款差异结构化。
4. 供应商声称"满足某某行业标准"，需核对该标准相对基线到底多了什么。

### 语言信号 (用户的话里出现这些就应激活)

- "JR/T 0071 和 GB/T 22239 差在哪？行业标准严在哪？"
- "两套标准怎么对？做 delta analysis / requirements mapping"
- "换版了，新旧条款差异怎么梳理？"
- "集团规范比国标多了哪些要求？"

### 与相邻 skill 的区分

- 与 `mlps-indicator-selection-rules`（指标确定规则集）的区别: 后者决定"选哪些指标"（S/A/G 对应、就高、不适用裁决）；本 skill 决定"两套标准之间怎么对照"——是其中"有行业标准时以行业为基本指标"一步的展开工具。
- 与 `mlps-level-diff-model`（逐级增强三层次 diff）的区别: 后者比较同一标准内部相邻等级的差；本 skill 比较两套平行标准在同一等级的差。

## E — 可执行步骤 (Execution)

1. **确定基准与对照**：明确"通用基线"（通常是国标/母标准）与"专属规范"（行业标准/集团规范/新版标准），固定以基准条款号为索引轴。
   - 完成标准: 两个标准文本就位，条款编号体系已对齐（无对齐表先建对齐表）。
2. **逐条比对并归入六关系**：每条标注 相同/细化/增强/新增/调整/合并；拿不准的标"待核"，不硬归类。
   - 完成标准: 基准每条条款都有关系标注（含"相同"与"无对应"），无遗漏。
   - 判停条件: 若对照标准覆盖范围与基准不同级（如只覆盖二三四级），先裁剪比对范围再继续，不跨级硬比。
3. **生成映射矩阵**：四列——基准条款号 / 对照条款号 / 关系类型 / 差异要点（参数、强度、措辞变化）。
   - 完成标准: 矩阵可按基准条款号查询；"调整"类逐条注明是加严还是弱化。
4. **导出结论**：汇总细化/增强/新增清单（从严执行项）、调整警示项（须人工研判方向）、合并项（检查面收窄风险）。
   - 完成标准: 三张清单 + 每张一条执行建议（直接采用/按行业执行/人工研判）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只有一套标准、做单标准合规自查——没有第二套作对照轴，六关系无从谈起。
- 法规条文与合同条款的法律效力比对——本方法只做技术要求差异结构化，不判断法律优先级。
- 平台配置基线核对（CIS vs 实际配置）——那是实测与基线的差集运算，不是两套标准的文本映射。

### 作者在书中警告的失败模式

- 逐条款"看上去都比过"却不归类，差异清单散落各处、不可复用——附录 B 的存在本身就是对该失败模式的矫正。
- "调整"关系被默认当成加严：措辞变化可能是弱化（先弱化再在别处加严），须逐条研判方向。

### 作者的盲点 / 时代局限

- **版本提示**：附录 B 对照基于等保 1.0（GB/T 22239—2008）与 JR/T 0071—2012/JR/T 0060—2010/YC/T 495；现行 GB/T 22239—2019 及行业新版已发布，旧矩阵数值不可直接引用，但六关系分类法本身可对任何新标准对重建矩阵。
- 矩阵只做文本级比对，未评估行业加严项的实测可达性（哪些 F 类项行业普遍做不到，书中未讨论）。

### 容易混淆的邻近方法论

- requirements traceability matrix（RTM）：追踪"需求↔实现↔测试"的覆盖关系；本法追踪"标准↔标准"的差异关系，六分类是其特化。
- gap analysis：通常只列差距清单不分类；本法强制封闭六分类，使差异可统计、可查询。
