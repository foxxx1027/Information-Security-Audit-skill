# 工具接入点布点法与双重取证价值

## R — 原文 (Reading)

> 「（1）由低级别系统向高级别系统探测；（2）同一系统的同等重要程度功能区域之间要相互探测；（3）由较低重要程度区域向较高重要程度区域探测；（4）由外连接口向系统内部探测；（5）跨网络隔离设备（包括网络设备和安全设备）要分段探测。」
>
> — 方法论出处，第4章 4.3.2（测试工具接入点选择原则；引文按 candidates 保留）

---

## I — 方法论骨架 (Interpretation)

"从哪里测"不是经验问题，而是按信任边界枚举的清单：

1. **五原则 = 信任梯度枚举**：沿三条梯度（等级梯度：低→高；重要度梯度：低→高；位置梯度：外→内）逐条布点，再加两条正交规则——同级互探（验证横向隔离是否真的存在）、跨隔离分段探测（防火墙/隔离设备两侧各测一次）。
2. **核心洞察：每一跳隔离设备都可能改变可达性**，所以必须分段测量而非一点打穿——从外网一点扫全网的结论对内部区域不可信。
3. **每个信任域至少一个探测点**：域内自查（该域暴露面）+ 跨域探测（域间隔离）两种结果都要。
4. **双重取证价值**：工具结果不止回答"有什么漏洞"，把不同区域的接入结果做对比，还能反证区域间访问控制是否生效——能从低信任域连通高信任域，即边界策略失效的直接证据。
5. 外推方法：对任何新架构（微服务、Service Mesh、多账号云环境），先画出信任边界图，再按五原则逐一落点——布点清单可以从拓扑直接生成。

## A1 — 书中的应用 (Past Application)

### 案例 1: 双边界拓扑的四接入点实例
- **问题**: 一个互联网+专网双边界、内分 DMZ 与核心服务区的典型系统，接入点怎么落。
- **方法论的使用**: 第4章 4.3.3 图4-1 给四接入点分工——接入点1（DMZ 内）测核心服务区对 DMZ 的暴露与 DMZ 内部横向；接入点2（核心服务区）测数据库漏洞；接入点3（Internet 侧）模拟外部攻击测两区对互联网暴露；接入点4（专网侧）测对专网暴露（引文含 OCR 噪声"接人点"）。
- **结论**: 每个信任域至少一个探测点、每个隔离设备两侧各测一次，五原则落到具体拓扑。
- **结果**: 该布点成为 4.3 部署环节唯一的实测示意图，网络测评布点的标准样板。

### 案例 2: 区域对比反证访问控制
- **问题**: "防火墙策略配置正确"之外，如何证明边界控制实际生效。
- **方法论的使用**: 第2章 2.2 / 第4章 4.1 指出在不同区域接入测试工具，对比结果可判断区域间访问控制情况——低信任域能探测到高信任域服务，即策略失效证据。
- **结论**: 工具测试的第二重价值——从"找漏洞"扩展为"验策略"，不应只用于漏洞指标。
- **结果**: 结构安全/访问控制类测评项获得动态证据来源，与配置检查互证。

### 案例 3: 布点原则与禁止全网扫描的衔接
- **问题**: 布点与作业红线如何配合。
- **方法论的使用**: 五原则产生的每条探测路径都限定在"指定网段地址内"，与 `mlps-assessment-redlines`"严禁全网扫描"衔接——布点清单即授权范围清单。
- **结论**: 布点清单同时是授权书里的网段清单与扫描日志的比对基准。
- **结果**: 方案中的接入点表直接服务合规核查（扫描日志目标地址与清单一致）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计网络层测评/渗透方案，被问"接入点选几个、放哪里"。
2. 验证网络分区/微分段/安全组策略是否真的隔离（east-west 流量验证）。
3. 微服务 Service Mesh、多命名空间集群、多账号云环境等新架构的布点外推。
4. 复盘一次"从外网扫了一遍就出报告"的测试，指出其内部区域结论不可信。
5. 编写测试方案/授权书，需要明确的探测范围与路径描述。

### 语言信号 (用户的话里出现这些就应激活)

- "扫描从哪里接入？""接入点怎么选？"
- "怎么验证两个区域之间是隔离的？"
- "内网横向/东西向流量要不要测？"
- "帮我在拓扑上标测试点"
- 英文: "vantage point"、"test placement"、"validate segmentation"、"east-west traffic testing"、"where to run the scan"

### 与相邻 skill 的区分

- 与 `mlps-tool-test-typology`（工具测试类型学）的区别: 后者决定"用什么类型的工具、产出什么证据形态"；本 skill 决定"工具放在哪、按什么路径探测"。位置不同，结论可比性不同。
- 与 `mlps-assessment-redlines`（作业红线）的区别: 后者限定测试的行为边界（授权/限域/限速）；本 skill 在边界内做空间设计——五原则产出的清单恰好成为红线要求的"指定网段"来源。
- 与 `mlps-intrusive-test-downgrade`（降级权衡与豁免）的区别: 后者处理"测不了"的降级豁免；本 skill 处理"测的话从哪测"。

## E — 可执行步骤 (Execution)

1. **画出信任边界图**
   - 完成标准: 拓扑上标出所有信任域（等级/重要度分层）与全部隔离设备（防火墙、网闸、安全组、mTLS 边界），无遗漏。
2. **按三条梯度枚举接入点**
   - 完成标准: 低→高（等级）、低→高（重要度）、外→内三类方向各有探测安排；每个信任域至少一个探测点。
3. **补两条正交规则**
   - 完成标准: 同级功能区之间的互探、每个隔离设备两侧各一次的分段探测均已列入。
4. **生成布点清单并与授权对齐**
   - 完成标准: 每个接入点写明位置、目标网段、探测方向；清单与授权书/扫描计划一致（衔接 `mlps-assessment-redlines`：扫描日志可逐地址比对）。
   - 判停条件: 若某高信任域无法合法接入（管理限制），标注"该域仅间接证据"，不得用从外网打穿的结果冒充该域自查结论。
5. **设计区域对比取证**
   - 完成标准: 对每个边界写明"从低信任侧探测高信任侧的预期结果"；实测连通即产生访问控制不符合证据，与配置证据互证。
6. **复盘覆盖完整性**
   - 完成标准: 逐隔离设备核对"两侧各测一次"已执行；存在未覆盖的域/边界已列入限制说明。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单主机/单应用无网络分层的测试——无信任梯度可枚举，直接按目标范围测。
- 社会工程/物理渗透规划——人的攻击面不按网络信任梯度组织。
- 只需漏洞清单不问边界有效性的快速扫描——但注意：此时结论的使用范围也要相应收窄（不能外推到区域隔离结论）。

### 作者在书中警告的失败模式

- 全网扫描/一点打穿：违反 `mlps-assessment-redlines` 红线，且跨隔离设备的结论不可信。
- 只做漏洞指标不利用区域对比：浪费工具测试的第二重取证价值（fw25/pr011）。
- 布点脱离实际拓扑：接入点表与真实组网不一致，扫描日志与授权清单对不上即违规证据。

### 作者的盲点 / 时代局限

- 五原则成书于传统边界防火墙时代（等保 1.0），云原生下"隔离设备"语义扩展为安全组、NetworkPolicy、service mesh mTLS 边界、云账号边界——枚举逻辑不变，但每跳的可达性判断需新的工具（如跨命名空间探测）支持。
- 作者未讨论"探测点本身被攻击者利用"的风险（在客户环境引入新接入点/跳板的安全责任），外推时应补接入点自身的加固要求。

### 容易混淆的邻近方法论

- 布点法 vs 攻击路径图（attack path）：前者服务取证覆盖（每个边界都要有证据），后者服务攻击模拟（找最短路径）——目标相反时布点策略不同。
- 布点法 vs 扫描策略调优（并发/限速）：那是 `mlps-assessment-redlines` 的执行纪律，与位置选择正交。
