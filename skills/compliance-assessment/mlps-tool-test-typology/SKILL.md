# 工具测试类型学与证据形态匹配

## R — 原文 (Reading)

> 「在等级保护测评中经常采用的工具测试类型主要包括漏洞扫描、实时监测、渗透测试三类。」「实时监测工具不是入侵检测系统（IntrusionDetectionSystem，IDS），对于网络上的异常流量行为，它不会产生警示或任何提示」
>
> — 方法论出处，第4章 4.1（工具测试类型总论）、4.1.2（实时监测划界）

---

## I — 方法论骨架 (Interpretation)

"用了工具"不等于"测了该项"——每类工具只产出一种证据形态：

1. **三分法**：漏洞扫描（主动探测、发现可利用漏洞）、实时监测（截包解码、观测传输内容）、渗透测试（模拟攻击者、验证可利用性），分别对应"发现—观测—验证"三种证据形态。
2. **证据形态不可互换**：观测能力（看到流量）与检测告警能力（识别异常并报警）是两种证据来源——抓包不告警不改包，拿抓包截图支撑"入侵防范"类指标就是证据错配，入侵防范须查 IDS/IPS/HIDS 的规则配置与历史告警。
3. **顺序约束**：渗透是扫描的验证与补充——先扫描定位，再对候选漏洞做针对性验证；渗透报告须能对应到扫描发现项，没有扫描记录的渗透报告是不完整的证据链。
4. **扫描内部再分层**：系统层（OS/设备）/应用层（Web）/数据库层，评什么层用哪类工具。
5. **方案完整性判据**：测评项 × 证据形态做成对应矩阵，缺项即错配——这是报告质量审查的实用规则，也是"工具选型"的决策表。

## A1 — 书中的应用 (Past Application)

### 案例 1: 抓包不能当入侵检测的证据
- **问题**: 现场用 Wireshark 类工具抓了包，能否据此判"入侵防范"项符合。
- **方法论的使用**: 第4章 4.1.2 明确划界——实时监测工具不是 IDS，对异常流量不产生警示或提示；它的正确用途是验证数据传输保密性（发现明文口令）、核对流量控制。
- **结论**: 观测证据支撑保密性/流量策略类指标，入侵防范须另查 IDS/IPS 部署、告警规则与历史报警日志——证据错配的判定被显式给出。
- **结果**: "用抓包截图支撑入侵检测类测评项"成为报告审查中可直接引用的反例判据（ce06）。

### 案例 2: 渗透报告必须对应扫描发现项
- **问题**: 只交一份渗透测试报告、无扫描记录，证据链是否成立。
- **方法论的使用**: 第4章 4.1.3 定位渗透测试"是在漏洞扫描的基础上，对系统漏洞进行针对性的验证，同时也是对漏洞扫描结果的补充"，且一般选择不影响业务正常运行的方法。
- **结论**: 先扫描定位再针对性验证；渗透报告应说明"验证了哪一条扫描发现、结果如何"。
- **结果**: "扫描→渗透验证→风险评估"成为证据链顺序，渗透不能替代扫描（无扫描记录即证据链不完整）。

### 案例 3: 扫描按对象分三层选型
- **问题**: 漏洞扫描工具怎么按对象匹配。
- **方法论的使用**: 第4章 4.1.1 分系统层（主机/网络/安全设备 OS，查弱口令、开放端口、本地策略）、应用层（Web 爬虫探索后按策略测试注入/跨站/敏感目录）、数据库层（记录访问行为、识别越权、检测配置弱点）（引文"隐惠"为 OCR 噪声，应为隐患）。
- **结论**: "评什么层、用哪类工具、找哪类问题"三段对应，选型变成查表。
- **结果**: 工具清单按三层配置，测评方案的覆盖审查有了结构。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 编制测评/安全测试方案，决定配哪些工具、每项指标靠什么证据支撑。
2. 审查他人报告时发现"用了 Wireshark/eBPF 观测"被用来证明检测告警能力，需要判断证据是否错配。
3. 客户问"你们已经扫过了为什么还要渗透"，需要解释两类证据的层次关系。
4. 新观测技术（eBPF、NDR、RUM）出现，判断它能支撑哪类指标、不能支撑哪类。
5. 采购安全测试服务，验收其证据形态是否与目标指标对应。

### 语言信号 (用户的话里出现这些就应激活)

- "用什么工具测比较好？"
- "抓包能证明入侵检测吗？""都是工具测的，还分什么？"
- "扫描和渗透有什么区别？"
- "报告里工具结果怎么用/算不算测过？"
- 英文: "which tool to use"、"scanner vs monitor vs pentest"、"does packet capture prove detection"、"tool selection matrix"

### 与相邻 skill 的区分

- 与 `mlps-test-vantage-point-placement`（接入点布点法）的区别: 本 skill 管"用什么工具、产出什么证据形态"；后者管"工具放在哪个位置测"。同一工具在不同位置产出不同结论（区域对比），两个维度叠加。
- 与 `mlps-preponderant-evidence`（优势证据法）的区别: 后者裁决"强证据压倒弱证据"；本 skill 在取证设计阶段防止"证据与指标错配"——错配的证据再强也不支撑该指标。
- 与 `mlps-method-role-allocation`（三法角色组合）的区别: 后者决定访谈/检查/测试三法的角色；本 skill 在"测试"内部再分三类并绑定证据形态。

## E — 可执行步骤 (Execution)

1. **列出待证指标清单并标注证据需求**
   - 完成标准: 每项指标标注它需要"发现/观测/验证"中的哪种证据形态（如入侵防范=检测告警证据，传输保密=观测证据）。
2. **建立指标×工具对应矩阵**
   - 完成标准: 每项指标至少对应一类工具与具体证据物（扫描报告/抓包记录/渗透验证记录），矩阵无空格；空格即方案缺口。
3. **自查证据错配**
   - 完成标准: 逐格核对"该工具产出的证据能否支撑该指标性质"——观测类证据不得填入检测告警类指标；发现错配即换工具或补证据。
   - 判停条件: 若某指标在本环境无任何工具能产出对应证据形态（如无 IDS 且不可部署），如实标注"无法用工具验证"，转检查类证据（配置与历史日志）并按 `mlps-intrusive-test-downgrade` 说明，不得以近似证据顶替。
4. **排工具间的顺序依赖**
   - 完成标准: 渗透安排在扫描之后且逐条对应扫描发现项；监测类在业务流量代表时段执行。
5. **输出证据形态说明书**
   - 完成标准: 报告中每条工具结果注明"来源工具类型+支撑的指标+证据形态"，审查者可按矩阵复核。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只需漏洞清单不管指标对应关系的裸扫描任务——但用户应知道其结果不能外推为合规结论。
- 访谈/检查类证据的设计——本 skill 只管工具测试。
- 工具产品的具体选型对比（Nessus vs Qualys 等）——三分法之下的品牌选择超出本 skill 范围。

### 作者在书中警告的失败模式

- 证据错配：抓包截图支撑入侵防范指标（ce06）——观测被冒充为检测。
- 渗透无扫描基础：盲打或只交渗透报告，验证链条断裂（pr013）。
- "用了工具就是测了"的外行直觉：三类工具各管一段，混同即漏项。

### 作者的盲点 / 时代局限

- 三分法与示例工具（Nessus、Paros、SqlMap、明鉴一代）成书于 2014–2015，工具已换代（云原生扫描器、DAST/SAST/IaaS 合并工具、eBPF 观测）；但"发现—观测—验证"三种证据形态的划分不过时，新工具按其产出证据形态归入即可。
- 阶段 0 批判：书中"工具选择四原则"含"优先国产自主知识产权"等政策性条款，属规范性命题而非技术论证，与本 skill 的证据形态逻辑并置时须辨析。
- 渗透"一般选择不影响业务正常运行的攻击方法"在高级威胁模拟（APT 类红队）语境下会系统性偏离，两类活动的证据用途不同。

### 容易混淆的邻近方法论

- 三分法 vs DAST/SAST/SCA 等工程分类：后者按被测对象的技术栈分，前者按证据形态分——渗透性验证与静态发现不能混同。
- 实时监测 vs IDS 的界线是证据形态界线，不是产品能力高低界线——NDR 类新产品若仅观测无告警，仍属监测形态。
