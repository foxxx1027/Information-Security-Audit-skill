# 算法退役与密码敏捷治理链

## R — 原文 (Reading)

> "分解一个RSA-1024大约比RSA-768难1000倍……完全有理由期望在今后十年内攻破RSA-1024。"
>
> — 方法论出处，第9章 9.2.3 RSA的安全性（source.txt 行13588区，引 [KLEI10]）

---

## I — 方法论骨架 (Interpretation)

"算法会老"人人知道，可执行的是一条五环治理链：

1. **结构相似预警**：新算法与已破算法"结构和基本数学运算相似"即视为风险信号——SHA-1 与 MD5/SHA-0 同构所以提前退役，不必等实际碰撞出现。反例方向也成立：与已破算法同陷门族的"变体"不解决根本问题。
2. **难度外推**：用"难度倍数+时间跨度"推退役期——RSA-1024 比 768 难 1000 倍、768 比 512 难几千倍、512→768 花了 N 年 ⇒ 十年内可破 ⇒ 现在开始淘汰。退役由攻击进展曲线触发，不是被公告触发。
3. **套件档位**：把算法按强度打包成套件（VPN-A/VPN-B/NSA B），升级=换档而非逐参数重谈——互操作压力才不会逼你把弱算法永远协商下去。
4. **格式算法中立**：长期存续的格式（X.509 证书）不锁定算法，算法标识是字段——迁移时只改值不改结构。
5. **冗余保险**：PRF 双散列各担一半，任一算法猝死则整体仍安全——单算法突然被破时的廉价保命符。

配套纪律：密钥长度按**十年后攻击成本**预留（Diffie-Hellman 1977 并行机预言的应验）；版本升级是砍旧套件的强制窗口（TLS 1.3 删套件）。

## A1 — 书中的应用 (Past Application)

### 案例 1: DES 的标准降级时间线
- **问题**: 56 位 DES 何时、如何退出。
- **方法论的使用**: 时间线治理：1977 标准化→1994 延期 5 年→1999 FIPS 46-3 降为"仅遗留系统"并转 3DES→AES 取代；1977 年 Diffie-Hellman 百万加密器并行机预言（约 10 小时、2000 万美元）随算力应验。
- **结论**: 退役是"标准化→争议→限期降级→迁移替代"的过程，遗留兼容期是已知风险窗口。
- **结果**: 治理模式被后续所有算法复用；密钥长度预留原则确立（按攻击者可购算力外推）。

### 案例 2: SHA-1 的结构相似预警淘汰
- **问题**: SHA-1 尚无实际碰撞，为何退役。
- **方法论的使用**: 预警触发：SHA-1 建立在 MD4 之上、与已破的 MD5/SHA-0 同构；[WANG05] 把碰撞代价从 2^80 量级大幅压低后，NIST 2005 年宣布逐步废除。
- **结论**: "结构与已破者相似"即充分的迁移触发条件；同一逻辑再用于"以 SHA-3 备份 SHA-2"。
- **结果**: 淘汰决策先于实际碰撞发生——预警式治理成为惯例。

### 案例 3: RC4 与套件/格式/冗余三环的联动
- **问题**: 一个算法（RC4）出问题后如何整体收场。
- **方法论的使用**: 先定位（WEP 事故根因在密钥派生而非算法），再跟踪后续研究（KSA 偏差）→ RFC 7465 禁止用于 TLS、SP800-52 禁止政府使用——禁用通过**套件协商层**落地；同时 X.509 的算法标识字段使证书侧无需改格式即可换算法。
- **结论**: 退役的执行面在套件与格式两层；治理链各环在此案例中全部显形。
- **结果**: TLS 后续以删套件+版本升级收口（TLS 1.3），PRF 双散列冗余则保证过渡期单一 Hash 出事不致全断。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **建算法台账**: 列出系统全部密码算法/参数/用途/位置，附"血缘"字段（与哪些已破算法同构）。
   - 完成标准: 台账行覆盖所有密码调用点；血缘字段无空白。
2. **跑预警与外推**: 对每行判结构相似性风险；对参数类条目（密钥长度）按难度倍数+时间跨度外推退役期。
   - 完成标准: 每行有"预警/正常"标记与预估退役年份。
   - 判停条件: 若任一在用算法已处于标准明确弃用期，直接进入第 3 步为该算法立迁移项，不等待其余条目完成。
3. **套件化与档位设计**: 把替换目标打包成套件档位（如 hybrid X25519+ML-KEM 成套），定义新旧档位与协商规则。
   - 完成标准: 有档位表（旧档/目标档/强制切换 deadline）。
4. **格式中立改造**: 检查证书/令牌/协商字段是否带算法标识、能否不改格式换算法。
   - 完成标准: 每类长期格式有"算法可替换"结论或改造项。
5. **冗余与强制窗口**: 关键派生处加双算法冗余（或至少留热替换）；把版本升级节点定为砍旧套件的强制窗口。
   - 完成标准: 输出路线图（动作/责任/时间），含冗余点与强制窗口标注。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单算法强度评估（名实是否相符）——用分析代价判据。
- 一次性/短期系统（寿命短于算法安全窗口）——迁移成本不划算，记录决策即可。
- 协议语义不兼容的改版（消息流变化）——那是协议演进治理，本 skill 只管算法层。

### 作者在书中警告的失败模式

- 等"实际攻破"才迁移——SHA-1 的教训是结构预警就该动。
- 遗留兼容期无治理：弱算法因互操作压力被永远协商（WEP 保留 40/104 位兼容、VPN-A 长尾）。
- 与已破算法同族的"改良变体"当解决方案——陷门族不变根本问题不变。

### 作者的盲点 / 时代局限

- 第7版成书于 2017 前后：**后量子迁移只有方向没有机制**——书中无 ML-KEM/混合密钥交换词条，抗量子路线需自行按治理链框架补内容。
- 密码敏捷性作者"指出方向但未给持续治理机制"（阶段 0 批判原话）：敏捷性需要库存、监控、演练三件套，书中只有格式层（算法标识）。
- 云托管密码服务（KMS 提供商单方面换算法）场景缺位。

### 容易混淆的邻近方法论

- 与漏洞管理生命周期: 漏洞打补丁是单点修复；算法退役是种群级、以年计的计划性迁移——节奏与工具完全不同。
- 与"默认安全配置"硬化: 硬化把当下配置收紧；敏捷性保证未来能换——一个管现在，一个管演变。
