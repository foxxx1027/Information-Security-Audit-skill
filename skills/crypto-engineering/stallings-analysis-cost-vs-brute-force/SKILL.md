# 理想原语判据：分析代价≥穷举

## R — 原文 (Reading)

> "评价MAC算法抗密码分析能力的方法是，将其与穷举攻击所需的代价相比，也就是说，理想的MAC算法要求密码分析攻击所需的代价大于或等于穷举攻击所需的代价。"
>
> — 方法论出处，第12章 12.4.2 密码分析（source.txt 行16973–16979）

---

## I — 方法论骨架 (Interpretation)

密钥长度只在一个前提下才等于强度：**结构没有给攻击者留捷径**。所以评原语的第一问不是"多少位"，而是：

1. **有没有比穷举更快的公开分析？** 理想状态=最优已知分析（差分、线性、代数、中间相遇、生日类）的代价 ≥ 穷举。达到这条，强度才能"只按密钥长度比较"，一切选型讨论才有统一标尺。
2. **轮数/参数是为已知攻击设的安全边际**：16 轮 DES 的差分代价 2^55.1 恰好压过穷举 2^55；减到 15 轮就反转——轮数不是拍脑袋，是"略高于当前最优攻击"的定标。同理 Hash 抗碰撞按 2^(m/2) 计而非 2^m。
3. **强度按最便宜路径封顶**：多条攻击路并行存在时，实际强度 = min(各路径)。MAC 的两条路（定钥 2^k、造标 2^n）给出 min(k,n)≥128 的参数要求；多对一映射还会把单次比对假阳性率变成攻击成本乘数（80 位密钥+32 位 MAC 需三轮收敛）。

选型动作由此固定：要求提交方给出针对该具体算法的公开分析结论（差分/线性界+文献）；无分析结论的算法按"分析代价未知"降档，只配低价值数据并预置替换。

## A1 — 书中的应用 (Past Application)

### 案例 1: 16 轮 DES 的差分定标
- **问题**: DES 轮数为什么是 16。
- **方法论的使用**: 比价：16 轮差分分析 2^55.1（选择明文 2^47）vs 穷举 2^55——分析略贵于穷举，结构无捷径；15 轮及以下反转。
- **结论**: 轮数=针对已知攻击留边际；"分析≥穷举"达标后强度按 2^55（密钥长）计。
- **结果**: DES 的弱不在结构而在密钥长度——56 位被算力追上是另一条路（穷举）封顶的实例。

### 案例 2: Hash 的生日捷径改变一切长度结论
- **问题**: 128 位 Hash 够不够。
- **方法论的使用**: 结构捷径检查：生日攻击把碰撞代价压到 2^(m/2)——128 位只有 64 位强度；1000 万美元碰撞机 24 天破 MD5。
- **结论**: Hash 长度按 m/2 折算，"结构给攻击留捷径"被量化。
- **结果**: 长度建议从直觉位数改为按 2^(m/2) 折算的等效强度。

### 案例 3: MAC 的 min(k,n) 封顶与多轮消解
- **问题**: MAC 参数（密钥长 k、码长 n）怎么配合。
- **方法论的使用**: 列路径：定钥 2^k（多对一折叠，2^(k−n) 假阳性需 α=k/n 轮消解）；直接造标 2^n。实际强度取小者。
- **结论**: min(k,n)≥N（128 位）；单次比对假阳性率是攻击成本乘数。
- **结果**: 参数设计从"都取大"改为"并联路径下限"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 为新轻量级算法（ASCON 类、国密、私有算法）做选型评审，需要问对问题。
2. 审查自研/小众算法宣传："密钥 256 位、抗差分"——核对公开分析是否存在。
3. 评估减轮实现（性能优化把轮数/步数砍半）的安全边际。
4. 校准 MAC/标签/摘要的参数组合（避免短板路径）。

### 语言信号 (用户的话里出现这些就应激活)

- "这个新算法安全吗 / 有没有分析"
- "security margin / 差分界 / 线性界"
- "轮数够不够 / 减轮会怎样"
- "密钥 256 位，肯定安全吧"
- "lightweight cipher 选型"

### 与相邻 skill 的区分

- 与 `stallings-hardness-dependency-audit` 的区别: 那个审公钥方案的**难题归约**（陷门、难题族、等效换算）；本 skill 审对称原语的**结构捷径**（分析 vs 穷举）。一体两面：对称怕统计/结构残留，公钥怕数学可逆。
- 与 `stallings-statistical-residual-order-analysis` 的区别: 那个针对自研/古典构造（保留几阶统计）；本 skill 针对有公开分析生态的现代原语（查文献比价）。
- 与 `stallings-computational-security-three-questions` 的区别: 三问定"要多强"；本 skill 定"这个原语声明的强度是否名实相符"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列攻击路径**: 对目标原语列出全部已知路径——穷举、差分、线性、代数、生日类、多对一折叠等。
   - 完成标准: 每条路径有代价表达式（含数据量前提）。
2. **查公开分析**: 核对该算法是否有第三方分析文献（差分/线性界、轮数攻击结果）；无则标"分析代价未知"。
   - 完成标准: 每条路径标注"有文献依据 / 厂商自述 / 未知"。
   - 判停条件: 若为自研或无公开分析，跳到第 4 步直接按"未知降档"处理，不做虚假比价。
3. **比价定标**: 比较最优分析代价与穷举代价；给出"理想/有捷径"结论与实际有效位数。
   - 完成标准: 得出 min(各路径) 封顶的实际强度与最便宜路径名。
4. **定档与约束**: 理想→按密钥长度选档；有捷径或未知→降档（限低价值数据、限轮数不减、预置替换通道）。
   - 完成标准: 输出"可用范围 + 禁止事项（如禁止减轮）+ 替换预案"。
5. **登记复核义务**: 记录本次比价依据的文献与日期，标注下次复核触发条件（新分析发布）。
   - 完成标准: 台账条目含文献、日期、复核触发器。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 需求侧强度定档（防谁/防多久/值多少）——先做三问，再拿本 skill 校验供给。
- 自研线性/简单构造的快速否决——先过线性可解性与统计阶检验（分析生态不存在，无从比价）。
- 实现层问题（侧信道、随机源）——分析 vs 穷举的前提是黑盒模型。

### 作者在书中警告的失败模式

- 以密钥长度代替强度声明（结构捷径可让 128 位实际只剩 64 位）。
- 减轮/减步的性能优化吃掉安全边际（15 轮 DES 反转）。
- MAC 公开分析稀缺的现实：书中承认只能逐算法查文献、难有通用结论——"没有已知攻击"不等于"理想"。

### 作者的盲点 / 时代局限

- 书中比价止于经典分析（差分/线性/生日）；对现代攻击维度（多目标、相关密钥、量子 Grover 折半）未纳入公式，量子下"穷举基线"本身减半需重标。
- 轻量密码与置换型构造（海绵）在成书时分析生态未成熟，书中按"查文献"处理的建议在无文献场景下过于乐观。
- "理想"判据只覆盖机密性/完整性原语，对格式保持加密、可搜索加密等功能化原语无对应判据。

### 容易混淆的邻近方法论

- 与 NIST 算法竞赛评估: 竞赛是流程化落地（安全+代价+实现三维打分），本 skill 是单算法比价问句——前者用到后者的推理。
- 与"密钥长度等效换算"（跨算法标尺）: 换算的前提是双方都"理想"；本 skill 正是检验该前提的闸门。
