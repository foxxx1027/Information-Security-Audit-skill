# 攻击能力×成功等级双轴声明

## R — 原文 (Reading)

> "适应性选择消息攻击允许C将A作为"oracle"进行轮询。这意味着A可以被要求对于特定的消息签名，而这些消息与C之前已经获得的<消息-签名>对相关。"
>
> — 方法论出处，第13章 13.1.2 签名方案的攻击与伪造分级（source.txt 行17853–17874）

---

## I — 方法论骨架 (Interpretation)

"本方案签名不可伪造"是一句没有信息量的声明——除非补上两个坐标：

1. **能力轴（攻击者被允许什么）**，从弱到强：唯密钥（只有公钥）→ 已知消息（拿到若干消息-签名对）→ 一般选择消息 → 定向选择消息 → **适应性选择消息**（把签名者当 oracle，按已获结果迭代挑选下一个求签消息）。对称侧同构：唯密文 < 已知明文 < 选择明文 < 选择密文 < 选择文本，**及格线=抗已知明文**（现实中固定文件头、协议魔数到处都是已知明文）。
2. **危害轴（成功算哪档）**，从高到低：完全破译（拿出私钥）> 通用伪造（任意消息可签）> 选择伪造（特定目标消息可签）> **存在性伪造**（签出"某一个"消息即可，危害最低）。

两轴叉乘才是可比较的安全声明。审计经验：厂商白皮书常只证"最低档能力 × 最低档危害"（唯密钥攻击下不存在性伪造）然后说"不可伪造"。配套两条推论：被攻破算法按**实际攻击模型**重估残余价值（MD5 裸用的离线碰撞能力 ≠ HMAC-MD5 的在线同钥伪造能力，后者需观察同密钥 2^64 分组）；给攻击定级还要标**利用前提**（物理接触/本地/远程+所需硬件），前提改变（云多租户）则重评级。

## A1 — 书中的应用 (Past Application)

### 案例 1: 对称攻击五档谱系与"及格线"
- **问题**: 算法"抗分析"到底指抗什么。
- **方法论的使用**: 第3章排谱：唯密文→已知明文→选择明文→选择密文→选择文本，并列出已知明文的现实来源（Postscript 头、金融消息标准头、源码版权串）。
- **结论**: "只有相对较弱的算法才抵挡不住唯密文攻击"，工程及格线是抗已知明文。
- **结果**: 算法评估从单点结论改为"能扛到第几档"的标注。

### 案例 2: 签名攻击五级×成功四级（GOLD88）
- **问题**: 签名方案的安全性声明如何标准化。
- **方法论的使用**: 第13章给双轴定义（R 段引文即最高档能力的定义），并把危害分四级。
- **结论**: 脱离双轴谈"不可伪造"无意义；声明必须落到坐标上。
- **结果**: 全书签名章的评估与习题均按双轴组织，成为可比较的审计语言。

### 案例 3: HMAC-MD5 的按模型重估
- **问题**: MD5 碰撞可算后，HMAC-MD5 是否必须全线下线。
- **方法论的使用**: 换模型计价：裸 MD5 碰撞可离线任选消息进行；HMAC-MD5 攻击者不知密钥 K，无法离线造(消息,Hash)对，必须观察同密钥消息流，128 位码需 2^64 分组（1Gb/s 链路约 15 万年）。
- **结论**: 同算法不同模型不同结论——两个方向（全弃/全保）都是误用。
- **结果**: 书中认为注重速度时 HMAC-MD5"完全可以接受"，同时保留升级到 SHA 族的热替换路径。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 审查 MPC/托管签名/门限签名厂商白皮书的"不可伪造"宣称。
2. 安全公告发布后复核"XX 算法被破，我们的用法还能撑多久"。
3. 给自家产品的安全声明写规范（能扛到哪档、防什么档的伪造）。
4. 威胁建模时判断某条攻击（如故障注入需物理接触）是否纳入当期预算。

### 语言信号 (用户的话里出现这些就应激活)

- "厂商说 unforgeable / 不可伪造"
- "chosen-message attack / oracle 轮询"
- "MD5/SHA-1 被破了还能用吗 / residual strength"
- "存在性伪造是什么档"
- "这条攻击需要什么前提"

### 与相邻 skill 的区分

- 与 `stallings-analysis-cost-vs-brute-force` 的区别: 那个比价"分析 vs 穷举"定结构强度；本 skill 定**声明的语义**（能力×危害坐标）——比价结果要放进坐标才成为可审计声明。
- 与 `stallings-computational-security-three-questions` 的区别: 三问是需求侧（防谁/多久/值多少）；本 skill 是攻击者的**能力精细分档**——"防谁"的展开工具。
- 与 `stallings-evidence-asymmetry-non-repudiation` 的区别: 那个判"证据由谁可生成/验证"（功能维度）；本 skill 判"攻击声明落在哪一档"（强度维度）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **重写声明为双轴**: 把被审声明改写为"在〔能力档〕攻击下不存在〔危害档〕伪造/破译"的句式。
   - 完成标准: 声明含两轴坐标；写不出坐标的声明标记为"无法审计"。
2. **核能力档**: 确认攻击者在实际部署中能拿到什么（已知明文来源？可否在线求签/求解密=oracle？）。
   - 完成标准: 列出部署中真实可用的 oracle 与数据样本。
3. **核危害档**: 确认最关心的危害（拿私钥？给特定转账消息签名？还是任意消息）。
   - 完成标准: 危害排序表，最高危目标置顶。
   - 判停条件: 若部署中存在适应性 oracle 且业务最高危目标是"特定消息伪造"，声明必须按"适应性×选择伪造"档重证，否则直接判不达标。
4. **标利用前提**: 给每条已知攻击标物理/本地/远程前提与所需硬件，判断部署环境是否降低前提。
   - 完成标准: 每条攻击有前提标注；云/共享环境下的前提变化被点名。
5. **出结论**: 声明是否名实相符、需补证什么、残余价值的适用范围。
   - 完成标准: 结论含"声明的真实档位 + 缺口 + 建议补证项"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 强度需求定档（要防国家级对手吗）——三问框架的事。
- 协议时序缺陷分析（重放、降级）——那是协议层，双轴只给原语/机制声明定语言。
- 纯性能/实现缺陷（侧信道泄漏速率）——除非用于给侧信道攻击定利用前提档。

### 作者在书中警告的失败模式

- "不可伪造"被滥用为绝对声明——厂商话术通常只对应最低档组合。
- 一个模型下的结论外推到另一模型（HMAC-MD5 双向误判：全弃或全保）。
- 忽略利用前提：故障攻击需物理接触就"不构成严重威胁"——但前提是物理接触门槛不被云/供应链降低。

### 作者的盲点 / 时代局限

- GOLD88 分级与选择文本模型成形于 1980s；对现代聚合签名、门限/多方签名、格签名的特殊攻击面书中无对应词条，双轴要配合新场景自行加行。
- 及格线"抗已知明文"在 Web/云环境已偏低——服务端在线 oracle（解密/校验接口）普遍存在，现实及格线常是适应性档。
- 残余价值评估未考虑组合攻击（跨协议同钥复用把低危存在性伪造成长为高危）。

### 容易混淆的邻近方法论

- 与 CVSS 评分: CVSS 给漏洞定级（含可利用性/影响）；本 skill 给**密码声明**定语义档位——一个评漏洞，一个评声明。
- 与"威胁建模 attacker persona": persona 定对手身份；本 skill 定对手**与机制的交互权限**（能问什么 oracle）。
