# 攻击面双杠杆：先测绘收缩、再分层防御

## R — 原文 (Reading)

> "入侵者的优势在于他或她仅需要找到一个弱点，而设计者必须找到并根除所有弱点来获得完全的安全。……一旦明确一个攻击面，设计者就可想方设法使这个攻击面变小，进而使攻击者的任务更加困难。"
>
> — 方法论出处，第1章 1.1.3 与 1.7.1（source.txt 行1282–1284、1664–1675）

---

## I — 方法论骨架 (Interpretation)

安全对抗结构性不对称：攻击面按"或"组合（攻击者命中任一弱点即赢），防御面按"与"组合（防御者堵住全部才平）。由此推出两个**互相独立**的杠杆：

1. **收缩攻击面（管暴露）**：先测绘——把系统拆成网络攻击面（开放端口、协议漏洞）、软件攻击面（应用/工具包/OS，核心是解析外部数据的代码）、人类攻击面（社会工程、人为错误、内部人员；人是一等攻击面，不是意外因素）三栏清点；再收缩——关端口、砍服务、收权限、删代码。收缩直接减少"或"分支的数量。
2. **分层防御（管纵深）**：对收缩后的残余暴露面叠多层防护，任一层失效不致裸奔。

关键纪律是**分账**：收缩是减法（面变小），分层是加法（层变多），两件事在预算表、验收表上都要分开记。常见病是混淆两者——"我们上了 IDS/WAF"是加了层，暴露面一寸没小；反过来只收缩不检测，会漏掉已经在面内的攻击者。书中还有一条隐性教益：TLS 1.3 直接删掉旧套件代码来收缩攻击面——删代码也是一种加固。

## A1 — 书中的应用 (Past Application)

### 案例 1: 测绘-收缩-分层的价值链（图1.3）
- **问题**: 加固工作不知从哪下手、怎么排优先级。
- **方法论的使用**: 第1章 1.7.1 给出顺序链：系统化分析漏洞→知道哪里需要安全机制→明确攻击面→设法缩小→攻击者任务变难；图1.3 用"浅层/深层×低/中/高风险"网格说明分层与收缩互补。
- **结论**: 收缩提供测试与加固的优先级依据，分层补收缩的残余。
- **结果**: 攻击面同时成为加固路线图与验收基线。

### 案例 2: TLS 1.3 用"删代码"收缩攻击面
- **问题**: TLS 历代套件堆积，旧弱算法长期滞留。
- **方法论的使用**: 第17章：TLS 1.3 直接移除一批旧密码套件——不是加新机制，而是做减法收缩攻击面。
- **结论**: 删除无人使用的弱选项本身就是安全增强。
- **结果**: 减少了可被降级协商利用的弱副本，简化了实现面。

### 案例 3: IPsec 边界集中保护防旁路
- **问题**: 逐应用做安全，覆盖不全且易被旁路。
- **方法论的使用**: 第20章：IPsec 在边界对流量集中保护（分层的部署形态），对上层应用透明，防止单个应用漏配成为旁路。
- **结论**: 把防护层放在所有流量必经之处，是分层的选址判据。
- **结果**: 透明性与通用性成为 IPsec 的定位优势（对照第17章 Web 安全三落点）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 新服务/新设备（IoT 家庭网关、工控上位机）上线前的暴露面评审与加固排序。
2. 安全投入争论："已经有 WAF/IDS 了还要不要砍服务、关端口"——需要把两个杠杆分账说明。
3. 攻击面持续膨胀的存量系统（端口越开越多、解析器越加越多）做收缩规划。
4. 需要向非安全背景的人解释"为什么删功能/删代码也是安全工作"。

### 语言信号 (用户的话里出现这些就应激活)

- "attack surface 怎么梳理 / 攻击面有哪些"
- "先关哪些端口 / 先砍哪些服务"
- "我们有 WAF/IDS 了，还需要 reduce exposure 吗"
- "defense in depth 怎么落地 / 要几层"
- "这个系统的暴露面清单"

### 与相邻 skill 的区分

- 与 `stallings-attack-tree-and-or-modeling` 的区别: 攻击树对单一攻击目的展开路径与成本；攻击面是对全部暴露接触点的测绘。树上的一个"或"分支 ≈ 面上的一个接触点，但面的输出是清单与收缩动作，树的输出是切断点。
- 与 `stallings-design-principles-review-protocol` 的区别: 那个评审设计符合 13 条准则（含分层准则本身）；本 skill 做攻击面的**测绘与收缩动作**，分层只作为第二杠杆出现。
- 与端口扫描/资产清点工具: 工具给资产列表；本 skill 给三栏分类、收缩优先级与分账验收框架。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **三栏测绘**: 按"网络（端口/协议/管理口）/软件（解析外部数据的代码、依赖）/人（可被社工的流程与角色）"列出接触点，每项标入口、数据流、所需权限。
   - 完成标准: 三栏各有条目；每项能回答"攻击者从这里碰到什么"。
   - 判停条件: 若测绘发现完全无主的暴露面（无人认领的监听服务），先处理归属再继续。
2. **逐项收缩**: 对每项问"能不能关掉/删掉/收权/挪进内网"，生成收缩动作清单并执行。
   - 完成标准: 每个接触点有"已收缩/保留原因"记录；保留者标明业务理由。
3. **残余面分层**: 对保留下来的接触点配多层防护（边界过滤、认证、监测），并确认覆盖每个残余入口。
   - 完成标准: 无残余入口仅靠单层防护（除非显式接受）。
4. **两杠杆分账验收**: 输出两张表——收缩账（面小了多少项）与分层账（每入口几层、层间是否独立）。
   - 完成标准: 两账分开可核；"上了检测"不再被计入"已收缩"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已知具体漏洞（CVE）的修复决策——单点修补不改变面结构。
- 设计准则符合性评审（默认拒绝吗、最小权限吗）——那是准则协议的职责。
- 收缩会切断核心业务可达性的取舍决策——本 skill 提供清单，取舍需业务方共同裁决（书中明示收缩"可能损伤业务可达性"）。

### 作者在书中警告的失败模式

- 混淆两杠杆: 加层当收缩、以为检测可以替代暴露面缩减。
- 只收缩不检测: 漏掉"已在面内"的攻击者。
- 只加层不收缩: 维护成本随层指数上升，每层本身又是新攻击面。
- 漏掉"人"这一栏: 社会工程与内部人员是正式攻击面，不是脚注。

### 作者的盲点 / 时代局限

- 三类攻击面面向企业 IT（第1章）；供应链（第三方依赖、构建管道）与物理设施书中明示不在其分类内（fw008 边界），现代使用需补第四栏。
- 第7版（2017 前后）无云原生/容器/K8s 攻击面词汇（API server、服务网格、镜像仓库），测绘模板需自扩。
- "解析外部数据的代码是软件攻击面核心"在书中有论断但无度量方法。

### 容易混淆的邻近方法论

- 与 CIS Benchmark 类加固基线: 基线给逐项配置值；本 skill 给"先收缩后分层"的顺序决策与分账结构。
- 与零信任: 零信任否认"边界内可信"假设并导向微观分段——可视为收缩杠杆在现代的激进化，与本书"门卫+内部第二道防线"模型有代际差异。
