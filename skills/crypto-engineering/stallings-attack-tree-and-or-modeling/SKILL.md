# 攻击树与/或建模

## R — 原文 (Reading)

## I — 方法论骨架 (Interpretation)

威胁清单告诉你"有哪些威胁"，但回答不了"先堵哪个"。攻击树补上决策结构：

1. **根节点**写攻击者的目的（"盗走账户"），不写攻击手法——目的只有一个，手法才有分支。
2. **逐层展开**到叶子=一种具体可执行的攻击方式。中间节点只有两种语义：**或节点**=任一子路径达成即成功（攻击面天然按"或"组合）；**与节点**=必须全部满足（多因子、多步骤攻击）。
3. **给分支标属性**：难度、成本、所需能力。属性让树变成可计算的结构。
4. **防御策略从树里读出来**：防御者的任务是打断"或"分支里成本最低的那一环，或在"与"路径上增加一个必要条件。给高成本叶子加防护（如给已钓鱼不到的用户加邮件验证）不在最便宜切断点上，等于白花。

这把"都要防"的无力感换成"打断最便宜路径"的可执行目标。

## A1 — 书中的应用 (Past Application)

### 案例 1: 网银认证攻击树（图1.4）
- **问题**: "网银认证是否安全"无法作为单点问题回答。
- **方法论的使用**: 根节点="攻击用户的账户"，下分三个或节点分支——用户终端（UT：凭证窃取、认证绕过）、用户与机构间信道（CC：窃听、重放、会话劫持、中间人）、机构内部系统（IBS：凭据泄露、内部人员、系统绕过），每个叶子再标注攻击策略组合。
- **结论**: 对策必须分派到三分支——终端侧多因子/反木马、信道侧端到端加密、机构侧流程控制与异常检测；五类对策与树的分支一一对应。
- **结果**: "认证被攻破"从一句结论变成可逐条封堵的路径清单，每个未覆盖叶子即显性残余风险。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 评估某类账户/资产（网银、NFT 市场、管理后台）的安全，要系统枚举攻击路径并排防御优先级。
2. 决策"加这一层防护（邮件验证/二次短信）值不值"，需要判断它是否在最便宜切断点上。
3. 安全评审/威胁建模工作坊，要把散乱的威胁头脑风暴收敛成结构。
4. 向管理层解释"为什么不能承诺绝对安全"，需要展示攻击按"或"组合的结构性原因。

### 语言信号 (用户的话里出现这些就应激活)

- "画个 attack tree / 攻击树分析一下"
- "攻击路径有哪些 / 攻击者会怎么打进来"
- "先防哪个 / 哪条攻击路径最便宜"
- "加一层 XX 验证有用吗"
- "threat modeling 怎么把威胁排序"

### 与相邻 skill 的区分

- 与 `stallings-attack-service-mechanism-alignment` 的区别: 矩阵管全谱覆盖（威胁有没有漏）；树管单一攻击目的的路径收敛与优先级（哪条最容易走通）。先树后矩阵或反之均可，不互相替代。
- 与 `stallings-attack-surface-shrink-then-layer` 的区别: 攻击面管理管"暴露面测绘与收缩"（面的尺寸）；树管"路径与成本"（面的走法）。收缩攻击面会砍掉整棵子树，两者互补。
- 与 STRIDE 等清单法的区别: 清单法给类别，树给组合语义（与/或）与属性排序——这是本书资产的核心。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定根目标**: 用一句话写出攻击者目的（针对什么资产、达成什么后果），只写目的不写手法。
   - 完成标准: 根节点语句满足"资产+后果"两要素。
2. **展开分支**: 按"终端/信道/服务端（机构）"或业务自有分段展开一级或节点，向下迭代到具体手法叶子。
   - 完成标准: 至少两层；每个叶子是一条可独立执行的手法，不再含"等/之类"。
3. **判定与/或**: 对每个中间节点标注语义——子路径须全满足（与）还是任一即成（或）。
   - 完成标准: 无未标注的中间节点；多步骤组合攻击正确标为与节点。
4. **赋属性**: 给每个叶子标相对成本/难度/所需能力（低/中/高即可，能量化更好）。
   - 完成标准: 每叶子有属性；主观数值注明估计来源。
5. **找切断点**: 找出或节点下成本最低的路径集合，确定打断它需要什么控制；同时检查与路径上增加一个必要条件的机会。
   - 完成标准: 输出"最便宜切断点 Top N + 对应控制"，并指出哪些已有防护其实挂在高成本叶子上。
   - 判停条件: 若树中存在无需任何能力即可走的路径（成本≈0），跳过排序，直接报告该路径为最高优先级。
6. **映射与登记**: 把每个控制映射回它打断的分支，未被任何控制覆盖的叶子登记为残余风险。
   - 完成标准: 每个叶子要么被控制覆盖、要么进入残余风险清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 需求覆盖核对（要提供哪些安全服务）——用三层对齐矩阵。
- 单一已知漏洞的深入分析（该漏洞的利用条件与修补）——树是宏观收敛工具。
- 需要概率/损失量化的事件树分析——攻击树属性是相对比较用的，不是精算输入。

### 作者在书中警告的失败模式

- 把树当穷尽集合：树是"可能技术集合"的数据结构，依赖已知攻击模式，对全新手法覆盖不足（fw010 明示边界）。
- 属性估计主观导致优先级失真：难度/成本若无依据，排序结果误导防御投入。
- 树建完不更新：书中要求用事件数据与红队结果持续补枝，静态树会腐烂。

### 作者的盲点 / 时代局限

- 诚实标注（来自阶段 1.5 验证）：本书攻击树的形式结构与应用案例（网银树）**证据集中于第 1 章**，跨章佐证只是同族"枚举→映射"模板的矩阵/清单降维形态（第12/17/18章）——即书本身未在不同领域反复演练此方法，使用时应预期需要按对象域重构分支，而不是照搬网银三分支。
- 第7版（2017 前后）未涉及攻击树的自动化构建（如从 ATT&CK 映射）、供应链攻击分支、云控制面分支，需自行扩展。
- 书中属性标注未给量化方法（难度如何折算成钱/时间），实战需补。

### 容易混淆的邻近方法论

- 与故障树（FTA）: 结构同源但方向相反——故障树分析偶然失效的"与/或"逻辑，攻击树分析故意对手；防御结论不能直接互换。
- 与漏洞评分（CVSS）: CVSS 评单漏洞严重性；攻击树评路径可达性，同一低分漏洞可能构成树上的廉价切断点。
