# 认证对象分解与保障分档

## R — 原文 (Reading)

> "仅仅依靠读取和验证CHUID，只提供了个人身份的某些保证，这是因为采用这种方式认证的是卡，而不是持卡人。PIN和生物特"
>
> — 方法论出处，第15章 15.6.1 PIV 卡认证机制（引文按 OCR 原样保留截断）

---

## I — 方法论骨架 (Interpretation)

认证设计的第一问不是"用什么算法"，而是"**验的是物还是人**"：机制再强，对象错位就白做——CHUID 验证链完整，但认证的是卡不是持卡人，卡被捡到即失守。由此展开六条决策规则：

1. **对象分解**：设备认证与用户认证分别进行（移动两层认证），"一人一机"的假定在被盗/共用/交接时全部失效。
2. **因子按失效模式定价**：知识可改、持有物可换，生物特征不可重置——模板泄露按永久失陷计价，不能与可换因子同档使用。
3. **同类别叠加不算多因子**：密码+_PIN 仍是一个类别。
4. **确信度翻译成档位**：按操作风险定档（PIV 三档/在场要求），档位之间用 step-up 递进，而非全局一刀切。
5. **需求矩阵填空**：认证需求按方向×内容两维填表（谁验谁、验什么内容），空白格=攻击面（缺正向验证=假服务器面）。
6. **旁路检查**：找回/重置/客服流程是全部因子的公共旁路，必须同档防护；身份信任与设备健康分别检查，不健康给修复通道而非一票否决。

## A1 — 书中的应用 (Past Application)

### 案例 1: PIV 五机制阶梯与三关顺序（第15章）
- **问题**: 政府发卡场景如何按风险配认证强度？
- **方法论的使用**: 机制按保障级别阶梯化——CHUID（只证物）→卡认证密钥→BIO→BIO-A→PKI；三关顺序证书→PIN→挑战响应，把"需要多确信"做成档位。
- **结论**: 认卡只是"某些保证"，升级到认人需 PIN 与生物比对。
- **结果**: FIPS 201 形成按风险选配的标准范式。

### 案例 2: 移动设备两层认证（第18章）
- **问题**: 企业移动接入只配单一设备专用认证器（假定一人一机）够吗？
- **方法论的使用**: 对象分解——设备可能被偷或被恶意访问，验设备与验用户必须分别进行。
- **结论**: 更好的策略是两层认证（设备证书+用户凭据），配合远程清除、存储加密构成移动安全三层。
- **结果**: 两层认证写入移动安全策略（SP800-14 关注点）。

### 案例 3: NAC 身份×健康双因子（第16章）与双向矩阵（第15章）
- **问题**: 网络准入只验身份够吗？客户端要不要验网络？
- **方法论的使用**: 身份信任与设备健康分别检查、不健康给隔离修复通道；认证需求按方向×内容填矩阵——缺正向验证就是假服务器面（WEP 单向挑战认证的三重缺陷同理）。
- **结论**: 矩阵空白格即攻击面，逐格补齐。
- **结果**: NAC 双因子与双向认证成为准入设计标准项。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 分级登录/交易认证设计（查询/转账/大额各配不同强度）。
2. 移动/设备管理方案评审——设备认证够不够。
3. 找回/重置/客服流程的安全评审。
4. 因子组合合理性评审（"两个密码算 MFA 吗"、"生物特征泄露怎么办"）。

### 语言信号 (用户的话里出现这些就应激活)

- "分级认证 / step-up authentication"
- "设备认证还是用户认证 / device vs user authentication"
- "MFA 因子组合 / something you know / have / are"
- "找回流程绕过 / account recovery bypass"
- "生物特征泄露怎么办 / biometric cannot be reset"

### 与相邻 skill 的区分

- 与 `stallings-evidence-alignment-binding` 的区别: 本 skill 定对象与档位（验什么、多确信），那个定多证据的对齐结构（怎么合成）——先分档后聚合。
- 与 `stallings-auth-mechanism-axes` 的区别: 那个在机制类型层比选（域级基础设施 vs 个人级追责），本 skill 在对象层分解（物/人）并定档位——两类分层维度不同。
- 与 `stallings-two-phase-gated-access` 的区别: 那个是认证后的开门状态机（认证≠通路开放），本 skill 是开门前的因子配置——先后衔接。

## E — 可执行步骤 (Execution)

1. **标注认证对象**：对每个受保护操作问"当前机制验的是物还是人"，写出对象标注。
   - 完成标准: 全部操作有对象标注，错位处标红。
2. **定档位表**：按操作风险定档（低/中/高→因子组合），档位间定义 step-up 触发条件。
   - 完成标准: 档位表+触发条件成文。
3. **核对因子类别与定价**：跨类别才算多因子；生物特征按不可重置定价并限定使用面。
   - 完成标准: 每个因子的类别与失陷代价登记。
4. **填需求矩阵**：方向×内容两维填表（客户端验服务端？验哪些内容？），空白格逐个解释或补齐。
   - 完成标准: 矩阵无未解释空白。
   - 判停条件: 封闭物理环境单用户设备（工控本地面板类）可降档并记录理由。
5. **审计公共旁路**：找回/重置/客服流程按最高操作档审计，配同等防护。
   - 完成标准: 旁路审计报告成文，弱于主路径的旁路被加固或下线。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 授权/权限模型设计——认证回答"你是谁"，"能做什么"不在本 skill 范围。
- 把档位当拖延借口——低档也必须有明确机制，"以后再加"是空白格不是档位。

### 作者在书中警告的失败模式

- CHUID 认卡不认人（对象错位）。
- 口令派生密钥加密的应答构成离线字典 oracle（v4/v5 均受威胁，预认证只能"更为困难"）——口令熵是整个体系的隐性下限（ce064）。

### 作者的盲点 / 时代局限

- 书中档位原型是 FIPS 201 PIV（政府卡场景，成书 2017 前）；消费级生物识别、行为因子、FIDO/平台认证器书内无内容——映射时按四条规则自行打分，勿引用书内不存在的机制。

### 容易混淆的邻近方法论

- v41 证据对齐（聚合结构）。
- v50 机制四轴（类型选型）、v45 两阶段开门（后置状态机）。
