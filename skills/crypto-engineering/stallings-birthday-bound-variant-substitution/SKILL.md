# 生日界换算与变式调包攻击

## R — 原文 (Reading)

> "本质上，如果我们在均匀分布的0到N-1的范围内选择随机整数变量，那么在VN次选择后发生重复的概率就会超过0.5。因此，对于m位的Hash值，如果我们随机选择数据块，预计在√2m=2m/2次尝试后就将找到两个具有相同Hash值的数据块。"
>
> — 方法论出处，第11章 11.3.2 生日攻击（source.txt 行15140–15174；"√2m"为 OCR 噪声，即 √(2^m)）

---

## I — 方法论骨架 (Interpretation)

三条互相咬合的工程结论：

1. **折算律**：抗原像/抗第二原像约 2^m，**抗碰撞只有 2^(m/2)**——选 Hash 长度时先问"我要的是哪种抗性"：防碰撞场景 m 至少 256 位（碰撞强度 128）；64 位截断哈希的碰撞代价仅 2^32，消费级算力数小时。
2. **变式可构造 ⇒ 碰撞=调包**：Yuval 攻击把"找碰撞"变成"准备两堆变式"——合法消息 x 与恶意消息 y 各造 2^(m/2) 个语义不变变式（插"空格-空格-退格"、同义改写），比对 Hash 找到同码对，让签名者签 x、事后把签名贴到 y 上。只要对象可被对手批量变造（memo 字段、空白差异、排版），碰撞攻击就从理论变成现实诈骗。
3. **动态标尺**：强度不是绝对位数，是"现实工程可达的搜索能力"——1000 万美元专用机 24 天破 MD5（128 位），同机对 160 位需约 4000 年但随算力缩水。结论要带复核周期。

配套对策方向：升位到 m/2≥目标强度；**规范化消变式**（canonicalization 压掉可变空间）；用带上下文域分隔的完整摘要（防跨上下文碰撞挪用）。

## A1 — 书中的应用 (Past Application)

### 案例 1: Yuval 策略——签名场景的调包
- **问题**: 对 Hash 值签名，攻击面在哪。
- **方法论的使用**: 分析攻击者能力：可构造变式 ⇒ 双堆各 2^(m/2) 比对，签合法贴恶意。
- **结论**: 签名安全性=签名算法+Hash 抗碰撞性的绑定；按 2^(m/2) 而非 2^m 定长度。
- **结果**: "签名场景 Hash 至少 256 位"成为推论；Bob 双借据（诱签小额主张大额）场景把风险落到业务话术。

### 案例 2: 碰撞机的美元×天标尺
- **问题**: 128 位 Hash 到底够不够。
- **方法论的使用**: 换标尺：van Oorschot-Wiener 估算 1000 万美元碰撞机 24 天破 MD5；160 位需 4000 年且随软硬件进步缩短。
- **结论**: 强度评估以可购买算力为参照的动态判断；"160 位现在看来也比较弱"。
- **结果**: 直接支撑 NIST 淘汰 SHA-1 的决策链（与结构预警叠加）。

### 案例 3: 64 位 Hash 链的 2^32 脆弱
- **问题**: 无密钥 CBC 链接 + DES 64 位的 Hash 方案强度。
- **方法论的使用**: 按生日界折算：64 位 ⇒ 2^32 即可造碰撞；且该构造无密钥、可用"截获一条已签名消息+正反各 2^(m/2) 计算"复用签名。
- **结论**: 短 Hash+无密钥=可伪造；裸 Hash 不能当认证标签。
- **结果**: 该类构造被弃用，认证转向带密钥 MAC——生日界从"数学趣题"变成选型红线。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 区块链/数据系统用 64 位或 128 位截断哈希做去重指纹、内容寻址，评估撞库与刷指纹风险。
2. 文档/合同电子签名方案选 Hash 长度，或评估"签名后文档被同码替换"的风险。
3. 审查对象是否可被对手批量变造（富文本、可加字段的 JSON、PDF 附加区）。
4. 给"MD5/SHA-1 还能用在哪"划线（按使用场景的抗性需求反推）。

### 语言信号 (用户的话里出现这些就应激活)

- "birthday attack / 生日攻击 / 碰撞概率"
- "截断哈希做去重/指纹，多长够"
- "collision resistance / 找两个同哈希的消息"
- "签了名的文件被换成同哈希版本"
- "hash length 怎么定"

### 与相邻 skill 的区分

- 与 `stallings-hash-property-application-mapping` 的区别: 那个管"应用需要哪种抗性"（原像/第二原像/碰撞的映射）；本 skill 深入碰撞这一档的**量化**（m/2 折算、变式攻击、成本标尺）——先映射到位，再用本 skill 算长度。
- 与 `stallings-meet-in-the-middle-cascade-audit` 的区别: 两者都在 2^(n/2) 量级出现但机理不同——生日界是计数论证（无结构），中间相遇是结构化双向匹配；对策分别落在"加长/消变式"与"增加中间未知量"。
- 与 `stallings-algorithm-retirement-crypto-agility` 的区别: 碰撞机标尺是退役治理的输入信号之一；本 skill 不涉迁移机制。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定抗性需求**: 明确场景要防的是碰撞（两消息同码）还是原像/第二原像，及对手能拿到什么。
   - 完成标准: 需求语句为"防〔对手〕在〔数据量〕下构造〔碰撞/原像〕"。
2. **折算长度**: 按需求档位折算所需 Hash 位长（防碰撞按 m/2≥目标强度）。
   - 完成标准: 得到位长结论与推导式；截断方案（如取 SHA-256 前 64 位）单独标注等效强度。
   - 判停条件: 若截断后碰撞强度低于 2^64 且对象可被对手构造变式，直接判不合格，进入第 3 步改造。
3. **评估变式可构造性**: 检查对象格式能否被批量语义不变地变造（空白、附加字段、编码差异）；能则碰撞攻击现实化。
   - 完成标准: 变式空间结论+对策（规范化 canonicalization/域分隔）落地方案。
4. **套动态标尺**: 以现实搜索能力（GPU/专用机/云租用成本）复核达成时间，写复核周期。
   - 完成标准: 攻击成本估算（美元×时间）+下次复核日期。
5. **输出选型结论**: 位长+算法+规范化+域分隔的组合建议。
   - 完成标准: 结论含"若未来算法被结构攻击，位长再大也无效"的交叉引用（结构 vs 长度两轴）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 原像/口令破解场景——那走 2^m 档与慢哈希路线（抗性映射）。
- 对称密钥长度选择——密钥空间无生日折减（除多目标场景），别把 m/2 套到 AES 密钥上。
- 单条消息完整性抽查（无对手变式构造能力的信道）——碰撞威胁模型不成立。

### 作者在书中警告的失败模式

- 按 2^m 估算抗碰撞强度（64 位当 2^64 用，实际 2^32）。
- 以为"找碰撞"只是理论——变式构造让对手主导攻击准备（先备好对再诱签）。
- 静态评估：碰撞机/算力演进会把"4000 年"变成"数周"，结论必须带日期。

### 作者的盲点 / 时代局限

- 标尺数字（千万美元/24 天）是 1990s 估算，现代 GPU/云成本需重算；书中也自认"会大大缩短"。
- 指定下载型（chosen-prefix collision，真实世界 MD5/SHA-1 滥用的主力形态）书中未区分——比随机碰撞更现实，评估时需另行引入。
- 量子对碰撞界的立方根加速（BHT 理论界）未覆盖。

### 容易混淆的邻近方法论

- 与"鸽笼原理必然碰撞": Hash 必然存在碰撞（多对一），生日界说的是**找到**它的代价——"存在"不构成攻击，"可找到"才构成。
- 与去重系统的概率性误判分析（False Positive 率）: 无恶意对手时 2^32 是可靠性问题；本 skill 的语境默认对抗性对手，两套预算算法不同。
