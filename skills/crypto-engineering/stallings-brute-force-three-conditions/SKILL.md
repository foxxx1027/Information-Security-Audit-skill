# 穷举可行三条件与明文可识别性

## R — 原文 (Reading)

> "Caesar密码的三个重要特征使我们可以采用穷举攻击分析方法。（1）已知加密和解密算法。（2）需测试的密钥只有25个。（3）明文所用的语言是已知的，且其意义易于识别。"
>
> — 方法论出处，第3章 3.2.1（source.txt 行3999–4001）

---

## I — 方法论骨架 (Interpretation)

评估"会不会被穷举"时，大多数人只算第二个条件（密钥空间多大）。穷举其实是一条三段流水线，任何一段断掉整体失效：

1. **算法已知**——黑盒场景下攻击者先要拿到算法（现实中基本成立：标准算法、逆向固件）。
2. **密钥空间可穷尽**——2^k 是否在攻击者预算内。
3. **候选明文可自动判定**——试完每个密钥后，机器能否自动判断"这是不是合理明文"。这一段最常被忽视：判定需要一个校验器（语言模型、格式魔数、校验和、响应差异）。

第三个条件给出两个反直觉的工程结论：其一，**压缩/编码是加固**——明文先 ZIP 压缩，输出近随机，25 个候选无法自动判定，穷举失效（书中图3.4 的反例）；其二，一次一密的"不可破"本质上也是不可判定——穷举出大量可读明文却无法定真伪。反过来，短 PIN 场景里与其加长 PIN，不如**破坏可识别性**：配对码只当 KDF 盐、比对常数时间、失败响应不可区分——改识别面比扩空间便宜。

## A1 — 书中的应用 (Past Application)

### 案例 1: Caesar 穷举——三条件齐备
- **问题**: 最简移位密码为何几步即破。
- **方法论的使用**: 三条件核对：算法公开、仅 25 个密钥、英语明文可自动判定（查词表/频率）。
- **结论**: 三段流水线全通，逐一试钥即可。
- **结果**: 穷举在密钥空间之外没有任何障碍，成为一切穷举分析的基线案例。

### 案例 2: ZIP 压缩后穷举失效（图3.4）
- **问题**: 穷举是否只由密钥空间决定。
- **方法论的使用**: 保持前两条件不变（同一算法、同一小空间），把明文先压缩——输出近似随机，25 个候选解都"不可读"，自动判定器失效。
- **结论**: 可识别性是独立支柱；破坏第三段与破坏第二段同样致命。
- **结果**: "压缩后加密抬高穷举成本"成为书中明确给出的低成本加固方向。

### 案例 3: 一次一密穷举出大量可读明文却无法定真
- **问题**: 不可破性的来源是什么。
- **方法论的使用**: 同一密文配两个密钥分别解出 "mr mustard" 与 "miss scarlet"——穷举得到大量可读明文，但没有任何判定标准分真伪。
- **结论**: 不可判定性本身即信息论安全的来源之一。
- **结果**: "可识别性"这一轴被论证为与密钥空间并列的安全维度。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 评估 IoT 4 位配对码/PIN/短口令是否"必然 3 秒被穷举"，以及怎么补救最省钱。
2. 设计防离线穷举的口令/密钥存储（识别面改造：哈希慢化、响应不可区分）。
3. 决策"要不要先压缩再加密"作为纵深（注意与 AEAD 场景的交互）。
4. CTF 或评审中判断某小空间密钥方案的真实强度。

### 语言信号 (用户的话里出现这些就应激活)

- "PIN/配对码 4 位/6 位够吗"
- "brute force / 穷举要多久"
- "密钥空间只有 10^4，怎么办"
- "怎么让攻击者试不出来/失败响应怎么设计"
- "压缩后再加密是不是更安全"

### 与相邻 skill 的区分

- 与 `stallings-statistical-residual-order-analysis` 的区别: 那个分析穷举**之外**的统计攻击路；本 skill 判定穷举**本身**成不成立——完整评估=两问都问。
- 与 `stallings-computational-security-three-questions` 的区别: 那个定"要多强才够"（价值/时限/对手）；本 skill定"现有方案的穷举面在哪、哪一段最便宜可断"。
- 与口令强度计分工具: 计分管空间熵；本 skill 把识别面（判定器）纳入同等地位。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **核对三条件**: 对目标方案逐条问——算法可得吗？空间多大？攻击者的自动判定器是什么（格式、校验和、响应差异、语言模型）？
   - 完成标准: 三条件各有明确答案；判定器具体到"攻击者拿什么信号判对错"。
   - 判停条件: 若空间本身在可拒绝范围且无任何扩空间可能，跳到第 4 步直接做识别面改造。
2. **算穷举成本**: 按空间大小×单次尝试成本给量级（含在线/离线之别）。
   - 完成标准: 得到"离线全空间 X 时间 / 在线受限于速率 Y"的双口径结论。
3. **定位最便宜断点**: 比较三种破坏的成本——扩空间（加长）、藏算法（通常不可行）、坏识别（常数时间比对、失败不可区分、KDF 折叠、压缩）。
   - 完成标准: 有"推荐断点+理由"的一句话结论。
4. **实施与验证**: 改造识别面（或扩空间），并构造攻击者视角验证：攻击者现在用什么信号判定候选？
   - 完成标准: 改造后所有失败路径的观测行为不可区分；文档记录残余信号（长度、时序）。
5. **登记边界**: 明确本防护只断穷举路——统计、代数、侧信道路另行评估。
   - 完成标准: 结论附"未覆盖的攻击路"清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 非穷举类攻击主导的场景（线性可解、协议逻辑漏洞、侧信道）——断掉穷举路不挡其他路。
- 在线账户口令以速率限制/锁定为主防的场合——那是通道治理问题，识别面是离线场景的第二道闸。
- 把"输出不可读"当保密手段的方案（编码≠加密）——识别面分析针对攻击者的判定器，不提供对人的保密性。

### 作者在书中警告的失败模式

- 只算密钥空间（漏第三条件）——评估系统性偏乐观。
- 反向误区：以为压缩/编码提供了"保密性"——书中对 base64 的定位仅是"对偶然侦听者不可读"，不是加密。
- 短消息样本不足时宣称频率分析免疫——攻击者可以等更多密文，识别面优势随数据量衰减。

### 作者的盲点 / 时代局限

- 现代判定器远强于成书年代：机器学习语言模型可对"近随机但含结构"的候选打分，压缩的加固价值需按现代判定器重估。
- 在线穷举与离线穷举的区分书中未系统化（速率限制、锁定、分布式尝试的对抗属运维议题）。
- GPU/ASIC 时代单次尝试成本与书中算力估算差距巨大，成本计算需按当前硬件重做。

### 容易混淆的邻近方法论

- 与"密钥长度治理"（v15 退役治理链）: 那个管算法/参数随时间退役；本 skill 管同一时刻穷举面的三段结构——空间只是其中一段。
- 与 KDF 慢化（bcrypt/argon2 类）: 慢化是拉高单次尝试成本（作用于第二条件）；识别面改造作用于第三条件，两者互补。
