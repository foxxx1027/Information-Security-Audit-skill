# 计算安全三问与一次一密判据

## R — 原文 (Reading)

> "破译密码的代价超出密文信息的价值。 破译密码的时间超出密文信息的有效生命期。 如果加密体制满足了上述两条标准中的任意一条，则它是计算上安全的。"
>
> — 方法论出处，第3章 3.1.2（source.txt 行3913–3921）

---

## I — 方法论骨架 (Interpretation)

"这个加密够安全吗"没有绝对答案，只有三个参数化的问题：

1. **防谁**——对手的能力与资源（脚本小子、国家级、未来十年的算力曲线）。
2. **防多久**——信息的有效生命期。账单数据 30 天后贬值，医疗与计量数据要保 30 年以上；保护期超过算法安全窗口就必须预置替换。
3. **值多少**——攻破它值得花多少钱。破译代价>信息价值即计算安全。

这三问把"拍 256 位"变成推导：先定对手与年限，再查该年限下的等效强度档位，并预置算法替换通道。配套一个验收判据：凡有方案宣称"不可破/信息论安全"，先查一次一密三条件——密钥与消息**等长**、**真随机**、**一次性**；任一不满足即退回计算安全框架。书里还给出一条资源视角：安全上限常由密钥分发带宽而非数学决定（OTP 密钥与数据等长，30 年数据=30 年等长密钥，不可分发）——所以工程上默认落在计算安全一侧。

## A1 — 书中的应用 (Past Application)

### 案例 1: RSA-1024 的十年退役外推
- **问题**: RSA-1024 现在还能用吗。
- **方法论的使用**: 用"防多久"作答：分解 RSA-768 的团队外推——RSA-1024 比 768 难约 1000 倍，学术界合力有望十年内攻破，建议 2010 年起几年内逐步淘汰。
- **结论**: 参数生命周期由攻击进展曲线（难度倍数+时间跨度）决定，不是由"尚未被破"决定。
- **结果**: 书中把该建议作为密钥长度治理的推理链示范——结论带时效，需定期复核。

### 案例 2: MD5 碰撞机把"值多少/防多久"变成工程数字
- **问题**: 128 位 Hash 够不够。
- **方法论的使用**: 用价值/时限量化：1000 万美元专用机 24 天找一个 MD5 碰撞；同机找 160 位碰撞约 4000 年。
- **结论**: 强度档位可以用"美元×天"动态标尺比较，而非只看位数。
- **结果**: 128 位不够、转 160 位的结论由成本外推得出（并提醒随软硬件进步持续缩短）。

### 案例 3: 一次一密的两大工程难点
- **问题**: 唯一具有完善保密的体制为何"实际很少使用"。
- **方法论的使用**: 按 OTP 三条件核对现实：大规模真随机密钥难以产生；每条消息需等长密钥分发，成本随流量线性膨胀。
- **结论**: 完美保密的安全上限由资源瓶颈（密钥带宽）决定；OTP 是判据与极限参照，不是默认方案。
- **结果**: 书中定位其"主要用于安全性要求很高的低带宽信道"，密钥分发难题进一步成为公钥密码诞生的动因。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 为需长期保存的加密数据（智能电表 30 年、健康档案、链上存证）选强度档位。
2. 回答"密钥 128 还是 256 / RSA 2048 还是 3072"类选型问题，需要论证而不拍脑袋。
3. 审查厂商"不可破/军工级/信息论安全"话术。
4. 制定带年限的密码路线图（多久后必须换算法/换参数）。

### 语言信号 (用户的话里出现这些就应激活)

- "数据要加密保存多少年 / 保护 30 年要什么强度"
- "key length 怎么定 / 128 还是 256"
- "这个算法能撑多久 / 什么时候该换"
- "厂商说不可破 / information-theoretically secure"
- "harvest now, decrypt later 怎么应对"

### 与相邻 skill 的区分

- 与 `stallings-brute-force-three-conditions` 的区别: 那个分析**给定方案**的穷举面（三段流水线哪段断）；本 skill 定**需求侧**的档位（三问推导要多强）——一个自下而上体检，一个自上而下预算。
- 与 `stallings-algorithm-retirement-crypto-agility` 的区别: 那个是退役治理链（预警→外推→套件→格式→冗余的具体机制）；本 skill 提供三问框架，是治理链的输入。
- 与 `stallings-hardness-dependency-audit` 的区别: 那个审难题依赖与等效换算；本 skill 先问价值与时限，决定"需要多少等效强度"再去做换算。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **问防谁**: 写明对手档位（机会主义/定向/资源充足）与其可获得的数据（唯密文/已知明文/选择输入）。
   - 完成标准: 对手画像一段话，含算力与数据获取假设。
2. **问防多久**: 数据的有效生命期 + 算力年增长假设，得出"需安全的年数"。
   - 完成标准: 年数明确；超过 10 年的标注"跨算法退役周期，需预置替换"。
3. **问值多少**: 估算单次泄露的损失量级，与攻破成本的美元×天标尺比较。
   - 完成标准: 得出"合理防护投入上限"量级结论。
4. **OTP 三查（如有"不可破"宣称）**: 核对密钥等长/真随机/一次性三条件。
   - 完成标准: 三条件逐项判定；任一不满足即写"退回计算安全"。
   - 判停条件: 若三条件全部满足且密钥分发带宽在预算内（低带宽高价值信道），确认 OTP 适用并结束，无需再选档。
5. **定档并预置替换**: 按三问结论选等效强度档位（对称位数/公钥参数），并把"算法可替换"写进设计。
   - 完成标准: 档位结论可追溯到三问答案；替换通道（套件协商/格式算法标识）有明确落点。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已确定信息论安全路线的低带宽场景（外交/军事专线）——直接执行 OTP 三纪律即可。
- 具体协议与模式设计（选 CBC 还是 GCM）——三问定档位，不定构造。
- 纯合规填表场景（标准已给死参数）——按标准执行，三问仅用于论证文档。

### 作者在书中警告的失败模式

- 把"尚未被攻破"当安全依据——RSA-1024 的退役建议由外推而非实际攻破触发。
- 把一次一密当方案部署——两大工程难点（真随机产量、等长分发）使其实际很少使用；密钥复用一次即全毁。
- 静态取档：作者承认估计破译工作量"非常困难"且信息价值/有效期随时间变化——结论必须带复核日期。

### 作者的盲点 / 时代局限

- 第7版成书于 2017 前后，**后量子未覆盖**：面对"先收取后解密"的长期数据，非对称部分的"防多久"必须叠加量子时间线重推（Shor 算法使 RSA/ECC 的年限假设失效），书中无此维度。
- 算力外推以经典硬件为基准（Diffie-Hellman 并行机、碰撞机），未含 GPU/ASIC 租赁经济学的现代成本曲线。
- "值多少"以直接损失计，未含连带损失（信誉、合规罚款）的放大系数。

### 容易混淆的邻近方法论

- 与风险量化（ALE 年化损失）: 那是全年风险期望；本 skill 是单资产的保护参数推导——输出是密钥档位不是保险额。
- 与合规参数表: 表给答案，三问给理由与复核义务——审计时能说清"为什么这个位数"。
