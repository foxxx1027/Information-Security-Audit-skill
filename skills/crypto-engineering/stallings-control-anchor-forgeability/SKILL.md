# 管控落点与锚点可伪造性

## R — 原文 (Reading)

> "一个DHCP服务器的安装和配置是简单的，但是它受限于多种形式的IP欺骗，提供了受限的安全性。"
>
> — 方法论出处，第16章 16.1.2 网络访问控制实施方法

---

## I — 方法论骨架 (Interpretation)

每个管控检查点（准入、过滤、风控、路由）都隐含信任某个**标识**：MAC 地址、IP、域名、序列号、设备指纹。评审动作是三元组核对：**依赖哪个标识？该标识可否被伪造（谁能在多长时间内伪造出来）？检查点落在哪一层？**

三条选型规律：
1. **落点越靠近 IP 层，可伪造的标识越多**——DHCP 准入简单但受多种 IP 欺骗绕过；802.1X 在端口分配 IP 之前的链路层执行，最难绕过。
2. **单一静态标识类控制只能叠加、不能独担**——MAC 地址明文可嗅探可伪造，"仅仅是安全策略的元素之一"。
3. **验证锚点选"早可得、难伪造"的字段**——SPF 锚定信封域+连接 IP，可在收到邮件内容之前判定，锚点选择兼顾时效与强度。

另有一条出站侧定律：不对称防火墙下的"允许任意出站"是隧道逃逸面（SSH 远程转发借出站通道反向打洞）。评估零信任/代理化方案时，每个落点都要出一张"标识×可伪造性"小表。

## A1 — 书中的应用 (Past Application)

### 案例 1: NAC 四实施方法比较（第16章）
- **问题**: 网络准入控制的检查点放在哪、锚定什么？
- **方法论的使用**: 四方法按"落点×绕过难度"比较——DHCP 准入（IP 层，简单但多种 IP 欺骗可绕）对照 802.1X（链路层、拿 IP 前执行授权，最难绕，书内注明使用最多）。
- **结论**: 落点越靠近物理接入越难绕过。
- **结果**: 802.1X 成为 NAC 主流实施，组合 VLAN/防火墙成纵深。

### 案例 2: MAC 过滤的定位（第18章）
- **问题**: 无线网络配 MAC 白名单，未授权设备进得来吗？
- **方法论的使用**: 标识可伪造性核对——MAC 明文可嗅探、静态可伪造，监听合法客户端后冒用即过。
- **结论**: 书内明确"仅仅是安全策略的元素之一"，只能与强认证叠加。
- **结果**: 单一静态标识控制的定位从"防线"降级为"纵深一元素"。

### 案例 3: SPF 锚点选择与 SSH 远程转发（第19、17章）
- **问题**: 邮件发件人验证锚定哪个字段？出站策略宽松有什么后果？
- **方法论的使用**: 锚点选"握手层可得、无法事后伪造"的信封域+连接 IP——收内容前即可判定（早可得收益）；SSH 远程转发利用不对称防火墙的任意出站建反向通道——出站面即逃逸面。
- **结论**: 锚点选择=时效×强度；出站白名单化是隧道逃逸的对策。
- **结果**: SPF 判定时机前移；远程转发成为出站策略审计的固定用例。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 准入控制/零信任方案的检查点设计（放哪层、锚定什么标识）。
2. 设备指纹/序列号类风控的有效性评审。
3. 防火墙出站策略的隧道逃逸审计。
4. 标识类控制（MAC/IP/域名白名单）的加固评估。

### 语言信号 (用户的话里出现这些就应激活)

- "MAC 过滤有用吗 / MAC filtering bypass"
- "设备指纹可伪造吗 / device fingerprint spoofing"
- "准入控制放哪层 / where to enforce NAC"
- "零信任检查点 / zero trust enforcement point"
- "SSH 隧道绕过防火墙 / SSH tunneling escape"

### 与相邻 skill 的区分

- 与 `stallings-security-layer-placement` 的区别: 那个决定安全机制长在哪一层（架构），本 skill 在网络/准入语境下核对每个检查点标识的可信度（细节）——那个画段，本 skill 验锚。
- 与 `stallings-unauthenticated-key-exchange` 的区别: 那个锚定密钥协商中公钥的背书，本 skill 锚定管控流程依赖的标识——同一"锚点可伪造性"思想，对象不同。
- 与 `stallings-environment-threat-rewrite` 的区别: 那个重推全量威胁模型时，标识可伪造性表是其中一张小表。

## E — 可执行步骤 (Execution)

1. **列检查点清单**：写出全部检查点（准入、过滤、风控、路由策略），各自填写依赖的标识字段。
   - 完成标准: 检查点×标识清单成文。
2. **评可伪造性**：对每个标识回答"谁能产生/嗅探/伪造？静态还是动态绑定？"——标出伪造成本。
   - 完成标准: 可伪造性评级成文。
3. **降级独担控制**：把任何单一静态标识独担的检查点改为纵深叠加元素。
   - 完成标准: 独担项清零或有书面风险接受。
4. **为验证流程选锚点**：优先"早可得+难伪造"字段；核对能否在收到内容/放行流量之前完成判定。
   - 完成标准: 锚点选择有对比记录（备选锚点的时效/强度对比）。
   - 判停条件: 标识已与强密码凭证绑定（如证书内含标识）时，引用 v35/v33 结论不再重评。
5. **审计出站面**：对"允许任意出站"的通道逐条标隧道逃逸面，改为代理化/白名单化。
   - 完成标准: 出站策略表无未审计的任意通道。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 标识/目录/命名体系本身的设计（那是身份基础设施问题）。
- 因"可伪造"全盘否定标识类控制——书内定位是"策略的元素之一"，纵深中仍有价值。

### 作者在书中警告的失败模式

- DHCP 准入受多种 IP 欺骗绕过（落点太靠上）。
- MAC 过滤可欺骗（ce083）；地址绑定在同网段冒充下失效（第15章 Kerberos 地址绑定的残余问题同理）。

### 作者的盲点 / 时代局限

- 书中四方法止于 2017 前的 NAC 形态；零信任/SASE/硬件远程证明（设备证明签名）是外推场景——书内没有"硬件签名不可伪造"的论述，使用时需自行验证该假设。

### 容易混淆的邻近方法论

- v35 公钥背书（密钥协商锚点）。
- v43 层次选型（架构层）、v42 认证对象（人/物分解）。
