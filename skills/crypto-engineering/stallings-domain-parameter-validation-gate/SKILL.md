# 域参数与输入校验闸门

## R — 原文 (Reading)

> "为了防止小子群攻击，素数p的选择应满足p=2q+1，其中p也是素数。"
>
> — 原作者，附录 B.9 防小子群参数（source.txt 行28616–28655）

---

## I — 方法论骨架 (Interpretation)

密码协议的运算函数对**任何输入都会给结果**——参数错了照样"能跑通"，这正是危险所在：错误参数不是兼容性问题，是安全漏洞。闸门清单：

1. **群存在性**：椭圆曲线参数 (a,b,p) 先验判别式 (4a³+27b²) mod p ≠ 0，否则加法无良定义，体制无从谈起。这是"能不能建群"的前置检查。
2. **小子群防护**：素数 p 取安全素数 p=2q+1、生成元限 q 阶子群（g^q=1）；ECC 侧用素数阶曲线。攻击者诱导对端在小子群中运算即可提取私钥低位——协议全程无报错、密钥持续泄露。
3. **对端公钥验群成员**：收到的公钥点是否在曲线上、是否无穷远点、是否在正确子群（防无效曲线/无效点攻击）；ECDH 协商结果是曲线点，须折叠过 KDF 才当会话密钥。
4. **概率判定的聚合**：素性测试单轮只证伪不证实（2047 骗过 a=2 的 Miller-Rabin、341 骗过古代判据）——多轮随机底数聚合置信，且"必要条件≠充要条件"要写进生成断言。
5. **自研运算先验代数结构**：数集在所选运算下是不是域（Z_2^n 不是域、2 无逆元；模 8 乘法表 3 出现 4 次而 4 出现 12 次——映射不均匀即弱）；密钥生成的数论结构（p−1 大素因子、gcd 小）做成断言与回归测试。

闸门失败的动作是**断开并告警**，不是降级继续。

## A1 — 书中的应用 (Past Application)

### 案例 1: Miller-Rabin 被 2047 骗过
- **问题**: 概率素性测试"通过"意味着什么。
- **方法论的使用**: 实测：n=2047=23×89 是合数，但对底数 a=2 满足 2^1023 mod 2047=1，单轮返回"可能是素数"。
- **结论**: 单轮只能排除部分合数；t 轮独立随机底数把错误率压到 (1/4)^t——概率判定+可调置信度是标准范式。
- **结果**: 密码参数生成规范要求规定测试轮数与随机底数来源；341 反例进一步警示"必要条件误当充要"。

### 案例 2: 安全素数与素数阶曲线的选参准则
- **问题**: DH/ECC 参数怎么选才能关掉小子群面。
- **方法论的使用**: 推导：p=2q+1 时 Z_p* 子群阶只能是 1/2/q/2q，生成元取 q 阶即把运算锁进大素数阶子群；ECC 侧"通常使用阶为素数的曲线"使子群结构平凡。
- **结论**: 参数选择直接决定协议安全性；私钥取值区间与子群阶对齐。
- **结果**: 附录 B 给出可运行的参数校验例程，"参数由对端提供时尤其要校验"成为实现纪律。

### 案例 3: ECDH 的点验证+KDF 折叠
- **问题**: 协商结果直接截断当密钥行吗。
- **方法论的使用**: 检查两处：协商结果 K=nA×PB 是曲线点（一对数），须取 x 坐标（或其函数）并过 KDF 才是对称密钥；未验点（不在曲线上/无穷远点）会遭无效曲线攻击。
- **结论**: "点验证+KDF"两步缺一不可；ECDH 输出是共享秘密不是最终密钥。
- **结果**: 实现清单固化为：验点→运算→KDF→用途派生。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. VPN 网关/服务端接受对端发来的自定义 DH 参数组，"能跑通"算不算兼容。
2. ECC 库/SDK 实现评审：收到公钥后做没做在曲线/子群检查。
3. 密钥生成代码审查：素性测试轮数、随机底数、p−1 结构断言。
4. 自研混淆/编码运算的代数结构体检（是不是域、映射均不均匀）。

### 语言信号 (用户的话里出现这些就应激活)

- "对端发来的 DH 参数 / 自定义 group 直接收吗"
- "small subgroup / invalid curve attack"
- "point validation / 公钥验证"
- "Miller-Rabin 要跑几轮 / 素性测试可靠吗"
- "能跑通是不是就够了"

### 与相邻 skill 的区分

- 与 `stallings-hardness-dependency-audit` 的区别: 那个管难题层（陷门/族/归约）；本 skill 管参数与输入层（群存在/子群/成员资格）——难题选对了参数错了照样破。
- 与 `stallings-randomness-engineering-governance` 的区别: 那个管随机**生产**；本技能管生成后的**结构自检**（p−1 因子、判别式断言）与对端输入校验——一个供给侧质量，一个输入侧闸门。
- 与通用输入验证（防注入）: 那是语法/语义合法性；本 skill 是**代数合法性**（输入是否属于使协议安全假设成立的代数结构），普通 Web 校验框架不管这个。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列输入面**: 枚举协议中一切由对端提供或外部注入的密码学输入（DH 参数、曲线、公钥点、nonce 范围）。
   - 完成标准: 输入清单成文；标注每项的信任来源。
2. **逐项配闸门**: 为每项输入指定校验（判别式/p=2q+1 或标准组白名单/g^q=1/点在曲线/点在子群），并规定失败动作=断开+告警。
   - 完成标准: 每项输入对应至少一条可执行检查；无"忽略并继续"分支。
   - 判停条件: 若对端参数完全不受控且无白名单机制，判定为架构缺口（需引入标准组白名单），闸门细则暂缓。
3. **审计生成侧**: 检查本地密钥/参数生成的断言（素性轮数与底数来源、p−1 大素因子、gcd、私钥区间对齐子群阶）。
   - 完成标准: 断言清单入代码（可回归测试），禁"为速度选小 d"类越界。
4. **验 KDF 折叠**: 确认一切协商型共享值（ECDH 点等）都经 KDF 派生用途密钥，无直接截断使用。
   - 完成标准: 每条密钥派生路径成文且过 KDF。
5. **造反例回归**: 用 2047/341、小子群样本点、非曲线点构造测试向量，验证闸门全部拦截。
   - 完成标准: 反例集入 CI；历史上有"能跑通"记录的路径被证明已封死。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 难题族/算法选型层的问题——先定族再谈参数闸门。
- 随机数生产质量（熵源、DRBG）——供给侧治理另有清单。
- 非密码学输入的业务校验——代数闸门只管密码输入。

### 作者在书中警告的失败模式

- "能跑通"当兼容通过——运算正确性与安全性无关（小子群下协议静默泄密）。
- 概率测试跑一轮就信（2047 反例）；底数固定/可预测会退化出可构造的伪素数攻击面。
- 忽略必要≠充要（341：n 整除 2^n−2 不代表素数）。

### 作者的盲点 / 时代局限

- 书中闸门素材分散（第2/5/10章+附录B），未整合为统一协议——本 skill 的清单化是提炼产物；现代实现可直接引用标准校验例程（如 Curve25519 的点编码设计天然免验，属设计级消解，书未覆盖）。
- 侧信道维度的校验（验证时序差异本身可成 oracle）未纳入。
- 后量子 KEM 的解封装输入校验（是否可拒收非法密文的权衡）不在第7版范围。

### 容易混淆的邻近方法论

- 与 TLS 的"命名组"协商: 命名组=把闸门白名单化（只允许预审参数）——是本 skill 闸门策略的一种实现，不是替代。
- 与模糊测试: fuzz 找崩溃；本 skill 找"不崩溃但违反代数假设"的接受行为——恰好是 fuzz 最容易漏报的一类。
