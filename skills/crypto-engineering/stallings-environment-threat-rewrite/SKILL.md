# 环境迁移的威胁模型重推

## R — 原文 (Reading)

> "恶意的内部成员在云计算范例中，一个组织放弃了许多安全方面的直接控制，给了CP一个很高级别的信任。"
>
> — 方法论出处，第16章 16.5 云安全所面临的威胁和对策（[CSA10] 恶意内部成员条目）

---

## I — 方法论骨架 (Interpretation)

换环境（换介质、上云、引入第三方服务）后沿用旧威胁模型，等于拿旧地图走新地形。重推的方法是**免费保障盘点**：

1. **列免费保障**：旧环境因物理/组织属性白送了哪些保障？有线网的物理连线附带接入认证与链路隐私；本地机房附带数据不出域、专属硬件、审计自主。这些从未出现在旧威胁模型里——因为不需要。
2. **判定丢失**：新环境逐项对照——保留、弱化、消失。消失项就是新攻击面（无线取消物理边界→窃听与冒充成默认面；上云放弃直接控制→内部人威胁从"个案"升级为结构性风险）。
3. **显式补回**：每个消失的保障设计替代控制，落成"威胁→对策→责任人"三列闭环；外包给供应商的责任写进合同/SLA，不能停在"责任共担"的标语。
4. **架构重估**：环境开放程度可能改变方案族（Kerberos v4 面向受控 LAN、v5 面向开放互联网）——先重估架构选型，再谈具体协议。

配套检查清单四因素：广播信道、移动性、资源受限、物理可接近——新环境逐项过。

## A1 — 书中的应用 (Past Application)

### 案例 1: 有线→无线的免费保障显式化（第18章）
- **问题**: 把有线网的安全方案照搬到无线，缺什么？
- **方法论的使用**: 盘点有线免费保障——物理连线附带"接入即认证"与链路隐私；无线（广播信道+物理可接近）全部取消，于是逐项补回：802.1X 准入认证、802.11i 加密与完整性。
- **结论**: 无线安全需求不是新发明，而是旧环境隐性保障的显式化清单。
- **结果**: 无线安全体系（认证、访问控制、带完整性的隐私）按丢失项逐项重建。

### 案例 2: 本地→云的矛盾与三列闭环（第16章）
- **问题**: 云的基本矛盾是什么？
- **方法论的使用**: 盘点本地免费保障——直接控制、物理隔离、审计自主；上云后"一个组织放弃了许多安全方面的直接控制，给了 CP 一个很高级别的信任"，恶意内部成员成为结构性威胁；CSA 七威胁逐条配对策，落"威胁→对策→责任人"闭环，供应商项入合同与 SLA。
- **结论**: 控制权让渡而安全隐私策略必须持续有效——这是迁移要解的矛盾本体。
- **结果**: 云威胁清单与责任矩阵成为选型与合同基础；VM 隔离"只是策略的一部分"的定位也由此而来。

### 案例 3: Kerberos 环境假设的换代（第15章）
- **问题**: 为什么 v4 之后要有 v5？
- **方法论的使用**: 环境开放程度驱动架构——v4 假定受控 LAN（环境缺陷清单：字节序、Ticket 生命期、认证符等），v5 面向开放互联网环境重推威胁（跨域、拦截环境）并成批修正。
- **结论**: 环境变化先于协议设计；架构选型是环境变量的函数。
- **结果**: v4→v5 的"环境缺陷/技术不足"双清单成为迁移分账的原始范本（同书第15章）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 系统上云/换部署形态（IDC→PaaS、容器化、Serverless）的威胁模型更新。
2. 引入第三方服务（LLM API、SaaS 风控、外部支付通道）的安全评估。
3. 设备从内网移到边缘/现场/车载环境的评审。
4. 并购或架构迁移后"旧安全设计还成立吗"的复核。

## E — 可执行步骤 (Execution)

1. **列免费保障清单**：写出旧环境的全部结构性前提（物理边界、专属硬件、可控链路、人员可控、审计自主、低延迟可信时钟等），标注哪些从未进过威胁模型。
   - 完成标准: 清单成文，每项注明其在旧环境中的保障来源。
   - 判停条件: 同构迁移（同信任域内换机器/升配置）可引用原模型做增量核对后结束。
2. **逐项判定丢失**：对照新环境标保留/弱化/消失，消失项登记为新攻击面。
   - 完成标准: 判定表成文。
3. **过四因素清单**：广播信道/移动性/资源受限/物理可接近，逐项查新环境特有威胁。
   - 完成标准: 四因素各有结论。
4. **补回并闭环**：每个消失保障设计替代控制，落"威胁→对策→责任人"三列；供应商承担项写进合同/SLA 条款。
   - 完成标准: 三列闭环表+合同条款草案成文。
5. **重估架构选型**：判断环境开放程度是否已越过原方案族的适用边界（受控→开放），必要时先换架构族再谈协议。
   - 完成标准: 架构复核结论成文。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 增量配置变更（单策略调整、版本升级）——那是 v47/v48 的对象。
- 把"责任共担"当结论——它是需要逐项落到合同与控制的起点，不是交差话术。

### 作者在书中警告的失败模式

- 云的基本矛盾：放弃直接控制而策略必须持续有效（cs050 原文）。
- VM 隔离"只是这个安全策略的一部分"（ce071）——单一技术手段不能整体替代丢失的物理隔离。

### 作者的盲点 / 时代局限

- 四因素清单以无线/云为样本（成书 2017 前），LLM API、边缘计算、数据跨境等新环境因素需自行扩充；书中云威胁清单是 CSA 2010 时代版本，引用时按当前版核对。

### 容易混淆的邻近方法论

- v33 信任拓扑（维度之一）。
- v02 三层对齐矩阵（工具）、v43 层次选型（后续动作）。
