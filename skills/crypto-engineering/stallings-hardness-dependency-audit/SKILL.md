# 难题依赖审计与等效强度换算

## R — 原文 (Reading)

> "一个函数，若计算函数值很容易，并且在缺少一些附加信息时计算它的逆是不可行的，但是已知这些附加信息时，可在多项式时间内计算出函数的逆，那么称这样的函数为单向陷门函数"
>
> — 方法论出处，第9章 9.1.3（source.txt 行13151–13193）

---

## I — 方法论骨架 (Interpretation)

一切公钥方案都站在某道数学难题上，审计就是把这个立足点挖出来：

1. **三问**：陷门是什么（哪个附加信息让求逆变容易）？依赖哪族难题（因子分解/离散对数/椭圆曲线离散对数/格/……），该难题被公开研究了吗、当前最好攻击代价多少？参数怎么随代价增长（RSA 位数、曲线阶、格维数）？答不出第一问的方案（"自造难题"）按不可审计拒收。
2. **同族即相关风险**：RSA/DSA/ElGamal/ECDH 表面是四个方案，底下是两三族难题——难题被破（尤其量子解离散对数与分解）则一族同亡。算法组合若全押同一难题族，多样性是幻觉。
3. **等效换算禁比位数**：不同算法族的位数不可直接比，换到同一标尺——128 位对称 ≈ RSA 3072 ≈ ECC 256；256 位对称 ≈ RSA 15360 ≈ ECC 512。厂商"8192 位"未经换算无意义。
4. **体制分野**：对称怕统计/结构残留，公钥怕数学可逆——分析清单按体制选，别拿频率分析套 RSA，也别拿因子分解套 AES。

## A1 — 书中的应用 (Past Application)

### 案例 1: RSA 以因子分解为基准的三路归并
- **问题**: RSA 的三条数学攻击路径（分解 n、直接算 φ(n)、直接求 d）哪条最便宜。
- **方法论的使用**: 归并：后两条已知至少与因子分解同难度 ⇒ 以"因子分解进展"为唯一基准跟踪（RSA-129→RSA-768 记录、GNFS 代价降至 20%）。
- **结论**: 安全余量是经验曲线不是定理；参数建议由分解记录外推。
- **结果**: "难度倍数+时间跨度"外推出 RSA-1024 十年退役线（并联动 p−1 大素因子、d 长度等参数自检）。

### 案例 2: DH/ECC 的离散对数族与换算表
- **问题**: ECC 凭什么"密钥短还更安全"。
- **方法论的使用**: 定族：DH 安全性建立在"模幂易、离散对数难"上（q=353 小例演示）；ECC 同族但换到曲线群。同长度下 ECC 与 RSA 计算量相当 [UURI97] ⇒ 同强度下 ECC 密钥更短更快。
- **结论**: 换算表（表10.3）给出跨族统一标尺；SP800-57 的建议带时效（"至少到 2030 年"）。
- **结果**: 选型讨论从"谁的位数大"改为"谁的等效强度高+代价低"。

### 案例 3: BBS 续位测试——可归约构造的范式
- **问题**: "伪随机"如何从直觉变成可验证性质。
- **方法论的使用**: 定义续位测试（不存在多项式算法以>1/2 概率由前 k 位预测第 k+1 位）；BBS 的安全性归约到分解 n——攻破 PRNG 即可分解 n。
- **结论**: 高保证场景可要求"可归约到已知难题"；归约是信任的硬通货。
- **结果**: 与"自造构造无归约"形成对照，审计口径由"看起来随机"升级为"归约到哪"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 审查厂商"自研抗量子算法，密钥 8192 位"的宣称（一句话戳破三问）。
2. 评估算法组合的集中度风险（是否全押离散对数族）。
3. 跨算法选型比较（RSA vs ECC vs 格）需要统一标尺。
4. 供应链引入新密码组件（SDK、HSM 固件）时的依赖面盘点。

### 语言信号 (用户的话里出现这些就应激活)

- "自研算法 / 私有公钥体制，可信吗"
- "trapdoor / 陷门 / hardness assumption"
- "RSA 3072 和 ECC 256 哪个强"
- "归约 / reduction / 可证明安全"
- "抗量子算法怎么评估"

### 与相邻 skill 的区分

- 与 `stallings-analysis-cost-vs-brute-force` 的区别: 那个评对称原语的结构捷径（分析 vs 穷举）；本 skill 评公钥方案的难题立足点与归约——体制分野正是两技能的接口。
- 与 `stallings-algorithm-retirement-crypto-agility` 的区别: 那个管退役与迁移的执行链；本 skill 提供退役判断的**输入**（难题族进展=结构预警信号源）。
- 与 `stallings-domain-parameter-validation-gate` 的区别: 那个管"参数对不对"（闸门校验）；本 skill 管"立足的难题真不真"（族与归约）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **挖陷门**: 对目标方案写出"正向易算靠什么、求逆靠什么附加信息"。答不出的标"陷门不明"。
   - 完成标准: 每个方案一行陷门描述；"不明"者单列。
   - 判停条件: 陷门不明且无公开分析 ⇒ 直接拒收（按"自造难题"处理），不再走后续比价。
2. **定难题族**: 把系统内全部公钥方案映射到难题族（分解/DL/ECDL/格/解码/……），统计集中度。
   - 完成标准: 族谱表；单族占比 >80% 的标"correlated risk 高"。
3. **查最好攻击**: 对每族查当前最优算法与代价（含经典与量子），对照自用参数算等效位数。
   - 完成标准: 每族一行"最优攻击+等效强度"；量子敏感族标 Shor 风险。
4. **统一换算**: 把所有在用/候选算法换算到对称等效位数，检查是否都达到目标档。
   - 完成标准: 换算表（含 SP800-57 类标准的时效标注）；位数直比在文档中被替换。
5. **输出依赖面报告**: 族集中度、最低等效强度、替换建议（异族多样化）。
   - 完成标准: 报告含"一族被破时的连带失效清单"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 对称原语评估——无陷门结构，走分析代价判据。
- 需求侧强度定档——三问（防谁/多久/值多少）先做。
- 具体参数校验（p−1 结构、曲线判别式）——那是参数闸门的职责，本 skill 只管"参数之前的难题层"。

### 作者在书中警告的失败模式

- 拿位数直接比较跨族算法（ECC 256 ≠ RSA 256 的语义）。
- 忽略"判据清楚而计算困难"的落差：算术基本定理判据漂亮但不可计算——存在性判据不是算法，反之"没听说能破"不是安全依据。
- 换算表当永久结论——表值随攻击算法与算力变化，标准建议自带到期日。

### 作者的盲点 / 时代局限

- 第7版成书于 2017 前后：**后量子（格、码、hash-based、等距）不在正文**——本 skill 的"难题族"清单需自行扩入 PQ 族；书中的量子提示仅散见。
- 归约的"具体性"（tight reduction vs 松归约导致参数膨胀）书中未讨论——归约松紧影响实际安全余量。
- 安全多方计算、聚合签名等复合原语的难题依赖叠加未覆盖。

### 容易混淆的邻近方法论

- 与"可证明安全"文献: 那是构造与证明的学术活动；本 skill是**消费侧审计动作**——不造证明，只问"你的证明站在哪道题上、那题还难吗"。
- 与标准选型（NIST/国密曲线清单）: 用标准清单是参数闸门的结果；本 skill 解释清单背后的族与等效强度逻辑。
