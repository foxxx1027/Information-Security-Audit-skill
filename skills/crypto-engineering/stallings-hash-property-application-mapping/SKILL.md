# Hash 抗性蕴含与应用映射

## R — 原文 (Reading)

> "Darth拦截了该消息，篡改或替换其中的数据，然后重新计算Hash值并附在后面。Bob收到篡改后的数据块以及新的Hash值，未能发现消息已经被篡改。为了防止该类攻击，由Alice生成的Hash值必须得到保护。"
>
> — 方法论出处，第11章 11.1.1（source.txt 行14912–14916）

---

## I — 方法论骨架 (Interpretation)

"用 SHA-256"是万能答案式偷懒。Hash 有三条独立抗性轴，应用各取所需：

1. **蕴含图**：抗原像（给定 h 找 M）、抗第二原像（给定 M₁ 找 M₂ 同码）、抗碰撞（任找一对同码）。关系只有一条单向边：抗强碰撞 ⇒ 抗弱碰撞；**其余互不蕴含**——满足前五条需求的是"弱 Hash"，加上抗强碰撞才是"强 Hash"。所以"能防 X 就能防 Y"的推理在 Hash 上大多是错的。
2. **应用映射**：数字签名（对摘要签名）需**抗强碰撞**（Bob 双借据：诱签小额变式、主张大额变式）；口令存储需**抗原像 + 慢化**（快哈希被 GPU 每秒 billions 次试——必须加盐+argon2/bcrypt 类内存困难慢哈希）；文件完整性/版本锚需**抗第二原像**；去重指纹只需碰撞档强度（可按 m/2 截断换性能）。
3. **校验值自身要保护**：Hash 函数公开无密钥——Darth 改数据后重算 H(M′) 一并转发，Bob 毫无察觉。"算得出"不等于"伪造不了"；完整性=Hash+对校验值的保护（MAC/签名/可信信道）。

同一系统里不同用法应分别映射，避免"处处同算法"的错配（口令用快哈希是典型事故）。

## A1 — 书中的应用 (Past Application)

### 案例 1: Bob 双借据——签名场景需抗强碰撞
- **问题**: 对 Hash 签名时，签名者防的是什么。
- **方法论的使用**: 场景推演：Bob 准备两条同 Hash 借据（小额/大额），诱 Alice 签小额后主张大额——攻击落在碰撞抗力而非原像抗力。
- **结论**: 签名场景的 Hash 需求=抗强碰撞（配合 m/2 折算定长）。
- **结果**: 签名方案安全性="签名算法+Hash 抗碰撞"的绑定，两轴任一失守即整体失守（第13章复用此结论）。

### 案例 2: Darth 重算攻击——裸 Hash 不构成认证
- **问题**: 发送 M‖H(M) 算不算防篡改。
- **方法论的使用**: 攻击推演：Hash 公开可算，Darth 篡改后重算附上，校验必过。
- **结论**: 完整性校验值必须受保护——H(S‖M) 共享秘密、MAC 或签名；"我们加了 SHA256 校验"要先问校验值怎么防伪。
- **结果**: 四种认证方案（加密 M‖H、只加密 H、H(S‖M)、整体加密）成为按"是否需保密/有无共享钥"选型的菜单，工程收敛为 HMAC。

### 案例 3: MAC 均匀性独立于底层 Hash 抗性
- **问题**: HMAC 的安全与 Hash 抗碰撞是什么关系。
- **方法论的使用**: 跨章对照：MAC 的均匀性要求（随机 M′ 匹配概率 2^−n）是独立于底层 Hash 抗碰撞性质的参数——HMAC-MD5 在 MD5 碰撞可算的背景下按实际攻击模型重估仍可用（需在线同钥观察 2^64 分组）。
- **结论**: 用法上下文改变所需抗性档位；蕴含图+攻击模型共同决定"还能不能用"。
- **结果**: "同算法不同上下文不同结论"成为退役决策的精细粒度。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 统一密码策略时被问"口令存储、文件去重、合同存证能不能都用 SHA-256 一把梭"。
2. 口令/令牌存储方案评审（发现快哈希、无盐、无慢化即违规）。
3. 设计文件完整性/软件供应链校验（校验值本身怎么发布与保护）。
4. "MD5/SHA-1 下线"公告后的存量用法盘点（按上下文划保留线）。

### 语言信号 (用户的话里出现这些就应激活)

- "口令哈希用 SHA-256 行不行 / argon2"
- "preimage / second preimage / collision 三种抗性区别"
- "文件指纹/去重用多长的哈希"
- "加了哈希校验是不是就防篡改了"
- "MD5 还能用在哪儿"

### 与相邻 skill 的区分

- 与 `stallings-birthday-bound-variant-substitution` 的区别: 本 skill 定"要哪种抗性"；那个算"这种抗性值多少位、怎么被变式攻击"。映射在前、折算在后。
- 与 `stallings-evidence-asymmetry-non-repudiation` 的区别: 那个判"证据由谁可生成"（MAC vs 签名的仲裁能力）；本 skill 判"Hash 用哪条性质"——一个管认证构件的**主体**，一个管构件的**性质档位**。
- 与 `stallings-structural-reduction-parameterized-construction` 的区别: 那个管 Hash 怎么造；本 skill 管 Hash 怎么用。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列 Hash 用法清单**: 枚举系统里每处 Hash 调用（口令、去重、签名摘要、完整性、缓存键、HMAC 内核），各标输入来源与对手能力。
   - 完成标准: 每处用法一行，含"对手能否选择输入/重算校验值"。
2. **逐处映射抗性**: 按蕴含图给每处标注所需抗性（原像/第二原像/碰撞）与所需强度档位。
   - 完成标准: 每处有"抗性+档位"结论；口令处若非"单向+慢化+盐"直接标违规。
   - 判停条件: 若存在"裸 Hash 当认证"的用法（校验值无保护），先修这一处（加 MAC/签名），它比档位不足更致命。
3. **核对校验值保护**: 对每个完整性用法检查校验值本身的传递与保护方式。
   - 完成标准: 每处标注保护机制（MAC/签名/带外可信信道）。
4. **统一或分化算法**: 按"满足全部映射需求的最低配置"出推荐——能统一则统一（运维简单），冲突则分化并写明各档理由。
   - 完成标准: 输出算法矩阵（用途×算法×参数×理由），无"一把梭"也无过度分化。
5. **登记退役线**: 对每档标注算法退役触发条件（结构预警/碰撞进展），与算法治理链衔接。
   - 完成标准: 每档有复核日期与替换预案。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- Hash 构造本身的设计/评审——那是结构归约的事。
- 碰撞强度的位数折算——生日界换算的事，本 skill 只定"要不要抗碰撞"。
- HMAC 构造细节（内外层 padding 为什么那样设计）——机制转述，直接用标准即可。

### 作者在书中警告的失败模式

- 把"改任何一位哈希都对不上"当防篡改——Darth 会重算。
- 处处同算法（口令用快哈希）；或反向过度分化（十种用法十种算法）。
- 蕴含方向搞反：以为抗原像能导出抗碰撞——互不蕴含是定义性的。

### 作者的盲点 / 时代局限

- 口令哈希的慢化（argon2/bcrypt/scrypt 类内存困难函数）在书中未展开——第7版时代背景尚浅，现代口令存储按本 skill 的映射结论必须外补慢哈希族知识。
- 可截断哈希（XOF、Hash 截断做指纹）的工程规范书中未系统化。
- 供应链场景（对摘要签名 vs 对清单签名、可复现构建）未覆盖。

### 容易混淆的邻近方法论

- 与"加密 vs 哈希"的入门区分: 那是可逆性区分；本 skill 在哈希内部再分三档——更深一层的选型。
- 与密码套件选择: 套件管协议级组合；本 skill 管单一函数的性质档位，是套件决策的输入之一。
