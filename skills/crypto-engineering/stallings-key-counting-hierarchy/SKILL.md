# 组合计数与密钥层次/频次分层

## R — 原文 (Reading)

> "网络中每一对想要通信的主机都需要一个密钥，即若有N台主机则需要的密钥数目为[N(N-1)]/2。"
>
> — 方法论出处，第14章 14.1 密钥分发模式

---

## I — 方法论骨架 (Interpretation)

密钥体系选型的第一步不是挑产品（"用 KMS"），而是**计数**：N 个实体逐对共享密钥需要 N(N−1)/2 把——1000 节点约 50 万把，再乘上应用层放大就不可运营。数字先于架构，把"要不要中心化"变成可计算问题。

计数不可行后走三步论证链：
1. **层次坍缩**：引入可信中介或派生结构，把逐对密钥坍缩为每实体一把主密钥（共 N 把），会话密钥在线派生。
2. **按"单位成本×发生频率"分层**：最贵的操作配最低频——根/主密钥离线保管、偶尔使用；会话/数据密钥高频在线、短命易换（低频换根、高频换叶）。
3. **减少需钥实体**：网关终止加密把需钥方从全部端点收缩到网关；一次交换只产一个主密钥、全部会话密钥从它单向派生，便于集中保护，也打断"旧钥加密新钥"的泄露链。

## A1 — 书中的应用 (Past Application)

### 案例 1: KDC 与混合分发（第14章）
- **问题**: 端到端逐对分发密钥组合爆炸（1000 节点≈50 万把），应用层再放大到 5000 万。
- **方法论的使用**: 先计数论证不可运营 → 引入 KDC 层次（每实体与 KDC 共享一把主密钥，会话密钥在线派生），并与公钥体制组成混合方案按频次分工。
- **结论**: 层次结构把密钥量从 O(N²) 压到 O(N)。
- **结果**: KDC/混合分发成为对称侧标准架构。

### 案例 2: Kerberos 跨域（第15章）
- **问题**: 域间两两共享密钥全连接，N 个域要 N(N−1)/2 次安全密钥交换，多域不可扩展。
- **方法论的使用**: 同一计数论证 → v5 用 FORWARDABLE 转发票据沿层次路径走（先向上到公共祖先域再向下），绕开全连接。
- **结论**: 信任关系层次化替代两两互信。
- **结果**: 跨域访问不再随域数平方增长。

### 案例 3: TLS 密钥派生与网关终止（第17、20章）
- **问题**: 每连接握手昂贵，密钥如何摊销？
- **方法论的使用**: 主密钥→key_block 单向派生全部会话密钥（低频换根、高频换叶）；隧道网关终止加密减少需钥实体（书列三项收益）。
- **结论**: 派生结构同时解决成本与保护问题。
- **结果**: 会话恢复/网关模式成为标准部署形态。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 多节点/多服务互访的密钥体系设计（K8s 集群 mTLS、服务网格证书）。
2. 组织/集群扩张后证书与密钥运维成本失控，评估要不要中心化。
3. 制定密钥轮换策略——哪些常换、哪些不换、换的代价。
4. 跨域/跨集群互访的密钥关系设计。

### 语言信号 (用户的话里出现这些就应激活)

- "密钥数量爆炸 / key explosion, pairwise keys, N(N-1)/2"
- "5000 个服务互相 mTLS / mesh certificate management at scale"
- "密钥轮换策略 / key rotation policy"
- "要不要集中式密钥管理 / centralized vs distributed key management"
- "主密钥、会话密钥怎么分层 / master key vs session key hierarchy"

### 与相邻 skill 的区分

- 与 `stallings-trust-topology-blast-radius` 的区别: 本 skill 用数量算架构（管理多少把），那个用拓扑算风险（谁能给我签、单点失陷波及多大）；同一个层次结构，本 skill 问运营成本，那个问爆炸半径，先后使用。
- 与 `stallings-credential-splitting` 的区别: 那个拆凭据的职责与寿命（票据 vs 认证码），本 skill 拆密钥的数量与频次层次——正交两刀。
- 与 `stallings-key-separation-binding` 的区别: 那个管一把钥匙能干什么（用途绑定），本 skill 管需要多少把、多久换。

## E — 可执行步骤 (Execution)

1. **计数**：数出实体数 N、需要通信的关系类型与应用放大系数，算出逐对密钥数量 N(N−1)/2 及总量级。
   - 完成标准: 计数表成文（含 1 年后的增长预估）。
   - 判停条件: 若 N<10 对且无增长预期，逐对密钥+登记在案即可，勿过度设计。
2. **判可运营性并坍缩层次**：不可运营则设计两级结构——每实体一把主密钥/中间 CA，工作密钥在线短期签发。
   - 完成标准: 层次图成文，密钥量级降到 O(N)。
3. **按成本×频率分档**：为每层密钥写明寿命、存放位置、轮换频率（根密钥离线低频；工作密钥小时级在线）。
   - 完成标准: 分档表每格有显式值与理由。
4. **引入需钥实体收缩**：评估网关终止/层次路径能否减少持钥方，数出收缩前后的需钥实体数。
   - 完成标准: 对比数字成文。
5. **画派生关系图**：一次协商只产一个主密钥，全部会话密钥单向派生——核对无"旧钥加密新钥"的链式依赖。
   - 完成标准: 派生图成文且通过泄露链检查（一处失陷不串联全部后续）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单应用单密钥场景（无组合爆炸问题）。
- 把层次化当安全增益本身——层次是为了可运营；单点风险要另交给 v33 评估，勿在此混谈。

### 作者在书中警告的失败模式

- 用旧密钥加密新密钥形成泄露链：攻击者获得一个密钥则后续全泄露，数百万密钥须重新分发（ce050）。
- 主密钥被当作数据加密密钥使用，根信任材料暴露在最大攻击面（ce051）。

### 作者的盲点 / 时代局限

- 书中层次原型是 KDC/Kerberos（成书 2017 前），未覆盖云原生 KMS/自动轮换/SPIFFE 类工程形态；迁移到现代栈需自行映射机制对应关系。

### 容易混淆的邻近方法论

- v33 信任拓扑（风险维度）。
- v38 凭据拆分（寿命维度）、v40 用途分离（用途维度）。
