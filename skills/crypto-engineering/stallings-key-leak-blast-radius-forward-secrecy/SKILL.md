# 密钥泄露爆炸半径与前向安全

## R — 原文 (Reading)

> "使用RSA的危险在于一旦私钥被攻破，所有使用这组加密套件的握手都将被攻破。而使用DH或ECDH时，每一个握手对应一个新协商的密钥。"
>
> — 方法论出处，第17章 17.2.9（source.txt 行22483–22485）

---

## I — 方法论骨架 (Interpretation)

密码分析的收益函数是**密钥**而非单条明文——一把钥匙解锁该钥下的全部过去与未来。所以密钥架构设计的核心问句是爆炸半径："拿走这把钥，能解多少历史、能冒充多久未来？"

1. **三档定损**：消息级（泄露一条消息/一次会话）、密钥级（一把会话密钥的全量流量）、主密钥级/身份级（信任锚失陷=系统级）。定损先归档，再谈修复。
2. **职责分离判据**：长期身份密钥（证书私钥）只用于签名/认证，绝不承载会话机密性；会话密钥每次由临时材料（瞬时 DH/ECDH）派生——未来泄露解不开过去流量，这就是前向安全。静态 RSA 密钥交换正是违反此判据的反面教材，TLS 1.3 直接禁掉它。
3. **属性逐项判定**：长期共享密钥可提供保密性与真实性，但**没有新鲜性**（不能抗重放）——"安全"必须拆成保密/认证/新鲜分别打勾。
4. **最小暴露目标=零留存**：通信前后不存在密钥（Merkle 方案的理想），工程上追求密钥生命周期最短、层级最少；警惕"旧钥加密新钥"的串联泄露链——上层一破层层塌。

## A1 — 书中的应用 (Past Application)

### 案例 1: Merkle 简单分发方案与它的中间人缺口
- **问题**: 能否设计"通信前后都不存在密钥"的分发。
- **方法论的使用**: A 发临时公钥、B 加密会话钥回传、用完即弃——零留存达成，被攻破风险最小、通信防窃听。
- **结论**: 静态优点（零留存）成立，但方案无身份认证，中间人替换公钥即可窃听——零留存不等于安全，缺的属性要另补。
- **结果**: 该方案成为"先看静态优点、再审缺失环节"的教学样本，也铺垫了前向保护思想。

### 案例 2: TLS 静态 RSA → 瞬时 DH 的迁移论证
- **问题**: TLS 四种密钥交换的安全性排序。
- **方法论的使用**: 按两维打标：参数是否被认证（防中间人）、密钥是否长期静态（前向安全）。静态 RSA 私钥失陷=历史全会话可解；瞬时 DH 每握手新钥，旧会话不受未来泄露影响。
- **结论**: 瞬时+签名=三种 DH 中最安全；判据落地为"私钥泄露的爆炸半径"。
- **结果**: TLS 1.3 禁用 RSA 密钥交换——架构判据驱动协议换代。

### 案例 3: 长期共享密钥的抗重放缺口（属性分判）
- **问题**: 可信目录+长期密钥的通信"既保密又真实"，够吗。
- **方法论的使用**: 逐属性判定：保密性✓（只有对方能算密钥）、真实性✓（只有对方能产生该密文）、新鲜性✗——旧消息原样重放仍有效。
- **结论**: 保密与认证不能替代新鲜性；属性分判防"笼统安全"错觉。
- **结果**: 补法指向 nonce/时间戳/会话重协商，成为密钥交换协议的标准配菜。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 评审车联网 TSP/IoT 平台等"集中保管海量终端私钥"的架构，评估 HSM 失陷后果。
2. TLS/长连接服务的 PFS 改造决策（是否强制 ECDHE、禁静态 RSA）。
3. 事故应急：一把私钥泄露后划定定损范围（哪些历史流量、哪些身份需要轮换）。
4. 密钥层次设计（主钥/密钥加密钥/会话钥）与串联泄露链检查。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **画密钥清单与层级**: 列出所有密钥类型（身份/主/密钥加密钥/会话），标出"谁加密谁/谁派生谁"的依赖图。
   - 完成标准: 依赖图完整；每把钥标注寿命与存放（内存/HSM/磁盘）。
2. **逐钥定损**: 对每把钥问"拿走它能解多少历史、冒充多久未来、还能解开哪些下层钥"。
   - 完成标准: 每把钥有爆炸半径档位（消息级/密钥级/主密钥级）与量化描述。
   - 判停条件: 若任何一把钥定损为"可解全部历史会话"（无前向安全），直接标记为架构缺陷并进入第 3 步整改，不再继续细评。
3. **查职责分离**: 检查长期身份密钥是否只用于签名/认证；会话密钥是否全部由临时材料派生。
   - 完成标准: 每把长期钥的用途清单里无"加密会话密钥"条目；无临时派生的会话钥列出改造项（ECDHE 等）。
4. **属性分判**: 对每个受保护通道逐项打勾——保密/认证/新鲜性。
   - 完成标准: 三属性矩阵；缺新鲜性的通道标注重放暴露面。
5. **输出整改优先级**: 按爆炸半径从大到小排整改序（零留存化、临时派生、缩短寿命、HSM 托管）。
   - 完成标准: 整改表每项含"缩小多少半径"的预估。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 算法/套件强度评估——爆炸半径与强度正交：强算法+静态架构照样全解。
- 证书体系运营问题（CRL 更新率、OCSP 可用性）——那是撤销传播议题。
- 单条消息的泄露处置——按消息级定损走事件响应流程即可。

### 作者在书中警告的失败模式

- "旧钥加密新钥"的串联泄露链：上层密钥一破，下层全体连坐（第14章密钥层次）。
- 长期密钥一身多职（又认证又保密）——静态 RSA 的教训。
- 笼统的"安全"结论掩盖属性缺口——长期密钥无新鲜性照样被重放。

### 作者的盲点 / 时代局限

- 前向安全在书中以 TLS 语境展开；对消息层前向安全（Signal 双棘轮）、群组密钥（树形 LSG）、以及"后量子 + 前向安全"的组合（PQ 会话密钥协商成书时刚起步）未覆盖。
- 零留存理想未讨论运维现实（会话恢复、审计取证需要短期留存）——工程折衷（限定留存窗口）书中无指导。
- HSM/TEE 托管的边界（物理侧信道、固件供应链）仅一笔带过。

### 容易混淆的邻近方法论

- 与"密钥轮换策略"：轮换缩短未来暴露窗口，但不缩小**历史**半径——只有临时派生（PFS）解决历史半径，两者常被混为一谈。
- 与零知识/最小披露：那是身份与属性证明的粒度问题；本 skill 是机密性材料的失陷结构问题。
