# 无钥变形测试清单

## R — 原文 (Reading)

> "以CRC做完整性检验的潜在弱点是一个线性函数。这意味着如果消息中的单个改变，你可以预测CRC的哪个位会发生改变。……因此，有许多明文消息的位翻转组合可以使CRC不改变，所以消息完整性就被攻破了。"
>
> — 方法论出处，第18章 习题18.4（source.txt 行24052–24057）

---

## I — 方法论骨架 (Interpretation)

判断一个"加密+校验"构造能不能防篡改，不需要密码学功底，只需要一组**不需要密钥的黑盒变形**——攻击者本来就没有密钥，测试也不该有。五类变形构成固定测试集：

1. **重排**：交换/重排密文块——异或 Hash（交换律）、无序号保护的帧格式会原样通过。
2. **截断**：砍掉尾部块——无长度绑定的构造照常通过（XOR 折叠截断后补拼）。
3. **追加/拼接**：把旧 (消息,校验值) 的片段拼出新消息——CBC-MAC 长度扩展（X‖(X⊕T) 标记不变）、XOR 折叠拼接是标准反例。
4. **定向位翻转**：CBC 的 P1=IV⊕D(K,C1)，翻 IV 的位=定向改首块明文；CRC 线性 ⇒ 翻明文位可预测 CRC 变化，流加密下位对位操纵后校验照过（WEP ICV）。
5. **解方程挑输入**：能从校验函数反解出合法输入——RSAH 拼装 Hash（RSA(RSA(B1)⊕B2)）可解出 C2 造任意目标值，连抗弱碰撞都不满足。

背后的判定规则：**完整性必须由"带密钥且攻击者造不出"的结构承担**。无钥校验码（CRC、外部 FCS——先加密再附校验）只防差错不防恶意；加密模式的扩散特性不是完整性机制（PCBC 交换块攻击）；组合次序（先 Hash 后加密的 H→E 是 WEP 根源之一）决定能否选择性篡改。五类全过≠安全，但任一类通过即证伪。

## A1 — 书中的应用 (Past Application)

### 案例 1: WEP 的 H→E 与 CRC 线性双重失守
- **问题**: WEP 用 RC4 加密+CRC 校验（ICV）为何被选择性篡改。
- **方法论的使用**: 跑变形 4 与次序检查：CRC 线性 ⇒ 定向翻转+预测 ICV；认证值放在加密之内的 H→E 组合本身有根本缺陷。
- **结论**: 无钥线性校验+可疑次序 ⇒ 不知密钥也能定向篡改；[BLAC05][BELL00] 确认后 WEP 整体被取代。
- **结果**: 802.11i 以 TKIP/CCMP（密码学 MIC/CCM）收口——加密与认证的次序成为显式安全决策。

### 案例 2: CBC-MAC 的长度扩展伪造与 CMAC 修复
- **问题**: 标准 CBC 链接做 MAC 为何不能用于变长消息。
- **方法论的使用**: 跑变形 3：已知单分组 X 的标记 T，则 X‖(X⊕T) 的标记仍是 T——无需密钥外推；"末轮异或密钥"的加固变异三次提问即破。
- **结论**: MAC 与长度/末块内容未绑定即存在拼接路径。
- **结果**: CMAC 用子密钥 K1/K2 区分整块/非整块末段，切断外推——修复模式是"绑定被变形的维度"。

### 案例 3: Kerberos v4 的 PCBC 交换块攻击
- **问题**: 用加密模式的扩散"顺带"做完整性检查行不行。
- **方法论的使用**: 跑变形 1：交换两个密文块，后续明文变化相互抵消，只污染相邻块——调包不被察觉。
- **结论**: 加密的扩散特性≠完整性；"顺手捎带"的安全性质最容易被结构性攻击绕过。
- **结果**: v5 改为独立校验码+标准 CBC——保密与完整性分构件承担。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 自定义 OTA 固件包/私有协议帧格式（"AES-CBC 加密+CRC32 校验"类）发布前自检。
2. 设计或评审认证加密方案时验证覆盖范围（长度、序号、版本、IV 是否都被 MAC 罩住）。
3. 渗透/红队中快速测试目标协议的篡改面（截断、重放、位翻转）。
4. 复核"我们加了校验和"类声明的实际抗恶意能力。

### 语言信号 (用户的话里出现这些就应激活)

- "加密再加个 CRC/校验和够不够"
- "tamper / 篡改测试怎么设计"
- "bit-flipping / 位翻转攻击"
- "length extension / 长度扩展"
- "为什么必须用 MAC / AEAD"

### 与相邻 skill 的区分

- 与 `stallings-crypto-operation-ordering` 的区别: 那个管加密/认证/签名的**次序与覆盖域**设计纪律；本 skill 是对成品构造的**黑盒证伪测试集**——一个设计时用、一个测试时用，判据同源。
- 与 `stallings-block-cipher-mode-five-axis` 的区别: 五轴在选型阶段把"认证轴"配好；本 skill 验证配的结果是否真的挡住五类变形。
- 与模糊测试（fuzzing）: fuzz 找崩溃与意外行为；本 skill 是定向的密码学语义测试（每类变形对应一个已知攻击原语），目标明确、用例少而致命。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **写构造规格**: 画出"明文结构（字段/长度/序号）→ 加密 → 校验值计算与放置位置 → 解析验证流程"。
   - 完成标准: 校验值的计算范围（哪些字节被覆盖）与验证顺序成文。
2. **逐类构造变形用例**: 对合法样本生成五类变形各至少 1 例（重排、截断、拼接、位翻转含 IV 位、若校验函数可逆则解方程挑输入）。
   - 完成标准: 每类变形有具体字节级操作脚本或步骤。
3. **执行并记录**: 每例提交验证流程，记录"接受/拒绝"。
   - 完成标准: 五类结果表；任一"接受"即标红。
   - 判停条件: 若位翻转类被接受（可定向篡改），直接判完整性缺失，停止其余测试进入修复——其余结果已无意义。
4. **修复设计**: 换带密钥认证（HMAC/CMAC/GCM），覆盖长度‖序号‖版本‖IV‖密文；错误响应不可区分；格式层加长度与序号绑定。
   - 完成标准: 修复方案逐条对应失败的变形类。
5. **回归**: 对修复后构造重跑五类用例。
   - 完成标准: 全部拒绝且错误响应一致；测试集入 CI 常驻。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 选型阶段（还没构造可测）——先走五轴/约束反推。
- 侧信道与实现缺陷测试（时序、填充预言）——变形测试只针对篡改面。
- 传输误码防护验证——CRC 防差错是正当用途，本 skill 反对的是把防差错当防恶意。

### 作者在书中警告的失败模式

- "有校验码=有认证"（外部 FCS：攻击者可自造正确码）。
- 扩散特性当完整性（PCBC）。
- 强原语拼装当强构造（RSAH 连抗弱碰撞都不满足）。
- 组合次序任意选（H→E 的 WEP 教训：设计恰当时各组合都能强，错在细节）。

### 作者的盲点 / 时代局限

- 五类变形整理自书中散落各章的反例（第7/11/12/15/18章），作者未将其组织为统一测试协议——本 skill 的清单化即阶段 1 的提炼产物，使用时可按对象继续加类（如跨协议重放、压缩比侧信道）。
- 认证加密标准（GCM/CCM/Poly1305）在书中已引入，但"自己拼组合"与"用标准 AEAD"的取舍指引较简略。
- 重放类变形（时序维度）在书中由防重放机制另行覆盖，本清单不含——勿以此替代重放测试。

### 容易混淆的邻近方法论

- 与否定测试/异常注入: 通用否定测试验证"改了必须失败"；本 skill 给出**密码学特定的五类改法**，每类背后有已知攻击数学。
- 与 MAC 强度评估: 那是原语层（分析代价）；本 skill 是构造层（拼装是否留下无钥路径）——HMAC 再强，套错次序照样被选择性篡改。
