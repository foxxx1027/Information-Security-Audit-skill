# 线性可解性检验

## R — 原文 (Reading)

> "尽管Hill密码足以抗唯密文攻击，但是它较易被已知明文攻击破解。……X=(p）和Y=（c）。那么我们可以得出矩阵等式Y=XK，若X可逆，则可得K=XY。若X不可逆，那么可以另找X和对应的Y，直至得到一个可逆的X。"
>
> — 方法论出处，第3章 3.2.4 Hill密码（source.txt 行4367区；OCR 噪声保留，K=XY 即 K=X⁻¹Y）

---

## I — 方法论骨架 (Interpretation)

对一个加密变换，先别问密钥多少位，先问它是不是（近似的）线性映射。因为线性结构把密码分析变成初等代数：

- 攻击者拿到若干**已知明文-密文对**（现实中几乎总能拿到：固定文件头、协议魔数、已知格式），联立方程 Y=XK，解出密钥——或根本不需要密钥。
- 更强形态：**选择密文**下，128 个选择密文构成状态空间的一组基，任何密文都是基的线性组合，解密结果直接线性组合得出——密钥全程无用。线性=密钥公开。
- 近似线性同样危险：存在大规模线性近似时，攻击退化为"用近似替代精确"，样本量上升但仍可行（线性密码分析的入口）。

这个检验是**一票否决闸**：方案若由移位、异或、固定查表（线性表）组合而成，宣称 128 位密钥毫无意义，直接换 AES-CTR 或引入非线性 S 盒。第二个教训是分级意识：Hill 完全隐藏单/双字母频率、"足以抗唯密文攻击"，却一击死于已知明文——抗住低档攻击不构成安全声明。

## A1 — 书中的应用 (Past Application)

### 案例 1: Hill 密码抗唯密文、败于已知明文
- **问题**: Hill 的 m×m 矩阵把频率特征抹得干干净净，唯密文攻击无从下手。
- **方法论的使用**: 检验代数结构：C=PK mod 26 是线性的，m 组明密文对构造 Y=XK，X 可逆即解出 K，不可逆换一组再试（两对即可定 2×2 密钥）。
- **结论**: 混淆（频率隐蔽）做得好≠抗已知明文；线性映射下密钥就是方程组的解。
- **结果**: 书中给出 "hillcipher"→HCRZSSXNSP 实例并归档为线性密码反例族。

### 案例 2: 习题 4.5——128 个选择密文解一切
- **问题**: 线性分组密码 EL(k,[m1m2])=EL(k,m1)⊕EL(k,m2) 能否保密。
- **方法论的使用**: 128 个选择密文的解密结果张成 128 维基，任意密文写成基的线性组合，明文即对应组合。
- **结论**: 线性结构下选择密文攻击不需要密钥即可解密任意密文。
- **结果**: 与 Hill 已知明文解方程同构，从字符域搬到二进制分组——线性禁忌跨域成立。

### 案例 3: SHA-3 的 χ 是唯一非线性步（结构性反证）
- **问题**: 海绵结构里哪一步承担"不可解"。
- **方法论的使用**: 审视 Keccak 轮函数：线性步（θ、ρ、π、ι）都可直接反解或联立，唯有 χ（非线性 S 盒层）阻断方程求解。
- **结论**: 若无 χ，整圈退化为线性——非线性的存在性本身就是设计的安全支点。
- **结果**: 从反面印证"线性度检验"是结构级检查而非实现细节。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 有人提交自研"加密"（固件保护、配置混淆、DRM 变换），由移位+异或+查表组成并宣传密钥长度，需要快速判定。
2. CTF/渗透中遇到未知编码变换，要判断能否用代数手段秒解。
3. 评审自定义混合函数/白盒混淆时决定第一道测试做线性度还是统计量。
4. 供应商宣称"抗频率分析"（唯密文档），需要按攻击能力分级追问。

### 语言信号 (用户的话里出现这些就应激活)

- "自研加密/私有算法，密钥 128 位"
- "就是一些移位和异或/查表"
- "linear / known-plaintext attack / chosen-ciphertext"
- "为什么不能自己写加密"
- "这个混淆能抗分析吗"

### 与相邻 skill 的区分

- 与 `stallings-statistical-residual-order-analysis` 的区别: 统计残留分析需要样本量、是渐近攻击；线性可解性是一击致命的代数攻击（有限几对明密文即破）。评审顺序：先本 skill（一票否决），再统计阶分析。
- 与 `stallings-brute-force-three-conditions` 的区别: 那个评估穷举可行性；本 skill 证明穷举之外的解方程路径存在——线性方案连"密钥空间"这个概念都被架空。
- 与 `stallings-analysis-cost-vs-brute-force` 的区别: 那个是标准算法的定标判据；本 skill 是自研方案的第一道死刑闸。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列变换组成**: 把方案的每一步操作列出（移位、异或、加、查表、位置换……），标注每步的代数性质。
   - 完成标准: 得到操作清单，每步标注线性/非线性/未知。
   - 判停条件: 若全部步骤线性（且查表为固定线性表），直接判"线性=密钥公开"，跳到第 4 步出否决结论。
2. **线性度检测**: 对可疑步骤做验证——固定输入其余位、扫描一位观察输出差分是否呈线性关系；或取已知明密文对联立方程试解。
   - 完成标准: 有"线性/非线性/近似线性（线性偏差）"三种结论之一，附检测数据。
3. **可解性确认**: 若近似线性，估算所需明密文对数量级（线性近似攻击的样本需求）。
   - 完成标准: 给出"几对已知明文/多少样本可恢复"的量级。
4. **出判定与替换**: 线性→否决并给替换方向（AES-CTR/GCM、引入经检验的 S 盒非线性+多轮）；近似线性→降档使用并限定数据量。
   - 完成标准: 判定含"否决/通过/降档"三态之一与理由；替换建议具体到构造。
5. **登记攻击档位**: 记录该方案在唯密文/已知明文/选择密文各档下的表现，防止未来被"抗唯密文"话术重新包装。
   - 完成标准: 三档状态表入评审档案。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 标准密码算法评估——它们的非线性已由公开分析（差分/线性界）覆盖，走"分析代价≥穷举"判据。
- 哈希/MAC 的内部设计审查——思路同源但对象与检验方法不同（需结合结构归约与原语判据）。
- 输出本就公开、不依赖保密性的编码（base64 等）——无密钥则无"密钥公开"问题，但别把它当加密（书中明确定位为编码非保密）。

### 作者在书中警告的失败模式

- 以唯密文档的强度外推整体安全（Hill："足以抗唯密文攻击"的完整下半句是"较易被已知明文攻击破解"）。
- 混淆好=安全：频率隐蔽与代数可解是两个独立轴，前者满分不救后者。
- "密钥参与了每步运算"的错觉：线性结构下密钥参与不等于密钥必要（128 选择密文案例里密钥被完全旁路）。

### 作者的盲点 / 时代局限

- 书中线性检验以经典案例呈现，未提供系统化的线性度/代数度测试流程（现实践中可用差分分布表、代数免疫度等工具），执行时需补现代方法。
- 线性密码分析（对非线性密码找线性近似）书中在 DES 章提及 Madden 式结论但未展开为检验步骤——"近似线性"档的判定标准需另行引入。
- 格密码等结构化噪声方案（部分环节近线性）为后量子时代议题，第7版未覆盖。

### 容易混淆的邻近方法论

- 与扩散（diffusion）: 扩散是让每位影响多位——线性扩散照样可解；非线性才是解不可解性的来源，两者不可互替。
- 与侧信道线性泄漏（如时序与秘密的线性关系）: 同名"线性"不同层面——一个在算法结构，一个在实现观测，检验手段不同。
