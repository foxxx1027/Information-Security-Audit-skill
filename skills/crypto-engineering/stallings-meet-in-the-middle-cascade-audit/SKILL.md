# 中间相遇：级联不叠加强度

## R — 原文 (Reading)

> "该算法称为中间相遇攻击，文献[DIFF77]首次对它进行了描述。它基于如下观察：假设C=E(K2, E(KI, P)) 则有［参见图7.1a)] X=E(K1, P)=D(K2, C)"
>
> — 方法论出处，第7章 7.1.1 双重DES（source.txt 行10364区；"KI"为 OCR 噪声，即 K1）

---

## I — 方法论骨架 (Interpretation)

"两层总比一层强"的直觉在密码学里要过一个数学闸门：**级联有没有引入新的中间未知量？**

双重 DES 的中间值 X=E(K1,P)=D(K2,C) 只依赖两把密钥之一，于是攻击者可以两头夹击：用全部 2^56 个 K1 正向算出中间值建表，再用全部 2^56 个 K2 反向解密查表匹配——两组已知明密文对即可唯一确定密钥，总代价约 2^56 时间+2^56 存储，名义 112 位实际掉回单层水平。这个攻击不依赖 DES 的任何特性，对一切"A∘B 复合"结构通用。

因此评审任何级联方案的固定动作：写出中间状态，问"它是否成为必须独立搜索的新未知量"。若是（如三密钥 3DES 把代价推到 2^112），级联有效；若否（如哈希链的可分段中点、拼接构造的独立子码），按中间相遇重算。同时记得强度是三维的——时间、存储、**所需数据量**（明密文对/选择明文）：Merkle-Hellman 对 3DES 的"攻击"只要 2^56 时间却需要 2^56 个选择明文，实际不可得——数据不可得性与计算不可行同样是安全边际。

## A1 — 书中的应用 (Past Application)

### 案例 1: 双重 DES 被 2^56+2^56 击穿
- **问题**: 想用两个 56 位密钥把 DES 强度提升到 112 位。
- **方法论的使用**: 检查中间状态：X=E(K1,P)=D(K2,C) 未新增未知量；对第一对 (P,C) 双向算 2^56 建表匹配，平均剩 2^48 候选，第二对筛到 2^-16。
- **结论**: 两组已知明密文对即破，代价 2^56 时间+2^56 存储——与单 DES 同量级。
- **结果**: "加密两次=强度翻倍"被否证；业界转用三密钥结构。

### 案例 2: 3DES 把中间相遇推到 2^112，但数据量维度补刀
- **问题**: 怎么构造才能真正叠加强度。
- **方法论的使用**: 三重加密使中间状态有两个，两头夹击需 2^112；书中同时记录 Coppersmith 穷举分析 2^112 量级、差分分析代价增长超 10^52。
- **结论**: 有效级联的标志是中间相遇代价真正上升；Merkle-Hellman 的 2^56 时间攻击需要 2^56 选择明文——数据量维度单独封顶。
- **结果**: 3DES 作为过渡标准长期存活，评估惯例变为"时间×存储×数据"三维。

### 案例 3: Rabin 无密钥 CBC-Hash 被同一攻击结构击穿
- **问题**: Hash 域的链接构造 H_i=E(M_i,H_{i-1}) 强度如何。
- **方法论的使用**: 同一中点匹配思路：保留原 Hash 值，2^(m/2) 个正向、2^(m/2) 个反向计算找拼接点，构造同 Hash 新消息复用签名；后续 Davies-Price/Meyer 修补同样被 [MIYA90] 攻破。
- **结论**: 中间相遇是对称加密与 Hash 两域通用的级联杀手；对被结构性攻破的族做小修补无效。
- **结果**: 无密钥 CBC-Hash 整族放弃，转向带密钥压缩函数迭代（HMAC/CMAC）路线。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 有人提出"AES 加密两遍""双算法各加密一次"或"两条哈希链串联当双重保护"的方案，需要核强度。
2. 评审 KDF/封装里的复合构造（H1∘H2、双哈希拼接），判断实际安全位数。
3. 供应商宣传"双层加密、强度翻倍"话术审查。
4. 设计多重加密时决定用双密钥还是三密钥结构。

### 语言信号 (用户的话里出现这些就应激活)

- "加密两次 / 双重加密是不是更安全"
- "meet-in-the-middle / 中间相遇"
- "两条哈希串联 / hash 链拼接"
- "cascade / 级联强度怎么算"——"级联"仅指密码构造的复合（多次加密、哈希拼接），不指网络串接
- "强度翻倍 / 位数相加"

排除信号 (用户的话里出现这些就不应激活)：

- "防火墙串接 / 双机热备 / 双链路 / 网络层面冗余"——部署层"双保险"串接的是设备与链路，没有密码级联对象（无中间状态可检查），此类拓扑冗余问题本书不设对应技能，应答不激活。

### 与相邻 skill 的区分

- 与 `stallings-birthday-bound-variant-substitution` 的区别: 生日界算的是"随机碰撞"的搜索成本（2^(m/2)）；中间相遇算的是"两头夹击的确定性匹配"。两者常在同一构造上先后使用（CBC-Hash 同时死于两者），但机理与对策不同。
- 与 `stallings-design-principles-review-protocol` 的区别: 那个检验多层**控制**是否同因失效（伪纵深），对象是安全控制/架构设计；本 skill 检验同一数据上的**密码复合**是否叠加强度。问"两台防火墙串接算不算双保险、网络层面冗余怎么评估"是拓扑冗余/高可用问题——既无密码级联对象，也不是 13 条准则的评审场景，两者都不应激活。
- 与 `stallings-analysis-cost-vs-brute-force` 的区别: 那个问"有没有比穷举更快的分析"；本 skill 专门处理"复合结构的成本核算错误"——即使组件理想，级联也可能不叠加。
- 与 `stallings-computational-security-three-questions` 的区别: 那个定需求档位；本 skill 校验给定方案的实际有效位数。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **画出复合结构**: 写出每层函数与层间数据流，标出所有中间状态。
   - 完成标准: 结构图上每个中间值有明确记号与依赖关系（依赖哪些密钥/输入）。
2. **检查中间未知量**: 对每个中间状态问"攻击者能否只用部分密钥/输入从一端到达它"。
   - 完成标准: 每个中间状态标注"新增未知量 / 可单向到达"。
   - 判停条件: 若存在可单向到达的中间状态且两端各可独立枚举，直接进入第 3 步按中间相遇重算；若所有中间状态都构成新未知量，跳到第 4 步。
3. **重算成本**: 估算两头夹击的时间（两端枚举量之和/积）、存储（建表一端的规模）、所需数据量（几组明密文对收敛）。
   - 完成标准: 输出三维成本（时间/存储/数据），并与名义位数对比给出"实际有效位数"。
4. **核对数据可得性**: 问攻击者现实中能否拿到所需明密文对/选择明文。
   - 完成标准: 每条攻击路径标注数据可得性（现实可得/理论需要但不可得），后者注明"以数据量封顶"。
5. **出结论与改造**: 级联无效则给出替代（换构造：宽管道/海绵/三密钥；或声明安全只归单层）；有效则登记三维成本。
   - 完成标准: 结论含"有效位数 + 最便宜攻击路径 + 改造方向"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单算法（无级联）的强度评估——没有中间状态可检查。
- 协议逻辑/时序类缺陷（重放、降级）——本 skill 只管结构成本核算。
- 密钥长度是否够用的需求侧推导——用计算安全三问。

### 作者在书中警告的失败模式

- 按位数线性估算级联强度（112 位名义值的教训）。
- 对被结构性攻破的构造族做小修补继续用（Davies-Price/Meyer 变体仍被攻破——整族放弃而非打补丁）。
- 只看时间不看数据量（Merkle-Hellman 的 2^56 选择明文使其不构成现实威胁）。

### 作者的盲点 / 时代局限

- 存储成本在书中按"建 2^56 表"计，未讨论现代内存/磁盘经济学与排序表（Hellman 表、并行 SSD）对实际可行性的影响。
- 第7版成书于 2017 前后：多目标攻击、量子下的级联语义（Grover 对级联的影响）未覆盖。
- "双哈希拼接 PRF"的冗余设计（TLS 双散列）是**有意**的容错而非强度叠加——本 skill 判"不叠加"时勿误杀这类以可用性为目标的设计，需问清目标。

### 容易混淆的邻近方法论

- 与"深度防御"：纵深是多层**独立**控制叠加（一层失效其余仍挡）；级联加密是同一秘密的多层复合——前者不承诺强度相加，后者常被误以为相加。
- 与生日攻击: 生日法是无结构的计数论证；中间相遇是结构化的双向匹配——对策分别落在"加长"与"增加中间未知量"上。
