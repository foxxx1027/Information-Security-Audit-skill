# 元数据与长度侧信道

## R — 原文 (Reading)

> "BEAST攻击的作者同样是2012CRIME（压缩比信息泄露）攻击的作者，当数据压缩使用TLS标准时,这种攻击能够导致网站cookies的内容被恢复IGOOD12]。"
>
> — 方法论出处，第17章 17.2.8 SSL/TLS 攻击史（引文含 OCR 噪声，按原样保留）

---

## I — 方法论骨架 (Interpretation)

"内容端到端加密了"不等于"只泄露密文"。机密性评估固定两问：**内容加密了吗？元数据抹平了吗？**第二问常被跳过。

而它有一条可操作的判定律：**加密之前的任何与明文相关的可观测变换，都是侧信道**——压缩比（CRIME 逐字节恢复 cookie）、填充模式、密文长度。

长度本身携带信息：消息长度指纹可识别发的是哪条指令/哪段语音，发送时刻与对象构成社交图谱。

对策按层级：

1. 可变填充切断长度-内容映射；
2. 固定长度分帧+随机延迟做流量整形；
3. 机密字段不与攻击者可注入内容进同一压缩上下文（或直接关压缩）。

再往外一层是**存在性**：谁在和谁通信是独立信道（流量分析是书内单列的被动攻击类型）；隐写与加密正交——隐写藏"存在"，被识破即整个方案（含历史数据）全失效且容量开销大，只用于需要隐藏通信本身的场景；隧道新头只防基于终端的流量分析。

## A1 — 书中的应用 (Past Application)

### 案例 1: CRIME 压缩比泄露（第17章）
- **问题**: TLS 已加密，压缩又发生在加密之前，看似无泄露——cookie 怎么被恢复了？
- **方法论的使用**: 判定律应用——压缩比是加密前与明文相关的可观测变换；攻击者注入可构造请求并观察密文长度变化，逐字节推断被压缩的机密字段。
- **结论**: 认证 cookie 被恢复即可劫持已验证 Web 会话。
- **结果**: 对策为禁用 TLS 压缩（TLSv1.3 整体移除压缩）、机密与可控内容不进同一压缩上下文、可变填充对抗长度分析。

### 案例 2: 流量分析作为独立攻击（第1章）
- **问题**: 加密之后攻击者还能得到什么？
- **方法论的使用**: 把流量分析（消息频率、长度、通信方身份与位置）单列为被动攻击类型——它不破解内容，抽取的是模式。
- **结论**: 内容保密≠模式保密；对策在流量整形与填充，而非更强的加密算法。
- **结果**: 全书评估机密性时"内容/模式"两问并立的框架来源。

### 案例 3: 隐写与加密正交（第3章）+ 隧道边界（第20章）
- **问题**: 想隐藏"正在通信"这件事，用隐写行吗？隧道模式防流量分析吗？
- **方法论的使用**: 正交性分析——加密藏内容、隐写藏存在（柯达 CD 单张可藏约 130kB，但"一旦被破解，整个方案就毫无价值"且载体开销大）；IPsec 隧道新头只防基于终端的流量分析，防不了全网观测者。
- **结论**: 隐写只承担存在性遮蔽，机密性仍靠加密；隧道对流量分析的防护有边界。
- **结果**: 需求先分流（藏内容 vs 藏存在），再选机制。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 端到端加密通讯"还能推出什么"的评估（消息长度指纹、社交图谱）。
2. 支付/查询类 API 的长度指纹与响应尺寸评审。
3. "要不要开压缩"的协议设计决策（同一压缩上下文的风险）。
4. 隐蔽通信需求评估——藏内容还是藏通信存在。

## E — 可执行步骤 (Execution)

1. **列可观测量**：写出信道上全部可观测项——长度、时序、方向、频率、压缩比、错误码、通信存在性。
   - 完成标准: 清单成文，无遗漏维度。
2. **评关联性**：对每个可观测量问"与明文/身份有无统计关联"，标出关联项。
   - 完成标准: 每项有关联/无关联判定及依据。
3. **消除或随机化**：对关联项逐个处理——固定长度分帧、可变填充、批量子查询、关压缩或域分隔。
   - 完成标准: 每个关联项有对策或书面接受残余风险。
   - 判停条件: 观测者无注入能力且内容与长度无关（已定长帧）时，登记后收工。
4. **存在性分流**：明确需求是藏内容还是藏通信本身；藏存在才考虑隐写/流量整形，并评估被识破的代价与容量开销。
   - 完成标准: 需求判定+方案选型理由成文。
5. **登记残留面**：把残留可观测面写进威胁模型，供后续审计引用。
   - 完成标准: 残留登记表成文。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 把填充/整形当免费——可变 padding 消耗带宽、整形加延迟，按业务定价后再决定强度。
- 用隐写承担保密性——与加密正交且被识破全失效，书内明确其为缺点。

### 作者在书中警告的失败模式

- 隐写"一旦被破解，整个方案就毫无价值"，且隐藏少量信息需要巨大载体开销（ce023）。
- 隧道新头只防基于终端的流量分析——勿宣称"隧道防流量分析"。

### 作者的盲点 / 时代局限

- 书中侧信道样本为 CRIME/BREACH 时代（成书 2017 前），对 HTTP/2 与浏览器压缩面的更广谱泄露、ECH/ESNI 类加密元数据（SNI 本身是元数据）书内无内容——外推需补。

### 容易混淆的邻近方法论

- v56 实现层侧信道（计时/缓存）。
- v17 确定性泄漏（相等关系特例）、v09 明文可识别性（v01–v28 段）。
