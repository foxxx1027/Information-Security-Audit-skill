# 被动/主动攻击的对策重心不对称

## R — 原文 (Reading)

> "X.800和RFC4949都将攻击划分为被动攻击和主动攻击。被动攻击试图获取或利用系统的信息但并不影响系统资源，而主动攻击则试图改变系统资源或影响系统运行。……但对于这样的被动攻击，通常可以使用加密方法来阻止攻击者的这种攻击。因此对于被动攻击，重点是预防而非检测。"
>
> — 方法论出处，第1章 1.3 安全攻击（source.txt 行1351区、1354）

---

## I — 方法论骨架 (Interpretation)

分类判据只有一条：攻击者有没有改动系统资源。这条判据直接决定钱该往哪花：

- **被动攻击**（窃听、流量分析）：不动资源、收发双方无感、几乎无法检测。所以对策重心是**预防**——加密、流量填充；并且要诚实接受一个推论：预防失败的那一刻失密已经发生，事后能做的只是缩短暴露窗口、缩小泄露粒度。给被动攻击采购检测设备是浪费预算。
- **主动攻击**（伪装、重放、篡改、拒绝服务）：可被发现（有改动痕迹），但弱点面太广、无法绝对预防。所以对策重心是**检测+恢复**——认证、完整性校验、日志、冗余；而且检测本身有威慑价值。

工程用法：给威胁清单的每一行标注"被动/主动"，预算按重心分派而不是均匀铺。同一事件可能混合两类（先窃听后重放），要拆开处置。资源极度受限时（传感器只够承担一种防护），按"哪一端有资源做检测"来转移重心，而不是硬塞。

## A1 — 书中的应用 (Past Application)

### 案例 1: 第12章八类攻击的两分支分派
- **问题**: 消息认证一章要说明"什么时候用加密、什么时候用认证符"。
- **方法论的使用**: 12.1 把八类攻击按同一判据分派：第(1)(2)类（消息透露、传输分析）归"加密预防"；第(3)–(6)类（伪装、内容/顺序/计时修改）归"认证符检测"。
- **结论**: 加密与认证不是替代关系，各管攻击谱的一半。
- **结果**: 得出"仅有机密性保护不够，需要独立的认证机制"的章节结论，并引出 MAC 一章的存在理由。

### 案例 2: 第17章 Web 威胁表按两分支列对策
- **问题**: Web 威胁种类多，对策容易堆砌。
- **方法论的使用**: 表17.1 把威胁先分为被动（浏览器-服务器通信窃听）与主动（伪装、消息篡改、站点篡改），再分别配对策（加密 vs 加密+证书、完整性校验）。
- **结论**: 威胁表的对策列天然按被动/主动分成两种重心。
- **结果**: Web 安全方案的结构变成"传输机密性 + 身份认证/完整性"两条线，与 17.2 TLS 的两大能力对应。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 安全预算/人力有限，要决定"这笔钱投加密改造还是投检测平台（IDS/SIEM）"。
2. 资源受限设备（LoRa 传感网、电池设备）只承担得起一种防护，要选投哪边、投在哪一端。
3. 评审检测方案时有人宣称"我们的流量分析能发现窃听"，需要判断此类宣称的边界。
4. 威胁清单已列好，要给每行威胁标注对策重心，避免均匀铺预算。

### 语言信号 (用户的话里出现这些就应激活)

- "预防重要还是检测重要 / detection 和 prevention 预算怎么分"
- "窃听/被动攻击能不能被发现"
- "设备端电量只够做一种防护"
- "上了加密还要不要 IDS"
- "passive attack / active attack 怎么分"

### 与相邻 skill 的区分

- 与 `stallings-attack-service-mechanism-alignment` 的区别: 那个做全谱覆盖核对（有没有漏）；本 skill 做预算重心分派（钱往哪边倾斜），是覆盖矩阵填完之后的资源分配决策。
- 与 `stallings-attack-tree-and-or-modeling` 的区别: 攻击树排路径优先级；本 skill 按攻击性质分对策类型，不做路径展开。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **逐行分类**: 拿到威胁/攻击清单，逐行问"这一攻击是否改变系统资源或影响运行"，标被动/主动。
   - 完成标准: 每行有分类标注；混合事件（如先窃听后重放）拆成两行。
2. **被动行配预防**: 检查每行是否有事前预防机制（加密、填充、访问收敛），并写明"失密后止损动作"（轮换、缩窗）。
   - 完成标准: 没有任何被动行被指派"上线检测"作为唯一对策。
3. **主动行配检测+恢复**: 每行指派检测手段与恢复手段，并检查检测的威慑面。
   - 完成标准: 每个主动行同时有"怎么发现"和"发现后怎么办"。
4. **资源受限重分派**: 若端侧资源不足，把检测/恢复移到资源充足的一端（网关/云），端侧只保留预防。
   - 完成标准: 分派结果附"哪端承担哪类重心"的说明。
   - 判停条件: 若被动行的预防机制也无力承担（连加密都跑不动），则该资产实质裸奔，应直接升级为架构问题而非继续分配预算。
5. **输出预算重心结论**: 给出预防/检测/恢复三类投入比例建议与理由。
   - 完成标准: 结论能追溯到具体威胁行的分类。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已知具体漏洞（CVE）的修复优先级决策——那是漏洞管理问题，不是分类问题。
- 内部人员滥用合法通道读数据：形式上是"被动读取"，但发生在授权边界内，预防手段是访问控制而非加密，需按业务场景重推。
- 合规控制清单编制——合规要求逐项满足，不按可检测性分配。

### 作者在书中警告的失败模式

- 给被动攻击投检测——检测几乎不可能，等于把钱扔进不可观测的事件。
- 只押边界预防而不建检测恢复——只覆盖攻击谱的一半（主动攻击无法绝对预防）。
- 误以为检测无价值——书中明确检测对主动攻击有威慑作用，不是纯成本。

### 作者的盲点 / 时代局限

- 二分法源自网络传输视角（第1章）；云时代"经合法 API 读取数据"跨在两类之间（不改资源但持续外泄），书中无此词条，需按数据出口模型扩展。
- 第7版成书于 2017 前后：加密预防的时效性受"先收取后解密"（harvest-now-decrypt-later）与后量子迁移压力，书中未覆盖——被动攻击的"预防"现在要带保护年限参数。
- 流量分析作为被动攻击书中仅点名，未给对策深度（填充的成本极高）。

### 容易混淆的邻近方法论

- 与"纵深防御"不同: 深度防御讲多层叠加；本 skill 讲两类攻击的对策**类型**不同，层内投什么由分类决定。
- 与 CIA 优先级定级不同: 定级按资产后果；本 skill 按攻击可观测性。
