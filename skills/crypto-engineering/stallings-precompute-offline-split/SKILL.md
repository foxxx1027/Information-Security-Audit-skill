# 预计算与在线/离线分离

## R — 原文 (Reading)

> "Schnorr方案将生成签名所需的消息计算量最小化。生成签名的主要工作不依赖于消息，可以在处理器空闲时执行。"
>
> — 方法论出处，第13章 13.3 Schnorr 数字签名方案

---

## I — 方法论骨架 (Interpretation)

延迟优化的密码学通用手法是**在线/离线分离**，审查只用一个问句：**输出中哪些量与输入无关？**——输入无关量是天然的预计算候选。

- Schnorr 签名的主要计算（α^r mod p）不依赖消息 → 空闲时预计算，在线只剩哈希+两次轻量乘法。
- DSA 的 r 与 k⁻¹ 完全与被签消息解耦 → 可按需批量预备许多个备用。
- 同族手法遍布全书：CTR 模式的密钥流提前生成降低在线时延；HMAC 的 f(IV,K⊕ipad) 预计算（书中明示同族）。

分离的约束是**安全内存上限**：预存池里躺着一次性随机数与中间值，池失陷=私钥失陷——预计算量按吞吐需求定，保护等级按私钥计价。审查产出一张依赖分析表：每个中间量标注"是否依赖输入消息"，重排为"取预存值+输入相关轻量运算"的在线路径。

## A1 — 书中的应用 (Past Application)

### 案例 1: Schnorr 的空闲时预计算（第13章）
- **问题**: 签名里最贵的模幂必须每次在线做吗？
- **方法论的使用**: 依赖分析——签名主工作量 α^r 与消息无关，移到处理器空闲时执行；在线只算 e=H(M‖x)、y=(r+s·e)。
- **结论**: "将生成签名所需的消息计算量最小化"成为方案的设计目标与卖点。
- **结果**: Schnorr 成为低延迟签名场景的基准方案。

### 案例 2: DSA 的 r 批量预备（第13章）
- **问题**: DSA 每次签名都要算 g^k mod p 与 k⁻¹，能否摊销？
- **方法论的使用**: r 是 k 与全局公钥的函数、完全不依赖被签消息 → "用户甚至可以根据需要预先计算许多个用于签名的 r"；安全性仍归于离散对数。
- **结论**: 最昂贵部分全部可预计算，且可批量。
- **结果**: 与 Schnorr 同族，成为标准算法内建的性能结构。

### 案例 3: HMAC 与 CTR 的预计算（第12、7章）
- **问题**: 高吞吐场景每消息的固定开销能否消除？
- **方法论的使用**: HMAC 预计算 f(IV,K⊕ipad)/f(IV,K⊕opad)（每密钥一次）；CTR 模式密钥流提前生成降低在线时延——书中明示与签名预计算同族。
- **结论**: 在线/离线分离是跨原语的通用手法，不限签名。
- **结果**: 预计算点成为性能评审的标准检查项。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 签名/解密延迟预算不达标（车载 ECU 5ms 预算 vs 20ms 模幂、支付 HSM 吞吐）。
2. 高吞吐 MAC/加密的每消息固定开销优化。
3. 审查请求关键路径上哪些计算可移出。
4. 预计算池的安全存储与补充策略设计。

### 语言信号 (用户的话里出现这些就应激活)

- "延迟预算 / latency budget"
- "预计算 / precompute"
- "签名太慢 / signing too slow"
- "在线路径/关键路径 / online path, critical path"
- "批量生成 / batch generation"

### 与相邻 skill 的区分

- 与 `stallings-cheap-check-first` 的区别: 那个把廉价校验放前（安全排序，挡 DoS），本 skill 把昂贵计算移出（性能重构）——都重排计算次序，目标相反，可同管线并用。
- 与 `stallings-key-counting-hierarchy` 的区别: 那个分密钥的层次与频次，本 skill 分计算的时间阶段——对象不同。
- 与 `stallings-nonce-iv-one-time-constraints` 的区别: 那个规定 k/nonce 的一次性红线，本 skill 的预存池正是这些一次性参数的批量形态——池的补充必须满足不复用约束。

## E — 可执行步骤 (Execution)

1. **列中间量并做依赖分析**：写出目标运算的全部中间量，逐个标注"是否依赖输入消息"。
   - 完成标准: 依赖分析表成文，无未标注项。
   - 判停条件: 在线计算已满足延迟预算时停止，避免引入预存管理复杂度。
2. **拆离线批量**：对输入无关量设计离线批量生成（启动时/空闲时），存入安全内存。
   - 完成标准: 离线生成与存储方案成文。
3. **重排在线路径**：在线路径重构为"取预存值+输入相关轻量运算"，度量重构前后时延。
   - 完成标准: 时延对比数据达标。
4. **定池大小与补充策略**：按吞吐峰值定池容量与补充触发条件。
   - 完成标准: 容量与补充策略成文。
5. **池安全计价**：预存池按与私钥同级的保护措施管理；一次性参数满足不复用约束；记录"池失陷=私钥失陷"的风险定价。
   - 完成标准: 保护措施与风险登记成文。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 为省预计算而复用随机数/中间参数——ElGamal 的 k 跨块复用即泄露明文比值（ce030 同族），这是 v18 的硬红线，性能优化不得越界。
- 输入无关性要在完整运算语境下判定——部分中间量与输入弱相关（经哈希/链接混入），误判会导致在线路径缺数据。

### 作者在书中警告的失败模式

- 预存池失陷等价私钥失陷——安全内存不足时池是第一攻击目标。
- 一次性随机数复用的连锁泄露机理（ce030）。

### 作者的盲点 / 时代局限

- 书中样本为离散对数签名族与 HMAC/CTR（成书 2017 前）；配对、同态、门限签名等运算的依赖分析需自行重做；预计算对侧信道的暴露（预存值使用时序）书内未涉及。

### 容易混淆的邻近方法论

- v31 校验排序（安全视角的重排）。
- v18 一次性参数（红线约束）、v40 用途绑定（预存材料的用途单一化）。
