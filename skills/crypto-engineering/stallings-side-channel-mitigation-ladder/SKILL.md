# 侧信道分层评估与缓解阶梯

## R — 原文 (Reading)

> "密码学顾问PaulKocher已证明，攻击者可以通过记录计算机解密消息所用的时间来确定私钥[KOCH9%6,"
>
> — 方法论出处，第9章 9.3 RSA 的安全性/计时攻击（引文含 OCR 噪声，按原样保留）

---

## I — 方法论骨架 (Interpretation)

"算法没被破"与"实现不泄露"是两张证书：**数学层安全**（离散对数、因子分解没被解）与**实现层安全**（运算路径不随秘密变化）必须分开评估、分开出具结论。实现层的泄露源可枚举：数据相关分支、查表、访存模式——Kocher 证明仅记录解密耗时即可逐位恢复 RSA 私钥，机理明确而非理论担忧。

缓解措施不是平级的，按**阶梯**排序：
1. **结构性盲化**（优先）：对输入做随机化再运算，改变攻击前提——RSA 盲化性能损失仅 2–10%（书内工程数据）；
2. **恒定时间实现**：彻底消除数据相关路径，但重写成本高；
3. **随机延时**（最弱）：加噪声——Kocher 指出攻击者可用更多样本统计平均抵消，只能作辅助。

两条升级路径配套：查表（256 字节表消时间差）会引入缓存侧信道 → 位切片 → 硬件指令；CRT 加速必须配输出校验——故障注入产生的错误分量会泄露因子。

## A1 — 书中的应用 (Past Application)

### 案例 1: RSA 计时攻击与三档缓解（第9章）
- **问题**: 算法数学上安全，私钥为何能被恢复？
- **方法论的使用**: 分层评估——数学层（RSA 未破）与实现层（模幂的乘法分支随密钥位变化）分开取证；缓解按三档给工程数据（盲化 2–10%、恒定时间简单但降性能、随机延时可被平均抵消）。
- **结论**: 计时泄露是逐位恢复私钥的充分信道；盲化是性价比首选。
- **结果**: 三档缓解成为实现层评审的决策阶梯。

### 案例 2: AES 乘 02 的查表权衡（第6章）
- **问题**: 列混淆的乘 02 用"移位+条件异或"实现为何有风险？
- **方法论的使用**: 升级路径——条件异或的时间随数据位变化（计时面），改 256 字节查表以空间换时间恒定；书中同时指出查表的代价与效率收益。
- **结论**: 缓解手段会转移泄露面（分支→访存），阶梯与升级路径要一起评审。
- **结果**: 查表成为 AES 软件实现的标准形态，缓存侧信道成为下一层议题。

### 案例 3: DES 计时评估与 SHA-3 的结构性防护（第4、11章）
- **问题**: 怎么在"算法层"讨论侧信道？
- **方法论的使用**: DES 计时攻击评估作为"数学层/实现层分开取证"的原型；SHA-3 则从设计上只用位运算、无查表——结构性防侧信道设计。
- **结论**: 抗侧信道可以成为算法设计目标，不只靠实现层打补丁。
- **结果**: 分层评估+结构优先的完整思路成型。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 硬件钱包/HSM 的签名实现审计。
2. 服务端私钥运算的计时泄露评估（共享主机上的 RSA 解密、TLS 私钥）。
3. 选缓解方案——盲化 vs 恒定时间 vs 随机化的决策。
4. 多租户/共享硬件的缓存侧信道评审。

### 语言信号 (用户的话里出现这些就应激活)

- "计时攻击 / timing attack"
- "恒定时间实现 / constant-time implementation"
- "盲化 / blinding"
- "缓存侧信道 / cache side channel"
- "私钥运算路径 / private key operation path"

### 与相邻 skill 的区分

- 与 `stallings-metadata-length-side-channel` 的区别: 那个管协议可观测面（长度/压缩比/存在性），本 skill 管实现层微观测（时间/缓存/故障）——观测介质不同，两套审计都要跑，勿互相替代。
- 与 `stallings-cheap-check-first` 的区别: 那个重排校验次序省资源，本 skill 消除运算路径的数据相关性——"把耗时操作移走"不等于"时间恒定"。
- 与 `stallings-domain-parameter-validation-gate` 的区别: 那个挡住恶意参数进运算（小子群等），本 skill 处理正常输入下的物理泄露——输入合法性与实现泄露是两道防线。

## E — 可执行步骤 (Execution)

1. **审查运算路径**：对私钥运算逐段列出数据相关分支、查表、访存模式点。
   - 完成标准: 泄露点清单成文，每处标注泄露介质（时间/缓存/故障）。
2. **优先结构性缓解**：能盲化/确定签名类的先做，评估性能代价（书内参照 2–10% 量级）并实测。
   - 完成标准: 结构缓解落地或有不可行说明。
3. **残余处恒定时间**：无法结构消除的段落做恒定时间实现（位切片/硬件指令），验证无数据相关分支残留。
   - 完成标准: 时间方差测试通过（输入变化±方差在阈值内）。
4. **拒绝随机延时作主缓解**：随机化只作辅助并标注统计抵消风险。
   - 完成标准: 主缓解不为随机延时的声明成文。
5. **CRT 输出校验**：使用 CRT 加速处加结果校验，防故障注入泄露因子。
   - 完成标准: 校验逻辑与故障测试通过。
   - 判停条件: 运算在可信边界内且观测者无测量通道（无并发攻击者、独占硬件）时，登记残余风险后收工。
6. **分层出结论**：报告把"算法是否被破"（数学层）与"实现是否泄露"（实现层）分开陈述。
   - 完成标准: 两层结论各自成文，不合并表述。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 把随机延时/加噪声当治理手段——书内明示样本足够时可被统计平均抵消。
- 因"算法没破"跳过实现层审计——Kocher 案例正是数学安全与实现失守并存的实证。

### 作者在书中警告的失败模式

- 查表消时间差但引入缓存侧信道——缓解转移而非消除，升级路径必须走完。
- CRT 加速无校验时，故障注入的错误分量直接泄露因子（书内 CRT 讨论的推论）。

### 作者的盲点 / 时代局限

- 书中侧信道样本为计时/缓存的入门级内容（Kocher 1996、AES 查表；成书 2017 前），功耗/电磁/Rowhammer/Spectre 类瞬态执行攻击书内无内容——外推时注明边界。

### 容易混淆的邻近方法论

- v46 元数据侧信道（协议观测面）。
- v31 成本排序、v23 参数校验（入口防线）。
