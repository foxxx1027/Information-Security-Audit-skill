# 结构归约与参数化构造

## R — 原文 (Reading)

> "Merkle[MERK89]和DamgardDAMG89]发现，如果压缩函数具有抗碰撞能力，那么选代Hash函数也具有抗碰撞能力……由此可见，设计安全Hash函数可简化为设计具有抗碰撞能力的压缩函数问题，并且该压缩函数的输入是定长的。"
>
> — 方法论出处，第11章 11.3.3（source.txt 行15288–15333；OCR 噪声保留）

---

## I — 方法论骨架 (Interpretation)

面对一个"任意输入"的密码构造需求（任意长消息的 Hash、无限流日志的锚、任意长度密钥派生），不要直接设计大而全的方案，分三步：

1. **归约到定长组件**：Merkle-Damgård 示范——把任意长消息切成定长分组迭代一个压缩函数 f，并证明"f 抗碰撞 ⇒ 整条链抗碰撞"。安全论证从此只落在 f 上（定长、可集中分析），迭代与填充只是搬运工。乘积密码（Feistel 多轮）是同一思想在对称侧的同构：结构保强度、组件可弱多轮复合。
2. **长度域是安全部件不是填充杂音**：填充里包含原始消息长度，迫使攻击者只能找"等长同码"消息，直接抬高攻击难度——长度域被封掉的是截断-拼接类结构攻击（长度扩展攻击的土壤）。
3. **参数化暴露权衡**：海绵结构把"分块-填充-迭代-取输出"抽象成三参数（f、位速率 r、填充 pad），一个置换派生 Hash 与 PRNG 一族原语；r 与容量 c 的分工显式化了通用取舍——每步多用状态（大 r）=快，少用状态（大 c）=难被消息直接控制=安全。凡是"共享一块有限状态"的构造都应把这个取舍暴露成参数，而不是焊死在实现里。

评审自研构造时按此骨架问：定长组件是什么？归约/继承关系成立吗？长度与边界处理参与安全了吗？权衡暴露成参数了吗？

## A1 — 书中的应用 (Past Application)

### 案例 1: MD 归约让 Hash 设计变成"设计一个压缩函数"
- **问题**: 任意长度消息的 Hash 怎么设计才可论证。
- **方法论的使用**: 结构选择：CV_i=f(CV_{i−1},Y_i) 迭代+含长度的填充；引用归约定理——f 抗碰撞则整体抗碰撞。
- **结论**: 设计与审计焦点收敛到定长 f；填充/长度域从"格式细节"升格为安全部件。
- **结果**: SHA 族按此结构展开；后续分析（含长度扩展类弱点）都按"压缩函数层 vs 结构层"两层归因。

### 案例 2: 海绵结构——一个置换派生一族原语
- **问题**: Hash 与 PRNG 能否共享已分析的内核。
- **方法论的使用**: 参数化：同一 Keccak-f 配不同 r/c——吸水阶段吸收消息、挤压阶段产出任意长度输出；SHA-3 取 c=1024/r=576。
- **结论**: 三参数抽象使"一个经过公开分析的置换"服务多种原语，减少实现面；c 与安全度挂钩（224/384/512 位摘要对应 c=448/768/1024）。
- **结果**: 降速换安全（大 c 小 r）成为显式旋钮而非隐藏取舍；同模板覆盖 Hash/PRNG/XOF。

### 案例 3: 乘积密码——结构保强度的对称侧同构
- **问题**: 弱组件能否构造强密码。
- **方法论的使用**: Feistel/乘积思想：单轮 F 可以很弱，多轮复合后混淆扩散叠加——"结构保强度、组件可弱多轮复合"；轮数由"已知最优分析≥穷举"定标。
- **结论**: 归约思想跨域成立：把安全论证放到可分析的最小单元，结构负责传递性质。
- **结果**: 从 DES 到 AES 的设计评审都按"组件强度×结构×轮数"三层展开。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计每秒 append 的流式日志/遥测完整性锚（不能整块重算），需要安全的链式结构。
2. 评审自研 Hash/PRNG/KDF 构造（"我们自己做了一个哈希"）的安全性论证方式。
3. 系统需要同时提供 Hash 与随机流，想减少密码组件的实现面。
4. 分析长度扩展/截断拼接类结构攻击该归因到哪一层。

### 语言信号 (用户的话里出现这些就应激活)

- "sponge / 海绵结构 / rate and capacity"
- "Merkle-Damgard / 长度扩展攻击"
- "流式日志哈希锚 / 增量哈希"
- "压缩函数"

### 与相邻 skill 的区分

- 与 `stallings-hash-property-application-mapping` 的区别: 那个管"用 Hash 的哪条性质、选多长"；本 skill 管"Hash 构造本身怎么设计/评审"——一个是消费者视角，一个是构造者视角。
- 与 `stallings-analysis-cost-vs-brute-force` 的区别: 那个给已有原语比价；本 skill 是造新原语时的**论证组织方式**（归约到组件+参数化取舍）——造出来的组件再拿去比价。
- 与 `stallings-keyless-mutation-test` 的区别: 变形测试是黑盒证伪；本 skill 是白盒论证——两者对自研构造一前一后（先论证结构，再黑盒踢一脚）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **拆出定长组件**: 写出方案的"核心函数"（定长输入定长输出）与外围搬运结构（分块/迭代/填充）。
   - 完成标准: 组件与结构分离成图；无"整体黑盒即方案"的写法。
2. **表述继承关系**: 声明"组件性质 P ⇒ 整体性质 P"的归约（如 f 抗碰撞⇒链抗碰撞），并核对长度域/边界处理是否参与该论证。
   - 完成标准: 归约语句成文；长度域、末块处理在论证中被显式引用。
   - 判停条件: 若归约不成立（外围结构引入新攻击面，如无密钥链接的中点匹配），停止参数调优，先换结构——结构级缺陷不能靠组件加强弥补。
3. **暴露权衡参数**: 把吞吐/安全类取舍（状态占用、轮数、输出率）写成显式参数与约束（如 c≥2×安全目标），不焊死。
   - 完成标准: 参数表+约束式；违反约束的配置被实现拒绝。
4. **组件级取证**: 对定长组件做强度论证（公开分析/标准构件/小域测试），列出已知弱点。
   - 完成标准: 组件强度结论+引用；未知强度者标注降档使用条件。
5. **结构级攻击推演**: 对外围结构跑截断/拼接/长度扩展/中点匹配四类推演。
   - 完成标准: 四类推演各有结论（被长度域/初始化/域分隔挡住，或需修结构）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 标准原语选型（直接选 SHA-256/AES 即可）——本 skill 用于设计或评审**非标准构造**。
- 协议时序与密钥管理问题——结构归约不覆盖协议层。
- 对已有标准构造的"重新发明"冲动——先查标准是否已覆盖需求，归约是不得已自造时的论证纪律。

### 作者在书中警告的失败模式

- 审实现只看压缩函数、不看迭代/填充/长度域——后者是常见结构性弱点来源（长度扩展攻击）。
- 参数取舍焊死在实现里（性能优先压低安全容量），评审无从发现。
- 多对一必然存在碰撞——归约保证的是"找碰撞不可行"，不是"无碰撞"；论证措辞要精确。

### 作者的盲点 / 时代局限

- MD 结构的长度扩展弱点在书中点到（长度域的作用）但未展开成攻击与 HMAC 补丁的完整链条；海绵的"可区分攻击安全"等现代形式化书中未引入。
- 归约定理只覆盖抗碰撞；对"抗原像/PRF 性质"的继承，MD 结构并非免费成立——读者勿过度外推。
- 增量哈希、同态承诺等高级构造不在第7版范围。

### 容易混淆的邻近方法论

- 与"分而治之"的一般工程原则: 结构归约多出的内核是**可证明的继承关系**（性质 P 传递），普通模块化不承诺这一点。
- 与 AEAD 的组合定理（encrypt-then-MAC 类）: 那是两个原语组合的安全性传递；本 skill 是单一原语内部"组件→整体"的传递——同属"结构保性质"族但层次不同。
