# 信任拓扑治理：集中度×密钥量×爆炸半径

## R — 原文 (Reading)

> "然而，如果因特网上成百上千个CA中的任意一部分被妥协，影响就会广泛蔓延。攻击者能够获取CA的私钥，在非法域名下发布证书，或者在根证书存储区内引入新的伪造的根证书。妥协单一CA对整个PKI系统完整性的损害，和全球PKI系统的涉及范围一样，是无可估量的。"
>
> — 方法论出处，第19章 19.7.1 DANE 的动机

---

## I — 方法论骨架 (Interpretation)

"中心化还是去中心化"是口号，不是设计。把它拆成两个独立坐标：**信任集中度**（背书权集中在几个实体）与**密钥数量**（体系要维护多少秘密）。

集中省钥但要求可信单点，分布免单点但密钥平方增长——两轴没有同时最优，只能按场景取舍。

设计任何信任体系先做一个量化动作：数出"**多少机构能为我签发/背书身份**"，再对每个背书者问"被攻陷后能冒充多少身份"——乘积就是爆炸半径。

半径过大时用四种工具收敛：

1. 层次分解——限制失陷危害在本地域；
2. 钉扎/限定名单——名字约束；
3. 域自有锚——DANE，本域显式指定信任；
4. 关键操作多签。

反向方案（去中心化信任网）也要按代价核对：认证质量参差、误签扩散。控制权外包（云多租户）则要识破"假独占"——隔离正确性实际外包给了供应商。

## A1 — 书中的应用 (Past Application)

### 案例 1: DANE/TLSA 收敛 CA 信任（第19章）
- **问题**: 浏览器/OS 内置成百上千个受信 CA，任一被妥协即可给非法域名发证书，影响全局蔓延；部分 CA 还滥发通配符证书。
- **方法论的使用**: 量化"谁能给我签"→半径=全网；改用域自有锚——域名管理员本就被授权给出本域标识信息，把域名与证书权威绑定（TLSA 记录四种用法模型）。
- **结论**: "用对 DNSSEC 提供安全性的依赖，取代对 CA 系统安全性的依赖"——把信任从"全网任一 CA"收敛到"本域显式指定"。
- **结果**: 单一 CA 失陷的影响面被限制在本域决策范围内。

### 案例 2: Kerberos 跨域层次化（第15章）
- **问题**: 域间两两互信全连接，N 域要 N(N−1)/2 次安全密钥交换，不可扩展。
- **方法论的使用**: 层次收敛——v5 用 FORWARDABLE 转发票据沿层次路径（先向上到公共祖先域再向下）。
- **结论**: 层次把信任关系的建立与维护从平方增长降为线性。
- **结果**: 跨域认证可运营，单域失陷危害限制在本地域。

### 案例 3: SSH 信任模型与 PGP 信任网对照（第17、19章）
- **问题**: 主机认证选本地密钥库模型还是 CA 模型？个人通信选信任网可行吗？
- **方法论的使用**: 两模型对照——SSH 本地库（首次信任+密钥变更告警）vs 服务器存目录+CA 签名；PGP 信任网"被另一个受信公钥签名即可信"对照 CA 链。
- **结论**: NIST SP800-177 裁决推荐 S/MIME 而非 PGP，理由是 CA 系统在验证公钥上更可靠——去中心化省掉 CA 却把认证质量交给用户互助签名。
- **结果**: 拓扑选型有了显式判据（认证质量与误签扩散），而非意识形态。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计联盟链/多组织联合的身份 CA 拓扑。
2. 评估现有 PKI/证书体系的系统性风险（我们依赖多少根）。
3. 内部工具信任模型选型（SSH 首次信任、内部 CA、证书钉扎）。
4. 多租户/外包场景的隔离责任评估（隔离是"假独占"吗）。

### 语言信号 (用户的话里出现这些就应激活)

- "多少个 CA 能给我签证书 / how many CAs can issue for my domain"
- "CA 被攻陷的影响 / CA compromise blast radius"
- "信任锚怎么定 / trust anchor, certificate pinning, DANE"
- "去中心化信任/信任网 / web of trust vs hierarchical CA"
- "多租户隔离是云商负责吗 / isolation responsibility in cloud"

### 与相邻 skill 的区分

- 与 `stallings-key-counting-hierarchy` 的区别: 那个数密钥量选架构（运营成本维度），本 skill 数背书者算爆炸半径（风险维度）；同一层次结构在那边是省钥手段、在本 skill 是限制失陷范围的手段——先定形、再定险。
- 与 `stallings-revocation-as-propagation` 的区别: 那个管"签出去的凭证怎么收回"（失效的时间语义），本 skill 管"谁有权签"（签发权集中度）——签发与撤销是两条独立治理线。
- 与 `stallings-environment-threat-rewrite` 的区别: 那个是全量威胁模型重推，本 skill 是其中信任维度的专项深化。

## E — 可执行步骤 (Execution)

1. **列背书者清单**：写出当前体系所有能为我签发/背书身份的实体（CA、目录、KDC、管理员、内置根库），数出数量。
   - 完成标准: 清单成文，含间接背书（中间 CA、通配符权限）。
   - 判停条件: 自签自用、无外部背书需求时，停在此步记录结论。
2. **算爆炸半径表**：对每个背书者问"被攻陷后能冒充多少身份、影响哪些域/服务"。
   - 完成标准: 半径表成文，标出最大半径者。
3. **选择收敛工具**：半径不可接受处，从层次分解（名字约束）、钉扎/限定名单、域自有锚、关键操作多签中选型落地。
   - 完成标准: 至少一种机制落地，或有书面豁免理由。
4. **反向核对分布式方案**：若选信任网/多点互认，逐条核对认证质量参差与误签扩散两条代价。
   - 完成标准: 代价核对记录成文。
5. **外包隔离核查**：对控制权外包的场景问"隔离正确性由谁保证、可否自证"，把结论写入合同/评估。
   - 完成标准: "任意一家被攻陷能冒充多少身份"作为验收指标写进风险评估。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单体系统内部模块间信任（无多方背书问题）。
- 把钉扎/DANE 当万灵药——按书内逻辑，DANE 是"用 DNSSEC 依赖替换 CA 依赖"，DNSSEC 自身的信任链与运维成本构成新的半径来源，需同表评估。

### 作者在书中警告的失败模式

- 公钥目录把信任压缩成管理员单点：管理员私钥被获取或记录被篡改即可假冒任何通信方（ce054）。
- CA 滥发通配符证书：持钥者可"在世界各处对任意域或实体发布子证书"。
- 云多租户标签"假独占"：隔离正确性外包给 CP，用户无法自证隔离未被旁路（ce072）。

### 作者的盲点 / 时代局限

- 成书 2017 前：书中收敛工具止于层次/钉扎/DANE，证书透明度（CT）、CAA 等现代 CA 治理机制书内未出现——外推时应补充说明。

### 容易混淆的邻近方法论

- v32 密钥层次（运营维度，勿混半径论据）。
- v34 撤销治理、v35 公钥背书检查（后者是本 skill 的前置问句）。
