# 敌手能力 × 攻击目标双轴建模

## R — 原文 (Reading)

> 乍一看选择密文攻击似乎有点不可思议。因为如果敌手只有一个感兴趣的密文串，那么在选择密文攻击下敌手明显能够解密密文串。然而，我们提出的敌手的目标通常是包括确定Alice和Bob之间使用的密钥，使得别的密文串也能够被解密。
>
> — 原作者,原始方法论来源第1章 1.2 脚注（中译本 OCR，逐字保留）

---

## I — 方法论骨架 (Interpretation)

"安全"不是一个布尔值，而是一张表格里的格子。任何密码方案的安全声明都必须先回答两个独立的问题：敌手能做什么（能力轴），敌手想要什么（目标轴）。能力轴从弱到强大致是：只能看密文 → 拿到部分明密文对 → 能自选明文求加密 → 能自选密文求解密 → 能主动篡改/注入/并行开会话。目标轴从弱到强：区分两条候选明文 → 恢复部分信息 → 解出一条新密文 → 伪造一条认证值 → 恢复密钥本身。声明"用了 HMAC"落在哪个格子里？在被签消息不含 nonce 时，重放格子上必败——这与 HMAC 算法本身的强度无关。缺格子的声明不可评估：能力与目标任何一轴没写清，评审就无法开始，攻击者恰恰从没声明过的格子进来。

## A1 — 书中的应用 (Past Application)

### 案例 1: 签名方案的六格分析表
- **问题**: "这个签名方案安全吗"无法一句话回答——RSA 签名在某些攻击者面前弱、另一些面前强。
- **方法论的使用**: 第 7 章 7.1 把攻击者按能力分唯密钥/已知消息/选择消息三档，把伪造目标分完全伪造/选择性伪造/存在性伪造三级，交叉成二维表，逐格分析。
- **结论**: 裸 RSA 签名的乘法同态在三种能力档下都能实现伪造，但只到"选择性伪造"档，不是完全攻破。
- **结果**: 同一方案在不同格子安全等级不同，安全声明必须指名格子（"在选择消息攻击下抗存在性伪造"）。

### 案例 2: Rabin 体制的格子天壤之别
- **问题**: Rabin 对选择明文攻击有到整数分解的归约证明，能否宣布"安全"？
- **方法论的使用**: 第 5 章 5.8.1 换到选择密文格子重评：敌手可自选 r² 提交解密谕示。
- **结论**: 一次解密查询即分解 n——同一方案在相邻格子从"可证明安全"跌到"一查询即破"。
- **结果**: 能力轴上移一格，结论完全反转；证明只覆盖声明过的格子。

### 案例 3: MAC 的 (ε,Q) 假冒者模型
- **问题**: 如何给"消息认证码有多安全"一个可比较的定量口径？
- **方法论的使用**: 第 4 章 4.4 把攻击者能力参数化为"可查询谕示 Q 次"，目标定为"伪造成功概率 ε"，得到 (ε,Q) 二元组。
- **结论**: CBC-MAC 在变长消息下存在 (1/2, O(2^{t/2})) 假冒者——成功率和查询量写在一起，不同 MAC 可同坐标比较。
- **结果**: 攻击强度从形容词变成可计算的参数对。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 评审第三方接口的"已用 HMAC-SHA256 防伪造/防篡改"安全声明，要给出漏洞结论或验收意见。
2. 威胁建模文档或安全评审报告中需要定义敌手假设，写出"防什么样的攻击者"。
3. 读密码论文/产品白皮书时遇到"可证明安全""语义安全"等声明，需要追问它到底在哪个模型下成立。
4. 渗透测试或红队拿到一个攻击成果，需要定性"这算部分攻破还是完全攻破"。

### 语言信号 (用户的话里出现这些就应激活)

- "这个方案/接口安全吗？用了 HMAC/RSA/AES 还能被伪造吗"
- "威胁模型怎么写 / threat model 怎么定 / 敌手假设是什么"
- "选择密文攻击 chosen-ciphertext、CCA、选择消息攻击 chosen-message"
- "存在性伪造 existential forgery、完全攻破 total break、部分攻破"
- "抗重放 anti-replay / 重放算不算攻破"

### 与相邻 skill 的区分

- 与 `stinson-security-notion-calibration` 的区别: 本 skill 拆"敌手能做什么×想要什么"的格子；那个 skill 管"用哪把尺子度量（计算/可证明/无条件）"。先定格子再选尺子——两者构成"建模→度量"的连续步骤。
- 与 `stinson-proof-coverage-audit` 的区别: 本 skill 建模所有安全声明；那个 skill 专审"数学证明覆盖了哪些格子"，只在对方已有形式化证明时用——证明的敌手模型边界以本 skill 的格子为坐标系。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **写下待审声明的原文**，圈出其中的安全词（"防伪造""不可解密""安全"）。
   - 完成标准: 每个安全词都对应一个待填格子；若声明连能力轴都没提，标注"格子缺失"。
2. **填能力轴**: 按唯密文 → 已知明文 → 选择明文 → 选择密文 → 主动介入（可修改/注入/并行会话）逐档列出该场景下敌手现实可获得的能力（能否拿到谕示、能否重放、能否开并发）。
   - 完成标准: 能力轴每档标注"现实可得 / 不可得 / 未知"，并给出理由。
   - 判停条件: 若发现系统根本不暴露任何交互面（纯离线验证），跳到步骤 4 只填低能力档。
3. **填目标轴**: 区分恢复密钥 / 解密新密文 / 伪造认证值 / 区分候选明文 / 恢复部分信息 / 重放旧消息，逐项声明。
   - 完成标准: 每个目标标注"声明防 / 未声明 / 声明不防"。
4. **把声明放进格子并找缺口**: 每个未声明的格子列为审计问题；重点检查目标轴上的重放格与能力轴上的最高现实档。
   - 完成标准: 输出一张"格子×证据"表，缺口格子逐个给出攻击路径或排除理由。
5. **给出结论**: 声明改写成"在（能力）模型下抗（目标）"，缺口按风险排序。
   - 完成标准: 结论句式完整（能力+目标双轴齐全），缺口列表可直接转为测试用例。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯功能/性能/可用性问题（延迟、崩溃、容量），没有对抗性参与者的场景。
- 对方问的是具体算法的数学原理（如 RSA 如何解密），不是安全声明评估。
- 系统尚无任何密码学组件，双轴表没有可填的对象——先选组件再回来。

### 作者在书中警告的失败模式

- "对一种类型的攻击是安全的，并不表示对其他类型的攻击也是安全的"（第 2 章 2.1）——把单格结论外推成全局安全是最常见的误读。
- 把选择密文攻击当平凡而无视：目标若是恢复长期密钥而非单条密文，该模型立即非平凡（第 1 章 1.2 脚注）。

### 作者的盲点 / 时代局限

- 成书于 2006 年：能力轴未覆盖侧信道/时序攻击、故障注入、批量并行 GPU 与云租用算力等现实能力档；评估现代系统时应自行把这些加进能力轴。
- 远程侧信道（padding oracle 类）在书中只有 CCA 谕示的理论形态，未展开为工程攻击面。

### 容易混淆的邻近方法论

- 把"能力×目标"与"风险=可能性×影响"混同：前者是密码学的形式化敌手建模，后者是风险管理框架，粒度和用途不同。
- 与 STRIDE 等威胁枚举框架：本 skill 不枚举攻击类别，而是给每条安全声明定坐标；两者可组合但不可互替。
