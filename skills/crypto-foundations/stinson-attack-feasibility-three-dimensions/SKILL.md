# 攻击可行性三维评估——算法 × 数据 × 存储

## R — 原文 (Reading)

> 这个密码分析并未对DES的安全性产生实际影响，由于这个攻击所需要的极端庞大的明-密文对数目，在现实世界里一个敌手很难能够积下用同一密钥加密的如此多的明-密文对。
>
> — 原作者,原始方法论来源第3章 3.5.2（中译本 OCR，逐字保留）

---

## I — 方法论骨架 (Interpretation)

"2^60 时间可破"这种头条只报了三维中的一维。给攻击定级要把三个坐标都填上。第一维，算法复杂度：不只看渐进阶，看常数与适用范围——评估必须按"对该对象最优的算法"算，Shanks 大步小步 O(√n) 但要 √n 存储，Pollard ρ 常数存储但同为 √n 时间，Shoup 下界证明通用群攻击 √n 已最优，而指数演算对特定群是非通用超越——最优算法随对象结构变。第二维，数据可得性：这是最常被忽略的硬瓶颈。Matsui 线性分析 2^43 对已知明文在算法上完全可行，他也真的花 40 天造出样本恢复了密钥——但要求全部同密钥，现实中敌手很难积累；而若攻击只需选择明文且系统 API 可触发，数据通道现实存在，威胁立即升级。差分 T≈c/ε、线性 T≈c/ε² 的标度律让样本需求可预估：偏差换算样本量，样本量对照系统寿命内的真实流量上限。第三维，存储：时间-存储折中（Shanks 的表、生日攻击的箱子）改变攻击经济学。定级结论由数据获取通道决定，不由时间复杂度头条决定。

## A1 — 书中的应用 (Past Application)

### 案例 1: Matsui 线性分析——算法可行、数据不可得
- **问题**: 1994 年 Matsui 真的用线性分析恢复了 DES 密钥，DES 算被破了吗？
- **方法论的使用**: 第 3 章 3.5.2 三维核算：时间上 2^43 已被实际执行（40 天造样本+10 天计算）；数据上需要同一密钥下 2^43 对已知明文——现实系统密钥定期更换，无法积累。
- **结论**: "并未对 DES 的安全性产生实际影响"——渐近可行+数据不可得=学术攻击，降级处理。
- **结果**: 威胁定级有了学科示范：先问数据从哪来，再看复杂度头条。

### 案例 2: 样本量标度律——偏差直接换算攻击预算
- **问题**: 结构攻击的样本需求能不能事先算出？
- **方法论的使用**: 第 3 章 3.3.3-3.4：线性攻击 T≈c/ε²（ε=1/32 时 T=8000 对）；差分攻击 T≈c/ε（扩散率 27/1024 时 50-100 个四元组）。
- **结论**: 样本量由偏差/扩散率定量换算——攻击成本可预估，防御侧可反推"多小的偏差需多少轮才够"。
- **结果**: 三维中的数据维从定性判断升级为计算。

### 案例 3: Shanks vs Pollard ρ——时间-存储折中的两条路
- **问题**: 同为 O(√n) 的离散对数攻击如何取舍？
- **方法论的使用**: 第 6 章 6.2：Shanks 建 √n 表项换 O(√n) 时间；Pollard ρ 用确定性迭代+Floyd 快慢指针做常数存储的同阶检测（生日分析给出 O(n^{1/4}) 分解）。
- **结论**: 存储维独立于时间维定价；Shoup 下界锚定通用算法底线，指数演算在特定群非通用超越。
- **结果**: "按最优适用算法评估"成为参数选型纪律——先问攻击者会用哪个算法，再算强度。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 密码分析论文发布（如某分组密码/哈希被"2^60 时间攻击"），决定是否立即迁移。
2. 给自家系统的攻击面定级：红队/研究报告声称某攻击可行，评估现实威胁。
3. 参数选型反推：要抗住某类结构攻击，需要把偏差/数据需求压到什么量级。
4. 攻防评审会上裁决"理论攻击 vs 实际风险"的争论。

### 语言信号 (用户的话里出现这些就应激活)

- "论文说 XX 被破了 / broken in 2^60，要迁移吗"
- "data complexity / 需要多少已知明文 / chosen plaintext 才能打"
- "academic attack / 理论攻击有实际影响吗"
- "time-memory tradeoff / 时间存储折中"
- "同一密钥下能积累多少数据"

### 与相邻 skill 的区分

- 与 `stinson-evidence-tier-labeling` 的区别: 那个评防御主张的证据成色；本 skill 评攻击主张的现实成色——一体两面，先分清问的是攻还是守。
- 与 `stinson-birthday-bound-parameter-sizing` 的区别: 那个是本 skill 数据维的特化工具（生日界换算）；本 skill 是三维总框架，换算结果带回定级。
- 与 `stinson-key-lifetime-rolling` 的区别: 本 skill 评估单次攻击的可行性三维；那个把评估结果代入时间轴做参数寿命与迁移预算——本 skill 的输出是那个 skill 的输入。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **摘出攻击主张的三维原始数据**: 算法（哪类、渐进阶+常数）、数据需求（类型：已知/选择明文，数量）、存储需求。
   - 完成标准: 三维数据表；论文只报一维时，把缺失维标为"未知——需补"。
2. **核对最优适用算法**: 该攻击是否对所评对象最优？有无更优的结构攻击或通用算法（对象不同最优解不同）。
   - 完成标准: "评估所用算法=对所评对象最优"论证一行，或改用更优算法重算。
3. **核算数据可得性**: 数据类型对照系统现实（同密钥流量上限、API 能否触发选择明文、密钥轮换周期）；用标度律（差分 c/ε、线性 c/ε²）换算样本量并与流量预算比对。
   - 完成标准: "数据需求 N vs 系统寿命内可得 M"的数字对比 + 通道判定（现实存在/不存在）。
   - 判停条件: 若数据通道现实存在（API 可触发/密钥长期不换），直接输出"立即升级处置"结论跳到步骤 5。
4. **核算存储与工程成本**: 折中表规模、并行度、专用硬件经济性。
   - 完成标准: 存储维数字 + 攻击总成本的经济量级。
5. **输出定级结论**: 学术攻击（降级监测）/现实威胁（立即处置）/条件威胁（写明触发条件：密钥延长、API 暴露等），并附"定级由数据通道决定"的依据句。
   - 完成标准: 三档定级之一 + 监控触发条件清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 漏洞利用的工程细节（exp 编写、绕过缓解措施）——那是渗透工程，不是密码分析定级。
- 合规/风险评分框架（CVSS 类）——评分维度不同，本 skill 的三维可作其输入。
- 非密码学的算法复杂度讨论。

### 作者在书中警告的失败模式

- 用"时间复杂度可行"直接等同"现实威胁"——Matsui 攻击的示范性降级（第 3 章 3.5.2）。
- 数据维被完全忽略：差分需选择明文、线性需已知明文，两者的获取通道难度不同，不可互换。
- 存储免费错觉：Shanks 的 √n 表在群很大时不可行，ρ 的常数存储才是可用形态。

### 作者的盲点 / 时代局限

- 成书 2006 年：云租用算力、GPU/FPGA 农场的攻击经济学未覆盖——现代定级应把"租用成本折算"补入时间维；加密流量可采集性（TLS 记录层）与协议层 nonce 使"同密钥数据积累"的上限与书中电话时代假设不同。
- 侧信道作为数据获取通道（一条曲线=一组已知明文）不在书内，现代评估应把侧信道采样并入数据维。

### 容易混淆的邻近方法论

- 三维评估 ≠ "复杂度比较"：单维比较会得出"2^60 比 2^64 危险"的空洞结论；定级取决于三维的乘积结构。
- 与证据分层的镜像区分：证据分层评"这个防御主张可信吗"，本 skill 评"这个攻击主张可怕吗"——同一份论文，两个 skill 各取一半。
