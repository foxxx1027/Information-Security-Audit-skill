# 平方根标度与参数反推——生日界作为通用决策下界

## R — 原文 (Reading)

> 如果取E=0.5，那么Q~1.17/M
>
> 这个攻击产生了一个(1/2,O(2/2))假冒者。
>
> — 原作者,原始方法论来源第4章 4.2.2 定理4.4、4.4.2（中译本 OCR，逐字保留：第一处 1.17/M 为 1.17√M 之 OCR 缺根号；第二处 O(2/2) 为 O(2^{t/2}) 之上标丢失）

---

## I — 方法论骨架 (Interpretation)

往 M 个箱子里投 Q 个球，只要 Q 到 √M 量级，两个球撞进同一箱的概率就过半——这个"生日悖论"把一切"空间够大所以安全"的直觉折半。工程上记住三条换算。第一条：n 位空间只给 n/2 位碰撞安全——碰撞攻击（找任意两个相同值）只需约 2^{n/2} 次尝试，而原像攻击（匹配指定值）才需要 2^n；所以"随机 ID 会不会撞""MAC 能不能被伪造""摘要抗不抗碰撞"全部按平方根档预算，"穷举不可能"的按全空间算法在此无效。第二条：参数反推流程——先估敌手在系统寿命内可承受的查询量 Q（请求数×年数），再令 √M > 安全倍数×Q 反推位长；例：64 位 token 每天千万请求，十年累计约 2^35 次已超过 2^32 的碰撞期望，必然撞车，需 ≥128 位。第三条：输出长度直接限定安全档——CBC-MAC 的 t 位标签只有 t/2 位生日安全（1.17×2^{t/2} 次查询出现 1/2 成功率伪造）；40 位摘要百万次哈希即破，128 位是下限。Pollard ρ 用同一标度把整数分解做到 O(n^{1/4})——平方根标度是跨对象的通用决策下界。

## A1 — 书中的应用 (Past Application)

### 案例 1: 碰撞 vs 原像——一个平方根的差距
- **问题**: 摘要多长才够？
- **方法论的使用**: 第 4 章 4.2.2 定理 4.2-4.4：原像成功率 ≈ Q/M；碰撞走生日论证 ≈ 1−e^{−Q(Q−1)/2M}，置 ε=0.5 得 Q≈1.17√M。
- **结论**: 找碰撞比找原像容易一个平方根量级；40-bit 摘要百万次哈希内即破，可接受最小 128-bit。
- **结果**: 摘要长度选型从经验值变为从敌手查询量反推的定量决策。

### 案例 2: CBC-MAC 的 t/2 位安全
- **问题**: MAC 标签 64 位，安全强度是 64 位吗？
- **方法论的使用**: 第 4 章 4.4.2：攻击者请求约 1.17×2^{t/2} 个随机消息的 MAC 找中间状态碰撞，再询一次即得新消息的有效 MAC——(1/2, O(2^{t/2})) 假冒者。
- **结论**: 输出长度限定伪造界：t 位标签只值 t/2 位生日安全，与底层分组密码强度无关。
- **结果**: MAC 位长按可接受伪造概率反推；变长消息另需长度域分离。

### 案例 3: Pollard ρ——生日标度跨对象复用
- **问题**: 通用离散对数/分解攻击的基线在哪？
- **方法论的使用**: 第 5 章 5.6.2 用生日悖论分析迭代序列碰撞（|X|≈1.17√p 时 50% 出现碰撞），第 6 章 6.2 的 Shanks 与 ρ 同以 √n 为基线，Shoup 证明通用群下界即此量级。
- **结论**: √n 是通用群攻击的基线，防御参数以此为下界锚点——群阶至少 2^{2b} 才给 b 位安全。
- **结果**: 平方根标度统一了"碰撞攻击、MAC 伪造、群攻击"三类对象的参数决策。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计防重放 token、会话 ID、随机文件名、API 密钥的位长，问"64 位随机数够吗"。
2. 选定哈希摘要或 MAC 截断长度（如 HMAC 截 96 位）并评估安全档。
3. 解释/反驳"128 位摘要挡 2^128"的误解，或评审系统碰撞概率预算。
4. 为 ECC/DL 群参数定阶：要 b 位安全需 2b 位群阶。

### 语言信号 (用户的话里出现这些就应激活)

- "birthday attack / 生日攻击 / 生日悖论在这里适用吗"
- "64 位随机 ID / token 会撞吗 / 2^{n/2} 是什么意思"
- "MAC 截断到 96 位安全吗 / 摘要长度怎么定"
- "collision probability / 碰撞概率怎么算"

### 与相邻 skill 的区分

- 与 `stinson-hash-property-usage-matching` 的区别: 那个决定"该用途需要哪条性质"（碰撞 or 原像）；本 skill 在确定需要抗碰撞后算参数——原像按 2^n、碰撞按 2^{n/2}，选错档位白花一倍位长。
- 与 `stinson-attack-feasibility-three-dimensions` 的区别: 那个是三维总框架（算法×数据×存储）；本 skill 是其中"数据/查询量维"的定量工具——生日界换算完成后仍要回到三维框架定级。
- 与 `stinson-key-lifetime-rolling` 的区别: 本 skill 给出静态位长下界；那个叠加算力增长与算法进展的时间衰减做寿命预算——静态预算是时间序列管理的起点。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **判定攻击类型档位**: 敌手要"匹配指定值"（原像，2^n 档）还是"任找一对相同"（碰撞，2^{n/2} 档）。
   - 完成标准: 档位判定一行 + 理由（对手能否两头自由选择）。
   - 判停条件: 若是原像档，按 Q/M 计算后直接输出参数建议，不走碰撞公式。
2. **估算敌手查询预算 Q**: 系统寿命 × 请求速率 × 攻击者可占用比例；并行与速率限制折算进去。
   - 完成标准: Q 的数量级 + 估算依据一行。
3. **按生日界反推参数**: 碰撞期望 ≈ Q²/2M，令 M ≥ 安全倍数×Q² 反推位长 n = 2·log2(Q)+裕度。
   - 完成标准: 给出位长建议（含裕度）+ 对应碰撞概率数字。
4. **核对输出长度限定项**: MAC 标签/摘要截断位单独复核（t/2 档）；服务端有无去重记录改变问题性质。
   - 完成标准: 每个输出长度项标注生日安全档位。
5. **输出参数决策表**: 对象×位长×碰撞概率×敌手预算，结论句"由敌手可承受查询量反推，非拍脑袋"。
   - 完成标准: 表内每行数字自洽（位长、概率、预算三者对应）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 抗原像/抗穷举需求的参数（口令哈希、密钥长度）——按全空间 2^n 计，用生日界会多花一倍位长（保守但浪费），关键是别把两档混谈。
- nonce 唯一性设计——nonce 要求"绝不重复"，概率预算只是权宜，确定性保障（计数器）优先。
- 分布式系统的哈希分桶（非对抗场景）——碰撞只影响性能不影响安全，预算逻辑不同。

### 作者在书中警告的失败模式

- "40 比特摘要在百万次哈希内即破"——位长不足时生日攻击是现实威胁而非理论（第 4 章 4.2.2）。
- CBC-MAC 按标签全位长宣传强度——实际只有 t/2 位（4.4.2）。
- OCR 警示的教训：数值例（Q≈1.17√M 缺根号）引用时须回源复核——平方根符号丢失会把结论错一个量级。

### 作者的盲点 / 时代局限

- 成书 2006 年：现代服务端去重/共识系统中的碰撞处置（重试与审计）未覆盖；本 skill 给参数下界，工程上"撞了怎么办"的兜底需另行设计。
- 量子 Grover 对平方根标度的交互（碰撞搜索的 BHT 算法等）未涉及，后量子场景参数需另查。

### 容易混淆的邻近方法论

- 生日界 ≠ 鸽笼原理：鸽笼给确定性上限（N+1 个必撞），生日界给概率拐点（√N 量级过半）——参数预算用的是后者。
- 与"熵估算"的区别：生日界算的是空间大小与查询次数的关系，不评估分布质量——分布有偏时实际碰撞更早，需先过伪随机性判据。
