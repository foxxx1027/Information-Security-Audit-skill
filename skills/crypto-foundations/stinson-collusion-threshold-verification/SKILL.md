# 合谋阈值显式化——"k 安全 / k+1 必破"的硬边界与双验证

## R — 原文 (Reading)

> 定理10.5Blom密钥预分配方案对抵抗k个用户的攻击是无条件安全的。但是任何k+1个用户都能够攻破方案。
>
> 定义13.1……任何t个参与者都能计算出K的值，但任何t-1个参与者都不能计算出K的值。
>
> — 原作者,原始方法论来源第10章 10.2 定理10.5、第13章 13.1 定义13.1（中译本 OCR，逐字保留）

---

## I — 方法论骨架 (Interpretation)

门限型方案（多签、秘密共享、密钥预分配、组播密钥）的安全声明是一对精确的硬边界：不超过 k 个合谋者时无条件安全，k+1 个必然攻破——k 是合谋门限，不是"强度参数"，调大 k 买到的只是"容忍更多人"，不是"更难攻破"。审计这类方案要做双验证，而现实实现几乎只做了前一半：验证 A（可用性）——任意 t 个份额能恢复；验证 B（机密性）——任意 t−1 个份额零信息。只演示"3 份能解锁"不构成对"2 份不泄露"的任何证据。第三条独立检查是份额独立性：份额若线性相关/同源派生（五份份额来自同一助记词），t−1 零信息失效，声明的 3-of-5 实际塌缩为 2-of-5 甚至 1-of-5。组播场景还有第四条：退出用户的信息多于从未加入者，注销必须换全新密钥且旧钥推不出新钥。审计动作可执行：显式测试任意 t−1 份的剩余熵（对低熵秘密尤其致命），而不是只跑恢复演示。

## A1 — 书中的应用 (Past Application)

### 案例 1: Blom 方案——k 与 k+1 的定理级边界
- **问题**: 参数 k 的密钥预分配方案"安全性"怎么表述？
- **方法论的使用**: 第 10 章 10.2 定理 10.5：任意 ≤k 个用户合谋无条件安全；任意 k+1 个用户联合即可解出对称矩阵秘密、算出全网任意用户对的密钥（k=1 时两人合谋即破，例中由 K_{U,V}=d·r_U·r_V 直接解出 d）。
- **结论**: k 是硬边界；"安全"必须写成"在至多 k 个合谋的假设下"；k+1 是必破不是风险。
- **结果**: 声明门限+显式假设"最多 t 个被收买"成为设计义务；加固唯一路径是多加一阶（存储线性增长）。

### 案例 2: Shamir 门限的双验证
- **问题**: (t,w) 方案的安全定义为什么是两句话？
- **方法论的使用**: 第 13 章 13.1 定义 13.1 同时要求"任意 t 个可恢复"与"任意 t−1 个不能计算出 K"；零信息半边由"对任意候选都能构造相容多项式"证明（例 13.1：p=17、(3,5)、K=13，任意 3 点插值恢复，任意 2 点对 K 有 17 种等可能值）。
- **结论**: 只验证恢复半边是不完整的验收；t−1 零信息必须独立证明。
- **结果**: 双验证模板确立，成为门限系统验收的标准动作。

### 案例 3: 组播注销——前成员比外部人知道更多
- **问题**: 用户退出组播组，换组密钥就够了吗？
- **方法论的使用**: 第 14 章 14.3：退出用户掌握旧组密钥与历史密钥，信息量大于从未加入者；注销必须生成全新密钥且旧钥推不出新钥（LKH 沿路径重加密是效率实现）。
- **结论**: 合谋威胁模型必须包含"前成员合谋"；只防外部人的方案高估安全。
- **结果**: KDP/CFF 的安全判据同样显式进入合谋体（覆盖特权子集的密钥集不可被合谋覆盖）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 审计 3-of-5 多签钱包/门限签名服务器：份额如何生成、是否同源派生。
2. 验收秘密共享系统（密钥分片备份、SSSS 工具、HSM 分片）：只测了恢复没测泄漏。
3. 设计组密钥/组播体系：注销流程是否换全新密钥、前成员能推多少。
4. 评审密钥预分配或多方密钥管理方案，核对合谋假设是否显式声明。

### 语言信号 (用户的话里出现这些就应激活)

- "threshold scheme / t-of-n / 门限怎么验证"
- "collusion attack / 合谋多少人会破"

- "任意 t-1 份额真的零信息吗 / 剩余熵怎么测"
- "用户退出群组后还能解密吗 / re-keying"

### 与相邻 skill 的区分

- 与 `stinson-simulatability-zero-knowledge` 的区别: t−1 零信息的证明用模拟/相容构造（那个 skill 的判据）；本 skill 是消费该判据做门限系统验收的总框架。
- 与 `stinson-feasibility-ceiling-first` 的区别: 那个管"信息论上界先立再构造"的可行性格局；本 skill 管门限声明本身的验收（双验证+独立性）——设计前的可行性门与设计后的验收门先后接力。
- 与 `stinson-public-key-parameter-hygiene` 的区别: 那个管单密钥的参数结构与泄露处置；本 skill 管多份额系统的合谋边界——份额同源塌缩是两者交叠点，从本 skill 发起检查。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **摘出门限声明与生成方式**: (t,w) 参数、份额生成算法、份额来源（独立生成/同源派生+派生方式）、存储位置。
   - 完成标准: 声明表（t、w、生成方式、派生域分离有无）填齐。
2. **验证 A（恢复半边）**: 任意 t 份组合（抽查多个子集）能否恢复；边界（恰 t、t+1）行为。
   - 完成标准: 抽查子集通过率 + 边界行为一行。
3. **验证 B（零信息半边）**: 任意 t−1 份对秘密的剩余熵——低熵秘密（口令、种子）直接测试可否暴力缩小候选；高熵秘密核对方案的零信息证明。
   - 完成标准: 剩余熵判定（零信息/部分泄漏/塌缩）+ 测试方法说明。
   - 判停条件: 若份额同源派生且无域分离，直接输出"实际门限塌缩至 X-of-w"结论跳到步骤 5。
4. **份额独立性核查**: 派生域分离、线性相关性测试（同源份额常线性相关，2 份即可插值）；前成员/已注销者的信息残留。
   - 完成标准: 独立性判定 + 注销换钥合规（全新密钥、旧推不出新）结论。
5. **输出验收结论**: 双验证+独立性三态结果；实际门限值指认；合谋假设（"最多 X 个被收买"）写进安全声明的建议。
   - 完成标准: 结论含"声明的 t-of-w 与实际门限是否一致"的明确判定。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 普通访问控制/权限系统（RBAC、审批流）——那是授权逻辑，无份额结构、无合谋边界语义。
- 法定人数的业务规则（董事会过半数）——法律语义，密码学门限只是其实现手段之一，验收维度不同。
- 单一密钥的保管与轮换（无分享结构）。

### 作者在书中警告的失败模式

- 把 k 当"强度"参数——k 只是合谋门限，k+1 必破（定理 10.5）。
- 只验证恢复半边——定义 13.1 的两半缺一即不完整；份额相关性使 t−1 零信息失效。
- 忽略前成员威胁——退出者信息多于从未加入者，注销必须全新密钥（14.3）。
- 门限恰好等于份额数时零检错能力（习题 13.2 的 w−t=1 不可解）——冗余既是攻击面也是容错资源。

### 作者的盲点 / 时代局限

- 成书 2006 年：门限签名（t-of-n 签名而非秘密重构）作为独立原语未展开，现代多签审计需补"部分签名组合的随机数门限"问题（nonce 在门限签名中的塌缩风险）；可验证秘密共享（VSS，防分发者作弊）书中只有思想级。
- 动态组（成员频繁进出）的份额刷新（proactive refresh）未覆盖。

### 容易混淆的邻近方法论

- 合谋边界 ≠ 权限边界："谁能发起操作"是授权问题，"多少份额合谋能重建秘密"是密码学问题——多签系统两层都有，勿混。
- 与拜占庭容错（BFT）阈值的区别：BFT 的 t 容错关于协议活性/一致性（f<t<3f+1 类），本 skill 的 t 关于秘密机密性——同名 t，不同代数。
