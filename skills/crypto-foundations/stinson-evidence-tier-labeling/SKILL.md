# 证据层级标注——四级证据链与最弱环节决策

## R — 原文 (Reading)

> （事实上这些随机变量并不相互独立，这意味着我们未能给这个逼近提供一个数学上的证明。然而，正如我们将要看到的，这个逼近在实际中很有效）
>
> — 原作者,原始方法论来源第3章 3.3.3（中译本 OCR，逐字保留）

---

## I — 方法论骨架 (Interpretation)

"有证明"不是布尔值，而是一条链，链上每一环的强度不同。给安全主张的证据分层，最粗可分四级：一级，标准模型证明——不依赖理想化假设的归约；二级，理想模型证明——随机谕示模型（ROM）下可证，但现实 Hash 不是谕示器，换成具体函数证明即失效，这一级必须诚实标注"绑定模型"；三级，启发式+实验——没有数学证明但实测有效（书中对线性分析的独立性假设就属此级，作者自己括号承认）；四级，未证假设——连实验都没有，只剩"没人破过"。分层的用途在决策：证据链的保证力由最弱一环决定，不由最强一环决定。A 方案有 ROM 证明但部署时换了新 Hash——链条在实例化处断裂，保证降为无证明；B 方案无证明但 20 年公开未被破——经验证据无上界保证但环环真实。高价值场景的正确动作不是无脑选"有证明"的，而是找出每个方案链条的断点，选断点可见且可维护的那个，并把断点的监控写成义务。

## A1 — 书中的应用 (Past Application)

### 案例 1: 线性分析的独立性假设——三级的自我标注
- **问题**: 线性攻击的偏差估算依赖 4 个活动 S 盒相互独立，这个假设成立吗？
- **方法论的使用**: 第 3 章 3.3.3 作者直接在括号里承认"并不相互独立、未能提供数学上的证明"，随后以实验有效性作为支撑。
- **结论**: 结论标注为"启发式+实验"层级；理论证明缺失不等于无效，防御方也不能指望攻击者"没证明"就打不进来。
- **结果**: 同一段里"相关变量误用堆积引理会算错"的对照提醒：同为独立性缺失，一处是近似可用、一处是公式失效——层级内部还要看误差方向。

### 案例 2: ROM 证明的实例化断链
- **问题**: FDH/OAEP 类方案"有证明"，部署时换成具体 Hash 会怎样？
- **方法论的使用**: 第 4 章 4.2.1 与第 7 章 7.5.2 把 ROM 明示为理想模型层级：现实 Hash 非谕示器，证明绑定模型。
- **结论**: 给方案换用新 Hash 反而打断原证明——证明链绑定理想对象。
- **结果**: 证据链维护义务进入运维：Hash 迁移须重做证明或显式接受降级。

### 案例 3: Blum-Goldwasser 的未定层级公开承认
- **问题**: 对固定模长的 BG 方案能宣布什么强度？
- **方法论的使用**: 第 8 章 8.4 明写"还不知道是否安全"——不装作有保证。
- **结论**: 未定层级也是一种可标注状态；诚实标注本身是证据纪律的一部分。
- **结果**: 读者可据此决定是否在高价值场景回避，而不是被模糊声明误导。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 方案选型争论：A 有学术论文证明（可能在 ROM 下），B 无证明但部署 20 年未被破，高价值场景选谁。
2. 评审安全白皮书/架构文档，需要给其中每条安全主张标注证据等级。
3. 组件替换决策（换 Hash、换曲线）后，判断原有安全声明是否仍成立。
4. 技术评审会上有人拿"数学证明"压"工程经验"，需要给出统一裁决框架。

### 语言信号 (用户的话里出现这些就应激活)

- "有安全证明 / provably secure，是不是就不用管 20 年未被破的方案"
- "随机谕示模型 / random oracle 的证明现实里算数吗"
- "启发式设计 / heuristic / 没有证明但一直没被攻破 unbroken"
- "证明在什么模型下成立 / 换了 Hash 证明还有效吗"

### 与相邻 skill 的区分

- 与 `stinson-proof-coverage-audit` 的区别: 那个用放大镜拆单个证明的四条边界；本 skill 把多个主张放进四级架子做横向比较与决策。一个是显微镜，一个是天平。
- 与 `stinson-attack-feasibility-three-dimensions` 的区别: 那个评估攻击方的可行性；本 skill 评估防御方主张的可信度——一体两面，先分清用户问的是哪面。
- 与 `stinson-provable-security-usability-cost` 的区别: 先信后买——本 skill 定"该不该信这个证据"，那个 skill 算"信了之后用不用得起"，两步分开。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列出待比较方案的全部安全主张**（机密性、完整性、抗伪造……逐条）。
   - 完成标准: 每条主张一行；无主张只有口号的方案标"主张未定义"。
2. **逐主张标注证据层级**: 标准模型证明 / ROM 等理想模型证明 / 启发式+实验 / 未证假设，附出处。
   - 完成标准: 每条主张有层级标签+一句依据；混层声明（如"证明"实为 ROM）被拆开标注。
3. **找每条证据链的断点**: 实例化差异（理想 Hash→具体函数）、假设未证处（独立性、困难性假设）、实验覆盖边界。
   - 完成标准: 每链至少标出一个最弱环节；无断点的链注明"未发现（仍非绝对）"。
   - 判停条件: 若某方案核心主张落在未证假设级且场景为高价值，直接输出"证据不足，不可采"结论。
4. **按最弱环节比较**而非按最强亮点比较；输出决策矩阵（最弱环节 × 场景容忍度）。
   - 完成标准: 决策建议明确写出"由最弱环节 X 主导"的推理句。
5. **写证据链维护义务**: 组件迁移、假设进展、新攻击发布时的重审触发条件。
   - 完成标准: 每个采信方案附至少一条"何时必须重审"的可观察事件。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 具体攻击能不能落地的定级（数据可得性、成本核算）——归攻击可行性评估管。
- 实现质量/代码缺陷审查——证据层级再高也挡不住实现 bug，但那是另一条审计线。
- 纯学术的证明细节复核（归约是否 tight）——除非它直接改变层级判定。

### 作者在书中警告的失败模式

- 把"可证明安全"当单一布尔值——它内部至少分标准模型/理想模型两档，且明确"只是与难题挂钩"（第 2 章 2.1）。
- 用"没有数学证明"否定实测有效的结论——线性分析的独立性假设无证明但攻击真实有效（第 3 章 3.3.3）。
- 用"一直没被破"当上界保证——经验证据无任何失败界，攻击进展可一夜清零（MD5/SHA-1 碰撞史，第 4 章 4.6）。

### 作者的盲点 / 时代局限

- 成书 2006 年：书中四级框架未包含"公开竞赛+多轮全球分析"（如 AES、SHA-3 竞赛）这种制度化证据形态，也无可计算复杂度（concrete security）参数的正式讨论；现代决策可把"竞赛史"作为介于三级与二级之间的证据补充。
- 侧信道/实现级证据完全不在书的射程内。

### 容易混淆的邻近方法论

- 证据分层 ≠ 信心打分：分层是结构判断（哪一环断了），不是主观概率——先找断点再谈信心。
- 与"安全性分级"（能力×目标格子）的区别：格子描述主张覆盖面，层级描述证据成色；一个主张=格子+层级双坐标。
