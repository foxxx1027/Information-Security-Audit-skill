# 参数强度 ≠ 结构强度——密钥空间大小只是必要条件

## R — 原文 (Reading)

> 上面的例子表明，一个密码体制安全的必要条件是能抵抗穷尽密钥搜索攻击，普通的做法是使密钥空间必须足够大。但是，很大的密钥空间并不是保证密码体制安全的充分条件。
>
> — 原作者,原始方法论来源第1章 1.1.1（中译本 OCR，逐字保留）

---

## I — 方法论骨架 (Interpretation)

评估密码方案有两条独立的审计线，大众直觉只看第一条。参数线：密钥多少位，穷举要多少次——它只设置攻击成本的地板，挡住最原始的敌手。结构线：方案是否把明文的统计规律、线性关系、格式特征漏给了不需要密钥就能算的分析者。密钥空间再大，结构线上一样是纸糊的：代换密码 26!≈2^88 的密钥空间，被字母频率+双/三字母组用 176 个密文字母手工击穿——因为单表代换保留了语言的统计指纹。更隐蔽的变体：自动密钥密码把明文混进密钥流让重复模式消失，但真正的秘密只有 26 个初始密钥，"动态化"不增加熵。语言冗余是第二攻击面：英语 75% 冗余度把密钥空间按唯一解距离折价（代换密码约 25 个字母的密文即可唯一定钥）。工程师的行动准则：评审任何"位数大"的声明，先承认它只堵了穷举，然后沿结构线查四件事——确定性加密低熵明文（枚举比对）、格式/统计残留、线性组件、密钥流周期与复用面。

## A1 — 书中的应用 (Past Application)

### 案例 1: 代换密码 26! 密钥空间被手工破译
- **问题**: 密钥空间 26!≈4×10^26、穷举不可行，是否安全？
- **方法论的使用**: 第 1 章 1.2.2 例 1.11 对 176 字母密文做单字母频率+双字母组（ZW→e?）+三字母组（the/and/ing）+词形（单字母词只能是 a 或 i），逐词回填。
- **结论**: 语言冗余提供的统计约束把搜索空间压到可手工处理；密钥空间大小与抗分析能力无关。
- **结果**: 整段明文与密钥纸笔恢复；作者顺势引出唯一解距离（代换密码 n0≈25 字母）。

### 案例 2: 自动密钥密码——动态密钥流不增熵
- **问题**: 用明文构造密钥流、消除周期重复，是否就堵住了维吉尼亚的弱点？
- **方法论的使用**: 第 1 章 1.1.7 拆熵账：密钥流除初始 K 外全部来自明文，真正的秘密只有 K∈Z26。
- **结论**: "动态化"只改变重复模式，不扩大秘密熵；26 个候选逐一试解即破。
- **结果**: 结构花招被熵核算一眼看穿——审计先数秘密总量，再看结构。

### 案例 3: LFSR——m 比特密钥生成 2^m−1 周期仍被线性破解
- **问题**: 短密钥换极长周期密钥流、硬件高效，是不是好交易？
- **方法论的使用**: 第 1 章 1.2.5：整个生成过程线性，2m 比特已知密钥流给出 m 个线性方程，一次求解得初态。
- **结果**: 周期再长也只值 m 个方程；结论确立"线性结构下密钥量坍缩"的普遍判据。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 评审自研/供应商"2048 位高强度加密算法"白皮书或安全声明，需要专业第一步。
2. 评估"我们密钥比 AES 还长所以更安全"类内部论证。
3. 代码审计中发现自定义异或/变换/多轮混合的混淆方案，需要判断强度。
4. 解释为什么标准化算法（AES）128 位密钥反而比自研 4096 位可信。

### 语言信号 (用户的话里出现这些就应激活)

- "密钥 2048 位 / 4096 位，够安全吧 / key size 够大"
- "密钥空间 2^xx，穷举不可能 / brute force infeasible"
- "自研加密算法评估 / custom cipher review"
- "为什么 AES 只有 128 位却比我们的长密钥安全"

### 与相邻 skill 的区分

- 与 `stinson-linearity-kills-ciphers` 的区别: 本 skill 是"参数线 vs 结构线"的总框架（四查）；那个 skill 专门处理结构线中的线性分支（方程组攻击）。本 skill 发现线性嫌疑时转那个深挖。
- 与 `stinson-structural-security-bound` 的区别: 那个从防御者视角看"好结构如何给出可证下界"；本 skill 从攻击者视角看"结构缺陷如何击穿大密钥"。
- 与 `stinson-public-key-parameter-hygiene` 的区别: 本 skill 是以古典密码为例的总框架；那个 skill 是结构线在 RSA/DL/ECC 公钥参数上的实例化检查表。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **承认参数线并只给它应得的分量**: 记下密钥位数与穷举成本，明确它只堵穷举。
   - 完成标准: 一行写出"穷举地板 = 2^k 次操作"，并注明这是必要条件。
2. **结构线四查之一——确定性低熵明文**: 同一明文是否总得同一密文？明文空间是否可枚举（结构化字段、编码域小）？
   - 完成标准: 标注确定性是/否；若否，枚举比对攻击路径成立性一行结论。
3. **结构线四查之二——统计/格式残留**: 密文是否保留明文的频率、重复模式、块对齐特征（ECB 型泄漏、语言冗余）？
   - 完成标准: 列出可观察的密文侧特征及对应明文推断。
4. **结构线四查之三——线性组件**: 密钥与数据是否存在线性/仿射组合（异或链、模乘、矩阵）？
   - 完成标准: 线性嫌疑标注；命中则转 `stinson-linearity-kills-ciphers` 流程，输出"强度=0"初判。
   - 判停条件: 若四查任一命中确定性可利用路径，跳到步骤 6 输出结论，无需继续逐项。
5. **结构线四查之四——密钥流周期与复用面**: 密钥流是否有周期？初始秘密总熵多少（参照自动密钥教训）？
   - 完成标准: 秘密熵账一行（真正保密的比特数），周期/复用入口列表。
6. **输出结论**: "位数大只挡住最原始的攻击；安全声明必须在结构线上单独成立"——四查结果表 + 最危险的一条结构路径。
   - 完成标准: 结论含结构线四查逐项判定，至少一条具体攻击推演。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 评估标准化且经全球公开分析的算法（AES、ChaCha20）的密钥档位选择——它们结构线已被社区反复验证，讨论退化为参数对比。
- 纯密钥管理问题（密钥怎么存、怎么换）——结构审计不涉及。
- 哈希函数选型（无密钥或密钥无关的结构问题），应转 Hash 三问题检查表。

### 作者在书中警告的失败模式

- 以密钥空间大小作为安全依据——第 1 章开篇即用代换密码反例打掉这一直觉。
- 唯一解距离折价：语言冗余让"密钥多"在长密文下失效（第 2 章 2.6，英语 75% 冗余）。
- 统计测试全过 ≠ 密码学安全（第 8 章 8.1）——"看起来随机"与"结构可破"并存。

### 作者的盲点 / 时代局限

- 成书 2006 年：结构攻击演示止于频率/线性/差分；未覆盖现代侧信道（时序、功耗、缓存）——现实中对自研算法最快的破法往往不是数学分析而是侧信道，本 skill 四查应视为"数学结构线"，侧信道需另行审计。
- 对"安全素数/标准参数生成"之外的现代密钥格式（如 Misuse-resistant 模式）无涉及。

### 容易混淆的邻近方法论

- "密钥长≠安全"≠"密钥长无所谓"：密钥长度仍是必要条件；本 skill 反对的是把必要当充分。
- 与伪随机性判据的区别：那个管生成器输出质量；本 skill 管方案结构是否泄漏明文信息——一个输出端、一个变换端。
