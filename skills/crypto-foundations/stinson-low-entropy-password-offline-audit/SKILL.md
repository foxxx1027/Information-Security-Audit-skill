# 低熵口令不能成为可离线验证的密钥

## R — 原文 (Reading)

> 这种攻击可以在Oscar希望的任何时间进行，所以属于离线攻击。由于Kpwd比较小，所以这种攻击也是高效的。
>
> — 原作者,原始方法论来源第11章 11.4（中译本 OCR，逐字保留）

---

## I — 方法论骨架 (Interpretation)

口令体系的安全上限不取决于加密算法，而取决于一个结构性问题：验证一次猜测需要跟谁交互？如果攻击者拿到一段记录（握手包、口令哈希文件）就能在自家机器上无限次试解——"对每个候选口令派生密钥、解密、看结果是否合法"——那么全部安全就压缩为字典大小 × 单次验证成本，算力全归攻击者支配，在线限速完全管不着。判定流程：先找验证面（哪份数据能验证猜测）；面若离线（文件/抓包可携带），则salt+内存困难慢哈希只能把单次成本抬高几个量级——是延迟不是加熵；面若在线（每次猜测都要跟服务器交互），限速/锁定才生效，这才是结构修复。PAKE 类协议的设计目标即在此：让每次口令猜测都必须与在线方交互。工程上还有两个推论：其一，"加密算法换强一点"对字典攻击无关紧要——瓶颈在口令熵不在算法；其二，低熵+确定性可验证的组合（口令哈希裸存、口令加密固定格式数据）与逐字母 RSA 是同一语法：枚举空间小+验证免费。

## A1 — 书中的应用 (Past Application)

### 案例 1: 口令直接加密会话密钥的离线攻击
- **问题**: EKE 思路里用口令派生密钥加密 DH 指数/会话密钥，抓包后会发生什么？
- **方法论的使用**: 第 11 章 11.4：攻击者录下握手，对字典每个候选口令派生 K_pwd 解密，用结果是否落在合法子群/是否为有效元素来判定命中。
- **结论**: 一次录音支持无限次离线试算，成本 ≈ |字典| × 单次加解密，与在线限制无关。
- **结果**: 结论固化为判据：口令成为可离线验证的密钥=离线字典可破；修复用专门 PAKE 使每次猜测都要在线交互。

### 案例 2: 静态凭据的窃听复用
- **问题**: 电话卡/磁卡/远程登录的账号+PIN 认证，弱点在哪？
- **方法论的使用**: 第 9 章 9.1：窃听者记录一次合法会话即得全部身份识别信息，之后原样重放。
- **结论**: 认证退化为"知道秘密字符串"；低熵+静态=必然失陷——泄漏一次即永久有效。
- **结果**: 修复方向是动态因子：一次性口令、密码学挑战-应答，使旧值不可复用。

### 案例 3: 与逐字母 RSA 同构的枚举验证
- **问题**: "低熵+可离线验证"的失败还有哪些变体？
- **方法论的使用**: 第 5 章习题 5.15：26 值明文空间+确定性公钥加密=敌手逐候选加密比对全破——验证免费、空间可枚举。
- **结论**: 同一语法跨对象成立：口令哈希裸存、口令加密会话密钥、低熵明文确定性加密，都是"枚举空间小 × 验证无交互"。
- **结果**: 审计时按此语法统一识别，而不是逐个发明补丁。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 审计本地密码管理器/加密备份：用 SHA-256(主口令) 或 PBKDF2 低迭代做文件密钥。
2. 评审登录/配网协议：口令参与握手的方式（直接加密 vs PAKE），判定离线攻击面。
3. 事故响应：口令哈希数据库泄露，评估被暴破的时间线与应急动作。
4. 制定口令策略争论："强制长口令 vs 加盐慢哈希 vs 上第二因子"的资源分配。

### 语言信号 (用户的话里出现这些就应激活)

- "offline dictionary attack / 离线暴破 / 哈希库泄露能撑多久"
- "salt 要不要加 / PBKDF2 迭代多少 / Argon2 参数"
- "PAKE / SRP / 口令认证密钥交换是什么"
- "口令哈希存储方案评审 / SHA-256(password) 行不行"

### 与相邻 skill 的区分

- 与 `stinson-deterministic-pke-fails` 的区别: 那个管公钥加密的枚举比对；本 skill 管口令场景的验证面位置——同一"低熵+免费验证"语法的两个对象。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定位验证面**: 攻击者验证一个口令猜测需要什么数据（哈希文件/握手记录/密文）、需要与谁交互。
   - 完成标准: 验证面声明为"离线（数据可携带）/在线（必须交互）"+ 依据。
   - 判停条件: 若验证面离线且口令空间小（人类口令），直接输出"离线字典可破"结论跳到步骤 4。
2. **核算攻击成本**: 字典大小（口令策略决定）× 单次验证成本（哈希迭代/内存参数），给出数量级估计。
   - 完成标准: 一行成本公式 + 撑过 N 年暴破所需的参数反推。
3. **盘点缓解措施的真实成色**: salt（防预计算表，不加熵）、慢哈希（抬单价，不改结构）、限速/锁定（仅在线面生效）。
   - 完成标准: 每措施标注"结构修复/成本延迟/仅在线有效"。
4. **给出结构修复路线**: 验证面迁移（在线化/交互式 PAKE）或第二因子；离线场景（本地文件）只能接受慢哈希+强口令并明示上限。
   - 完成标准: 修复建议按"结构/延迟"分层；明示"本质是延迟而非加熵"的边界。
5. **输出结论**: 口令体系真实安全上限 = 字典大小 × 单次验证成本（离线时）；"换更强加密算法无关紧要"的判定句。
   - 完成标准: 结论含量化上限与修复优先级。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 高熵密钥的存储与保护（HSM、KMS、密钥封装）——熵不缺，攻击结构不同。
- 生物特征认证（不可更换、模糊匹配，另一套成本模型）。
- 口令策略的人因管理（记忆负担、用户行为）——本 skill 只管密码结构层。

### 作者在书中警告的失败模式

- "离线攻击可以在 Oscar 希望的任何时间进行"——在线限速对离线面无效（第 11 章 11.4）。
- 静态凭据窃听一次永久复用（第 9 章 9.1）。
- 口令的低熵无法靠"加密传输"补足——加密不改变验证面的位置。

### 作者的盲点 / 时代局限

- 成书 2006 年：Argon2（2015）及内存困难函数未出现，书中密钥拉伸只有概念；GPU/ASIC 暴破经济学的现代数字需外部更新，但"延迟而非加熵"的定性结论不变。
- PAKE 部分只给 EKE/SPEKE 思路级介绍，SRP 的工程细节与广泛部署（如苹果生态）后的攻击面不在书内。

### 容易混淆的邻近方法论

- "加盐"≠"加熵"：salt 只消灭预计算与跨用户共享表，单个目标的暴破成本不变——把 salt 当结构修复是最常见的错觉。
- 与 nonce 复用清单的区别：那边是一次性值的生成事故；这边是口令的验证面位置——一个管"值重复"，一个管"验证在哪"。
