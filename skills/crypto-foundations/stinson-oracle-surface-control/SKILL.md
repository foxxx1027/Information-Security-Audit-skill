# 谕示面收敛——对外能力接口是可组合的攻击原语

## R — 原文 (Reading)

> 注意到TA只计算特殊的、预定格式的数的平方根，比方说，对于用户U有h(ID(U))或者-h(ID(U))。这点是非常重要的，因为如5.8.1节所示，一个平方根谕示器可被用来分解n。
>
> — 原作者,原始方法论来源第12章 12.5.3（中译本 OCR，逐字保留）

---

## I — 方法论骨架 (Interpretation)

攻击者不需要"破"你的系统，只需要能"问"它。任何对外提供密码计算能力的接口——解密、开平方根、求逆、签名、错误提示——在攻击者眼里都是一个谕示器（oracle）：可以自由选择输入、观察输出、组合多次调用。单独看每次调用无害，组合起来却可能拼出数学上不该存在的算法：对一个 Rabin 类结构提交自选的 r² 拿回一个平方根，若根不等于 ±r，做一次 gcd 就分解了模数——身份验证服务瞬间变成因子分解服务。防御思路不是"接口要鉴权"（那是访问控制），而是三条密码学特有的纪律：限型（只接受协议规定格式的输入，如 Cocks IBE 的 TA 只对 h(ID) 格式开根，不碰任意值）；封锁端点（白化——首尾注入密钥使攻击者"无法开始"一次分析，DES/AES 的设计实践）；预算审批（每个接口按它发放的谕示能力对应到攻击模型里的哪一档——解密接口一开，CCA 模型就从理论变成现实能力）。评审清单化：列出全部能力接口→每个标注它发放什么谕示→组合攻击推演→限型或关闭。

## A1 — 书中的应用 (Past Application)

### 案例 1: Rabin 解密谕示被组合成分解算法
- **问题**: Rabin 对选择明文可证明安全，那把解密能力开放出去呢？
- **方法论的使用**: 第 5 章 5.8.1 算法 5.12：攻击者自选 r，提交 y=r² mod n 求解密，得根 x；若 x≠±r，gcd(x±r,n) 给出因子。
- **结论**: 一次自选输入的解密查询即分解 n——谕示与私钥等价。
- **结果**: "可证明安全"在解密谕示面前反转；证明只对不开放谕示的模型负责。

### 案例 2: 平方根识别协议——验证方变成分解服务
- **问题**: "能对任意二次剩余开根"当身份凭证行吗？
- **方法论的使用**: 第 9 章习题：Bob 送随机二次剩余 x，Alice 回根 y 证明身份；但任何冒充 Bob 的攻击者可自选 r² 提交，拿到 y≠±r 即分解 Alice 的模数。
- **结论**: 应答者对任意输入开根=向所有对等方提供分解谕示；协议把身份验证做成了分解服务。
- **结果**: 识别协议必须让证明者先承诺、应答不构成对任意输入的有用谕示（Schnorr 的承诺-挑战结构）。

### 案例 3: Cocks IBE 的限型边界（正面样本）
- **问题**: TA 必须为用户算某种平方根，怎么不算漏？
- **方法论的使用**: 第 12 章 12.5.3：TA 只计算 h(ID(U)) 或 −h(ID(U)) 这类预定格式的数，拒绝任意提交值。
- **结论**: "只算预定格式的数"本身就是安全边界——限型把谕示面从"任意根"收敛到"不可自选的根"。
- **结果**: 限型输入使 5.8.1 式的组合攻击无从构造；接口格式校验上升为密码学防线。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计硬件加密协处理器/密管系统的"调试解密""测试解密"接口，评估风险。
2. 审计 KMS/HSM 的对外 API：哪些密钥用途、哪些算法操作对哪些调用方开放。
3. 协议设计中发现某参与方要提供"对输入做私钥运算"的应答服务（识别、证明、脱敏）。
4. 评估系统错误回执/填充校验失败提示是否构成隐式谕示（现代对应：padding oracle）。

### 语言信号 (用户的话里出现这些就应激活)

- "解密谕示 / decryption oracle / chosen-ciphertext 场景现实里存在吗"
- "调试接口能解任意密文，只有内部能用，有问题吗"
- "oracle attack / padding oracle / 错误信息泄露"
- "对任意输入做签名/开根/求逆的服务"

### 与相邻 skill 的区分

- 与 `stinson-partial-leakage-amplification` 的区别: 那个讲"泄漏的一位如何被放大成全恢复"（信息面）；本 skill 讲"能力接口如何被组合成谕示"（计算面）——常配合使用，放大器需要谕示面提供入口。
- 与 `stinson-signature-homomorphism-breaking` 的区别: 本 skill 是"每个接口=谕示预算发放点"的收敛总框架；那个 skill 给出签名类谕示"先选 s 再定 x"的具体攻击语法——签名 API 审计中两者叠加。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **清点全部能力接口**: 任何"输入密码相关值→返回密码计算结果"的端点（解密、验签回执、开根、求逆、脱敏、调试），含错误/时序侧通道。
   - 完成标准: 接口清单逐条列出（名称、输入域、输出、调用方、鉴权方式）。
2. **对每个接口标注发放的谕示类型**: 解密谕示/签名谕示/平方根谕示/区分谕示（错误回执类）。
   - 完成标准: 每接口一行"发放 X 谕示，对应攻击模型档位 Y"。
3. **做组合攻击推演**: 攻击者能否自选输入？能否跨接口组合？（重点：自选 r² 型输入、可验证格式的任意提交。）
   - 完成标准: 每个可自选输入的接口附一条组合攻击路径或"不可构造"的理由。
   - 判停条件: 若发现对私钥结构（Rabin/RSA 类）开放的自选输入谕示，直接输出"等价于私钥泄露"结论并跳到步骤 5。
4. **应用收敛三手段**: 限型（输入格式+用途绑定标签）、默认关闭、白名单密钥用途；端点封锁（白化式：外层先注入会话秘密）。
   - 完成标准: 每个接口标注采用的手段；无法收敛的接口标注"必须关闭"。
5. **输出谕示预算审批表**: 接口×谕示类型×收敛手段×残余风险。
   - 完成标准: 表可直接并入威胁建模文档；每行有明确的开放/关闭决定。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 纯业务 API 的鉴权/授权设计（RBAC、OAuth）——那是访问控制；谕示面审计的前提是鉴权已做但密码计算能力本身有组合风险。
- 接口只做公开计算（哈希、验签）且无私钥参与——无谕示可发放。
- 性能/限流治理——限流减缓谕示消耗速率但不消除组合风险，不能作为本框架的替代。

### 作者在书中警告的失败模式

- 平方根谕示=分解谕示（第 5 章 5.8.1、第 12 章 12.5.3）——"帮用户算个根"的服务性接口可拼成分解器。
- 裸提供解密能力：Rabin 的选择密文一查询即破；选择密文模型下的"平凡"仅在目标是单条密文时成立，目标是密钥时立即非平凡（第 1 章 1.2 脚注）。
- 接口不校验输入形状：Cocks TA 若接受任意二次剩余，即重复 5.8.1 事故。

### 作者的盲点 / 时代局限

- 成书 2006 年：padding oracle、时序侧信道作为工程谕示面未展开（书中 CCA 停留在理论谕示形态）；现代审计应把"可区分的错误回执/响应时间差"补入步骤 1 的清单。
- 未覆盖 API 网关/微服务架构下谕示跨服务组合的现实路径。

### 容易混淆的邻近方法论

- 谕示面收敛 ≠ 接口鉴权：鉴权回答"谁能调"，谕示面回答"调了之后能拼出什么"——通过鉴权的合法调用同样可能构成组合攻击。
- 与最小权限原则的区别：最小权限管权限粒度；本 skill 管输入域与计算能力的密码学组合性，两者的检查表不同。
