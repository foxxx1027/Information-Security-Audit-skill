# 完美保密的形式化——观察不改变分布 + 代价下界与充要条件

## R — 原文 (Reading)

> 定义2.3一个密码体制具有完善保密性，如果对于任意的xeP和yeC，都有Pr[x|j]=Pr[x]。也就是说，给定密文y，明文x的后验概率等于明文x的先验概率。
>
> — 原作者,原始方法论来源第2章 2.3 定义2.3（中译本 OCR，逐字保留，Pr[x|j] 应为 Pr[x|y]）

---

## I — 方法论骨架 (Interpretation)

"绝对安全"有一个精确的数学判据：看到密文之后，你对明文的信念必须和看到之前完全一样——观察零信息增益。这个定义的工程价值不在定义本身，而在它逼出的三条可检验结构条件。第一，规模下界：密钥空间不得小于明文空间（|K|≥|C|≥|P|），即想保护多少信息就得消耗多少密钥熵——"短密钥+聪明算法实现完美保密"被数学禁止。第二，充要结构：密钥必须均匀分布，且任一明文-密文对恰好被唯一密钥连接——一次一密是标准样本，任何"变体"若破坏均匀性或配对唯一性即自动出局。第三，使用前提：每钥只加密一条消息，复用瞬间崩溃（两条密文异或=两条明文异或）。审计任何"绝对安全"宣称的流程因此是机械的：查密钥随机源是否真均匀（QKD 原始输出还需隐私放大）、查是否严格一钥一次、查密钥供给速率是否覆盖业务流量——瓶颈永远在密钥速率与配送，不在密码学本身。

## A1 — 书中的应用 (Past Application)

### 案例 1: 定理 2.4 充要条件的证明与应用
- **问题**: 怎么判断一个体制是不是真的完善保密，而不是"看起来很像"？
- **方法论的使用**: 第 2 章 2.3 定理 2.4 给出充要刻画：密钥等概率 + 每个 (x,y) 对恰有唯一密钥连接；证明用 Bayes 分解与反例（密钥概率为 0 或不均时后验偏离先验）。
- **结论**: "完美"被拆成两条可独立检验的结构条件。
- **结果**: 任何自创"一次一密变体"（密钥有偏、复用配对）无需攻击实验即可由结构判定不达标。

### 案例 2: 完善秘密共享与完善保密同构
- **问题**: 秘密共享的"未授权子集零信息"如何严格化？
- **方法论的使用**: 第 13 章把"t−1 个份额对任意候选密钥都能构造相容多项式"对接到第 2 章的同一形式化——观察不改变分布。
- **结论**: 同一形式化跨对象复用；Shamir 方案在信息论意义上达到零信息。
- **结果**: "零信息"论证模板：对每个候选值构造与观察相容的解释，证明观察无法排除任何候选。

### 案例 3: 无条件安全 MAC 的下界与等号
- **问题**: 认证一侧能到信息论档吗？
- **方法论的使用**: 第 4 章 4.5 证明欺骗概率 Pd ≥ 1/M 的下界，并给出达界条件（强泛 Hash 族），例 4.1 中 Pd0=Pd1=1/3=1/|Y|。
- **结论**: 信息论安全是可量化区间：有下界、有可达构造。
- **结果**: "完美"不是修辞而是带数值的极值问题。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 审计 QKD+一次一密、量子密钥分发、专线加密机等宣称"信息论级/绝对安全"的方案。
2. 评估密钥管理体系的真实上限：密钥生成速率、配送信道、一次性使用纪律是否支撑宣称。
3. 设计需要"零泄漏"论证的方案（匿名投票、隐私保护查询），需要写"观察不改变分布"式的证明义务。
4. 敌方或红队声称"拿到密文也无任何信息"时，验证该说法成立的边界条件。

### 语言信号 (用户的话里出现这些就应激活)

- "一次一密 / one-time pad / OTP / 完美保密 perfect secrecy / 完善保密"
- "绝对安全 / 零信息泄漏 / 信息论安全 information-theoretic"
- "QKD / 量子密钥分发 + 一次一密，还需要审计什么"
- "密钥流重复了会怎样 / two-time pad"

### 与相邻 skill 的区分

- 与 `stinson-security-notion-calibration` 的区别: 那个管"三把尺子选哪把"；本 skill 是无条件档内部的审计流程（三查）。先由那个 skill 定档，再用本 skill 核验。
- 与 `stinson-nonce-reuse-failure-checklist` 的区别: 本 skill 从"完美的代价"角度看待一次性；那个 skill 是各种一次性值复用的事故清单（含签名 nonce、IV 等），覆盖面更广、判据是代数攻击而非分布论证。
- 与 `stinson-simulatability-zero-knowledge` 的区别: 两者都是"零信息"论证，本 skill 是非交互的分布判据（后验=先验），那个是交互场景的模拟器判据。
- 与 `stinson-pseudorandomness-criterion` 的区别: 本 skill 是无条件档的分布判据；那个是计算档的预测器判据——用 PRBG 替代真随机即从本 skill 的档位降级到那个 skill 的档位。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确认对象真的是无条件档声明**（"绝对/信息论/零信息"字样或等价含义）。
   - 完成标准: 摘出声明原文；若实际只是计算安全方案（AES、RSA），输出"口径不适用，改用计算档评估"并终止。
2. **查密钥均匀性**: 密钥从哪来（物理源/熵池/协商），分布是否均匀，QKD 类方案是否做了隐私放大。
   - 完成标准: 均匀性证据链（随机源、提取器）逐环列出，任一环缺失即标红。
3. **查一次性使用纪律**: 是否严格一钥一条消息；密钥流生成是否有计数器/状态回退风险（重启、VM 快照）。
   - 完成标准: 复用路径清单为空，或列出每条复用入口及后果（两条密文异或暴露明文异或）。
4. **查密钥供给速率**: 密钥生成速率 ≥ 业务流量？配送信道本身安全吗？
   - 完成标准: 给出速率对比数字；不覆盖的窗口标为"安全保证空窗期"。
   - 判停条件: 若步骤 2–4 任一条破坏，跳到步骤 5 输出降级结论，无需继续核验其余。
5. **输出结论**: "绝对安全"在何窗口、何条件下成立；瓶颈定位（速率/配送/纪律）；修正后的可审计声明。
   - 完成标准: 结论含成立的充要条件清单 + 至少一条最脆弱前提的失效推演。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 评估常规计算安全方案（AES-GCM、TLS、RSA）——它们不追求也不该用这把尺子，套用会得出"都不安全"的废结论。
- 签名/MAC 的伪造问题（结构上另属一类；MAC 的信息论审计另有欺骗概率框架）。
- 与敌手算力无关的隐私合规话题（数据脱敏、差分隐私是另一套"泄漏"语义）。

### 作者在书中警告的失败模式

- 密钥复用：K=x⊕y 一次已知明文即得密钥流，两密文异或暴露明文异或（第 2 章 2.3）。
- "工程上用短密钥流生成器替代真随机长密钥，就必然失去完善保密性"——伪随机替代真随机自动降档。
- 完善保密对已知明文攻击脆弱的表面悖论：安全声明绑定"每钥一次"前提，前提一破全盘崩溃。

### 作者的盲点 / 时代局限

- 成书 2006 年：QKD 工程化（设备侧信道、测量设备无关协议）未覆盖；书中的"绝对安全"论证止于数学层，工程实现降级路径需借现代侧信道文献补充。
- 无条件安全 MAC 部分只覆盖对称认证码，未涉及现代 AEAD 语境（书成于 AEAD 普及前）。

### 容易混淆的邻近方法论

- "完美保密"≠"很强": 前者是与算力无关的档位；计算安全方案可以比不达标的一次一密变体实际更安全。
- 与语义安全（不可区分性）区分：完美保密是信息论版的"观察零增益"；语义安全是计算版"多项式时间敌手无法区分"——前者是尺子不是后者的替代。
