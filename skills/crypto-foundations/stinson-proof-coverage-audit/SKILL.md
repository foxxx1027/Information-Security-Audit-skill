# 可证明安全的覆盖域审计——证明只保护声明过的格子

## R — 原文 (Reading)

> 然而，该体制对选择密文攻击是完全不安全的。事实上，算法5.12可以用来在选择密文攻击中攻破Rabin密码体制！
>
> 我们提出的证明并没有排除如下的可能性：可能找到能以75%准确率计算parity或者half的有效算法。
>
> — 原作者,原始方法论来源第5章 5.8.1、5.9.1（中译本 OCR，逐字保留）

---

## I — 方法论骨架 (Interpretation)

"有数学证明"不是安全性的同义词，而是一份覆盖域有限的保修单。归约证明的逻辑是：若敌手能攻破方案，则可用它解决某个公认难题——这只说明方案"不比难题更弱"，且仅在你声明的那个攻击场景内有效。审计一份证明要拆四条边界：一是敌手模型边界，证明里敌手能拿到什么（有无解密谕示、错误回执）；二是量化范围边界，证明排除了"完整解密"还是只排除了"压倒性优势"，半区归约只挡住约一半比特的优势算法，75% 准确率的单比特算法可能完全不在排除范围；三是证明模型边界，随机谕示模型（ROM）里的证明在换成具体 Hash 函数时链条即断；四是构造性边界，概率方法只证"存在好参数"，不给可部署的构造。给证明换任何一个组件（换个 Hash、换个群），原证明不自动继承——证据链由最弱一环决定。

## A1 — 书中的应用 (Past Application)

### 案例 1: Rabin 体制——归约完美但格子反转
- **问题**: Rabin 是全书唯一给出完整可证明安全叙述的体制（攻破 ⇔ 分解 n），是否就此安全？
- **方法论的使用**: 第 5 章 5.8.1 逐字检查证明的敌手模型：归约只对选择明文攻击成立。
- **结论**: 换到选择密文格子，自选 r² 查询一次解密谕示即分解 n——证明越强（等价归约），反噬越狠：解密谕示恰好就是分解器。
- **结果**: "可证明安全"四个字必须附带模型声明；同章 5.9.1 半区归约进一步显示量化范围也只到"一半比特"级优势。

### 案例 2: FDH/OAEP 类证明绑定随机谕示模型
- **问题**: 签名/加密方案在"理想 Hash"下有证明，换成 SHA-1 还算数吗？
- **方法论的使用**: 第 4 章 4.2.1 与第 7 章 7.5.2 把 ROM 标为独立证据层级：理想 Hash 是一本巨大的随机数书，现实 Hash 不是。
- **结论**: 证明绑定证明模型——实例化即断链；给方案换用更新的 Hash 反而可能使原 ROM 证明失效的路径更明确。
- **结果**: 审计结论写为"归约证明(ROM)→实例化即断链"，把 Hash 迁移预案列为证明链维护义务。

### 案例 3: 概率方法只证存在、不给构造
- **问题**: 覆盖自由族（CFF）的存在性证明能否直接指导部署？
- **方法论的使用**: 第 10 章 10.3 指出概率方法没有给出明确公式或有效确定性算法。
- **结论**: 证明覆盖的对象（随机存在的好族）与实现对象（具体参数）不是同一个。
- **结果**: 落地必须另给确定性构造与显式参数，存在性结论不能当部署依据。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 供应商/开源项目宣称"可证明安全"或"安全性归约到 DDH/格/LWE"，采购或选型评审需要核实。
2. 论文阅读中遇到 security proof/reduction theorem，需要判断其结论能外推到自己的部署场景吗。
3. 系统要把有证明的方案换个组件（换 Hash、换曲线、换群），需要判断原证明是否还有效。
4. 安全架构争论中一方拿"有数学证明"压倒另一方拿"20 年未被破"，需要给出裁决框架。

### 语言信号 (用户的话里出现这些就应激活)

- "可证明安全 / provable security / 有安全证明 / 归约到 XX 难题 / reduction to ..."
- "随机谕示模型 / random oracle model / ROM / 标准模型 standard model"
- "这个证明覆盖 CCA 吗 / 证明在什么假设下成立"
- "A 有证明 B 没证明，选哪个"

### 与相邻 skill 的区分

- 与 `stinson-evidence-tier-labeling` 的区别: 本 skill 拆单个证明的四条边界；那个 skill 把证明/实验/假设放进四级证据层级做整体决策。本 skill 是放大镜，那个是分层架。
- 与 `stinson-reduction-comparison` 的区别: 本 skill 审"证明覆盖到哪里"（读证明）；那个 skill 用黑盒转译比较"两个性质谁强谁弱"（写证明）。
- 与 `stinson-adversary-capability-goal-matrix` 的区别: 那个 skill 建模声明与威胁；本 skill 专门针对已有形式化证明的方案，拆证明文本本身——证明的敌手模型边界以那个 skill 的格子为坐标系。
- 与 `stinson-security-notion-calibration` 的区别: 先由那个 skill 决定"这次评估用哪一档口径"，本 skill 只在可证明档内部工作。
- 与 `stinson-provable-security-usability-cost` 的区别: 那个 skill 完全接受证明、只审输出形态（扩张/歧义/吞吐）；本 skill 审证明本身——证明再完美也过不了那个 skill 的可用性账。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定位证明原文或其精确表述**（论文定理、白皮书章节）。
   - 完成标准: 拿到定理的完整陈述句；若只有"可证明安全"四个字而无定理，直接输出"声明不可评估，要求提供证明陈述"并终止。
2. **拆敌手模型边界**: 证明中敌手是否有解密/签名谕示、能否并行会话、询问次数是否受限。
   - 完成标准: 写出"证明模型 = CPA/CCA/其他"，并与实际系统的暴露面（有无解密侧信道、错误回执）对照。
3. **拆量化范围边界**: 证明排除的是完整攻破、还是 epsilon 优势的区分、还是单比特部分信息。
   - 完成标准: 写出优势参数 epsilon 的含义与归约损失；标注"未排除的部分信息算法"类别。
4. **拆证明模型边界**: 标准模型还是 ROM/理想密码模型；实例化用哪个具体组件。
   - 完成标准: 声明改写为"在 [模型] 下对 [敌手] 抗 [目标]，优势界 [ε]"；换组件的影响单独列出。
   - 判停条件: 若步骤 2–4 任一边界与实际部署场景不匹配（如证明是 CPA 而系统暴露解密接口），跳到步骤 5 直接输出"保证不适用"结论。
5. **输出边界清单与决策**: 四条边界各一行 + 最弱一环 + 组件变更的证明链维护义务。
   - 完成标准: 清单可直接写进评审意见；给出"接受/要求补充/拒绝"三选一建议。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 方案完全没有形式化证明（纯启发式设计）——没有证明就没有覆盖域可拆，改用证据分层评估。
- 非密码学的形式化验证（模型检验、定理证明器验证协议逻辑）——那是另一套"证明"语义。
- 对方只是问"XX 算法本身安不安全"的科普问题，不涉及具体证明文本。

### 作者在书中警告的失败模式

- 可证明安全明言"只是与难题挂钩、非完全证明"，类比 NP 完全表述（第 2 章 2.1）——把归约当绝对保证是第一误读。
- ROM 证明在具体 Hash 上的失效（第 4、7 章）；解密谕示把 Rabin 归约反噬成分解器（第 5 章 5.8.1）。
- Blum-Goldwasser 对固定模长"还不知道是否安全"——作者自己示范了未定层级的公开承认。

### 作者的盲点 / 时代局限

- 成书 2006 年：无 tight reduction（紧归约损失）的系统性讨论，归约损失在书中常只作定性处理；标准模型下实用方案的证明进展（如后续的 lossy reduction 技术）不在射程内。
- 后量子假设、侧信道模型下的证明（leakage-resilient）完全未覆盖。

### 容易混淆的邻近方法论

- "证明覆盖域审计"≠"证据分层"：前者拆一个证明的边界，后者跨多个证据类型排层级。
- ≠ 形式化验证（model checking）：密码学归约证明针对计算敌手，不是对协议状态空间穷举。
