# 伪随机性判据——统计测试只是必要条件，种子即密钥

## R — 原文 (Reading)

> 通过上面提及的各项测试只是获得密码学意义下安全的必要条件，而不是充分条件。密码学意义下的安全依赖于多项式时间可预测性等概念，这些将在8.2.1节介绍。
>
> 这样，种子就好比是一个密钥，而PRBG可以看做一个流密码的密钥流生成器（当然，在用一个PRBG来代替一次一密体制时，也同时失去了完善保密性）。
>
> — 原作者,原始方法论来源第8章 8.1、8.2.1（中译本 OCR，逐字保留）

---

## I — 方法论骨架 (Interpretation)

"输出看起来随机"和"输出不可预测"是两个天差地别的性质，前者挡不住任何真攻击者。判定逻辑分三层。第一层，统计测试（频率、游程、扑克）只是必要条件：能排除低级偏差，排除不了"通过所有固定测试但由可预测规则生成"的序列——你可以构造一个过全绿却可预测的发生器。第二层，真正的判据是不可预测/不可区分：不存在多项式时间的下一比特预测器，等价于（Yao 定理双向归约）任何多项式时间区分器无法把输出和真随机分辨开——注意一阶均匀（0/1 各半）远远不够，位间相关就足以被区分（s_{i+1}=s_i 类序列一阶完美、二阶全漏）。第三层，种子即密钥：PRBG 把 k 比特种子扩展成任意长输出，全部熵来自种子——种子可猜测则整条输出可重放（128-bit 种子能再生成整条密钥流时，一切安全压缩为种子管理）；工程上种子的熵源、生成时机、存储与派生链是审计重心，时间戳/进程号/低熵口令直接当种子等于没有种子。验收结论的形态转变：从"测试报告全绿"改为"预测器不存在（归约论证）+ 种子链路可审计"。

## A1 — 书中的应用 (Past Application)

### 案例 1: LFSR——周期 2^m−1、测试近似全过、仍被线性破解
- **问题**: 周期极长、统计性质好、硬件省的 LFSR 密钥流能用吗？
- **方法论的使用**: 第 1 章 1.1.7+1.2.5：本原多项式反馈使周期达 2^m−1、输出近似均衡；但 2m 比特已知密钥流给出 m 元线性方程组，一次解出初态。
- **结论**: 周期长/看起来随机都不构成安全判据；"全运算线性"才是致命结构。
- **结果**: 第 8 章的形式化判据（不可预测）由此案例反推建立——判据必须排除"结构可预测"而非"分布不均"。

### 案例 2: 例 8.3——一阶均匀仍可区分
- **问题**: 0/1 等概率产生，够随机了吗？
- **方法论的使用**: 第 8 章 8.2 例 8.3：构造每位等概但相邻位强相关的序列，区分器检查相邻位相关性即高概率判定非随机。
- **结论**: 一阶矩合格、高阶结构与长程相关仍泄露；判据必须是对任意多项式时间区分器的优势可忽略。
- **结果**: "统计测试通过"与"不可区分"的落差有了最小反例。

### 案例 3: 种子即密钥的归位
- **问题**: PRBG 算法有证明（如 BBS 归约到二次剩余判定），部署还需查什么？
- **方法论的使用**: 第 8 章 8.2.1：种子好比密钥，PRBG 是流密码的密钥流生成器；种子短或可猜测时敌手穷举种子即还原全部输出。
- **结论**: 算法安全≠系统安全——全部安全压缩为种子熵与种子管理；用 PRBG 替代一次一密同时失去完善保密性（降为计算安全）。
- **结果**: 验收清单落到种子链路：熵源、长度、生成时机、存储、派生。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 验收密钥生成器/随机数服务："随机性检测套件全绿"能否放行。
2. 审计 CSPRNG 种子链路：熵源质量、状态持久化、重启/快照后的可预测窗口。
3. 评审自研"混合多个弱随机源"的方案，判断输出是否达到密码学随机。
4. 事故调查：生成的密钥/nonce 出现碰撞或被预测，定位是分布问题还是种子链路问题。

### 语言信号 (用户的话里出现这些就应激活)

- "随机性测试全过 / statistical tests pass，能验收吗"
- "next-bit test / 下一比特预测 / distinguisher 区分器"
- "seed entropy / 种子熵够吗 / 种子怎么来的"
- "CSPRNG 验收 / /dev/urandom 够不够 / 熵池"

### 与相邻 skill 的区分

- 与 `stinson-perfect-secrecy-formalization` 的区别: 那个是无条件档的分布判据；本 skill 是计算档的预测器判据——用 PRBG 替代真随机即从前者降级到后者（书中原句）。
- 与 `stinson-nonce-reuse-failure-checklist` 的区别: 那个管"一次性值被用了两次"的确定性崩溃；本 skill 管"输出可预测/种子可猜测"的质量问题——即使从不复用，可预测的输出照样失陷。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **定位随机性在系统中的用途**: 密钥生成、nonce、会话令牌、IV——标注每处对可预测性的敏感度。
   - 完成标准: 用途清单 + 每处"输出被预测的后果"一行。
2. **审计种子链路**: 熵源（物理/系统熵池）、种子长度、生成时机、状态持久化与恢复（重启/快照）、派生方式。
   - 完成标准: 链路图 + 每环"熵贡献/风险"标注；低熵源直接当种子项标红。
   - 判停条件: 若发现时间戳/设备 ID/低熵口令直接播种高敏感用途，输出"可预测密钥流"结论跳到步骤 4。
3. **区分"测试通过"与"判据满足"**: 明确统计测试全绿只是筛查；核对该生成器有无不可预测性论证（标准 CSPRNG 的公开设计 vs 自研无论证）。
   - 完成标准: 判据状态三选一（标准算法+正确播种/自研有归约/自研无论证=不可验收）。
4. **核查状态可复现面**: 能否由种子重放整条输出；128-bit 种子再生成全部密钥流时，安全压缩为种子管理（与输出检测无关）。
   - 完成标准: 复现路径清单 + 种子保护等级要求。
5. **输出验收结论**: 验收对象改为"预测器不存在 + 种子链路可审计"；统计测试降级为健康筛查。
   - 完成标准: 结论含验收三查（种子熵源/状态复现/预测面）逐项判定。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 统计模拟、蒙特卡洛、游戏抽卡类非对抗随机——分布质量够用即可，预测器判据是过度要求。
- 具体 PRNG 算法的实现 bug 排查（状态溢出、弱初始化向量）——属实现审计；本 skill 管判据与种子链路层。
- 真随机源（硬件熵池）本身的物理认证——那是另一套计量工作。

### 作者在书中警告的失败模式

- 测试全绿≠安全：必要条件当充分条件用（第 8 章 8.1）。
- 一阶均匀≠不可区分：位间相关即可区分（例 8.3）。
- 种子即密钥被忽略：种子管理失败把计算安全降为可穷举（8.2.1）。
- 前置教训：LFSR 的长周期与好统计都救不了线性结构（第 1 章）。

### 作者的盲点 / 时代局限

- 成书 2006 年：现代操作系统熵池（getrandom、加固后的 /dev/random）、Intel RDRAND 的信任争议未覆盖；本 skill 的种子链路审计应补充"多源混合与启动早期熵饥饿"的现代问题。
- Yao 定理之外的计算不可区分性在书中只做比特序列版，未展开函数族（PRF）语境。

### 容易混淆的邻近方法论

- 不可预测 ≠ 分布均匀：前者是对抗性判据（无预测器存在），后者是统计性质——评审中两者都要，但安全声明只认前者。
- 与熵估算的区别：熵估算评"源头有多少不确定"，本 skill 评"展开后敌手能否预测"——种子熵是输入条件，预测器不存在是输出判据，中间靠算法连接。
