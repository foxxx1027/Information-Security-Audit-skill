# 公钥参数卫生与泄露处置检查清单

## R — 原文 (Reading)

> 注意到这一点并仅仅是理论兴趣。它告诉我们如果α被泄露（由于意外或其他原因），那么Bob重新选择一个加密指数是不够的，他必须选择一个新的模数n。
>
> p应该至少取300个十进制位，p-1应该具有至少一个较"大"的素数因子。
>
> — 原作者,原始方法论来源第5章 5.7.1、第6章 6.1（中译本 OCR，逐字保留，"注意到这一点并仅仅是"为 OCR 脱字）

## I — 方法论骨架 (Interpretation)

公钥密码的强度不由位数单独决定，而由"针对参数结构的专用攻击"决定——同一长度的模数，因子挨得近就被 Fermat 试探快速分解；同一长度的群，阶光滑就被 Pohlig-Hellman 分治拆碎。参数卫生因此是一份反攻击清单：RSA 侧查 p、q 距离（过近→Fermat）、解密指数大小（过小→Wiener 连分数恢复私钥）、模数独占性（共模→任一用户可分解 n 读所有人私钥）、加密指数与广播（e=3 无填充群发→CRT 拼回明文）；DL/ECC 侧查群阶因子分解（光滑阶→分治）、曲线类型（超奇异→MOV 归约到有限域 DLP；迹一→直接易解）、基点阶与余因子、生成种子可复现（防陷门）。泄露处置是清单的另一半且最反直觉：已知解密指数 d 可用 Las Vegas 算法分解 n——所以 d 泄露不是"换把钥匙"而是"模数级失陷"，必须换 n 而非换 e，历史密文与同模/同源派生密钥一并作废。验收密钥生成器的动作：把上述结构攻击逐条对生成器输出跑一遍。

## A1 — 书中的应用 (Past Application)

### 案例 1: Wiener 攻击——为提速 75% 打开私钥大门
- **问题**: 选小解密指数 d 把解密时间降 75%，这笔交易划算吗？
- **方法论的使用**: 第 5 章 5.7.3：d 小于 n^{1/4} 且 p、q 相近时，未知的 t/a 必是公开 b/n 的连分数收敛子；枚举收敛子逐个代入二次方程试分解，例 5.17 中 n=160523347 由收敛子 14/37 分解为 12347×13001。
- **结论**: 参数级"优化"直接对应多项式时间攻击；正确提速靠 CRT 分模（结构性），不靠缩 d。
- **结果**: 参数卫生条款确立：d 下界 + p、q 距离上界同查。

### 案例 2: 共模失败——一个 n 配多把钥匙的连锁失陷
- **问题**: 全组织共用一个 n、各用户不同指数，密钥不是独立的吗？
- **方法论的使用**: 第 5 章习题 5.16：任一用户用自己的 d 即可分解 n（5.7.2 的 Las Vegas 算法），进而读出所有其他用户的私钥。
- **结论**: 模数跨信任域共享使"多把密钥"退化为"可互相推导的方程组"；参数大小不能补救共享结构。
- **结果**: 审计动作：扫公钥目录查相同 n 对应多用户，命中即判高危。

### 案例 3: 泄露处置——换指数不够，必须换模数
- **问题**: d 意外泄露后，换个新加密指数沿用 n 行不行？
- **方法论的使用**: 第 5 章 5.7.1 算法 5.10：随机取 w 反复平方找 1 的非平凡平方根 v，gcd(v±1,n) 出因子，成功率 ≥1/2——已知 d 者可分解 n。
- **结论**: d 泄露=模数失陷；只换 e 则新私钥同样暴露，旧 n 下历史密文全部可解。
- **结果**: 事件响应条款：任何私钥分量泄露按模数/曲线级处置——重生成 n、吊销旧公钥、作废历史密文与同源派生密钥。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 验收 CA/密管的自定义 ECC 曲线或 RSA 密钥生成器，列出检查项。
2. 私钥泄露事件响应：判定失陷半径（这把钥？整个模数？全部历史数据？）与处置动作。
3. 审计多用户/多环境密钥配置：是否存在共模、同源派生、低指数群发组合。
4. 评审"性能优化"提议：小 d、复用模数、共享参数，逐项对照结构攻击。

### 语言信号 (用户的话里出现这些就应激活)

- "Wiener attack / 小解密指数 / d 太短有什么风险"
- "common modulus / 两个部门共用一个 RSA 模数"
- "Pohlig-Hellman / p-1 光滑 / 超奇异曲线 / MOV"
- "私钥泄露了，换个证书/换 e 就行吗"
- "safe prime / 安全素数为什么要"

### 与相邻 skill 的区分

- 与 `stinson-keysize-not-security` 的区别: 那个是"参数线 vs 结构线"的总框架（以古典密码为例）；本 skill 是公钥参数（RSA/DL/ECC）的具体结构检查表——总框架在此对象上的实例化。
- 与 `stinson-key-lifetime-rolling` 的区别: 那个管参数随时间/算力进展的寿命预算与滚动策略；本 skill 管单次生成时的结构卫生与泄露处置——一个是时间维，一个是结构维。
- 与 `stinson-collusion-threshold-verification` 的区别: 那个管多份额系统的合谋边界；本 skill 管单密钥参数独立性——份额同源塌缩是两者交叠点。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **采集参数事实**: RSA 的 n 位长、p/q 距离、d 大小、模数使用范围；ECC 的曲线方程、群阶及其因子分解、余因子、基点阶、生成种子。
   - 完成标准: 参数事实表填齐；无法取得的项标"不可审计"。
2. **RSA 侧逐项核对**: Fermat 距离检查、d>n^{1/4}、模数独占（目录扫描重复 n）、e=3 类广播+无填充组合、CRT 提速而非缩 d。
   - 完成标准: 每项攻击标注"可排除/命中/未检查"。
3. **DL/ECC 侧逐项核对**: 群阶大素因子（防 Pohlig-Hellman）、排除超奇异/迹一曲线、子群阶与余因子校验、种子可复现验证。
   - 完成标准: 同上三态标注；命中项附攻击名称与代价估算。
   - 判停条件: 若发现共模或已知 d 泄露，直接输出"模数级失陷"结论跳到步骤 4 处置段。
4. **核对泄露处置预案**: 事件分级（单钥/模数/曲线/主密钥）、处置动作（换 n、作废历史密文、同源派生清理）、旧钥不可推出新钥要求。
   - 完成标准: 处置矩阵（泄露物×动作×波及范围）输出。
5. **输出验收/审计结论**: 检查表逐项结果 + 未过项的修复（重新生成参数的规范路径）。
   - 完成标准: 结论含"参数强度=位数 AND 结构卫生"的判定句。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 协议逻辑缺陷（顺序、覆盖域、重放）——参数卫生假定协议正确。
- 对称密钥管理（生成/存储/轮换）——无公钥参数结构可查。
- 具体分解/求对数算法的数学推导本身——本 skill 消费结论做检查表。

### 作者在书中警告的失败模式

- "应该避免采用这种办法来降低解密时间"——小 d 与 Wiener 攻击（第 5 章 5.7.3）。
- "应注意确保q-p不是太小"——因子过近与 Fermat 分解（习题 5.29）。
- 共模失败（习题 5.16）与低指数广播（习题 5.17）——结构性失败，参数再大不救。
- 迹一曲线"这些曲线上的离散对数问题是易解的"（第 6 章 6.5.3）。

### 作者的盲点 / 时代局限

- 成书 2006 年：未覆盖 ROCA（Infineon RSA 生成器缺陷）类"生成器实现缺陷"与后门化参数（Dual_EC_DRBG 型）的现代检查；种子可复现验证（ANSI X9.31/SEC 2 的 verify procedure）在书中只有思想。
- 侧信道防护（恒定时间、blinding）不在参数清单内，现代密管验收应并行补审。

### 容易混淆的邻近方法论

- 参数卫生 ≠ 密钥长度选型：长度对齐的是通用攻击（穷举/数域筛），卫生挡的是结构攻击——两者都过才算合格。
- 与密钥寿命管理的区分：本 skill 假定当前参数已生成，检查其结构；寿命管理决定"何时该换更大/别的参数"。
