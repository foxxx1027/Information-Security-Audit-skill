# 三种安全度量口径——计算 / 可证明 / 无条件不可混用

## R — 原文 (Reading)

> 无条件安全性（unconditionalsecurity）这种度量考虑的是对攻击者Oscar的计算量没有限制时的密码体制的安全性。即使提供了无限的计算资源，也是无法被攻破的，我们定义这种密码体制是无条件安全的。
>
> — 原作者,原始方法论来源第2章 2.1（中译本 OCR，逐字保留）

---

## I — 方法论骨架 (Interpretation)

"安全"有三把不同刻度的尺子，混用它们是营销和评审事故的共同源头。第一把是计算安全：破译需要至少 N 次操作——但书中直言没有已知实际体制能在这个朴素定义下被证明安全，它只是直觉。第二把是可证明安全：把破译归约到公认难题——它只保证"不比难题更弱"，难题本身未被证明难。第三把是无条件安全：即使敌手算力无限也攻不破——这是唯一"绝对"的档位，但代价极贵（密钥熵不小于明文熵）且有结构性禁区：签名方案的验证算法是公开的，任何人可穷举签名空间，因此签名在原理上不可能无条件安全，只能落计算档。工程含义：每个安全声明先问用哪把尺子量的；宣称"信息论级安全"的产品，要么在偷换对象（密钥隔离存储的性质），要么在混用口径。同一本书里秘密共享用无条件尺、RSA 用可证明尺——不同对象配不同尺子是学科常态，但声明必须写明。

## A1 — 书中的应用 (Past Application)

### 案例 1: 签名被证明不可能无条件安全
- **问题**: 能否设计一个对无限算力也安全的签名方案？
- **方法论的使用**: 第 7 章 7.1 用口径判定：验证算法 ver_k 公开，Oscar 可对给定消息穷举整个签名空间直到命中。
- **结论**: 签名结构上排除无条件档，只能追求计算/可证明档。
- **结果**: 安全声明的档位由对象结构决定，不是由设计者愿望决定——评估签名方案时不该再问"能否信息论安全"。

### 案例 2: 无条件安全 MAC 的欺骗概率下界
- **问题**: 认证码在信息论口径下能做到多强？
- **方法论的使用**: 第 4 章 4.5 把无条件安全量化为欺骗概率 Pd ≥ 1/M 的信息论下界，并刻画等号条件（强泛 Hash 族）。
- **结论**: 口径可量化：例 4.1 的认证矩阵方案 Pd0=Pd1=1/3 恰达 1/|Y| 下界。
- **结果**: 无条件档不是口号，是有数值下界和可达构造的精确区间。

### 案例 3: 秘密共享取无条件口径
- **问题**: 门限方案的安全性按哪把尺子声明？
- **方法论的使用**: 第 13 章 13.1 对 Shamir 方案验证"t−1 个份额零信息"——信息论意义，与算力无关。
- **结论**: 同一本书里不同对象用不同尺子：加密可计算、MAC 可无条件、签名必计算、秘密共享天然无条件。
- **结果**: 混用口径的评价（如拿计算假设批评门限方案）是范畴错误。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 密钥管理/加密产品宣传"信息论级安全""量子安全""绝对不可破"，需要核实宣传口径是否成立。
2. 安全评审中要比较两个方案的安全声明强度（一个说计算安全、一个说可证明安全）。
3. 设计新方案时需要判断目标安全档位是否结构上可达（如"能不能做信息论安全的签名"）。
4. 写安全声明文档/合规材料时，需要给每个 claim 标注正确的度量口径。

### 语言信号 (用户的话里出现这些就应激活)

- "信息论级安全 / information-theoretic security / 绝对安全 / 理论上不可破"
- "无条件安全 unconditional security vs 计算安全 computational security"
- "可证明安全是什么意思 / provable security 到底证明了什么"
- "这个方案是哪种安全 / 量子计算机能不能破"

### 与相邻 skill 的区分

- 与 `stinson-adversary-capability-goal-matrix` 的区别: 那个拆敌手能力×目标；本 skill 管度量口径——"对多强的敌手"之外还有"按什么标准算破"。先定格子再选尺子。
- 与 `stinson-proof-coverage-audit` 的区别: 那个拆可证明档内部的证明边界；本 skill 先决定"这次评估该用哪一档口径"。
- 与 `stinson-perfect-secrecy-formalization` 的区别: 本 skill 管三把尺子的选择与混用判定；那个 skill 深入无条件档的形式化定义与代价下界。本 skill 是选尺，那个是用尺。
- 与 `stinson-feasibility-ceiling-first` 的区别: 本 skill 选尺在前；那个 skill 用选定的尺子（尤其信息论档）算资源天花板——算界在后。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **摘出待审声明的安全措辞**，识别它隐含的口径档位（"绝对/不可破"→无条件档嫌疑；"归约/难题"→可证明档；"需要 2^n 次运算"→计算档）。
   - 完成标准: 每个安全词标注其暗示的档位。
2. **检查对象结构是否允许该档位**: 验证算法公开的方案（签名、公钥加密）结构上排除无条件档；短密钥方案排除无条件档。
   - 完成标准: 输出"该对象可达档位 = {…}"，并给出结构理由（如穷举签名空间论证）。
   - 判停条件: 若声明档位 > 可达档位，直接输出"口径不成立的判定 + 正确档位指认"，跳到步骤 5。
3. **核对无条件档的代价条件**: 密钥熵 ≥ 明文熵、每钥一次、秘密与随机源独立（对应完美保密下界）。
   - 完成标准: 每个代价条件标注满足/不满足/偷换对象。
4. **按口径分别重写声明**: 把单一"安全"改写成三档各自成立与否的表格。
   - 完成标准: 声明表三档齐全，每档附证据或"不适用"理由。
5. **输出结论与风险定级**: 指认宣传真实档位，标注混用之处。
   - 完成标准: 结论含"真实档位 + 混用点 + 修正后的声明句"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 讨论具体算法实现细节（填充、库选型、性能），不涉及安全声明口径时。
- 纯密码学数学推导问题（熵计算、证明细节），那属于具体档位内部的工作。
- 通用信息安全合规话题（等保、ISO27001），其"安全"语义与这三把尺子不同层。

### 作者在书中警告的失败模式

- 把可证明安全当完全证明——书中明言它只是"与难题挂钩"，类比 NP 完全表述（第 2 章 2.1）。
- 把加密的无条件直觉搬到签名上——公开验证使穷举总能成功（第 7 章 7.1）。
- "绝对安全"话术：一次一密的安全依赖等长密钥+严格一次，任一条件破坏立即降级（第 2 章 2.3）。

### 作者的盲点 / 时代局限

- 成书 2006 年："后量子安全"作为第四类口径（针对量子敌手的计算安全）未出现；今天遇到"量子安全"宣传需自行映射为"对量子敌手的计算/可证明档"。
- 书中计算安全档基本只作铺垫，未展开现代具体安全（concrete security）的参数化表述。

### 容易混淆的邻近方法论

- 口径选择 ≠ 敌手建模：前者回答"按什么标准算被攻破"，后者回答"敌手能做什么"；两者正交。
- "信息论安全"≠"很高强度的计算安全"：前者与算力无关，后者只是参数大——宣传中最常见的偷换。
