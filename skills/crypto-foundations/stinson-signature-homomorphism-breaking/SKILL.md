# 签名的代数同态必须被 Hash/编码破坏

## R — 原文 (Reading)

> 对RSA签名方案的另一种攻击是基于它的乘法特性。假设y=sigk(x）和y2=sigk(x2）是任意两个由Alice以前签名的消息，那么
>
> 然而而，通过同时选择，和x，存在一种方法使Oscar能对任意的消息签名
>
> — 原作者,原始方法论来源第7章 7.1、7.3（中译本 OCR，逐字保留，第二句"然而而"及"，和x，"为 OCR 噪声）

---

## I — 方法论骨架 (Interpretation)

签名体制的数学运算如果对消息有好的代数性质（可乘、可加、可自由选参数配平），这个性质就是伪造者的工具箱。裸 RSA 签名 sig(x)=x^d 完全乘性：两个旧签名相乘即是新消息乘积的合法签名，攻击者全程无需私钥、无需签名者参与；唯密钥档甚至更便宜——任选 y，令 x=y^e，(x,y) 自动有效。ElGamal 不 Hash 时另一条路：验证方程允许攻击者先选辅助随机数再反解出"消息"，自由参数成为配平方程的杠杆。两条路的共同解药是把消息先送进一个把代数结构打碎的编码——抗碰撞 Hash（可选加随机化填充如 PSS、域分离标签）——使"可乘的消息"不再对应"可乘的摘要"、"自由选择的参数"不再能配平验证式。工程推论：任何"对任意 32 字节输入做私钥运算"的服务（授权服务器、类盲签名 API）都在重新开放这条路——攻击者先选 s 再令 x=s^e 请求运算即得对 x 的零成本伪造；"签的是摘要"不等于"签的是消息"，编码域绑定（Hash+域标签）是签名服务的一部分，不是可选优化。

## A1 — 书中的应用 (Past Application)

### 案例 1: RSA 签名的乘法伪造（三档攻击者通杀）
- **问题**: 裸 RSA 签名在什么攻击者面前弱？
- **方法论的使用**: 第 7 章 7.1-7.2：唯密钥档任选 y 令 x=y^e 得存在性伪造；已知消息档 y1·y2=sig(x1x2)；选择消息档把目标 x 分解成 x1x2 请签后相乘（选择性伪造）。
- **结论**: 同态性使"已有签名可组合出新签名"，三档能力下均有伪造路径。
- **结果**: 安全定义必须落到"抗存在性伪造"；对策 Hash-and-Sign 破坏可乘结构。

### 案例 2: ElGamal 不 Hash——"同时选 x 与 k"的存在性伪造
- **问题**: 离散对数难解是否已保证 ElGamal 签名不可伪造？
- **方法论的使用**: 第 7 章 7.3：攻击者先任选 e、v，令 γ=α^e·β^v、δ=−γ·v^{-1}，则消息 x=γ·e·v^{-1} 满足验证式——消息内容由攻击者反推出来。
- **结论**: 可自由选择的结构就是伪造入口；唯密钥档即可行（假定未用 Hash）。
- **结果**: 签名前必须 Hash，把消息映射到不可控摘要，使配平方程的构造失效；DSA/Schnorr 的标准化均内置该处理。

### 案例 3: Hash 三性质与三类伪造的对应
- **问题**: "Hash 一下再签"里的 Hash 要满足什么？
- **方法论的使用**: 第 4 章 4.2 与第 7 章 7.2 对应：选择消息攻击者先造碰撞 (x,x') 请签 x、再以签名用于 x'——该路径当且仅当 h 碰撞稳固时被堵住。
- **结论**: 编码层的性质选择直接决定签名方案的伪造等级；Hash 不是格式转换，是证明链的一环。
- **结果**: "先 Hash 再签"从工程习惯升格为带理由链的设计规则（背后是三性质-三伪造对应）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 评审授权/凭证服务器提供"对任意摘要做 RSA 私钥运算"的 API（类盲签名、代签服务）。
2. 审计发现代码直接对整数/原始消息做签名运算（无 Hash 或 Hash 覆盖不全）。
3. 有人问"为什么必须先 Hash 再签/直接签不行吗，消息又不长"。
4. 设计可组合签名服务（批量签名、代理签名）时评估组合攻击面。

### 语言信号 (用户的话里出现这些就应激活)

- "multiplicative forgery / 两个签名相乘 / 签名能拼出来吗"
- "existential forgery / 存在性伪造是什么等级的破"
- "盲签名 API / 对任意摘要做私钥运算的服务"
- "Hash-and-sign 为什么必须 / 直接签消息会怎样 / PSS 干嘛用的"

- 与 `stinson-partial-leakage-amplification` 的区别: 那个是加密侧的"密文谓词×同态放大"；本 skill 是签名侧的"同态组合伪造"——同一同态性质，攻的是不同目标。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **写出签名的代数形态**: 签名函数对消息的运算、已验证的同态关系（可乘/可加/可交换）、消息进入运算前的编码（裸消息/Hash/带填充）。
   - 完成标准: 形态三元组（运算、同态关系、编码层）写明；编码层缺失即标红。
2. **推演组合伪造路径**: 唯密钥档（选 y 反推 x）、已知消息档（旧签名相乘）、选择消息档（目标分解请签）三档逐一尝试。
   - 完成标准: 每档给出可构造/被阻断的判定与一行推导。
   - 判停条件: 若编码层缺失且同态关系成立，直接输出"存在性/选择性伪造成立"结论跳到步骤 4。
3. **核对编码域绑定**: Hash 是否抗碰撞并覆盖完整消息；有无域分离标签（用途/上下文）；随机化填充（PSS 类）是否按规范。
   - 完成标准: 编码层三要素（覆盖完整性、域分离、填充规范）逐项判定。
4. **对"私钥运算 API"专项检查**: 输入是否限型（只能签协议格式的摘要）、输出能否被上层重组为合法凭据。
   - 完成标准: 给出"先选 s 再定 x"式攻击的可行性判定与限型建议。
5. **输出结论与修复**: Hash-and-sign+域分离标签为最低配置；遗留可组合面逐一列出。
   - 完成标准: 结论含"签的是摘要≠签的是消息"的边界指认与编码域绑定清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 加密（非签名）场景的同态性质讨论——同态加密是有意设计，用途相反。
- 已标准化且强制编码的方案（ECDSA/RSA-PSS 的规范实现）内部实现细节——编码已破坏同态，审计点在实现是否符合规范。
- 签名性能与密钥长度选型——那是参数寿命问题。

### 作者在书中警告的失败模式

- 裸 RSA 签名的三档乘法伪造（第 7 章 7.1-7.2）；ElGamal 未 Hash 时"同时选 x 与 k"的任意消息伪造（7.3）。
- 把"哈希一下再签"当格式习惯而不声明 Hash 性质——碰撞不稳固时"先造碰撞再求签"路径重开（7.2）。
- Hash 只覆盖部分消息/无域分离——扩展与拼接攻击面残留（principle 层警告）。

### 作者的盲点 / 时代局限

- 成书 2006 年：随机化签名（PSS 及其安全证明细节）、RSA 同态在区块链脚本（延展性攻击）中的应用形态未覆盖；现代评审应把"签名可延展性"（同一消息多个有效签名）补入检查表——书中的三档伪造未细分此形态。
- 盲签名协议本身（Chaum 系）未展开，只有"类盲签名 API"的风险可由书内推理覆盖。

### 容易混淆的邻近方法论

- 同态组合伪造 ≠ 密钥恢复：前者利用结构拼新签名，私钥始终未泄露——所以"私钥在 HSM 里"不能作为反驳。
- 与重放攻击的区别：重放复用旧 (消息,签名) 原对；同态伪造产出新消息的有效签名——修复手段分别是新鲜性绑定与编码域绑定。
