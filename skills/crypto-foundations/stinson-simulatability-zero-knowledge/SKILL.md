# 可模拟性——"零信息"的证明方法是构造同分布假本

## R — 原文 (Reading)

> 也就是说，存在一个多项式α(x)，B所收集到的t-1个共享正好是此多项式的t-1个函数值，并且以y作为密钥值。由于上面的推理对于任意的yeZ，都成立，所以不能排除任何密钥值。因此，由t-1个参与者组成的群体不能获取关于密钥K的任何信息。
>
> — 原作者,原始方法论来源第13章 13.1（中译本 OCR，逐字保留，yeZ 为 y∈Z_p 之 OCR）

---

## I — 方法论骨架 (Interpretation)

证明"我没泄露信息"的最强方式听起来像悖论：造一个假货，并证明假货与真品不可区分。如果旁观者仅用公开信息（不需要秘密、不需要参与真实交互）就能生成一份与真实会话记录统计相同的文本，那么这份记录对旁观者的信息量就是零——因为他自己也能造出来。这就是模拟器范式。操作化为三步：第一步，枚举会话的全部痕迹（消息、时间、错误模式、格式量）；第二步，对每个痕迹问"能否只用公开参数造出同分布版本"；第三步，造不出的痕迹即泄漏点——判据是可模拟性，不是"传输内容清单"里有没有秘密。两个书内实例：Shamir 秘密共享的 t−1 个份额，对任意候选密钥都能构造相容多项式（每个候选都有解释=没有候选被排除=零信息，与完美保密"观察不改变分布"同源）；Schnorr 识别的零知识，模拟器先猜挑战再倒推承诺，生成与真实会话同分布的文本——配合合理性（同一承诺两个响应可代数提取私钥）构成"不泄露"与"不可假冒"的双面证明。审计时这是泄漏面的系统清点法：谓词×痕迹逐项过模拟测试。

## A1 — 书中的应用 (Past Application)

### 案例 1: Shamir 方案——穷尽候选的相容性证明
- **问题**: 怎么严格证明 t−1 个份额对密钥"完全无信息"？
- **方法论的使用**: 第 13 章 13.1：对任意候选 y，都存在一条过这 t−1 个点且常数项为 y 的多项式——每个候选都与观察相容，观察无法排除任何值。
- **结论**: 零信息=对所有候选的可模拟（每个候选都有同分布解释）；这是完善保密形式化在秘密共享上的复用。
- **结果**: "t−1 份额零信息"从直觉成为定理；门限安全的第二半（与可恢复性对偶）有了证明模板。

### 案例 2: Schnorr 识别——先猜挑战再倒推承诺的模拟器
- **问题**: 身份证明每次交互会不会逐渐泄露私钥信息？
- **方法论的使用**: 第 9 章 9.4.1：模拟器先随机猜挑战 r，由响应式倒推承诺 γ，生成的 (γ,r,y) 与真实会话同分布——旁观文本可伪造，故无信息。
- **结论**: 零知识=transcript 可被无参与者模拟；配合合理性（同一 γ 对两个不同挑战的有效响应可提取私钥）双面成立。
- **结果**: "诚实验证者零知识"的证明结构定型；非随机挑战下"现有证明技术失效"的边界也被明示。

### 案例 3: 完美保密——同一思想的非交互版
- **问题**: "观察不改变分布"与模拟器有什么关系？
- **方法论的使用**: 第 2 章 2.3 定义 2.3：后验=先验——密文对明文信念零增益；与模拟器范式同源异用（一个非交互、一个交互）。
- **结论**: 零信息判据家族统一：非交互场景看"观察不改变分布"，交互场景看"transcript 可模拟"。
- **结果**: 审计泄漏面时按对象选判据形态，判定标准一致（观察者自己能造=信息为零）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 设计"隐私保留登录/证明知道口令而不发送口令"类方案，需要论证不泄露信息。
2. 审计零知识证明系统或身份识别协议的泄漏声明（每轮交互泄漏多少私钥信息）。
3. 评审秘密共享/门限方案时验证"未授权子集零信息"半边。
4. 判断"我们没传敏感字段"的合规声明是否等于"没泄露敏感信息"。

### 语言信号 (用户的话里出现这些就应激活)

- "zero-knowledge / 零知识证明怎么论证不泄露"
- "simulator / 模拟器 / transcript 可模拟"
- "每轮交互会不会泄漏私钥 / 识别协议的泄漏面"
- "证明知道口令但不发口令 / privacy-preserving authentication"
- "t-1 个份额真的什么都不泄露吗"

### 与相邻 skill 的区分

- 与 `stinson-perfect-secrecy-formalization` 的区别: 那个是无条件档非交互场景的分布判据（后验=先验）；本 skill 是交互场景的模拟器判据——同一家族两种形态，交互协议审计用本 skill。
- 与 `stinson-partial-leakage-amplification` 的区别: 那个找"密文上可计算谓词"的泄漏并演示放大；本 skill 证明"会话痕迹零信息"——一个是攻的泄漏分析，一个是守的零泄漏论证，配合使用（先模拟测试，造不出的谓词再查放大器）。
- 与 `stinson-collusion-threshold-verification` 的区别: 那个 skill 消费本 skill 的模拟/相容构造判据，验收门限方案"t−1 份额零信息"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **枚举会话/方案的全部可观察痕迹**: 消息内容、响应时间、错误模式、格式量、交互轮数、失败重试行为。
   - 完成标准: 痕迹清单完整；声称"未涉及秘密"的痕迹单独列出。
2. **对每个痕迹构造模拟测试**: 仅用公开参数（不需要秘密、不需要真实参与方）能否生成与真实场景同分布的该痕迹。
   - 完成标准: 每痕迹"可模拟/不可模拟"判定；可模拟的附构造思路。
   - 判停条件: 若核心消息痕迹可模拟且其余痕迹（时序/错误）声明不敏感，输出"零信息声明成立（在所列痕迹范围内）"结论。
3. **定位泄漏点**: 造不出的痕迹逐个分析其与秘密的相关性（响应时间与口令有关、错误模式区分候选）。
   - 完成标准: 每个泄漏点附"观察→缩小候选空间"的推演一行。
4. **核对合理性对偶面**: 零泄漏之外，同一承诺对两个挑战的响应能否提取秘密（假冒不可能性）；只有模拟器没有合理性的方案是"安全但无用"。
   - 完成标准: 双面判定（零泄漏✓/✗、合理性✓/✗）+ 各自依据。
5. **输出泄漏面报告**: 可模拟痕迹清单+泄漏点清单+修复（痕迹最小化、时序恒定化、域分离）。
   - 完成标准: 结论含"判据是可模拟性，不是传输内容清单"的指认句。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 普通加密机密性审计——非交互场景用分布/不可区分判据更直接；模拟器是交互协议的工具。
- 可用性/性能问题（协议慢不慢、轮数多不多）——除非轮数本身影响泄漏。
- 数据最小化合规的字面检查（"我们没传身份证号"）——本 skill 是它的强化版：还要证明没传的东西无法从痕迹重构；若用户只要合规字面答案，别过度展开。

### 作者在书中警告的失败模式

- "没发送秘密"≠"没泄露秘密信息"——判据是可模拟性；痕迹与秘密相关即泄漏。
- Schnorr 零知识证明在非随机挑战下"现有证明技术失效"——证明绑定挑战分布假设（第 9 章 9.4.1 边界）。
- 只有模拟没有合理性=安全但无用；只有合理性没有模拟=可用但泄密——双面缺一不可。

### 作者的盲点 / 时代局限

- 成书 2006 年：书内零知识是"诚实验证者"版本（HVZK），恶意验证者下的通用零知识（commit-challenge-response 加陷门）只在思想层；现代 ZKP 系统（zk-SNARK、Fiat-Shamir 在 ROM 下的争议）超出书内范围，本 skill 判据可迁移但证明技术需外部补充。
- 侧信道痕迹（时间、功耗）不在书内痕迹清单中，审计时应并入步骤 1。

### 容易混淆的邻近方法论

- 模拟器范式 ≠ "测试没发现泄漏"：模拟是数学论证（对所有候选构造解释），测试只是抽查——前者成立才有零信息声明。
- 与数据脱敏的区别：脱敏移除显式字段（内容清单思维）；可模拟性覆盖一切可观察痕迹（分布思维）——脱敏后的输出仍可能不可模拟。
