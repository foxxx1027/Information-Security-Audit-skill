# 结构性安全界设计——用可计算不变量压低攻击上界

## R — 原文 (Reading)

> 然而可以证明这8个S盒中的每一个的每一行都是整数0，，15的一个置换。这一性质正是为了防止某些类型的密码攻击而采取的设计S盒的若干准则之一。

## I — 方法论骨架 (Interpretation)

对抗统计型攻击（差分/线性）的最高境界不是"随机生成、测试通过"，而是把安全性做成可计算的计数下界。原理链：此类攻击的代价由"最好的一条特征"决定——差分看高概率差分链（样本量 ≈1/链概率），线性看高偏差线性逼近（样本量 ≈1/偏差²）；链的强度等于沿途活动 S 盒（输入差非零/进入线性式的 S 盒）的乘积衰减。于是防御有两个抓手：把单个 S 盒的最坏性质压到理论界附近（AES 的 S 盒用有限域逆+仿射显式定义，最大差分值与最大线性偏差可查表验证，逼近均匀——与 DES 的"随机挑选表"形成对照：可代数定义=可计算性质=可审计）；用扩散层保证"最少活动 S 盒数"下界（MixColumns 使任何有效差分/线性特征不得不激活很多 S 盒——宽轨道策略），轮数由该下界乘以每盒衰减推出，而不是拍脑袋加几轮。评审含义："无已知攻击"与"有可证界的无攻击"是两种声明——后者给出"任何差分攻击至少需要 2^X 数据"的可验算数字；前者只是没人试过。

## A1 — 书中的应用 (Past Application)

### 案例 1: DES S 盒的行置换准则
- **问题**: S 盒的表是怎么填的，能随机填吗？
- **方法论的使用**: 第 3 章 3.5.1 例 3.4：每个 S 盒的每一行都是 0…15 的置换——这是"为防止某些类型的密码攻击"的准则之一（非随机数）。
- **结论**: 查表组件的结构不变量（行置换、差分分布）是可审计的安全参数；DES 的准则出于经验，但确立了"表不是随便填的"。
- **结果**: 审计自研 S 盒/查表混淆的第一步：列出并验证其宣称的结构不变量。

### 案例 2: AES S 盒的代数定义——可解释=可审计
- **问题**: AES 的 S 盒凭什么信？
- **方法论的使用**: 第 3 章 3.6.1 例 3.5：S 盒=有限域求逆+固定仿射变换（0x53→0xED 演算）；其线性逼近表与差分分布表可显式计算，最大值趋近均匀分布的理论界。
- **结论**: 可代数表达意味着可被分析、可被证明（也招来代数攻击的讨论）——"可解释的设计"与 DES 的经验随机表形成方法论对照。
- **结果**: 评审查表组件时要求给出其差分/线性分布表并核对最大值位置。

### 案例 3: 宽轨道——把安全下界做成活动 S 盒计数
- **问题**: 轮数怎么定才不是拍脑袋？
- **方法论的使用**: 第 3 章 3.6.2：MixColumns 保证任何有效差分/线性特征必含较多活动 S 盒，每激活一个、概率/偏差乘性衰减一次；攻击样本需求由（最小活动数 × 单盒衰减）推出。
- **结论**: "对 AES 不存在快于穷尽密钥搜索的已知攻击"有结构底座——轮数由可计算下界支撑，安全声明可验算。
- **结果**: 自研密码的结构审要素化：S 盒最坏性质、扩散层活动数下界、轮数推导三件套缺一即"不可评估"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 评估自研分组密码/白盒查表混淆器/置换网络，需要结构层审什么。
2. 评审方案书里"随机生成 S 盒、无已知攻击"的安全声明，判断可评估性。
3. 设计定制密码（轻量级、领域专用）时确定轮数与扩散层规格。
4. 解释"AES 为什么可信"或"为什么不能随手造一个"。

### 语言信号 (用户的话里出现这些就应激活)

- "wide trail / 宽轨道 / 活动S盒怎么数"
- "差分均匀度 / 线性偏差多少算好"
- "轮数怎么定 / 加几轮才够"
- "随机生成的 S 盒安全吗 / 混淆表要审什么"

### 与相邻 skill 的区分

- 与 `stinson-keysize-not-security` 的区别: 那个是攻击者视角"结构缺陷击穿大密钥"；本 skill 是设计者视角"好结构给出可证下界"——同一结构线的攻防两面。
- 与 `stinson-linearity-kills-ciphers` 的区别: 那个判死全线性构造（代数方程攻击）；本 skill 管非线性组件的残余统计性质（差分/线性分布）——一个管有无非线性，一个管非线性够不够好。
- 与 `stinson-composition-not-amplification` 的区别: 那个讲坏组合为何零增益；本 skill 的宽轨道/活动 S 盒论证说明好结构的增益有代数机制——互为正反面。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **要素清单化**: S 盒/非线性组件（个数、定义方式）、扩散层（置换/矩阵）、轮数、密钥编排（白化有无）。
   - 完成标准: 三件套（非线性组件、扩散层、轮数）各一行；缺失项标"未声明"。
2. **审 S 盒最坏性质**: 计算或索取差分分布表与线性逼近表的最大值；对照理论界（l 比特盒的最大差分计数下界 2^{l-2} 量级）评估距离。
   - 完成标准: 最大差分值、最大线性偏差两个数字 + 距界判定。
   - 判停条件: 若 S 盒为"随机生成、无任何分布表"，输出"安全主张不可评估"结论跳到步骤 5。
3. **审扩散层活动数下界**: 单个活动 S 盒的输入差/线性式经扩散后至少扩散到几个盒（分支数）；"最少活动 S 盒数/每轮"是否可证。
   - 完成标准: 分支数或活动数下界数字 + 论证方式（可证/经验）。
4. **审轮数推导**: 轮数是否由（活动数下界 × 单盒衰减 → 攻击样本 >2^密钥强度）推出；白化（首尾密钥混合）有无。
   - 完成标准: 轮数推导链一行或"拍定"判定。
5. **输出结构评估**: 三件套逐项结果；区分"有可证界的无攻击"与"无已知攻击"两种声明等级，给出补齐路径（重新设计 S 盒/扩散层，或改用标准算法）。
   - 完成标准: 结论含声明等级判定与至少一条量化依据。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 流密码/PRNG 输出质量——归伪随机性判据；本 skill 的差分/线性工具箱针对分组结构。
- 协议层与模式层设计（怎么加密多条消息）——归组合检查表。
- 哈希函数内部设计（虽有相似的差分分析，但三件套框架不直接映射）。

### 作者在书中警告的失败模式

- "随机表"当安全依据——DES 行置换准则说明查表内容是有攻击指向的设计（第 3 章 3.5.1）。
- 无结构性上界的安全主张：只说"无已知攻击"——缺可验算下界，主张不可评估。
- 线性分析的独立性假设虽是启发式（见证据分层），防御侧不能指望攻击者"没证明"就打不进来——结构界要按最坏情况留裕度。

### 作者的盲点 / 时代局限

- 成书 2006 年：积分攻击（integral/square attack）、代数攻击（XSL 类）在书中未覆盖——三件套之外现代结构审还应补"高阶差分/积分性质"一科；AES S 盒的代数简洁性带来的代数攻击面（书内点到）后来成为研究线。
- 轻量级密码（PRESENT 类）与白盒安全的设计范式未出现。

### 容易混淆的邻近方法论

- 结构安全界 ≠ 测试通过：前者是数学下界（任何攻击至少 2^X 数据），后者是抽查——"过了全套统计测试"不构成结构界。
- 与组合增益的区分：多轮增益不是"叠加玄学"，是活动 S 盒计数的乘性衰减——有代数机制支撑的轮数才有效（组合≠增强 skill 的正面引用）。
