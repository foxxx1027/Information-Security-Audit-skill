# 审核员独立性处理（不审自己、两年咨询回避、技术专家角色红线、受审方异议权）

## R — 原文 (Reading)

> "审核员的选择和审核的实施应确保审核过程的客观性和公正性。审核员不应审核自己的工作。"
>
> — 原作者、原作者，原始方法论来源第1章 内部审核·独立性（source.txt L518–519，引 27001 正文）

## I — 方法论骨架 (Interpretation)

"独立客观"不能停留在口号，本书把它拆成一套**可核对、可留痕的量化与程序装置**：

1. **不审自己的工作**：内审员识别其内审之外的其他职责，分工表上回避自己负责/编写的领域——这条是 27001 对内审的强制要求，且被翻译成第5章 5.5 的直接检查题（"是否审核员审核了自己的工作"）。
2. **两年咨询回避**：审核组每一成员最近两年内未参与受审核方相关管理体系的认证咨询及影响公正性的其他活动。
3. **角色红线**：技术专家不能作为 ISMS 审核员——只能就技术充分性提供建议，不出具审核判断、不签署发现、不计人天；审核发现与结论的签署权在审核员一侧。
4. **受审方异议权**：审核计划送受审方确认时，特别告知其有权对审核组组成（含组长）提出异议；更换理由示例——前雇员、曾提供咨询、缺乏职业道德。
5. **承诺存档**：公正性、保密承诺书双向存档。

每个装置都有可查证据：名单 × 履历 × 分工表 × 承诺书比对——独立性从道德要求变成了审计追踪对象。处理利益冲突是分层的：两年内为该体系提供过咨询→整组回避；仅编写过部分文件→至少不审自己写的部分；确需其技术能力→降格为技术专家角色。

## A1 — 书中的应用 (Past Application)

### 案例 1: 原则→检查题落地链（第1章+第5章 5.5）
- **问题**: "不审自己"如何从原则变成可执行检查？
- **方法论的使用**: 第1章引 27001 正文立红线；第5章内审检查表直接配检查题"是否审核员审核了自己的工作"，核对其分工。
- **结论**: 原则→具体行为→证据（岗位职责与分工表比对）三段完整落地。
- **结果**: 成为全书少见的完整落地链（cs04）。

### 案例 2: 两年回避与更换理由（第3章 3.3/3.4）
- **问题**: 审核组组建时的硬约束是什么？
- **方法论的使用**: 每一成员近两年未参与认证咨询及影响公正性活动；组长须至少 3 次完整 ISMS 审核经历；计划送确认时特别告知异议权，更换理由示例=前雇员/曾提供咨询/缺乏职业道德。
- **结论**: 时间窗（两年）+ 经历门槛（3 次）+ 异议程序三件套。
- **结果**: ce43/ce26 分别记录咨询回避与异议权告知两个易漏点。

### 案例 3: 技术专家角色边界（第3章 3.3）
- **问题**: 组里带的技术专家能独立开不符合吗？
- **方法论的使用**: "技术专家不能作为ISMS审核员，但可就受审核方管理体系中技术充分性事宜为审核员提供建议"——计划中两类角色分列。
- **结论**: 建议≠判断；签署权与发现归属审核员。
- **结果: ** ce44 将"让技术专家履行审核员职责"定为硬性反例。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 编制年度内审计划、分配内审员分工（谁能审哪个部门）。
2. 外请顾问/咨询公司既帮建体系又要参与内审，判断其可否进组。
3. 某员工去年参与编写了体系文件，今年安排其内审任务。
4. 受审部门对某审核员有意见（前同事/曾给差评），走更换程序。
5. 审核组需要引入外部技术专家（云、工控），界定其权限。

### 语言信号 (用户的话里出现这些就应激活)

- "内审员能不能审自己负责的那块？" / "self-review, audit own work"
- "请的咨询顾问能来当审核员吗？"（两年回避）
- "技术专家能不能开不符合项？"（不能）
- "受审方对审核组有异议怎么办？" / "objection to audit team"
- "conflict of interest / independence check for audit team"

### 与相邻 skill 的区分

- 与 `isms-two-stage-audit-gate`：那是阶段准入；本 skill 是人员准入。审核组独立性是启动审核前的独立关卡。
- 与 `isms-four-column-checklist-design`：本 skill 产出一条专项检查题（内审独立性）进入检查表；检查表 skill 是通用容器。
- 与回避制度（采购/评审专家回避）：同族装置，但本 skill 带审核特有的"技术专家≠审核员"角色红线与异议权程序。

## E — 可执行步骤 (Execution)

1. **建履历-职责矩阵**：列出审核组全员，标注其近两年与受审范围的交集（咨询、建设、文件编写、雇佣关系）及日常职责。
   - 完成标准: 成员×交集矩阵，无空白格。
2. **逐人过装置**：不审自己（分工回避）、两年咨询回避（整组退出或降角色）、前雇员/职业道德问题（更换）。
   - 判停条件: 某成员两年内参与过该体系认证咨询 → 该成员退出审核组；仅编写部分文件 → 至少回避对应条款/部门，记录回避决定。
   - 完成标准: 每人一个处置结论（可任审核员/仅限某范围/转技术专家/退出）。
3. **角色分列**：技术专家在计划中单列角色栏，注明"仅技术建议、不签署发现、不计人天"。
   - 完成标准: 计划文本含角色栏与权限说明。
4. **异议权告知与存档**：计划送受审方确认时书面告知异议权；收集公正性/保密承诺书并归档。
   - 完成标准: 确认回执含告知痕迹；承诺书双向存档。
5. **复核与留痕**：把"独立性核查"本身作为一项记录归档（矩阵+处置+承诺书编号）。
   - 完成标准: 独立性档案可独立复查，逐人可追溯。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 小团队"人人有份"时的绝对僵化——正确做法是分层处置（回避具体条款/外部互审/技术专家降格），不是取消审核。
- 判断受审方体系本身合规性——独立性只保证裁判中立，不替代取证与判定技能。
- 第三方尽调中的利益冲突审查（投资/采购场景）——同族原则但装置与法规不同。

### 作者在书中警告的失败模式

- ce11/ce27 语境：审核员审核自己的工作——客观公正性破坏，发现天然失真。
- ce43：让前雇员/曾提供咨询者或利益冲突者进审核组——"审核组每一一成员在最近两年内都应未参与过受审核方相关管理体系的认证咨询"（OCR"每一一"原样保留）。
- ce44：让技术专家履行 ISMS 审核员职责——建议权与判断权混同。
- ce26：不告知受审核方对审核组组成的异议权——程序性不符合。

### 作者的盲点 / 时代局限

- **版本提示**：两年回避、3 次经历等具体数值出自 2012 年认证实践（对标当时 CCAA/CNAS 规则）；现行 ISO 19011:2018 以"威胁公正性的风险"框架（自评审、利益、胁迫等）表述，27001:2013/2022 对内审独立性的要求不变但引用条款号已变（2013/2022 版为 9.2 内部审核）。数值装置沿用前应核对本机构现行规则。
- 书中未处理"只有一名安全人员"的极小组织独立性死角（只有分层处置原则，无操作方案）。
- 异议权是受审方权利，书中未讨论恶意滥用异议拖延审核的处理。

### 容易混淆的邻近方法论

- 职责分离（SoD，权限设计）：面向系统权限的常态控制；本 skill 面向审核任务的临时回避。逻辑同源（自评审威胁），适用域不同。
- 回避申报制度（一次申报终身有效）：本 skill 要求逐项目核对（每次审核过矩阵），不是一次性声明。
