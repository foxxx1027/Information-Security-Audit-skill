# 结合审核准入与质量底线（三条件 go/no-go、评审机制同构判定、时间削减受整合度约束）

## R — 原文 (Reading)

> "对于两个运行在不同组织范围（例如完全不同的两个部门）内的管理体系，是不能进行结合审核的。因此结合审核必须满足以下三个基本条件：
> （1）标准之间有共同的实施范围；
> （2）实施的标准之间有共同的关注点；
> （3）组织对运行的体系进行了整合实施。"
>
> — 原作者、原作者，原始方法论来源第7章 7.1.1（source.txt L5634–5639）

## I — 方法论骨架 (Interpretation)

"一起审省事"是直觉，本书给的却是反直觉的准入装置——结合审核（两个或多个审核准则同时审）先过三道闸，再守一条底线：

1. **三条件同时成立才 go**：共同实施范围（不同组织范围的体系不能结合）、共同关注点、**确已**整合实施——"理论上可以整合"不算，要看组织是否真的整合运行。
2. **机制同构前置**：可整合实施 ≠ 可结合审核。CMMI、PCI-DSS、等保这类评审机制不同的标准（成熟度评估/合规鉴证/备案测评），可以整合实施、协调进场，但**不进入结合审核**——判据是评审机制是否同为周期性第三方管理体系审核。
3. **质量底线**：结合不得对审核质量产生负面影响，必须为每一标准的**每一项要求**分别提供充分信任——"合并掉某套要求"越线。
4. **时间削减是函数不是常数**：省多少时间由标准整合程度决定，整合差省得少，强省必损覆盖。

三条件过不了就退回逐套审核，这不是失败而是判定的正确输出。

## A1 — 书中的应用 (Past Application)

### 案例 1: 三条件与范围反例（7.1.1，cs45/ce37）
- **问题**: 什么情况绝对不能做结合审核？
- **方法论的使用**: 作者给出三条件判据，并以反例立边界："两个运行在不同组织范围（例如完全不同的两个部门）内的管理体系，是不能进行结合审核的"；三条件判定结果同时作为结合审核策划的预备信息（哪些条款有整合、有哪些条款）。
- **结论**: 准入判定即策划输入——go/no-go 不是行政流程，是信息收集动作。
- **结果**: 认证机构接单时先用三条件 go/no-go，不满足即退回逐套审核。

### 案例 2: 排除清单与机制同构（7.1.2，cs46/ce40）
- **问题**: 能与 27001"一起审"的边界在哪？
- **方法论的使用**: 正面列出可结合对象（ISO9001、ISO14001、OHSAS18001、ISO/IEC20000-1），同时点名排除：CMMI、PCI-DSS、GB/T22239 等保**可整合实施但因评审机制差异不涉及结合审核**。
- **结论**: "整合实施"与"结合审核"是两个判定层——先判机制同构，再谈结合。
- **结果**: 排除清单成为"别什么都往一场审核里塞"的显式边界。

### 案例 3: 质量底线与时间函数（7.1/表7-2，cs43/ce41）
- **问题**: 省时间的诱惑怎么约束？
- **方法论的使用**: 7.1 开篇立底线：结合审核不应对质量产生负面影响，须为每一管理体系标准或规范性文件的每一项要求提供充分信任；表7-2 注明"结合审核可以减少标准实施的审核时间，但标准的整合程度，对审核时间的减少比例有影响"。
- **结论**: 收益（减少访问、缩短中断、共用会议）与质量必须同时成立；时间削减从整合度推导，不拍脑袋。
- **结果**: 底线成为后续一切"过程可略"类裁剪（见 `isms-common-difference-evidence-split` 的取舍判据）的前提条件。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 组织同时持 ISO27001 认证与 SOC 2 报告，两家机构想一次进场都审完。
2. 集团推行三标一体（27001+9001+14001），认证机构设计结合审核方案。
3. 咨询顾问为客户设计整合体系后评估认证路径（哪些能合、哪些只能协调）。
4. 大型组织想把多个框架的内审合并成一轮，先判断可行性。

### 语言信号 (用户的话里出现这些就应激活)

- "能不能一次进场把两个标准都审了？" / "combined audit feasibility"
- "SOC 2 和 ISO27001 能一起审吗？"
- "三标一体化审核怎么策划、怎么准入？"
- "合并审核能省多少人天？"（省多少是整合度的函数）
- "等保测评能不能和 ISO 审核一起做？"（机制不同构——不能结合，可协调）

### 与相邻 skill 的区分

- 与 `isms-combined-audit-planning-calibration`：本 skill 是 go/no-go 准入判定；过了门槛之后的策划信息校准与路径选择归 `isms-combined-audit-planning-calibration`。顺序：先本 skill，后它。
- 与 `isms-common-difference-evidence-split`：那是过门槛后现场"怎么合并取证"的执行技术；本 skill 是"能不能合并"的准入与底线。
- 与 `isms-multi-site-sampling-formula`：多场所是空间维度（场所怎么抽），结合审核是准则维度（标准怎么合）——两个正交的策划问题。

## E — 可执行步骤 (Execution)

1. **机制同构判定**：逐个框架问"它的评审机制是否为周期性第三方管理体系审核"。
   - 完成标准: 每框架一行判定（同构/不同构 + 依据）；不同构者 → 输出"可整合实施+协调进场，不做结合审核"，流程结束。
2. **核三条件**：共同实施范围（组织范围重叠证据）、共同关注点（条款关注点交集）、整合实施证据（文件/流程/组织是否真整合运行，用业务流程、部门职责、文件结构佐证）。
   - 完成标准: 三条件各带证据或缺口说明。
   - 判停条件: 任一条件不成立（尤其"仅有可能性无整合事实"）→ no-go，退回逐套审核，记录判定依据。
3. **定质量底线与时间预算**：从整合程度推导时间削减比例；建"每标准×每要求"覆盖矩阵。
   - 完成标准: 覆盖矩阵无洞；时间削减说明与整合度证据挂钩（不引用固定百分比）。
4. **输出准入结论**：go（转 isms-combined-audit-planning-calibration 做策划）或 no-go（逐套审核/仅协调进场）。
   - 完成标准: 一页判定书——三条件结果、机制判定、底线承诺、去向。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单体系审核策划——无结合问题。
- 联合审核（两个以上审核组织合作审同一对象）——那是机构间协作概念，不是准则结合，判定逻辑不同。
- 机制不同构的框架（SOC 2 鉴证、CMMI 评估、等保测评）——按本书排除逻辑本就不该进结合审核，别硬凑。

### 作者在书中警告的失败模式

- ce36：为省时间把结合审核做成"一遍过"，逐标准覆盖打折——质量底线违例。
- ce37：运行在不同组织范围的体系硬凑结合审核。
- ce40：把 CMMI/PCI-DSS/等保当结合审核对象——机制不同构。
- ce41：预设"结合省 X%"不看整合程度机械砍时间。

### 作者的盲点 / 时代局限

- **版本提示**：可结合标准清单停在 2012 年（ISO9001:2000、ISO14001:2004、OHSAS18001、ISO/IEC20000-1:2005）；现行为 ISO9001:2015、ISO14001:2015、ISO45001:2018（替代 OHSAS18001）、ISO/IEC20000-1:2018、ISO27001:2022，且 2015 版起 HLS 高阶结构使共同点更多但条款对应关系全部要重核。SOC 2/等保 2.0 的类比判定是 verified.md V2 的外推，书内无此例。
- "确已整合实施"的判定本身需要判断（阶段 0 已指出三条件可判定性是未证明假设），书中给的是清单不是判定程序——实操需配合 `isms-combined-audit-planning-calibration` 的交叉校准。
- 时间削减"函数"只给了方向，无公式或系数表。

### 容易混淆的邻近方法论

- 联合审核（joint audit）：两个审核组织合作，对象与机构维度不同。
- 一体化管理体系（IMS）建设方法论：讲怎么把体系建成一套；本 skill 只管建成之后的审核侧准入。
