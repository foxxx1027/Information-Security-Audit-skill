# 结合审核策划校准（客户自述须交叉验证、文件整合程度定审核路径、一阶段后校准）

## R — 原文 (Reading)

> "上述信息中，前三个方面，可以通过跟客户沟通的方式来获取，但为了避免沟通时信息的偏差，可以通过分析受审核方的业务流程，部门职责和文件的结构来进一步确认。当然即使如此，也难免会和实际情况有差异，这些差异，可以在审核的第一个阶段结束后进行进一步的调整。"
>
> — 原作者、原作者，原始方法论来源第7章 7.2.1 表7-1 注（source.txt L5690–5695）

## I — 方法论骨架 (Interpretation)

策划阶段最大的风险是把受审方（或客户）的**自述当事实**："我们已经整合成一套了"——信了，方案就建立在假设上。本方法把策划做成三步假设检验：

1. **信息分类采集**：六类策划信息（体系数量与范围、运行成熟度、整合程度、业务流程、部门职责、文件结构）中，前三类靠沟通可得但带偏差，后三类是客观材料。
2. **交叉校准**：每条自述用至少一类客观材料复核——说"整合实施"，就抽查文件结构看隐私/质量程序是否真并进同一套文件、部门职责是否一套班子两块牌子。
3. **文件形态定路径**：同一套体系文件控制相同要素 → 路径一，文件评审阶段一次评多标准符合性；各自独立文件 → 路径二，分别审核**并增设"文件间一致性检查"**防要求冲突。
4. **留校准点**：即使交叉校准仍有差异——一阶段结束后按实际整合度调整二阶段人日、分工与路径。**先带假设进现场，用一阶段校准策划**，而不是策划一次定死。

## A1 — 书中的应用 (Past Application)

### 案例 1: 表7-1 六类信息与取证技巧（7.2.1，cs47）
- **问题**: 结合审核策划前收集什么、怎么防信息不实？
- **方法论的使用**: 作者列出六项准备信息（体系数量与覆盖范围、运行成熟度、整合程度、业务流程、部门职责、体系文件结构），并明确前三项可沟通获取、但须以业务流程/职责/文件结构交叉确认，仍有差异则一阶段后调整。
- **结论**: 沟通信息=待验证假设；客观材料=校准器；一阶段=校准窗口。
- **结果**: 形成"先带假设进现场、第一阶段校准策划"的完整落地，必要时辅以预访问。

### 案例 2: 文件整合程度分支（7.2.2，cs48/ce39）
- **问题**: 拿到信息后，审核方案怎么分岔？
- **方法论的使用**: 同一套文件控相同要素→较容易：文件评审阶段评这套文件对多标准的符合性，现场评多体系实施；各自独立文件→复杂：分别审核，"适时需要增加一个'不同管理体系文件之间的一致性检查'步骤"。
- **结论**: 文件整合程度这个**可观测变量**决定审核路径——比"客户自述整合度"可靠。
- **结果**: 两条路径成为结合审核策划的标准分支，分散文件必挂一致性检查步骤。

### 案例 3: 申请信息回核的同构做法（第3章 3.1）
- **问题**: 自述信息的交叉验证只用于结合审核吗？
- **方法论的使用**: 申请资料中的咨询情况、外包过程信息，在审核组选择与计划制定时同样须回核——自述信息用独立渠道核验的做法跨章复用。
- **结论**: "不信自述、验形态"是通用策划纪律。
- **结果**: 与 `isms-auditor-independence-checks`（咨询关联独立性）互为印证——自述信息须用独立渠道核验是跨章复用的策划纪律。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 集团声称"27001 与 27701（隐私）已整合成一套文件"，策划阶段决定信不信、怎么验。
2. 多体系内审合并（安全+质量一轮做完）前的计划编制。
3. 接手他人做了一半的整合审核项目，复核其策划假设是否成立。
4. 咨询交付整合体系后，帮客户安排认证路径与现场安排。

### 语言信号 (用户的话里出现这些就应激活)

- "客户说已经整合了，能信吗？" / "client claims full integration"
- "整合审核计划怎么编？" / "integrated audit plan"
- "两套文件要不要加一致性检查？"
- "策划信息从哪来、可靠吗？"
- "一阶段之后计划还能改吗？"（能——校准点就是为此设的）

### 与相邻 skill 的区分

- 与 `isms-combined-audit-admission`：它管"能不能结合"（三条件 go/no-go）；本 skill 管过门槛之后"怎么策划、怎么校准"——顺序上先准入后本 skill。
- 与 `isms-document-consistency-matrix`：文件间一致性检查是本 skill 路径二中挂载的一个执行动作（由 `isms-document-consistency-matrix` 执行）；本 skill 决定走哪条路径、挂不挂该步骤。
- 与 `isms-two-stage-audit-gate`：一阶段后校准借用了它的阶段结构（门禁+校准点）；本 skill 特指多标准整合度假设的校准内容。

## E — 可执行步骤 (Execution)

1. **采集六类信息并标注来源**：体系数量与范围、成熟度（建立时间/内审管评结果/外审历史）、整合程度、业务流程、部门职责、文件结构；前标注"自述"、后标注"客观材料"。
   - 完成标准: 信息表，每项标注来源类型。
2. **交叉校准自述项**：每条自述用业务流程/部门职责/文件结构中至少一类客观材料复核（如抽文件目录核"同一套文件"声明）。
   - 完成标准: 每个自述项有印证结论或差异标注。
   - 判停条件: 若发现自述与客观材料严重背离（声称一套文件、实际两套且互不引用）→ 按实际形态而非自述定路径，并把差异记入策划风险。
3. **判文件形态定路径**：同一套文件（含部分整合按占比判主导形态）→ 路径一；独立文件 → 路径二并在计划中显式列入"文件间一致性检查"步骤。
   - 完成标准: 路径判定 + 依据（文件结构证据）；路径二计划含一致性检查的时机与责任人。
4. **排一阶段后校准点**：策划文件留"一阶段结束后校准"栏目，复核整合度假设、调整二阶段人日/分工/路径。
   - 完成标准: 策划文件含校准栏目；执行后留有实际修订痕迹（或"无需调整"的复核记录）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单体系审核策划——无整合度假设需要校准，直接排检查表。
- 尚未通过结合审核准入（`isms-combined-audit-admission`）的场景——先判定可行性，本 skill 不背 go/no-go 的责任。
- 受审方完全无自述争议、文件形态一目了然的小项目——校准可压缩为一次文件抽查，不必铺满流程。

### 作者在书中警告的失败模式

- ce39：分散文件下不做"文件间一致性检查"，两套文件要求冲突无人发现。
- 客户说什么记什么（沟通偏差未经客观材料复核即入计划）——表7-1 注明示的偏差风险。

### 作者的盲点 / 时代局限

- **版本提示**：表7-1 六类信息与路径分支基于 2012 年的标准组合（9001:2000/14001:2004/27001:2005 等）；现行 27001:2022、27701:2019、45001:2018 等换版后，信息项照用但条款映射与"共同要素"清单须重建；27001+27701 组合的校准（PII 控制并入 ISMS）是 verified.md V2 外推，书内无此例。
- 交叉校准无量化判据（抽多少文件算"印证"），依赖审核员手感。
- 一阶段校准点依赖两阶段结构；一次性内审合并场景需自行设替代校准点（如中场复盘）。

### 容易混淆的邻近方法论

- 尽职调查（due diligence）的信息验证：同族思想，目的在交易决策；本方法的产出是审核路径与资源计划。
- 敏捷计划的滚动式规划（rolling wave）：形态相似（近细远粗、迭代修正），但本方法的校准锚点是"文件整合形态"这一特定可观测变量。
