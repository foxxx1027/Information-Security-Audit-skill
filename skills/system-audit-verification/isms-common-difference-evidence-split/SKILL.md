# 共同点一次取证、差异点单独深查（11 共同关注点底表 + 管评"过程可略、输入输出必查" + 成对条款对照）

## R — 原文 (Reading)

> "在结合审核时，审核员可以不必关心三个标准在管理评审的过程上有什么差异，但一定要关注管理评审的输入和输出，保证整合的管理评审活动对与各个标准没有偏颇和遗漏。"
>
> — 原作者、原作者，原始方法论来源第7章 7.3.5 监视评审与持续改进（source.txt L5935–5937）

## I — 方法论骨架 (Interpretation)

合并审核的正确姿势不是"能并的并掉"，而是**先界定可合并集，再死守不可合并集**：

1. **共同关注点底表**：表7-3 把 27001×9001×14001 逐条款对照归并出 11 个共同关注点（实施范围、文件管理、记录管理、管理承诺、方针、角色职责、资源、培训意识能力、内审、管评、持续改进）——对所有 PDCA 型国际标准必不可少。共同点可**一次取证、共用证据**。
2. **差异点即审核重点**：合并的代价是"独有要求被共同点稀释"。每套标准的单侧要求（27001 方针须体现风险评价准则；整合体系记录须满足保密性完整性可用性；等保的定级备案流程）必须逐标准单列深查。
3. **取舍判据范例**：管理评审"过程差异可略、输入和输出一定要逐标准核对"——**过程可共用，接口必须逐标准点名**。这是"哪些能省、哪些不能省"的模板。
4. **成对条款三段式**：同主题按"A 标准条款→B 标准条款→审核方法"成对展开（27001×20000-1 的风险管理六问、有效性测量八问即成品），保证同主题两边无遗漏。

## A1 — 书中的应用 (Past Application)

### 案例 1: 表7-3 的 11 共同关注点（7.3，cs49）
- **问题**: 三套标准的条款对照从哪入手？
- **方法论的使用**: 作者用表7-3 做 27001×9001×14001 逐条款对照，归并出 11 个共同关注点，并说明其普适性（PDCA 型国际标准必不可少）；若整合时大部分关注点未整合，结合后审核会很困难。
- **结论**: 共同关注点底表既是合并取证的边界，也是整合度的前置体检表。
- **结果**: 7.3 全节围绕这 11 项逐个做结合审核分析。

### 案例 2: 三个差异点实例（7.3.1/7.3.2/7.3.5，cs50/cs51/cs52）
- **问题**: 差异点单查具体查什么？
- **方法论的使用**: 方针——27001 特有"信息安全方针须体现风险评价的准则"；记录——整合体系中记录须考虑法律法规合同义务、留存重大事件记录，且保密性完整性可用性应被考虑；管理评审——过程差异可不关心，输入输出必须逐标准核对、无偏颇无遗漏。
- **结论**: 差异点落在"同一关注点下的单侧加严/独有要求"，逐标准列清单单查。
- **结果**: 三例成为"共同点省资源、差异点保质量"的操作样板。

### 案例 3: 27001×20000-1 的成对三段式与成品问题清单（7.4，cs53/cs54）
- **问题**: 与非 HLS 标准怎么对照？
- **方法论的使用**: 七个关注面按"27001 条款→20000 条款→审核方法"三段式成对展开；风险管理六问（第②问"是否有明确的风险接受准则"）、有效性测量八问可直接使用，27001 侧更严时以 27001 为主轴拉齐。
- **结论**: 成对条款对照保证同主题两边都被取证；严标准主轴防漏。
- **结果**: 六问/八问成为该结合场景的即用检查题。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 组织做 27001 与等保 2.0 的整合内审，要排一张不漏两边的检查表。
2. 多体系内审员把安全与质量两轮内审合并为一次现场。
3. 认证机构结合审核现场分工：谁查共同点、谁守差异点。
4. 合规团队把多框架映射成统一控制表后，验证覆盖没有稀释独有要求。

### 语言信号 (用户的话里出现这些就应激活)

- "两个标准的检查表能合并吗？怎么合并？" / "merged checklist two standards"
- "哪些能一起查、哪些必须分开查？"
- "等保和 ISO 的差异点在哪？" / "differential requirements"
- "合并审核会不会漏掉一边的要求？"（会——差异点不单查就漏）
- "管理评审两套要求怎么合着审？"（过程合审、输入输出分列）

### 与相邻 skill 的区分

- 与 `isms-combined-audit-admission`：它管"能不能结合"（准入）；本 skill 管"结合之后怎么排表、怎么分配取证"（执行层）。
- 与 `isms-four-column-checklist-design`：四栏表是单标准的题型结构；本 skill 在其上叠加跨标准分配维度（共同点共用题、差异点单侧题）。
- 与 `isms-combined-audit-planning-calibration`：它是策划期的路径与资源校准；本 skill 是现场取证层的题目分配——它定"走哪条路"，本 skill 定"路上查什么、怎么分工"。

## E — 可执行步骤 (Execution)

1. **建条款映射底表**：两套准则逐条款对照（A↔B 或单侧）。
   - 完成标准: 映射表覆盖双方全部适用条款，单侧条款显式标出。
2. **归并共同关注点**：以 11 项底表（范围/文件/记录/承诺/方针/职责/资源/培训/内审/管评/改进）为参照归并，可加场景特有共同点（如双框架都要求的物理安全）。
   - 完成标准: 共同点清单 + 每项设计一份共用取证方案（一次取证、双方引用）。
3. **列差异点单查清单**：映射表中的单侧条款与"同关注点单侧加严"项（27001 方针载风险评价准则、记录 CIA 等）逐条列入必查。
   - 完成标准: 差异清单无遗漏（与映射表单侧项对账）；管理评审类按"输入/输出逐标准两列打钩"排表。
4. **成对三段式排题**：同主题条款按"A 条款→B 条款→审核方法"成对编题，严标准主轴拉齐。
   - 完成标准: 检查表中无单侧裸条目——每个主题两边条款同时出现或已归入差异清单。
5. **复核覆盖矩阵**：每标准每项要求至少落入"共同点（含共用证据引用）"或"差异点单查"之一。
   - 完成标准: 标准×要求覆盖矩阵无洞；被共同点合并的独有要求（如定级备案）确认已单列。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 两框架机制差异过大（管理体系标准 vs 渗透测试规范 vs 产品认证）——没有共同关注点基础，合并无意义，退回分别审。
- 单体系审核——无分配问题。
- 尚未通过结合审核准入判定的组合——先走 v24，别在不可结合的组合上排合并表。

### 作者在书中警告的失败模式

- ce42：结合审核管理评审只看过程合一处，不核各标准输入输出——某标准在管评中被系统性遗漏。
- ce38：体系整合时大部分共同关注点未整合实施仍硬做结合审核——"结合后审核实施是很困难的"，且直接诱发质量受损（ce36 的成因）。

### 作者的盲点 / 时代局限

- **版本提示**：表7-3 基于 ISO9001:2000×ISO14001:2004×27001:2005；现行 9001:2015/14001:2015 已采 HLS 高阶结构，与 27001:2013/2022 的共同点更多但条款号全变，底表须重建；27001×等保 2.0 对照是 verified.md V2 的外推（书内等保仅作为"不涉及结合审核"的排除项出现）。11 关注点清单对非 PDCA 框架（如 SOC 2 TSC）不保证适用。
- 书中共同关注点的"一次取证"无共用证据的记录格式规范（一份记录引用两标准条款的标注法），实操需自行定义。
- 无合并审核节省与遗漏的量化对照数据。

### 容易混淆的邻近方法论

- 统一控制映射表工具（CCM/OSCAL 类）：工具化同类思想；本 skill 给的是"哪些可合并、判据是什么、哪里必须拆"的方法论，不依赖特定工具。
- 差距分析（gap analysis）：单方向对照（现状 vs 一套标准）；本 skill 是双向条款分配（两套标准互为参照）。
