# 控制非普适性与等效替代判定（审"同一控制目标的达成"，而非逐条抄控制）

## R — 原文 (Reading)

> "例如，10.1.3描述如何分割责任，以防止欺诈或错误。在较小的组织中分割所有责任是不太可能的，实现同一控制目标的其他方法可能是必要的。"
>
> — 原作者、原作者，原始方法论来源第2章 选择控制措施（source.txt L1475–1477，引 27002 注文）

## I — 方法论骨架 (Interpretation)

照标准控制清单逐条打勾的审核，默认控制放之四海皆准——本书立场相反：**控制非普适**，"没有一个控制措施集合能实现全部的安全"。判定单元因此要换：不审"这条控制实施了没有"，审"这条控制所要达成的**控制目标**有没有被达成"。

操作序列四步：

1. **提炼控制目标**：把具体控制抽象成"防什么"（职责分离→防欺诈与错误/防未授权变更）。
2. **识别替代措施**：做不到原控制时，组织用了什么其他方法（补偿性控制：双人复核、外部审查、事后审计）。
3. **验证替代运行**：替代不是自我声明——抽查实例（如 3 次变更记录）核对替代动作真实发生。
4. **冲突分支**：控制与适用法律冲突（日志监控 vs 隐私保护）时，取舍本身须在文件中记录理由，而不是悄悄不做或悄悄硬做。

附一个常被忽略的边界：控制的定义含策略、规程、指南、惯例、组织结构——只查技术配置等于漏审半数控制，等效替代同样可以落在管理动作上。

## A1 — 书中的应用 (Past Application)

### 案例 1: 小组织无法分割全部责任（第2章，cs06）
- **问题**: 10 人规模的公司做不到职责完全分离，判不符合吗？
- **方法论的使用**: 作者借 27002 注文给出判定：较小的组织中分割所有责任不太可能，"实现同一控制目标的其他方法可能是必要的"——审核动作转为寻找并验证替代方法。
- **结论**: 机械按"职责分离"开不符合是错的；审的是同一目标（防欺诈/错误）的等效达成。
- **结果**: 该判定思路延伸为第6章"控制目标达成情况"的审核思维（审目标达成，而非逐条对照实施指南）。

### 案例 2: 事件日志监视与隐私保护法律冲突（第2章，cs07）
- **问题**: 日志监控这条"好控制"与适用法律（工作场地/顾客隐私保护）冲突怎么办？
- **方法论的使用**: 作者用第二个标准自带示例说明：控制可能与适用的法律相冲突——审核 A.10.10 时必须同时核对法务/合规输入，检查日志策略是否声明隐私边界。
- **结论**: 法律情境是控制适用性的合法变量，冲突的取舍须明示而非回避。
- **结果**: 与案例 1 共同支撑"控制选择必须结合国情与法律"的全书立场。

### 案例 3: 实施指南的豁免表述（第2章，ce08）
- **问题**: 等效替代会不会变成"想不做就不做"的后门？
- **方法论的使用**: 豁免只对指南性内容成立——"本指南的某些内容可能不适用所有情况，所以其他实现控制措施的方法可能更为合适"；指南不能当 shall 开不符合，但标准要求本身没有豁免。
- **结论**: 等效替代的边界=指南层可替代、要求层（shall）不可替代。
- **结果**: 判定纪律落地：先分清审的是要求还是指南，再谈等效。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 审计一家 12 人的初创公司，"职责分离"（开发不得直接改生产数据）做不到。
2. 组织的日志/监控策略与个保法"最小必要"原则冲突，需要审取舍处理。
3. 自己团队被审核方指出缺控制，要论证补偿性控制等效。
4. 上云迁移中部分本地控制（门禁、介质销毁）转由服务方承担，判断等效性。

### 语言信号 (用户的话里出现这些就应激活)

- "团队太小做不了职责分离怎么办？" / "segregation of duties in a small team"
- "能不能用补偿性控制替代这条控制？" / "compensating control"
- "这条控制对我们不适用，怎么写理由？"
- "监控要求和隐私法规冲突了" / "logging vs privacy law"
- "没有做标准里的 X 控制，但我们是小公司"（正是本 skill 的入口）

### 与相邻 skill 的区分

- 与 `isms-soa-justification-traceback`：它查"选/不选的理由链在不在"（决策留痕）；本 skill 查"替代措施是否等效达成目标"（运行实质）——它回答"为什么不做"，本 skill 回答"那你怎么兜底、兜住了吗"。删减理由中常引用等效论证，先说理后判等效。
- 与 `isms-nonconformity-grading-loop`：替代不成立时的不符合分级开单用 `isms-nonconformity-grading-loop`；本 skill 止于"等效成立/不成立"判定。
- 与 `isms-two-step-conformity-audit`：两步法是条款符合性总序；本 skill 处理其中"控制类要求在特殊情境下"的判定分支。

## E — 可执行步骤 (Execution)

1. **提炼控制目标**：把争议控制写成一句"防什么"的目标陈述。
   - 完成标准: 目标陈述可脱离具体实现（如"防未授权变更"），并与原文出处对得上。
2. **判定适用性争议类型**：做不到（能力/规模）、与法冲突（合规）、已由他方承担（外包/云）。
   - 完成标准: 争议类型标注 + 依据（规模事实/法条/合同条款）。
3. **识别替代措施并映射目标**：列出组织实际采用的替代/补偿性控制，逐一映射到同一控制目标。
   - 完成标准: 替代链图——原控制 → 控制目标 ← 替代措施；出现映射不上的空缺即替代缺口。
4. **验证替代真实运行**：抽 3 次实例核对替代动作发生（审批签字、外部审查报告、事后审计记录）。
   - 完成标准: 实例抽查记录；无运行证据=替代未实施，不得凭文件声明判等效。
5. **冲突分支处理**：法律冲突情形下，核取舍理由是否已成文（SoA/方针/记录）并经批准。
   - 完成标准: 文件出处 + 批准痕迹；无记录则开"控制与法律冲突未记录取舍"方向发现。
6. **判定输出**：等效且运行→按替代记录符合；不等效→按 isms-nonconformity-grading-loop 分级（目标未达成且无任何措施=要素缺失方向）。
   - 完成标准: 判定结论附证据清单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 有能力有资源做到的控制不做——那不是情境不适用，是实施缺失，不得借"等效"洗白。
- 高危领域的强控制（特权管理、生产数据访问）不轻信纸面等效——替代验证必须到运行证据层。
- 标准的 shall 要求本身（区别于实施指南）——要求层没有等效豁免，等效只发生在实现方式上。

### 作者在书中警告的失败模式

- ce05：声称"所有控制措施必须全部实施/已全部实施"——"没有一个控制措施集合能实现全部的安全"，两头都是反例。
- ce08：把实施指南当强制项开不符合（误导组织过度控制），或反向随手删（借豁免表述逃避）。
- ce06：机械套用控制，不评估组织情境与法律——正是本 skill 要替代的审法。

### 作者的盲点 / 时代局限

- **版本提示**：两个情境例子（10.1.3 职责分割、10.10 日志监控）直接引自 27002:2005 注文，条款号在 27002:2013/2022 已全部移位（职责分离现为 5.3/6.1 类、监控为 8.15 类）；2022 版 Annex A 属性化（标注 process/people/physical/technology 类型）与"控制宽边界"立场一致。
- 2012 年成书，个保法/网安法（2017/2021 后）使"日志 vs 隐私"冲突远比当时普遍，书内冲突处理深度不足（只有"记录理由"一道要求）。
- 等效判定无量化判据（替代覆盖率、残余风险对比），依赖审核员经验。

### 容易混淆的邻近方法论

- PCI-DSS 等框架的 compensating control 正式流程（定义四要件+批准）：比书内更严格，高风险场景建议借用其判据。
- 风险接受（`isms-risk-acceptance-criteria-first`）：接受是"承担不处理"，等效替代是"换一种方式处理"——决策性质不同，不可混用。

## 相关 skills

- 组合 `isms-soa-justification-traceback`：审 SoA 删减项时先由它查"理由链在不在"，再用本 skill 判"替代措施是否等效兜底"——先说理、后判等效，同一清单上的两道工序。
- 对比 `isms-risk-acceptance-criteria-first`：风险接受是"承担不处理"（换处置选项），等效替代是"换一种方式处理"（同一控制目标）——两种决策性质不同，混用即误判。
- 组合 `isms-nonconformity-grading-loop`：本 skill 止于"等效成立/不成立"判定；替代不成立（目标未达成且无任何措施）时的开单与分级归它。
