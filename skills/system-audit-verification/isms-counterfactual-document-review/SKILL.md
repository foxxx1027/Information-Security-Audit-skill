# 反证式文本审读（5W1H 与 SMART 各配"缺失后果"链，用"缺了会坏什么"审文件）

## R — 原文 (Reading)

> "（5）方针中声明的自标应该考虑SMART标准，如果不这样做：
> ·不明确（specific）的目标不容易被清晰地认识，负责实现它的人员通常也不明确；
> ·如果目标不可测量（measurable），组织很难能够证实它是否被实现；"
>
> — 原作者、原作者，原始方法论来源第6章 6.2.3 方针和目标·SMART（source.txt L4778–4781，OCR"自标"原样保留）

## I — 方法论骨架 (Interpretation)

常规的文件审读问"写了没有、全不全"，结果只能发现**漏写**；漏不掉的空洞文本（"及时响应""加强管理"）照样过关。本方法把审读方向反转：**对每个要素追问"缺了它会坏什么"**，用失效后果来定位真缺陷。

两套判据各配后果链：

1. **5W1H 六问**（方针/程序结构）：谁来做、什么时间做、为什么做、做什么、在什么地方做、如何做——不定义责任人则无人实现目标；不定义起止时间则何时开始结束不明；做法不清晰则无法正确执行。
2. **SMART 五项**（目标/承诺质量）：不明确→责任人不明；不可测→**无法证实是否被实现**（审核直接判"目标不可证实"）；不沟通不被接受→控制被误解、不执行；不现实→难实现；无时限→**很可能没有行动**。

输出两种结论：要么补全要素的可审计改写（who/时限/度量值/动作），要么判"该条款不可证实/不可执行"——后者本身就是一个可开单的审核发现。这套判据适用于一切承诺类文本：方针、目标、程序、SLA、合同安全条款。

## A1 — 书中的应用 (Past Application)

### 案例 1: 方针/程序的 5W1H 审读（6.2.2，L4763–4765）
- **问题**: 方针或程序文本怎么判断"可执行"？
- **方法论的使用**: 作者列出六问并逐问配反证："（3）方针或程序中宜考虑基本的问题：谁来做、什么时间做、为什么做、做什么、在什么地方做、如何做 ·如果没有定义负责执行活动人，那谁（谁来做）来实现设置的目标？"
- **结论**: 要素缺失不是格式瑕疵，而是责任链与执行链的断裂点。
- **结果**: 该六问成为第6章非技术控制文本审核的基础判据组。

### 案例 2: 目标的 SMART 审读（6.2.3）
- **问题**: 信息安全目标写到什么程度才算"可审"？
- **方法论的使用**: 五项逐条展开失效后果（见 R 段引文），并与第5章条款审核合用——方针须建立风险评价准则、目标可测量方能证实被实现（5.3 检查题）。
- **结论**: 不可测量的目标在审核上等于没有目标——"组织很难能够证实它是否被实现"。
- **结果**: 两套判据在第5章条款检查与第6章控制审核两条线合用，成为文本质量的双重底稿。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 审供应商 SLA/合同安全条款："发生安全事件时及时响应"这类模糊承诺。
2. 内审审信息安全方针与年度目标：目标可测量吗、谁负责、什么时限。
3. 起草或评审内部程序文件时自检可执行性（写完后先被自己审一遍）。
4. 制度文本合规评审（等保/ISO 文件化信息、隐私政策承诺）。

### 语言信号 (用户的话里出现这些就应激活)

- ""及时响应"这种条款怎么审？" / "vague commitment, how to audit"
- "这个目标可测量吗？怎么写才可审？" / "measurable security objective"
- "方针/程序缺什么要素？" / "what makes a policy auditable"
- "SMART 检查一下这个目标"
- "文件写了但总觉得是空话"（正是反证式的靶子）

### 与相邻 skill 的区分

- 与 `isms-document-consistency-matrix`：一致性核对管"程序↔产出对得上"（跨文件关系）；本 skill 管单份文本自身的要素完备与可证实性。一份文件先过本 skill，再进关系核对。
- 与 `isms-four-column-checklist-design`：检查表把 shall 转成检查题；本 skill 产出的"缺了会坏什么"清单可直接充当检查题素材，但定位是文本缺陷诊断。
- 与通用 SMART/5W1H 培训：工具相同，增量不同——本方法强制每项挂失效后果，判据是"可审计性"而非管理时髦。

## E — 可执行步骤 (Execution)

1. **定文本类型与判据集**：方针/程序类→5W1H；目标/承诺类→SMART；混合文本（如含目标的方针）两套都过。
   - 完成标准: 文本清单每份标注适用判据集。
2. **逐项反证**：对每个要素问"缺了会坏什么"，写出具体后果（对照后果链模板：责任人/时限/可测性/沟通接受/现实性/执行方法）。
   - 完成标准: 每份文本产出要素核对表，缺失项均附后果说明。
3. **判定**：关键要素缺失且后果触及"无法证实/无法执行"→ 判"目标不可证实"或"程序不可执行"，按不符合项流程处理（衔接 isms-nonconformity-grading-loop）。
   - 判停条件: 若文本连基本框架都没有（纯口号、无任何要素）→ 不必逐项反证，直接判"文本不适宜"，转入文件评审暂停分支（isms-two-stage-audit-gate 步骤 4）。
4. **改写**：给出补全要素的可审计改写——who（责任角色）、time（时限值）、measurable（度量值与验证载体）、what/how（动作）。
   - 完成标准: 每个缺陷条款附一条改写建议，改写后的条款能直接回答"怎么验证"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 非承诺类文本（背景说明、培训材料、宣传文案）——不承担可执行义务，反证无对象。
- 已有充分运行实测证据的成熟流程——文本瑕疵降级为观察项，不必按不可执行重判。
- 一次性、非体系化的临时规定（值班表、一次性授权）——要素按需简化，套满六问是过度审核。

### 作者在书中警告的失败模式

- ce30：目标不满足 SMART——不明确的目责任人不识别、不可测的目标无法证实实现、无时限的目标"很可能没有行动"。
- ce31：方针/程序缺 5W1H 要素——只有口号，缺谁做/何时/为何/做什么/在哪/怎么做，"方针是否可执行、可审核"的最低标准不成立。

### 作者的盲点 / 时代局限

- **版本提示**：SMART/5W1H 为通用管理工具，与标准版本无关，可直接沿用；但书中条款挂接（4.2.1 b/c）基于 27001:2005，现行 27001:2013/2022 的 6.2 已明确目标须可测量并回答 who/what/监测方式/何时完成/如何评价——与本方法高度同构，换版后判据反而更硬。
- 作者给了后果链但无企业实测数据（多少目标因不可测而失效），属规范性推演。
- 对"谁来写后果链"（审核员 vs 文本作者自评）未区分，自评时容易自我豁免。

### 容易混淆的邻近方法论

- 需求工程的可验证需求写法（"shall + 验证方法"）：同族思想在工程侧的应用；本方法面向管理文本，判据集为 5W1H/SMART。
- OKR/INVEST 等目标管理框架：目的在激励与交付管理，本方法只回答"可不可审计、可不可证实"。
