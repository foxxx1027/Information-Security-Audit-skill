# 降级取证（到期数据不足时以配置证据替代实效证据并标明层级）

## R — 原文 (Reading)

> "注：对于刚运行不久的新系统，审计日志还没到约定的保存期限，在这种情况下，为了实现下面2.3，2.1和2.2必须进行检查"
>
> — 原作者、原作者，原始方法论来源第6章 6.4.2 审计日志·实践指南注（source.txt L5196–5197，OCR 原样保留）

## I — 方法论骨架 (Interpretation)

有些控制的效果要等时间过去才能验证（日志保存 6 个月、SLA 运行一年、备份保留三年）。受审对象太新、合作太短，实测法在物理上不可能成立——机械套用会把"尚未到期"误判成"不符合"。

本方法的处理是三步：

1. **先判可实证性**：证据要求的观察期是否已经过去？没有 → 实测路线作废。
2. **降级到约定层 + 配置层**：查合同/SLA/策略中写明的承诺（约定层），再查系统当前配置是否使承诺在未来可兑现（保存周期配置、计费存储设置、留存策略）。
3. **把降级本身写成审核输出**：结论标注"配置级证据、待约满后复核"，写入报告的"可能降低结论可靠性的不确定因素和/或障碍"栏（第4章 4.3 报告必须包含此项）。

关键点：开"暂不符合"或"符合"都是错的——证据只支持"配置就绪、实效待验"这一中间结论。审核结论的可信度建立在如实披露"没看到什么"之上。

## A1 — 书中的应用 (Past Application)

### 案例 1: 新系统日志保存期限（6.4.2）
- **问题**: 约定日志保存 12 个月，系统刚上线 2 个月，"回溯 12 个月日志"的实测（2.3）不可能执行。
- **方法论的使用**: 作者注规定：此时必须退回 2.1（设计文档中的保存期限）+ 2.2（系统配置与实际留存设置）补证。
- **结论**: 用"策略 + 设计 + 配置证明未来可保存"替代"历史实测"，避免新系统被机械误判。
- **结果**: 书中将该处理固化为 2.3 的注，作为保存期限检查的标准分支；未附实测案例。

### 案例 2: 报告的不确定因素栏（第4章 4.2.2/4.3）
- **问题**: 证据受限时审核报告怎么写才不越权？
- **方法论的使用**: 第4章要求报告必须载明"可能降低结论可靠性的不确定因素和/或障碍"，且审核计划保持灵活性——证据受限时如实记录边界是同一原则在报告端的落点。
- **结论**: 披露不确定性不是削弱报告，而是给结论划定有效范围。
- **结果**: 与首次会议"告知证据基于样本、存在不确定因素"（`isms-sampling-uncertainty-disclosure`）构成三处闭环披露。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 验收/审计一家合作仅 3 个月的 SaaS 或外包供应商，合同承诺（日志留存、SLA 可用率、事件响应时限）观察期未满。
2. 组织新上线系统（统一日志平台、SIEM、备份系统）不满一个考核周期，内审要对其留存/恢复承诺下结论。
3. 写审核报告时，发现部分检查项证据只到配置层，需要合规的结论措辞。
4. 供应商声明的年度指标（RPO/RTO/检测率）年内尚无完整周期数据可查。
5. 被审方质疑"你们没看到的就判不符合？"，需要程序化回应。

### 语言信号 (用户的话里出现这些就应激活)

- "系统才上线 X 个月，日志/数据还没到期，怎么审？" / "data not yet due"
- "合同签了没多久，SLA 还没有完整周期数据" / "SLA observation period not elapsed"
- "证据不足能不能先开个'暂不符合'？"（应回答：不能，降级并披露）
- "报告里这段结论怎么措辞才不越权？" / "qualified conclusion wording"
- "配置都对，就差运行数据，能不能给符合？"（不能给，给配置级结论）

### 与相邻 skill 的区分

- 与 `isms-three-layer-evidence-chain`：那是完整三层走到底的默认路径；本 skill 只在其运行层"客观不可得"时接管，且必须书面声明降级。
- 与 `isms-sampling-uncertainty-disclosure`：抽样披露处理"看得但只看了部分"，本 skill 处理"这一层根本还没发生"；两者都写入不确定因素栏但成因不同。
- 与 `isms-test-event-method`：测试事件可主动制造运行证据；若受控触发可行，优先触发而非降级（例如验证"会记录"不必等真实事件）。

## E — 可执行步骤 (Execution)

1. **确认承诺与观察期**：找到被审承诺原文（合同条款/策略/SLA），计算其验证所需观察期，与对象实际存续时间比较。
   - 完成标准: 一张对照——承诺项 | 所需观察期 | 实际已存续时间 | 是否可实测。
2. **判停分流**：观察期已满 → 退出本 skill，回 isms-three-layer-evidence-chain 第 4 步实测；未满 → 继续。
   - 判停条件: 若承诺本身未被任何文件写明（连约定层都没有）→ 这不是降级问题，是承诺缺失，转 isms-nonconformity-grading-loop 判不符合。
3. **取约定层证据**：摘录合同/SLA/策略中的承诺值与时限，注明文件名与版本。
   - 完成标准: 每项承诺有原文出处。
4. **取配置层证据**：核对当前配置使承诺"到期可兑现"（留存周期设置、计费/容量、导出能力）。
   - 完成标准: 每项承诺对应一条配置实测值；无法兑现的配置直接列为发现。
5. **写降级结论**：结论措辞为"配置级证据表明承诺可兑现，实效待观察期满后复核"，并给复核时点。
   - 完成标准: 结论句含证据层级声明 + 复核时点 + 写入报告不确定因素栏。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 观察期已满、运行数据可得——降级是没有理由的，直接实测；此时用降级措辞是遮掩取证懒惰。
- 承诺本身缺失/配置与承诺矛盾——那是实质不符合，不是证据不足，不许用"降级"洗白。
- 一次性事件类验证（如"上线时做了恢复演练"）——要么发生过有记录，要么没有，不存在"待到期"。

### 作者在书中警告的失败模式

- ce21：对日志保存期限仅做时间戳推断（新系统误判）——"拿日志最早/最晚时间戳直接推断保存期限是否达标"是陷阱。
- 报告漏载不确定因素即违反 4.3 的报告必备内容要求（第4章）。

### 作者的盲点 / 时代局限

- **版本提示**：出处 6.4.2 基于 27001:2005 A.10.10；现行 27001:2013/2022 对日志留存无固定期限要求（由组织自定并保持一致），"约定保存期"应映射为组织自己的策略/法规义务（如网安法等级保护要求 ≥6 个月，属中国法规而非 ISO 条款）。
- 作者只给了一处降级示范（日志保存期），合同/SLA 类降级是该方法的外推（verified.md V2 已验证可外推至 SaaS SLA），书中无更多展开。
- 第三方认证视角：内审使用时应保留"降级必须书面披露"的纪律，但复核时点可按内部节奏定。

### 容易混淆的邻近方法论

- "暂缓结论/搁置"：管理上的缓议不等于审核上的降级——降级必须给出配置级结论和复核时点，不能悬空。
- 保留意见（qualified opinion）式审计语言：同族思路，但本方法要求的是"证据层级声明"，不是笼统保留。

## 相关 skills

- 依赖 `isms-three-layer-evidence-chain`：降级只在三层链的运行层"客观不可得"时接管——不理解完整三层路径，就无从判断"哪一层断了、能不能降"。
- 对比 `isms-test-event-method`：运行证据缺失时的两条出路——受控触发可行则优先制造证据（它），观察期物理上未到才降级披露（本 skill）；看情境选一。
- 组合 `isms-sampling-uncertainty-disclosure`：两类局限同写报告"不确定因素"栏——本 skill 披露"这一层还没发生"，它披露"只看了样本"；成因不同、栏目相同、都不可省。
- 组合 `isms-recovery-time-verification`：服务刚上线、演练窗口未满时，先按本 skill 出配置级结论并约期实测，到期由它做耗时实测——降级不是替代演练。
- 组合 `isms-network-service-three-line-audit`：其日志线"由供应商持有且不可导出"时，按本 skill 降级并披露，或改要求第三方鉴证报告。
