# 文件评审一致性核对法（程序↔产出互证、强制文件差集、SoA 完备合理）

## R — 原文 (Reading)

> "针对ISMS审核活动中文件评审需要特别注意：
> （1）文件体系的完整性；
> （2）风险评估程序与风险评估报告的一致性；
> （3）风险处置程序与风险处置计划的一致性；
> （4）适用性声明的完备性和合理性。"
>
> — 原作者、原作者，原始方法论来源第4章 4.1 文件审核（source.txt L2445–2449）

## I — 方法论骨架 (Interpretation)

文件评审不是通读文档打印象分，而是**核对几组固定关系**。文件可以造假，关系很难同时造圆：

1. **完整性 = 差集核对**：拿标准（或合同/框架）要求的强制文件清单，与实有文件做差集——缺强制文件就是体系要素缺失的直接证据，连深查都省了。
2. **程序↔产出互证**（本方法核心）：风险评估程序写了步骤，评估报告是否真按这些步骤产出？处置程序与处置计划是否对得上？"程序说的"与"产出物"对得上，文件才可信——表演性文件（为审核而编）在程序与产出的缝隙处最先穿帮。
3. **SoA 完备合理**：控制清单既是文件又是审核准则，其完备性与合理性单独成查（细节转选控双向说理）。
4. **多体系加查**：多套体系文件并存时，增设"不同管理体系文件之间的一致性检查"——两套文件对同一对象的要求不打架、不遗漏。

断链不等于直接开不符合，而是"文件与运行脱节"的信号——指向该领域需要现场深查运行证据。

## A1 — 书中的应用 (Past Application)

### 案例 1: 第一阶段文件评审四查（第4章 4.1，cs13）
- **问题**: 第一阶段文件评审审什么？只看文件齐不齐吗？
- **方法论的使用**: 作者压缩成四项特别注意：完整性、评估程序↔报告、处置程序↔计划、SoA 完备合理——后三项全部是"程序与产出物互相印证"式检查。
- **结论**: 文件评审的对象是四组**对应关系**，不是文件的文采与厚度。
- **结果**: 四查成为一阶段文件阶段的硬核内容，任何一项断链即一阶段不通过的信号。

### 案例 2: 表4-1 强制文件差集核对（第4章，cs14）
- **问题**: "必须成文的项"与"组织自选的项"怎么分？
- **方法论的使用**: 依据 27001 4.3.1 编制强制性文件列表，逐条给出"标准原文→对应文件"映射，受审方文件清单与表 4-1 做差集。
- **结论**: 缺强制文件=体系要素缺失的直接证据，防止把"必须成文"误当可选。
- **结果**: 差集核对成为文件齐套性检查的对照底表。

### 案例 3: 结合审核的文件间一致性检查（第7章 7.2.2，cs48）
- **问题**: 两套体系文件各自独立时，结合审核怎么防"文件打架"？
- **方法论的使用**: 分散文件情形下增设"不同管理体系文件之间的一致性检查"步骤，确保要求上的一致性。
- **结论**: 一致性核对法从单体系扩展到多体系文件关系。
- **结果**: 成为结合审核路径二（各自独立文件）的必增步骤。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 认证一阶段/内审首轮的文件评审，需要一套不流于"翻目录"的核对法。
2. 穿透云供应商"表演性"安全白皮书：判断认证材料是抄的还是真的。
3. 并购/合作尽调：审目标公司的制度文件是否与实际运行脱节。
4. 组织整合多体系（27001+9001+27701）后核对文件间是否冲突。

### 语言信号 (用户的话里出现这些就应激活)

- "文件评审到底审什么？" / "document review checklist"
- "白皮书/认证材料怎么判断是不是抄的？"
- "程序文件和实际记录对不上" / "procedure doesn't match records"
- "两套文件要求打架怎么办？" / "conflicting requirements across documents"
- "第一阶段文件看多久、看多深？"

### 与相邻 skill 的区分

- 与 `isms-counterfactual-document-review`：那是单份文本的要素质量（缺了会坏什么）；本 skill 是跨文件的关系核对（程序↔产出、文件↔文件）。先单份后关系，顺序不颠倒。
- 与 `isms-soa-justification-traceback`：SoA 完备性是四查之一；控制选与不选的双向说理展开用该 skill，本 skill 只管"有没有、完不完整"入口判断。
- 与 `isms-two-stage-audit-gate`：本 skill 的结论（文件不适宜不充分）触发该 skill 的暂停分支——核对法是门禁的判据来源。

## E — 可执行步骤 (Execution)

1. **强制文件差集核对**：列准则要求的强制/必备文件清单，与实有文件做差集。
   - 完成标准: 差集表（缺失项 | 对应的准则要求条目）。
2. **程序↔产出配对互证**：至少核对风险类两对（评估程序↔评估报告、处置程序↔处置计划），并按场景追加对子（事件响应程序↔事件记录、培训程序↔培训记录）。
   - 完成标准: 每对一张对照——程序规定的步骤/频次/角色 vs 产出物实际呈现，断链点显式标注。
3. **SoA/控制清单完备合理性核对**：确认清单三要素（所选控制及理由/实施状态/删减理由）存在，深度说理转 isms-soa-justification-traceback。
   - 完成标准: SoA 完备性结论 + 转办标注。
4. **多套文件加查一致性**（仅多体系场景）：抽同一对象在两套文件中的要求条款比对。
   - 完成标准: 冲突条款清单（对象 | 文件A要求 | 文件B要求 | 冲突性质）。
5. **汇总判定与分流**：断链项进入深查线索池（现场验证运行证据）、强制文件缺失按不符合处理、整体文件不适宜不充分则触发暂停决策。
   - 完成标准: 四组关系各有一句话结论 + 断链项去向（深查/开单/暂停）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 文件齐全且运行证据充分的成熟组织——一阶段可压缩，不要为查而查。
- 非体系类文档（营销材料、技术白皮书之外的产品手册）不在四查范围。
- 单份文本的写作质量问题（空洞、不可测）——先走反证式审读，不是关系问题。

### 作者在书中警告的失败模式

- ce49：第一阶段只看文件"有没有"，不做四项一致性核对——表演性文件轻松过关。
- ce39：分散文件下不增设文件间一致性检查，两套文件要求冲突无人发现。

### 作者的盲点 / 时代局限

- **版本提示**：表4-1 强制文件清单基于 27001:2005 4.3.1（文件化要求分散在多处）；2013/2022 版已将文件化信息要求合并至 7.5 且数量简化，清单必须按现行版本重建，否则差集核对会拿错基准。
- 书中假设"受审方文件齐备可读"，对文件严重缺失只给了暂停分支一条路；对电子化/在线文件库（如今常见）的抽样方式未涉及。
- 无据此判定不合格的实测记录，四查是规范性框架。

### 容易混淆的邻近方法论

- 文档成熟度评估（CMMI GG2 类）：重体系建设水平评价；本 skill 只做最小可行的关系核对。
- 版本控制/文档管理审计（有没有受控、审批）：那是文件管理控制的审核对象，不是本方法的核对内容——两者可在同一场审核中并行。
