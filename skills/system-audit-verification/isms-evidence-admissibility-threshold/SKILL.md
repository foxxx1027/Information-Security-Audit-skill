# 证据可证实门槛（与准则相关、能够证实、予以记录；听说/表态不是证据）

## R — 原文 (Reading)

> "现场调查的目的是收集和积累相关的、充分的、有说服力的和有用的证据，以得出正确的审核结论。只有能够证实的信息方可作为审核证据。审核证据应当予以记录。"
>
> — 原作者、原作者，原始方法论来源第4章 4.2.2 现场调查（source.txt L2755–2759）

## I — 方法论骨架 (Interpretation)

"要讲证据"人人会说，本方法把"证据"操作化为三道可检查的门槛：

1. **与审核准则相关**：信息必须能对照到某条准则（标准条款、策略、合同、法规）。与准则无关的八卦再真也不是审核证据。
2. **能够证实**：信息本身可被独立复查——记录、配置截图、日志条目、可复现的观察。传闻、"领导说了""供应商承诺过"、访谈中的口头表态，未证实前一律**不是证据，是线索**。
3. **予以记录**：不落记录的证据等于没取——记录载体（检查表、笔记、截图归档）是第三道门。

由此推出**线索与证据的两条处理路径**：线索可以也应该追查（顺藤取证），但不得直接作为开不符合的依据，也不得写入符合结论；口头陈述必须与配置观察、文件记录交叉印证后才升格为证据。这是证据法学式纪律在审核里的移植——防止审核员凭印象定案。

## A1 — 书中的应用 (Past Application)

### 案例 1: 现场调查双判据（第4章 4.2.2）
- **问题**: 现场收集来一大堆信息，哪些算证据？
- **方法论的使用**: 立两条判据——现场只能抽样，不可能查所有人和点；"只有能够证实的信息方可作为审核证据。审核证据应当予以记录"。
- **结论**: 收集→验证→记录三步缺一不可；传闻、未核实陈述一律不算。
- **结果**: 与首次会议的抽样性告知构成同一条原则的会议端与现场端（verified.md V1）。

### 案例 2: 证据定义三重限定（第1章 1.1）
- **问题**: "审核证据"的正式边界是什么？
- **方法论的使用**: 定义=与审核准则有关并且能够证实的记录、事实陈述或其他信息。
- **结论**: 三重限定（相关、可证实、是记录/陈述/信息载体）成为全书证据观的定义基座。
- **结果**: 三层取证（`isms-three-layer-evidence-chain`）以"越靠近运行记录证实度越高"落实同一门槛（第6章）。

### 案例 3: 口头承诺处理（V2 外推示例）
- **问题**: 云供应商口头承诺"静态数据都是加密的"，这句话怎么处理？
- **方法论的使用**: 承诺与准则相关，但未证实前只是线索——要求出示可证实载体（存储配置、密钥管理说明、第三方鉴证），记录载体名与获取人，交叉印证后才升格。
- **结论**: 不能直接写入符合结论，也不能凭直觉开不符合。
- **结果**: verified.md V2 判定为该方法对新场景的有效外推。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 访谈听到"我们都有做"类表态，决定能否据此下结论。
2. 供应商/云厂商口头或宣传材料声称某能力，审核要落地成证据。
3. 写审核发现时被质疑"你这条依据是什么"，需要证据资格自查。
4. 团队审核口径培训：区分线索、证据、结论三层。
5. 事件复盘会上各方转述矛盾，需要裁决哪些可采信。

### 语言信号 (用户的话里出现这些就应激活)

- "他们口头说做了，这算证据吗？" / "is verbal assurance evidence?"
- "'听说/据说'能写进审核报告吗？"
- "供应商宣传白皮书里说的能信吗？"
- "这条发现的证据链是什么？" / "what is your evidence?"
- "evidence vs lead / hearsay in audit"

### 与相邻 skill 的区分

- 与 `isms-three-layer-evidence-chain`：本 skill 判"够不够格当证据"；三层链是"合格证据怎么取、取多深"。门槛在前，路径在后。
- 与 `isms-sampling-uncertainty-disclosure`：本 skill 处理单条信息的资格；抽样披露处理"合格证据总量只覆盖了样本"这一总体局限。
- 与 `isms-interview-questioning-discipline`：访谈纪律保证取到的陈述不被引导污染；本 skill 决定陈述本身的证据地位（陈述仍需印证）。

## E — 可执行步骤 (Execution)

1. **标注信息来源**：对每条待用信息标来源类型（文件记录/系统观察/口头陈述/第三方转述/宣传材料）。
   - 完成标准: 信息清单带来源列。
2. **过三道门槛**：逐条问——相关（对应哪条准则）？可证实（独立复查的载体是什么）？已记录（落在哪个载体）？
   - 完成标准: 每条信息标"证据/线索"二值；线索标注缺哪道门。
3. **线索追查或降级**：线索类信息——能取载体的索取载体（配置截图、文件、鉴证报告，记录获取人与时间）；取不到的登记为"待证实"，不进入结论。
   - 判停条件: 若关键判据全部只有线索级信息 → 该检查项按证据不足处理（披露），不得硬判符合或不符合。
   - 完成标准: 追查动作与结果记录在案。
4. **交叉印证升格**：口头陈述与独立来源（配置、记录）比对一致后升格为证据；矛盾处记为发现线索。
   - 完成标准: 升格项有"陈述+印证载体"双来源。
5. **结论绑定**：报告中每条结论/发现只引用证据级信息，线索级信息单独列入"待证实事项/不确定因素"。
   - 完成标准: 结论句引用可复查载体；无私据。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 决定"怎么取证"（方法选择）——那是三层取证/测试事件等技能的事。
- 对"样本是否代表总体"的担忧——用抽样披露技能，与单条证据资格无关。
- 法律取证/诉讼证据链要求（哈希固化、司法鉴定程序）——同名"证据"不同规则，审核证据标准低于司法但方向一致。

### 作者在书中警告的失败模式

- 凭访谈印象开不符合（第4章"只有能够证实的信息方可作为审核证据"的直接反面）。
- 外部报告只听受审方转述而不取原件（rejected.md 归并的"外部报告勿只听受审方"语境）。
- 证据不记录——"审核证据应当予以记录"，口头结论事后无法复查。

### 作者的盲点 / 时代局限

- **版本提示**：三门槛源自 GB/T19011—2003/ISO 19011:2002 证据定义；19011:2018 表述微调（基于证据的方法、审核证据的可验证性）但三门槛实质未变，可直接沿用；相关准则涉及 27001:2005 条款时须映射 2013/2022 版。
- 书中未展开"可证实"在数字化远程审核下的形态（截图的元数据、导出日志的完整性校验），远程审核（19011:2018 新增）需补充取证保全手段。
- "能够证实"的边界（证人陈述算不算可证实）书中未深究——本书立场：陈述需印证，单独不构成。

### 容易混淆的邻近方法论

- 法律证据规则（传闻排除规则等）：形似但服务于裁判；审核语境更宽松（陈述+印证即可），纪律目的相同——防凭印象定案。
- 事实核查（fact-checking）：针对断言真伪；本 skill 额外要求"相关+记录"两道门。
