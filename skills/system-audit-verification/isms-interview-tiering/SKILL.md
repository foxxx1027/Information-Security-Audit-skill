# 访谈分层体系（一般性/针对性 × 代表性/特定/综合，绑定"存在→正确→有效"证据深度）

## R — 原文 (Reading)

> "综合访谈提供一定的覆盖面，从而可以判断控制措施是否执行且没有明显的错误，以及是否有可以提供额外的证据用以断控制措施是否被正确实施并按预期进行操作，而且提供证据支持来判断控制措施有效性、是否在持续改进。"
>
> — 原作者、原作者，原始方法论来源第6章 6.2.2 针对性访谈·3.综合访谈（source.txt L4729–4733，OCR"用以断控制措施"缺字原样保留）

## I — 方法论骨架 (Interpretation)

访谈不是聊天，也不是"聊得越多越好"——它是一台测量仪器，**档位就是量程**。选错档位，结论就超量程。

本书把访谈拆成两级五档，每档绑定一种它能支撑的结论：

1. **一般性访谈**（6.2.1）：高水平问题、广泛讨论，只能判"控制措施是否执行且没有明显错误"——到此为止。
2. **针对性访谈**（6.2.2）三档递进：
   - **代表性**：在关键组织角色中选代表，保证覆盖面——仍是"实施+无明显错误"级；
   - **特定**：追加对评审目的重要的特定人群，多取一层"被正确实施并按预期操作"的证据；
   - **综合**：再进一步，提供"有效性、是否在持续改进"的证据。
3. 档位与结论权限一一对应：存在→正确→有效。只做了员工代表的一般性访谈就写"控制有效"，是仪器读数越界。
4. 取证前按**关注项**（人力资源和安全/方针/组织/物理环境/事件管理等）预制问题清单，对 13 类访谈对象配题——访谈是设计出来的，不是现场即兴。

## A1 — 书中的应用 (Past Application)

### 案例 1: 按关注项预制访谈问题清单（6.2.3，cs25）
- **问题**: 非技术性控制（意识、职责、物理）没有配置和日志可查，现场时间又有限，怎么取证据？
- **方法论的使用**: 作者给出"访谈关注项 × 参考问题"对照设计，如人力资源和安全项下问"员工是否认识到自己的责任并为行为负责？是否有随时可获得的安全知识解答与激励？"，覆盖方针、组织、物理环境、事件管理等类目、13 类访谈对象。
- **结论**: 访谈的价值密度取决于事前按关注项配题，而非现场发挥。
- **结果**: 该清单被定位为"非技术性控制措施有效性审核的支持工具"，成为第6章管理控制审核的标准准备动作。

### 案例 2: 一般性访谈的用途限定（6.2.1）
- **问题**: 广泛聊聊能不能顺便判断控制有效性？
- **方法论的使用**: 作者明确定界：一般访谈"判断控制措施是否执行且没有明显的错误"——判断"正确实施"须进入针对性访谈并可辅以测试手段。
- **结论**: 档位即结论权限，浅档不得出深结论。
- **结果**: 与 6.2.2 三档构成完整的"存在→正确→有效"阶梯，供审核员按需选档。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 内审前规划访谈对象名单与深度：全员远程办公组织的终端安全控制，找谁谈、谈到哪层。
2. 供应商尽调：要判断其"安全意识培训"控制是有效运行而非仅有台账。
3. 认证审核现场安排：哪些角色一般性访谈即可、哪些必须综合访谈（如安全负责人须拿出改进证据）。
4. 事故复盘/控制有效性评估：需要"持续改进"层证据支撑管理评审输入。

### 语言信号 (用户的话里出现这些就应激活)

- "访谈该找哪些人、谈到多深？" / "who to interview and how deep"
- "抽几个员工聊聊能不能证明控制有效？"（不能——档位不够）
- "访谈问题怎么设计？按什么分类？" / "interview question design"
- "非技术控制/意识类控制怎么审？" / "soft controls audit"
- "有效性证据除了日志还能从访谈拿吗？"

### 与相邻 skill 的区分

- 与 `isms-interview-questioning-discipline`：那是单场访谈现场的提问纪律（避免引导性提问、结尾总结评审）；本 skill 在其上游，管访谈前的对象选择与深度设计。先本 skill 定档定人，再由它执行单场纪律。
- 与 `isms-four-column-checklist-design`：检查表把 shall 转成检查题；本 skill 把问题匹配到"对象×深度"，是检查题在访谈侧的调度层。
- 与 `isms-three-layer-evidence-chain`：三层取证管技术控制（文档→配置→运行记录）；本 skill 管管理/非技术控制的访谈证据——两者拼起来才是完整的证据面。

## E — 可执行步骤 (Execution)

1. **定结论层级**：明确本次审核要对这项控制下什么层级的结论——存在（有没有执行）/ 正确（是否正确实施）/ 有效（有效性+持续改进）。
   - 完成标准: 每个待审控制标注目标结论层级。
2. **按关注项列问题清单**：对照类目（人力资源和安全、方针、组织、物理环境、事件管理，可按现行标准扩展）为每项控制配问题。
   - 完成标准: 问题清单覆盖全部待审控制，每个问题可归入一个关注项。
3. **选档配对象**：存在层→一般性访谈（各部门代表即可）；正确层→代表性+特定访谈（关键角色+对该控制重要的特定人群）；有效层→综合访谈（安全负责人/运维，须能出示改进记录与测量结果）。
   - 完成标准: 访谈计划表——问题 | 档位 | 对象角色 | 预期证据。
4. **档位-结论匹配校验**：起草结论前核对"取样档位是否支撑结论层级"。
   - 判停条件: 若结论需要有效层而取样止于存在层 → 退回步骤 3 补档，不得先写结论。
5. **有效性结论交叉印证**：有效层结论与运行记录（isms-three-layer-evidence-chain）、必要的受控测试（isms-test-event-method）交叉，访谈不单独支撑有效性。
   - 完成标准: 有效层结论至少有一个非访谈证据源。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 技术配置类取证（查设置、翻日志）——直接用三层取证，访谈只作辅助。
- 只需存在性判断且只有一轮访谈机会的场景——不必铺五档，一般性访谈+记录即可。
- 对外部专家的技术咨询式交流——不产生审核证据，无档位可言。

### 作者在书中警告的失败模式

- 只做一般性访谈（找员工代表广泛聊聊）就下"控制有效"结论——档位错配，书中明文限定一般访谈止于"执行且无明显错误"。
- 访谈对象全部落在一线而缺关键组织角色——代表性访谈明确要求"关键的组织角色中选取"，覆盖面不足即取样失效。

### 作者的盲点 / 时代局限

- **版本提示**：13 类访谈对象与关注项类目基于 27001:2005 附录A 11 域结构；2013/2022 版控制已重组（114→93 项、4 主题，新增云/数据脱敏/威胁情报类），关注项清单须按现行标准重映射后方可用于配题。
- 书中无访谈命中率/证据转化率数据，档位与结论权限的绑定是规范性设计，未附实测校验。
- 远程/视频访谈的节奏与记录问题（19011:2018 已补充远程审核方法）书中未涉及。

### 容易混淆的邻近方法论

- 结构化访谈（structured interview）/ 关键知情人访谈（KII）：社会研究同族方法；区别在本 skill 把档位与"审核结论权限"显式绑定——档位不够就不许下深结论。
- 焦点小组（focus group）：团体访谈形态在本 skill 的一般性访谈中被提到，但其目的是取证不是激发讨论。
