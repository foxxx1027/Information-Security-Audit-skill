# 不符合项判定与分级闭环（判定纪律、三级判据、答否开单、评审确认、有效性验证）

## R — 原文 (Reading)

> "（1）缺少，或不执行一个以上所需要的体系要素（如ISO/IEC27001：2005标准4～8章中任何一条要求，或ISMS方针和程序）；"
>
> — 原作者、原作者，原始方法论来源第1章 1.1 审核发现分级·重大不符合判据一（source.txt 第1章）

## I — 方法论骨架 (Interpretation)

发现问题后不能凭"感觉严重"定级。本方法是一整条判定与闭环链：

**先过判定纪律**：开不符合的依据只能是强制要求（shall/组织自己定义的策略、合同、法规）；实施指南、最佳实践建议（如 CIS 基线、通用导则）**不能直接开不符合**——"某些内容可能不适用所有情况，其他实现方法可能更合适"（第2章）。

**再套三级判据**：
- **重大不符合**：①缺少或不执行所需体系要素（该有的过程整个没有）；②对满足已识别要求存在重大怀疑；③一般不符合持久、稳固存在，可升级为重大。
- **一般不符合**：不会造成体系崩溃、容易纠正的较轻缺陷（个别记录不完整、个别缺陷未按期纠正）。
- **观察项**：当时不会造成有意义影响、但审核员认为有潜在影响的发现——**不是不符合**，带"下次审核跟踪澄清"义务。把观察项当不符合开、或反之，都是分级错误。

**然后走闭环**：检查表答"否"即不符合项，一般应开报告要求纠正措施并说明理由（第5章）；与受审方一起评审发现，确认证据准确性、记录未解决分歧（第4章）；关闭判据是**验证纠正措施完成情况与有效性**——"交了整改计划"不等于关闭。

## A1 — 书中的应用 (Past Application)

### 案例 1: 三级判据（第1章 1.1）
- **问题**: 同样是发现"漏洞"，怎么区分重大与一般？
- **方法论的使用**: 给出判据链——缺/不执行体系要素→重大；重大怀疑→重大；一般不符合持久稳固→升级重大；轻缺陷易纠正→一般；潜在影响→观察项（跟踪澄清）。
- **结论**: 分级是判据推导，不是严重性直觉。
- **结果**: 全书不符合处理均以此为纲（第5章检查表答案、第4章发现评审都挂回此分级）。

### 案例 2: 答否开单（第5章 5.2.2）
- **问题**: 检查表答了"否"，发现怎么落地？
- **方法论的使用**: "这个审核的结果应属于不符合项，一般应该开出不符合项报告，要求组织采取纠正措施……对于'否'的答案，应说明理由"（L3026–3028）。
- **结论**: "否"与开单刚性绑定，不许私下消化。
- **结果**: 检查表与不符合台账可逐条对账（审核落点）。

### 案例 3: 评审确认与有效性关闭（第4章 4.2.2/4.4）
- **问题**: 审核组内部定案就写报告，行吗？
- **方法论的使用**: "应当与受审核方一起评审不符合，以确认审核证据的准确性"；纠正措施须验证完成情况与有效性，努力解决分歧并记录未决事项。
- **结论**: 不评审=程序缺陷；只收计划不验证=未关闭。
- **结果**: 形成"发现→评审→纠正→验证关闭"完整闭环。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 现场/演练/扫描后发现一个问题，纠结开重大、一般还是观察项。
2. 被审方抗议"这条不能开不符合，那只是最佳实践"——需要判定纪律支持。
3. 整改跟踪：收到整改计划，决定能不能关闭不符合项。
4. 内审报告撰写：给每条发现定级并写理由。
5. 红队/渗透结果转化成管理体系发现时的定级。

### 语言信号 (用户的话里出现这些就应激活)

- "这个问题开重大还是一般？" / "major or minor nonconformity?"
- "观察项算不算不符合？"（不算——带跟踪义务的第三级）
- "基线/最佳实践没做到，能开不符合吗？"（不能直接开）
- "他们交了整改计划，可以关单了吗？"（不能——验证有效性）
- "nonconformity grading / corrective action closure"

### 与相邻 skill 的区分

- 与 `isms-evidence-admissibility-threshold`：证据门槛管"这条发现有没有资格成为发现"；本 skill 管"合格的发现怎么定级与闭环"。先后关系。
- 与 `isms-four-column-checklist-design`：检查表的"否"是本 skill 的输入；本 skill 的分级结论回写台账。
- 与 `isms-two-step-conformity-audit`：过程整体缺失（第一步不过）直接构成重大判据①；两步法是本 skill 重大判据的主要供给者。

## E — 可执行步骤 (Execution)

1. **核对证据资格**：确认发现背后有可证实证据（记录/事实/观察），传闻与推定退回取证。
   - 完成标准: 发现句式="证据 X 与要求 Y 不符"，X 有载体可复查。
   - 判停条件: 证据只是线索 → 转取证（isms-three-layer-evidence-chain / isms-test-event-method），不定级。
2. **核对判定依据**：找到被违反的强制要求原文（shall/组织策略/合同/法规）；指南性内容 → 不得开单，只能作观察建议。
   - 完成标准: 要求原文与出处绑定到发现。
3. **三判据定级**：逐问——该体系要素整体缺失或不执行？→ 重大；对满足已识别要求有重大怀疑？→ 重大；一般不符合持久稳固？→ 升级重大；轻缺陷易纠正？→ 一般；暂无实质影响但需跟踪？→ 观察项。
   - 完成标准: 定级附一句判据引用（不是"感觉严重"）。
4. **开单与评审**：按"否必开单+说明理由"开不符合报告；与受审方一起评审发现，确认证据准确性，记录未解决分歧。
   - 完成标准: 受审方知悉/异议记录在案。
5. **有效性验证关闭**：核对纠正措施已完成**且有效**（措施落地证据 + 防再发验证），非仅收计划。
   - 完成标准: 关闭记录含"完成情况 + 有效性验证"两栏证据；观察项登记下次跟踪项。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 证据尚未收集/证实——先过证据门槛，跳级定级会被推翻。
- 风险处置类判断（某风险接不接受）——那是风险决策（isms-risk-acceptance-criteria-first），不是不符合。
- 技术漏洞的修复优先级排序（CVSS 打分）——严重性评分≠体系不符合分级，两者判据不同源。

### 作者在书中警告的失败模式

- ce27：检查题答"否"却不开不符合项报告——"否"被私下消化，检查表与台账对不上账。
- ce28：审核发现不与受审核方一起评审确认——争议后置、纠正措施针对性差。
- ce08：把 27002 实施指南当唯一方法或强制项开不符合——"本指南的某些内容可能不适用所有情况"；观察项与一般不符合混用（第1章明确观察项不是不符合）。

### 作者的盲点 / 时代局限

- **版本提示**：重大判据①引用"27001:2005 标准 4～8 章任何一条要求"——27001:2013/2022 下章节号已变为 4–10 与重组条款（2022 另有"文件化信息的可用性"等新判据面），引用时映射现行版；三级分级模型本身为行业通识，仍与 19011:2018 及 IAF MD 系列实践兼容。
- 书中判据面向第三方认证（影响发证结论）；内审使用时"重大/一般"对认证的影响维度应替换为对内部风险与目标的权衡。
- "有效性验证"的具体方法书中未展开（如何验证不再发生），实操需结合测试事件/复抽样。

### 容易混淆的邻近方法论

- 风险等级评定（高中低风险）：基于后果×可能性；不符合分级基于**与要求的偏离程度与持续性**——高危风险可能只是观察项（尚无证据），低危问题可能是重大（要素缺失）。
- 缺陷严重级（bug severity）：产品缺陷管理，无"要素缺失/持久升级"类体系性判据。
