# 抽样性与不确定性披露（会前告知、会中记录、报告载明的三处闭环）

## R — 原文 (Reading)

> "（4）实施审核所用的方法和程序，包括告知受审核方审核证据只是基于可获得的信息样本，因此，在审核中存在不确定因素；"
>
> — 原作者、原作者，原始方法论来源第4章 4.2.2 首次会议·14 项议程之四（source.txt L2737–2738）

## I — 方法论骨架 (Interpretation)

审核永远在有限时间与资源下进行，证据必然建立在样本上——"抽样的合理性与审核结论的可信性密切相关"（第1章）。这不是缺陷宣言，而是必须被**程序化管理**的结论边界。本书把它落成三个可核查的动作：

1. **首次会议告知**：14 项议程中单列一项，明确告知受审核方"证据只是基于可获得的信息样本，因此存在不确定因素"。
2. **末次会议提示**：必要时告知可能降低结论可信度的情况。
3. **报告载明**：审核报告必须包含"可能降低结论可靠性的不确定因素和/或障碍"。

三处闭环的意义：把认识论限制（看不到全部）转化为**程序合规项**（漏告知=过程不符合），同时给结论措辞设限——只能说"所抽样本未见不符合"，不能说"全集团合规"。未披露局限的结论默认被高估；一旦未抽对象事后出事，披露记录是审核方唯一的程序抗辩。漏掉首次会议告知，争议发生时连程序依据都没有。

## A1 — 书中的应用 (Past Application)

### 案例 1: 首次会议议程第四项（第4章 4.2.2）
- **问题**: 抽样局限怎么从"审核员自知"变成"双方共识"？
- **方法论的使用**: 列入法定议程，会上口头披露并留会议记录痕迹。
- **结论**: 披露是会议动作，不是报告里一句套话。
- **结果**: cs17/ce22 记录该议程项；漏告知即审核过程不符合。

### 案例 2: 报告必备内容（第4章 4.3）
- **问题**: 结论写"符合"后，样本局限写不写？
- **方法论的使用**: 报告必须包含不确定因素和/或障碍——与首会告知首尾呼应。
- **结论**: 不确定因素栏与结论栏同等强制。
- **结果**: 三处（首会/末会/报告）一致披露构成闭环（verified.md V1）。

### 案例 3: 样本结论误用（第1章 1.2 + V2 外推）
- **问题**: 200 家连锁店抽 15 家全过，董事会上能宣布"全集团终端合规"吗？
- **方法论的使用**: 结论限定为"所抽 15 家样本未见不符合"，同时披露未覆盖的 185 家及抽样依据。
- **结论**: 结论可信度建立在"披露了什么没看到"之上。
- **结果**: verified.md V2 判定该方法可外推至多门店集团汇报场景。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 编写审核/验收/测评报告，需要规范的不确定性与局限性措辞。
2. 准备首次会议议程与说辞（首会告知环节）。
3. 向管理层/董事会汇报抽查结果，被追问"能不能代表全部"。
4. 抽样方案被质疑（抽了 15 家凭什么说合规），需要程序化回应。
5. 事后未抽对象出事，倒查审核结论边界是否当时已披露。

### 语言信号 (用户的话里出现这些就应激活)

- "抽查都过了，能不能说整体合规？"（不能）
- "审核报告的局限性/不确定因素怎么写？" / "limitations section"
- "首次会议都要讲什么？"（议程含样本性告知）
- "sampling limitation / sample-based conclusion wording"
- "没抽到的店出了事，审核结论站得住吗？"

### 与相邻 skill 的区分

- 与 `isms-multi-site-sampling-formula`：公式决定"抽多少、抽哪些"；本 skill 决定"抽完之后怎么说、怎么披露"。公式在前，披露在后。
- 与 `isms-evidence-admissibility-threshold`：证据门槛管单条信息的资格；本技能管总体结论的边界。一条证据完全合格，仍改变不了"结论基于样本"。
- 与 `isms-degraded-evidence-fallback`：降级披露处理"某层证据客观拿不到"；本 skill 处理"拿到的只覆盖样本"——都写入不确定因素栏，成因不同。

## E — 可执行步骤 (Execution)

1. **盘点抽样边界**：列出本次审核抽取对象 vs 未覆盖对象（门店数、系统数、记录期间、人员范围），以及抽样依据。
   - 完成标准: 一张"覆盖/未覆盖"对照清单 + 抽样理由一句话。
2. **首会告知**：首次会议议程中执行样本性告知，并在会议记录留痕。
   - 完成标准: 会议记录含告知条目（日期、到场人）。
   - 判停条件: 审核已在进行且首会漏告知 → 在末次会议补提示并在报告中书面载明，不能假装发生过。
3. **结论措辞限定**：所有结论句式改为样本限定式（"在所抽取的 N 个 X 中，未发现……"）。
   - 完成标准: 报告草稿中无全量断言（搜索"全部/所有/整体合规"类字样并改写）。
4. **报告载明**：报告"不确定因素和/或障碍"栏写入：未覆盖范围、抽样依据、影响结论的情形。
   - 完成标准: 该栏非空且与结论对应。
5. **末会与交付**：末次会议提示局限，报告交付时保留三处披露的一致性。
   - 完成标准: 三处（首会记录、末会记录、报告）内容一致可互查。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 设计抽样量与抽样对象——用 isms-multi-site-sampling-formula（本 skill 只管披露）。
- 单条证据真伪之争——用证据门槛。
- 全量核查（对象本就 100% 覆盖，如总部必查）——对全量对象不存在抽样局限，硬写披露反成噪音。

### 作者在书中警告的失败模式

- ce22：首次会议不告知"审核证据基于样本"的不确定性——"漏掉即形成审核过程的不符合"。
- ce23：把抽样结论当全量结论——"样本通过即宣布总体通过，样本失败即全盘否定"。
- 披露当作报告模板套话，未覆盖范围与抽样依据不落实（形同未披露）。

### 作者的盲点 / 时代局限

- **版本提示**：议程与报告项源自 19011:2002/GB/T19011—2003 的 14 项议程与报告要求；19011:2018 报告要素与远程审核表述有更新（如"审核证据的可获取性"），沿用时按现行版核对议程编号。
- 书中给了"必须披露"，未给"披露到什么颗粒度"（多少未覆盖算重大局限）——需按风险自行判断。
- 第三方认证语境下披露对发证结论的缓冲作用，内审语境应转译为对管理决策的边界说明。

### 容易混淆的邻近方法论

- 统计学的置信区间：抽样披露借用其思想但非统计推断——审核样本通常非概率抽样，不给区间，只给边界陈述。
- 免责声明：法律免责是推责任；本方法是**程序动作 + 措辞限定**，必须配合抽样合理性论证才有效，单写免责条款无效。
