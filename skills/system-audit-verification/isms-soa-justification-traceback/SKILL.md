# 安全要求回溯与 SoA 双向说理（选与不选都要理由，任抽控制回溯三来源）

## R — 原文 (Reading)

> "由于附录A推荐的控制目标和控制措施是最佳实践，所以如果没有正当性理由，都要加以选择，要防止漏选。"
>
> — 原作者、原作者，原始方法论来源第5章 5.3.2 4.2.1 j) 适用性声明·注释（source.txt L3295–3299，表格跨栏拼接按原行序复原）

## I — 方法论骨架 (Interpretation)

控制清单在本书里不是"越多越好"的购物车，而是**决策审计对象**——每一条"选了"或"没选"都是一个决策，决策都要留理由链：

1. **三来源回溯（正向）**：安全要求来自风险评估结果、法律法规与合同要求、组织自身业务要求。任抽一条已选控制，必须能对到三者之一——答不出即"选控无理由"，抄模板清单的典型症状。
2. **删减说理（反向）**：最佳实践清单（如附录 A）默认全选，未选的必须给正当性理由，且理由要能对到风险或情境（规模、法律冲突），不能是"嫌麻烦"。无理由漏选是要防的反向失败。
3. **起点清单的定位**：通用基线（27002 类"信息安全起点"）只是良好起点，"并不能取代基于风险评估而选择的控制措施"。
4. **SoA 双重身份**：既是受审方文件，又是审核准则——三内容（所选控制及理由/当前实施状态/删减及正当性）缺一不可审。

双向抽查合起来，"清单齐全"从合规证据降格为待验证表象。

## A1 — 书中的应用 (Past Application)

### 案例 1: SoA 三内容审核要点（第5章 5.3.2，cs23）
- **问题**: 4.2.1 j) 适用性声明条款怎么审？
- **方法论的使用**: 作者定要点：SoA 至少含三内容；"不选择的理由必须是合理的，或证明其是正当的"——因为附录 A 是最佳实践，不选就要给正当性理由，防止整体性推诿删减。
- **结论**: SoA 从一张清单升格为"选择理由 + 删减理由"的双向审核点。
- **结果**: 核三内容齐全后，再抽删减项逐条追问正当性，成为 5.3.2 的固定审法。

### 案例 2: 起点清单不能取代风险评估选控（第2章 0.6，ce04）
- **问题**: 组织直接采用标准/最佳实践的全套控制算不算完成选型？
- **方法论的使用**: 作者引标准原文定性："虽然上述方法被认为是一种良好的起点，但它并不能取代基于风险评估而选择的控制措施"（source.txt L1376–1377）——控制是否合适须由组织面临的特定风险确定。
- **结论**: 起点≠终点，跳过风险评估的清单是未完成选型。
- **结果**: 该定性成为 SoA 选控理由回溯的上位依据。

### 案例 3: 前言行业病灶的对位检查（前言，cs01/ce02）
- **问题**: "风险评估和控制措施脱节"这个行业病灶怎么在审核端戳中？
- **方法论的使用**: 前言批评从业者只抠条款字面、知其然不知其所以然；回溯法（抽控制问风险）正是让"脱节"当场显形的对位动作。
- **结论**: 回溯链断点=风险评估与控制脱节的直接证据。
- **结果**: 全书 SoA 审核均按"理由链存在性"展开。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 内审/外审抽核自家或受审方的 SoA、云安全控制清单，判断是不是抄模板。
2. 组织上云后控制清单迁移（本地清单直接搬上云），需要验证选型理由还成立。
3. 标准换版（27001:2005→2013/2022、等保换版）时重建 SoA 并保留说理。
4. 客户/监管问"你们为什么部署这些控制、为什么不做 X"时的说理准备。

### 语言信号 (用户的话里出现这些就应激活)

- "这份清单是不是抄的模板？" / "copy-paste SoA"
- "为什么没选 X 控制？要写理由吗？" / "tailoring justification"
- "控制怎么和风险对上？" / "trace controls to risks"
- "SoA 怎么审？" / "how to audit statement of applicability"
- "清单齐全是不是就合规了？"（不是——齐全只是表象）

### 与相邻 skill 的区分

- 与 `isms-control-equivalence-judgment`：它处理"这条控制做不到，替代措施是否等效达成目标"；本 skill 处理"选/不选的理由链是否存在"——一个说"为什么不做、拿什么兜底"，一个说"理由链在不在"。删减理由常引出等效判定，先说理后判等效。
- 与 `isms-document-consistency-matrix`：SoA 完备性是该 skill 四查之四的入口；本 skill 在入口之后做深度展开。
- 与 `isms-risk-acceptance-criteria-first`：准则是处置决策的标尺（处理/转移/规避/接受）；选控说理发生在处置决定为"处理"之后——处置链的上下游关系。

## E — 可执行步骤 (Execution)

1. **备齐三份底稿**：控制清单（SoA）、风险登记册（评估结果）、法规/合同要求清单。
   - 判停条件: 若没有风险登记册（回溯无对象）→ 这本身指向体系要素缺失，转 isms-two-step-conformity-audit 第一步查风险评估过程存在性，本流程暂停。
2. **正向抽样回溯**：任抽 N 条已选控制（覆盖高、中、低投入各档），逐条追问"对应哪条已识别风险/法规合同/业务要求"。
   - 完成标准: 抽样表——控制 | 来源类型（风险/法规合同/业务）| 具体条目编号；答不出的标记断链。
3. **反向抽样说理**：从未选/删减项中抽 N 条，追问删减正当性。
   - 完成标准: 删减理由表——未选项 | 所给理由 | 理由能否对到风险或情境；"不适用"无论证的标记。
4. **判定与开单**：断链项按不符合流程处理（个别项通常一般不符合；系统性抄模板、多数控制无理由可按缺体系要素方向升级，衔接 isms-nonconformity-grading-loop）。
   - 完成标准: 每个断链项有分级判定与去向。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 小型组织以行业基线为全部选型依据、且其风险情景与基线假设一致时——可接受简化说理，不要为说理而说理。
- 初始建设期的过渡清单——可标注"理由待回填"，但须带时限并纳入跟踪。
- 控制运行有效性验证——理由链审完才是"选对了"，"跑没跑"归三层取证管。

### 作者在书中警告的失败模式

- ce34：附录 A 控制无正当理由漏选——"最佳实践，无正当性理由都要加以选择，要防止漏选"。
- ce04：拿起点清单替代风险评估选控——新手组织最常见（怕麻烦、求速成）。
- 前言病灶：只抠条款字面，风险评估和控制措施脱节——回溯法正是其检测器。

### 作者的盲点 / 时代局限

- **版本提示（重点）**："附录 A 默认全选、删减须说理"的规则基于 27001:2005 附录 A（11 域 133 控制）；2013 版 Annex A 重构为 14 域 114 控制、2022 版再并为 4 主题 93 控制并引入属性，SoA 条款也从 4.2.1 j) 移到 6.1.3 d)（删减须有理由并形成文件）。**旧清单或旧条款号照搬即审错依据**，换版时须整体重映射。
- 书中未给"理由质量"的分级判据（何种理由算正当），实操依赖审核员判断。
- 前言只批评病灶，无修复期的过渡安排（如理由回填时限），易被形式化应对。

### 容易混淆的邻近方法论

- 控制基线符合性检查（CIS benchmark 类）：核对"配置是否符合基线"，不是"选型是否有理由"——对象与方向都不同。
- 风险处置计划评审（`isms-risk-acceptance-criteria-first`）：那是"处理/转移/规避/接受"四选决策的审查；本 skill 在"处理"落地为控制之后的清单层。
