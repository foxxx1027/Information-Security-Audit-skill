# 两阶段审核的阶段门禁（一阶段买信息与判断、整改后方可进二阶段、文件不充分可暂停）

## R — 原文 (Reading)

> "（1）影响进人第二阶段审核的问题（主要为信息安全法规风险、文件、策划、内审、
> 管评的问题）均已得到整改后方可进入第二阶段。"
>
> — 原作者、原作者，原始方法论来源第3章 3.5.5 第二阶段审核计划（source.txt L2359–2360，OCR"进人"原样保留）

## I — 方法论骨架 (Interpretation)

把一次完整评审拆成两个阶段的意义在于：**两个阶段买的东西不同**。一阶段买"信息与判断"——只覆盖部分要素、只找关键部门（管理者代表、策划归口、安全重点部门），用最小成本换取对受审方的判断力；二阶段才买"覆盖与证据"。一阶段不是缩小版的二阶段。

门禁是硬条件而非顺延安排：

1. **门槛问题清单化**：五类问题（法规风险、文件、策划、内审、管评）任一未整改，二阶段不启动——"已提交整改计划"不等于"已整改"。
2. **暂停分支**：文件质量差到不适宜、不充分时，审核组长的动作是通知各方并**决定继续或暂停**，而不是带着坏文件进场。
3. **校准点**：一阶段同时是信息校准机会——按一阶段实况调整二阶段的范围、人日与抽样。

这个"门槛准入 + 聚焦换信息 + 暂停分支"的三件套可迁移到任何分阶段评审（供应商准入、供应链审查、验收流程）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 第一阶段计划的要素与重点部门取舍（第3章，cs10）
- **问题**: 第一阶段审什么、找谁谈、审多深？
- **方法论的使用**: 作者规定一阶段只涉及部分要素（4.1、4.2.1–4.2.3、4.3.1、5.1、5.2、6、7，且不涉及要素的全部要求），重点部门圈定为管理者代表、体系策划归口部门、信息安全重点部门及保护部门，并要求这些部门时间充分；多现场时重点放总部并顺带定抽样方案。
- **结论**: 一阶段的价值密度取决于"聚焦"——用少量关键接触面换取对体系成熟度与风险的判断。
- **结果**: 该取舍被固化为 3.5.5 审核计划编制的组成要求，成为认证流程的标准节点。

### 案例 2: 文件不充分触发暂停决策（第4章 4.1）
- **问题**: 一阶段文件评审发现文件严重不良，怎么办？
- **方法论的使用**: "如果发现文件不适宜、不充分，审核组长应当通知审核委托方和负责管理审核方案的人员以及受审核方。应当决定审核是否继续进行或暂停，直到有关文件的问题得到解决。"（source.txt L2542–2543）
- **结论**: 文件质量是可触发暂停的独立判据，不是"扣点分继续走"。
- **结果**: 暂停决定权在审核组长，与 3.5.5 的整改门禁共同构成第一阶段的两道闸。

### 案例 3: 结合审核中的一阶段校准（第7章 7.2.1）
- **问题**: 结合审核策划信息不足时如何推进？
- **方法论的使用**: 作者允许"先带假设进现场"，在第一阶段结束后再按实际情况校准二阶段策划——阶段门禁同时被用作信息校准点。
- **结论**: 门禁不是纯阻拦装置，也是策划迭代的机会窗口。
- **结果**: 与 `isms-combined-audit-planning-calibration` 衔接为同一机制。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 认证机构/咨询顾问设计初次认证方案，划分一阶段文件评审与二阶段现场审核。
2. 企业做供应商准入：文档初审通过后决定是否进入现场/深度审计阶段。
3. 软件供应链/开源组件准入：SBOM 与声明材料初审后决定是否进入代码审计或渗透验证。
4. 内审负责人规划"先文件自查、后现场核查"的两轮内审，纠结第一轮发现的问题没改完要不要开第二轮。
5. 项目管理中的 gate review / readiness review 设计。

### 语言信号 (用户的话里出现这些就应激活)

- "一阶段发现的问题还没整改完，能不能直接进二阶段？" / "stage 2 before remediation"
- "第一阶段到底审什么、审多深？" / "scope of stage 1"
- "对方文件太烂，这审核还做不做？" / "insufficient documentation, proceed or pause"
- "readiness review 怎么安排？过不了怎么办？"
- "整改计划交了算不算整改完成？"（不算——须验证完成与有效性）

### 与相邻 skill 的区分

- 与 `isms-four-column-checklist-design`：那是单场审核的检查表设计；本 skill 决定"这一场要不要开、能不能进下一场"，位于策划层。
- 与 `isms-nonconformity-grading-loop`：它管发现的分级与关闭判据；本 skill 引用其"有效性验证"结论作为门禁的放行条件，但不重复分级学。
- 与 `isms-combined-audit-planning-calibration`：那是多标准结合审核场景的一阶段后校准（调人日/路径）；本 skill 是通用的阶段门禁模型，先于它成立。

## E — 可执行步骤 (Execution)

1. **定义各阶段目标与买点**：一阶段=信息与判断（要素清单+重点部门+抽样方案雏形），二阶段=全覆盖取证。
   - 完成标准: 一张两阶段对照表——阶段 | 范围 | 对象/部门 | 输出物 | 放行条件。
2. **列门槛问题清单**：以书中五类（法规风险/文件/策划/内审/管评）为底，加上场景特有类目（如供应链准入的许可证冲突、加密出口管制、漏洞响应承诺）。
   - 完成标准: 每类门槛问题配可验证的"整改完毕"判据（证据形式，非口头承诺）。
3. **执行一阶段并记录问题**：按步骤 1 的聚焦范围取证。
   - 完成标准: 问题清单每条附证据指向与责任方。
4. **门禁判定**：逐条核对门槛问题状态。
   - 判停条件: 若仅有整改计划或部分整改 → 不放行二阶段；若基准文件严重缺失（连最起码的体系文件/ SBOM 都无）→ 触发暂停分支，通知各方并书面决定继续或暂停，本流程终止于该决定。
5. **放行后保留校准点**：按一阶段实况（规模、成熟度、风险）调整二阶段计划。
   - 完成标准: 二阶段计划文件中有一阶段信息回填/修订痕迹。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 一次性完成的内审或小范围 review——没有阶段结构，硬拆两阶段是流程空转。
- 单场审核内部的取证顺序问题（先查什么后查什么）——那是取证方法的事，不是阶段门禁。
- 已处于证书有效期内的一次监督审核（门禁逻辑不同，不存在"进二阶段"问题）。

### 作者在书中警告的失败模式

- ce25：带着一阶段的法规风险、文件、策划、内审、管评问题直入第二阶段——顺序性红线。
- ce49：一阶段文件评审只看"有没有"不做四组一致性核对，门禁失去了判据来源（与 `isms-document-consistency-matrix` 衔接）。

### 作者的盲点 / 时代局限

- **版本提示**：两阶段审核是第三方认证的特有流程，书中明确 27001 内部审核并无此分法；本书基于 GB/T19011—2003/27001:2005 与当时的认证机构惯例，现行 IAF 强制性文件及 19011:2018 对两阶段目的、时机（如远程一阶段）已有更细规定——用于现实认证项目须对照现行认可规则，内审使用时按规模裁剪。
- 作者给了门槛问题类别但未给"整改完毕"的量化验收标准，实际依赖 `isms-nonconformity-grading-loop` 的关闭判据（验证完成情况与有效性）。
- 默认第三方认证场景，对普通组织"准入审查"的外推（供应链、供应商）是 verified.md V2 验证的迁移，书内无此类案例。

### 容易混淆的邻近方法论

- 预审核（pre-audit）：书中注明非强制，且预审核不等于第一阶段——两者目的与法律地位不同。
- 敏捷开发的迭代 gate / stage-gate 产品流程：同族"阶段门"思想，但本 skill 的门禁判据是"整改完毕"而非"里程碑达成"。
