# 反滥用识别的三维特征建模与对抗成本评估

## R — 原文 (Reading)

> "如果仔细分析垃圾行为特征，可以大致分成：内容的特征、行为的特征、客户端本身的特征。"
> "Shaun Friedle写了一个GreaseMonkey的脚本，通过JavaScript操作Canvas中的每个像素点，成功地自动化识别了Megaupload提供的验证码。"
>
> — 方法论出处，第 16 章 16.4.2；第 6 章 6.1.4

---

## I — 方法论骨架 (Interpretation)

识别"滥用者"（垃圾账号、爬虫、欺诈者）的特征体系，结构上应该按三个正交维度展开：

1. **内容维**——它生产了什么：文本/链接/图片的静态特征。检测见效最快，也衰减最快（模仿、改写、生成即可绕过）。
2. **行为维**——它怎么行动：注册节奏、操作序列、输入模式、访问路径。模拟成本高于内容维（要伪造一整条行为时间线）。
3. **主体维**——它是谁：账号画像、设备指纹、环境特征。最稳定（换内容换行为也难换设备/账号历史），但单用最容易误伤新用户与共享设备。

三条设计纪律：

- **单维不可依赖**：任一维单独使用，要么被模拟（内容），要么撞上正常用户（行为/主体的巧合），必须交叉验证——多维度同时命中才判滥用，误杀率显著下降。
- **指纹看差异不看自述**：可靠的主体特征来自功能差异与行为结果（各浏览器独有对象、执行能力），客户端自报的字段（UA）随手可伪造。
- **按对手能力重估衰减**：特征的对抗价值不是恒定的——客户端计算能力越强（Canvas 像素处理使验证码自动识别门槛骤降），纯内容/图形类特征衰减越快。评估周期要跟对手的自动化能力挂钩，而不是跟自己的发布节奏。

## A1 — 书中的应用 (Past Application)

### 案例 1: 垃圾行为特征的三维拆分（第 16 章 16.4.2）
- **问题**: 反垃圾规则越加越多，误杀与漏杀并存，特征体系怎么组织。
- **方法论的使用**: 把垃圾行为特征正交拆为内容（文本/链接特征）、行为（频率/批量操作模式）、客户端（环境/设备特征）三维，并指出任一维单独使用易被模拟或误伤。
- **结论**: 三维交叉验证是降误杀的结构性手段，成为反垃圾特征架构。
- **结果**: 该三维体系与"识别后延迟分批处置"（另立技能）配套，构成反垃圾运营的完整方法。

### 案例 2: 浏览器识别——功能差异而非 User-Agent（第 3 章 3.2.2.3）
- **问题**: 服务端按 UA 识别客户端类型与版本，为何既不准又不可信。
- **方法论的使用**: 主体维的实现改用功能差异探测：逐级检查各浏览器独有对象（ActiveXObject、window.opera、styleSheetSets 等）判定版本，"几乎不会误报"；配套一行式指纹（如 `(function x(){})[-5]=='x'`）可压进长度受限的注入点。
- **结论**: "通过分辨差异判断，比读取 User-Agent 准确得多"——自述字段不可信，差异行为可信。
- **结果**: 功能差异识别成为主体维指纹的范式，服务端识别伪造客户端同理。

### 案例 3: Canvas 破解验证码——特征衰减的实证（第 6 章 6.1.4）
- **问题**: 图形验证码在设计时被认为"机器认不出来"，凭什么重新评估。
- **方法论的使用**: 按对手自动化能力重估：GreaseMonkey 脚本用 Canvas 逐像素操作完成灰度化→阈值分割→字符分离，在浏览器环境内自动识别验证码——原本需要本地图像处理能力的攻击门槛骤降。
- **结论**: 纯图形类对抗的强度随客户端可计算能力衰减；验证码只能当辅助手段（与 Token 分层），且要按"攻击者当前可得的自动化能力"计算成本曲线。
- **结果**: "评估对抗方案要按对手当前能力，不按设计时技术水平"成为量化原则。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 从零设计反垃圾/反爬/反欺诈系统，或重构混乱的规则堆。
2. 现有识别系统误杀严重（正常用户被拦）或漏杀严重（批量注册刷量），找结构原因。
3. 评估验证码/人机挑战/设备指纹方案还能撑多久（对手自动化能力变化）。
4. 出现新型滥用（AI 生成内容、群控设备），决定特征体系怎么扩展。
5. 给识别系统定"命中阈值"：多维特征如何组合判定。

### 语言信号 (用户的话里出现这些就应激活)

- "垃圾注册/爬虫/羊毛党太多了，怎么设计识别？"
- "风控规则误杀太多正常用户。"
- "设备指纹/验证码还能用吗？"
- "特征要怎么选、怎么组合？"
- "anti-spam feature design / bot detection features / false positive too high / is captcha still effective"

### 与相邻 skill 的区分

- 与 `whitehat-signal-reliability` 的区别: 那个裁决"单个信号可不可靠"（可伪造/可缺失分级）；本 skill 设计"特征体系怎么架构"（三维展开+交叉+衰减管理）。单点判断用那个，体系设计用本 skill。
- 与 `whitehat-delayed-enforcement` 的区别: 那个管"识别之后怎么处置"（延迟/分批，防规则被探测）；本 skill 管"识别本身怎么做"。识别与处置必须解耦，两个 skill 恰好各管一端。
- 与 `whitehat-requirement-decomposition` 的区别: 那个把"要更安全"拆成威胁条目；本 skill 是某条威胁（防滥用）落地为特征工程的方法。

## E — 可执行步骤 (Execution)

当 skill 被激活后， agent 应按以下步骤执行：

1. **按三维展开特征**：分别列内容维（文本/链接/图像统计）、行为维（节奏/序列/输入模式/会话路径）、主体维（账号历史/设备指纹/环境一致性）候选特征。
   - 完成标准: 每维至少有 3 个候选特征，各标注数据来源与采集时机。
2. **评估单维可靠性与误杀面**：对每个特征问——被模拟的成本多高？正常用户命中（误杀）的概率多大？
   - 完成标准: 每特征有"对抗成本（高/中/低）× 误杀面（大/中/小）"标注；自述类字段（UA、客户端自定义头）直接降级或剔除。
   - 判停条件: 若某维完全无数据可采（如无登录体系的内容站缺主体维），显式记录体系缺口并补替代锚点（隐私合规的设备信号），不硬造特征。
3. **设计交叉判定**：多维组合评分/规则（如内容+行为同时命中才处置；仅内容命中只进观察池），误杀代价高的动作（封号）要求更高维度证据。
   - 完成标准: 判定矩阵明确"几维命中→什么动作"；有对照的正常样本集验证误杀率。
4. **标注衰减预期与重估周期**：为每个特征标注预期衰减因子（对手自动化能力：打码平台/无头浏览器/生成模型），定重估节奏与衰减告警指标。
   - 完成标准: 有"特征 × 对抗手段 × 当前是否仍有效"的复审表与负责人。
5. **接入处置与回流**：识别结果交给与处置解耦的执行策略（延迟/分批，见处置技能）；被绕过的样本回流为新特征素材。
   - 完成标准: 处置动作不直接暴露命中维度；有绕过样本回流管道。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 无对抗性的普通分类/推荐问题——没有"对手在适应"的前提，三维正交与衰减管理是过度设计。
- 单个信号够用的小场景（内部工具限速）——直接配置即可。
- 把它用于"用户画像/增长分析"——本 skill 的输出服务于对抗性处置，滥用画像做营销属合规问题。

### 作者在书中警告的失败模式

- 单维依赖：只用内容特征（关键词过滤）被拆分/改写绕过（Samy Worm 字符串拆分）；只用行为/主体特征误伤正常用户。
- 相信自述字段：UA、客户端头可任意篡改——"识别看行为与功能差异，不看自述"。
- 静态评估对抗方案：验证码按设计时技术水平评估强度，Canvas 类能力演进使其提前失效——衰减要按对手当前能力重估。

### 作者的盲点 / 时代局限

- 2014 年的对抗生态（打码平台、代理猎手）之后已升级（无头浏览器、群控、生成式 AI 使内容维几乎瞬时失效）——三维架构与衰减管理不变，但各维的初始可信度需按当代对手重标。
- 未讨论特征采集的隐私合规边界（设备指纹在 GDPR/个保法下的合法性），现代落地需与数据最小化联合设计。

### 容易混淆的邻近方法论

- 信号可靠性分级：三维中的每个特征仍要过"可伪造成本"检验——本 skill 定架构，那个定单点可信度，组合使用。
- 检测规则保密（不可预测性的运营面）：规则不下发客户端、只给黑名单——与本 skill 的交叉判定互补：架构决定"看什么"，保密决定"对手看得到什么"。
